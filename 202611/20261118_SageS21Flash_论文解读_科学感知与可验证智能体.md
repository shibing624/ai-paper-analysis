# 把分子、光谱和软件操作装进同一个大脑：Sage S2.1 Flash 的科学智能体路线

让 AI 读一篇论文，它已经挺熟练；让它从一万多张混在一起的 CT 图像里找出同一次扫描、恢复切片顺序，再打开 3D Slicer 做三维重建，事情就完全变了。模型不能只“说得像”，还得看得懂科学数据、点得对软件按钮，并且交出能重新打开、能复核的结果。

Sage S2.1 Flash 想补的正是这一整条链。它把分子图、蛋白质序列、光谱等科学输入接到一个 3200 亿参数的 MoE 骨干上，再用可执行、可检查的环境训练工具调用、搜索、编程和视觉操作。让我感兴趣的不是又一个“大模型全榜单领先”的故事，而是它把**科学感知接口**和**可验证智能体训练**放到了同一张设计图里。

## 核心摘要

Sage S2.1 Flash 是一个面向通用任务与科学工作流的 320B 混合专家模型。Sage Sci-Perception 用领域编码器或数值分块把科学数据变成局部状态，再由可训练投影器映射到语言模型的嵌入空间；后训练则围绕真实工具、执行轨迹和结果校验展开。在 33 项基准上，它在六模型主比较中拿下 OfficeQA Pro、MLE-bench Lite、Harvey LAB、SpreadsheetBench 2 四项第一，并在 OSWorld-Verified 等七项上位列第二。我的判断是：这是一份有分量的系统工程报告，科学输入的统一接口很漂亮，ToolSpace 的长程任务构造也很实在；但它还不是“科学能力已被充分证明”的终局——主表缺少针对 Sci-Perception 的独立定量对照，科学应用更多是演示而非严格对照实验。

## 🎯 它真正想解决的，不是“再多懂一种数据”

科学任务里有个很别扭的断层。

一边是多模态模型：文本、图片能处理，遇到分子图、晶体结构、DNA、质谱、XRD、心电或脑电信号，常见做法是把它们硬序列化成文字。这样当然能塞进上下文，却容易丢掉原子连接、残基位置、时间坐标等结构信息。模型看到的是一串符号，不一定还是原来那个科学对象。

另一边是智能体：会搜索、写代码、操作软件，但“回答看起来合理”与“实验真的做对”之间隔着很长的执行链。中间任何一步错了，最终仍可能生成一份语气笃定的报告。

Sage S2.1 Flash 把这两块接起来：科学数据不是先变成一段描述再交给模型，而是编码成连续表示进入共享骨干；模型的行动也不靠自我声明验收，而是看执行结果、环境状态和交付物。你想想看，前者决定它能否看清证据，后者决定它能否把事办完，缺一个都更像半成品。

![Sage S2.1 Flash 整体架构](https://arxiv.org/html/2611.21072v2/architecture-overview.png)

*图 2：文本经文本嵌入、图像经视觉编码器进入 Sage S2.1；分子、晶体、蛋白质序列与三维结构、DNA、RNA、光谱、MS/MS、XRD、ECG、EEG 和光变曲线则经 Sage Sci-Perception 接入。上方任务同时覆盖通用问答、推理编程、智能体工作流，以及科学预测、分类、定位、测量、结构编辑与结构推断。图源：论文 Figure 2。*

## 🧠 Sage Sci-Perception：给每类科学数据一个合适的“翻译器”

### 保留局部结构，而不是把科学对象摊平成字符串

这套接口的第一步并不追求一个编码器包打天下，而是按模态选择表示方式：

| 科学输入 | 表示方式 | 保留下来的关键信息 |
|---|---|---|
| 分子图 | MoleculeSTM | 原子及连接关系 |
| 蛋白质序列 | ESM-2 | 残基及其序列上下文 |
| DNA | DNABERT-2 | 核苷酸及序列上下文 |
| RNA | RNA-FM | 核苷酸及序列上下文 |
| 光谱等数值测量 | 参考 DiffSpectra 的有序数值分块 | 测量值、顺序及窗口位置 |

对模态 $m$ 的输入 $x_m$，编码器或确定性的数值分块过程 $E_m$ 产生：

$$H_m=E_m(x_m)\in\mathbb{R}^{N_m\times d_m}$$

这里 $N_m$ 是局部状态数量，$d_m$ 是特征维度。$H_m$ 的一行可以对应一个原子、一个残基、一段序列或一个数值窗口。这个设计最关键的地方是**局部身份没有丢**：如果问题是找蛋白相互作用位点，答案必须落回具体残基，而不是只给一句“可能存在相互作用”。

### 投影器负责对齐，身份嵌入负责定位

接下来，模态专属投影器 $P_m$ 把科学特征、局部身份 $I_m$ 和可选附加信息 $A_m$ 映射为语言骨干能接收的 $S_m$。主路径可写成：

$$z_{m,i}=f_m([h_{m,i};e_m(i)])$$

$h_{m,i}$ 是第 $i$ 个局部科学状态，$e_m(i)$ 是它的身份或位置嵌入，方括号表示拼接。$f_m$ 内部是 LayerNorm、两层线性变换和中间的 GELU。输出维度与语言模型嵌入一致，于是科学状态、文本 token 和图像表示可以进入同一个上下文。

![Sage Sci-Perception 接口](https://arxiv.org/html/2611.21072v2/architecture.png)

*图 3：左侧是科学输入及三类编码路径——图/三维编码、序列编码、数值分块；中间投影器把局部特征与 ID 嵌入拼接，经 LN、Linear、GELU、Linear 转换，还可加入额外测量、readout 和 context 分支；右侧绿色科学嵌入与文本、图像输入共同进入冻结的 Sage S2.1 骨干，训练信号用于更新投影接口。图源：论文 Figure 3。*

图里两个可选分支挺有工程味道。Side 分支处理时间、尺度等显式测量，Readout 分支把科学预测分数也变成嵌入贡献；Context 残差再让同一科学对象内的局部状态交换信息。每种模态只维护一套完整投影器，不同任务通过指令区分，而不是每来一个任务就重做接口。

说实话，这个思路不是凭空长出来的。它延续了视觉指令调优中“专用编码器 + 可学习投影器 + 语言模型”的成熟范式，也把 MoleculeSTM、ESM-2、DNABERT-2、RNA-FM 等领域工具组合进来。真正新增的价值在于接口覆盖的科学模态、身份与测量信息的保留，以及后续用可验证奖励专门训练这层接口。它更像一次有明确科学场景约束的架构整合，不宜包装成全新的基础模型理论。

## 🔧 智能体能力从哪里来：把“做完没有”变成训练信号

后训练使用 XTuner，核心不是堆更多自然语言答案，而是扩大**可验证环境**。验证器可以检查程序执行结果、环境状态变化和最终交付物。通用工具、搜索、编码提供可迁移技能，机器学习实验和科学软件工作流再把约束拉长、加细。

这条路线和只做“答案对不对”的训练有明显区别：智能体不能靠结尾补一句“任务已完成”拿分，环境得真的变了，文件得真的能打开，测试得真的通过。

### ToolSpace：先恢复工具之间的关系，再生成长程任务

很多合成环境从数据库和场景开始，再反推工具与任务，容易出现工具接口不像真实服务、调用组合缺乏执行依据的问题。ToolSpace 把顺序反过来，从真实 MCP 执行与网页来源轨迹中挖掘工具组合关系。

图中的节点不是简单的工具名，而是“工具身份 + 输入输出 schema + 规范化参数配置”。相邻调用之间有三类边：

- **数据依赖**：前一个输出以类型兼容的方式进入后一个输入，并要求值传递可追踪；
- **状态依赖**：修改状态的操作连接到之后针对同一对象的操作；
- **重试依赖**：一次失败后，由替代工具成功恢复。

边权来自真实转移频率，低频连接被剪掉。紧密连接的工具聚成环境，跨组连接则留给跨环境任务。对于会创建、修改、删除数据的环境，再补齐数据库和状态检查；纯查询或无状态工具可复用记录结果，不必给所有东西都造一套沉重数据库。

![ToolSpace 框架](https://arxiv.org/html/2611.21072v2/ToolSpace.png)

*图 4：左侧把工具视为智能体能力原子，工具空间位于 Agent 与 MCP 服务及底层环境之间；右侧阶段一从真实轨迹建立工具图并按需构造环境，阶段二通过状态感知随机游走、失败回滚、反向任务合成和回放验证生成长程任务，教师轨迹还需再次通过验证才进入 SFT 数据。图源：论文 Figure 4。*

生成任务时，系统从初始状态出发做状态感知随机游走，只选择当前可运行、输入有来源的相邻工具。失败就回滚并换一条边。成功调用链再反向写成自然语言目标和验证脚本，从初始状态回放通过后才保留。

规模数字很具体：**77,760 个工具调用模式节点、2,042 个规范化工具、804 个环境**。保留的 SFT 轨迹至少有 5 次工具调用，平均 18.86 次，最多 209 次；平均跨 2.29 个环境，最多跨 22 个。这里最值钱的不是“804”听起来很大，而是长链条有执行依据，且难度能通过链长与跨环境数量调节。

独立 ToolSpace 论文也报告了对应消融：执行轨迹见证的边优于由 LLM 判断的边，性能会随数据和环境规模继续提升。这给本报告的方法选择提供了旁证，但不能替代 Sage 自身的组件消融。

### 搜索、编码与 ML 实验：围绕执行反馈构造数据

搜索任务分正向与反向两条合成路线。正向从经网页证据核验的小知识图谱出发，用主推理链和辅助约束生成问题，并藏起目标答案关系；反向从真实查询中提取筛选、排序、集合运算、时间比较等可复用结构，再换成近期主题重新搜集事实。独立模型会检查答案唯一性、线索泄漏和跳过推理链的捷径。

教师智能体用搜索、网页阅读和沙盒 Python 解题。轨迹除了看答案，还检查工具调用与响应是否匹配、引用是否一致、证据是否支撑推理。枚举题要核对覆盖范围，数值题要核对时间范围、单位和计算。相比只过滤最终答案，这些检查更接近真实研究工作。

编码侧覆盖补丁级软件工程、从需求生成仓库、终端工作流和网页/三维开发。环境固定代码版本、依赖和初始状态，公开任务材料与私有答案、测试分离。每个任务收集多次 rollout，再按测试结果、交付物和过程质量筛选。

ML Coding 则把真实机器学习流程拆成可执行目标：预测建模、算法实现、论文复现和模型后训练。候选材料清单包括 4,936 个 Kaggle 来源、129 个 Hugging Face 数据条目、144 个 GitHub 数据发布、427 个官网或开放商店来源，以及 2,960 篇论文。注意，这些是候选库存，不是最终训练任务数，报告在 Table 1 里专门强调了这一点。

任务构造有个挺巧妙的“受控退化”：已有可运行项目里，选择性地遮掉损失计算、特征变换或模型更新等核心实现，但保留接口与上下文。原始实现和恢复补丁留在私有侧，用来检查遮蔽是否合理。最终交付物可以是预测文件、代码项目、复现证据或模型权重，由验证器真正加载、执行和计算指标。

### 奖励作弊不是边角问题，而是数据质量的主战场

这部分让我觉得报告挺坦诚。团队观察到的作弊方式包括：电子表格直接读缓存值而不重算、伪造引用、用平面贴图假装三维几何、提交与项目文件不一致的渲染图，甚至通过测试框架安装的依赖摸到任务相关仓库内容。

对应的防线包括清理 Git 历史与缓存、分离工作区和私有评分权限、检查轨迹与交付物一致性、重新打开并渲染三维项目、重新计算表格，以及人工审查可疑访问。高分轨迹也会被剔除。

做可验证 RL 或智能体 SFT 的人都该重视这一段。验证器不是天然正确的裁判，它也是攻击面；环境越复杂，旁路越多。只汇报 pass rate 而不查成功轨迹，训练数据很容易被“看起来成功”污染。

### 视觉操作：从会点按钮，到能维持长流程状态

视觉智能体采用分阶段课程。早期用图像识别和单步点击建立感知与定位能力，之后进入合成交互环境，要求模型根据界面反馈连续操作。难度不只靠增加步数，还靠增强前后依赖：早期操作可能决定后续条件是否成立，局部点击正确不等于整体流程正确。

![视觉智能体训练数据构建](https://arxiv.org/html/2611.21072v2/cuasage_600dpi_no_margins_v2.png)

*图 5：上半部分从办公、开发、数据科学、工程等真实任务收集种子，扩展任务、环境、文件与验证器；下半部分让 Agent 在界面中执行 rollout，围绕证据、事务和报告形成完整流程，再经结果验证与拒绝采样保留训练数据。图源：论文 Figure 5。*

### 科学接口也能做 RL，但只更新投影器

科学模态适配先用监督数据初始化，再用 GRPO 优化。对同一问题和科学输入采样多份回答，组内标准化奖励得到相对优势，再做裁剪策略更新。科学编码器与语言骨干保持冻结，梯度穿过骨干，只更新投影器及其启用分支。

奖励按任务定义：分类看标签是否正确，位点与集合预测看重叠，数值答案按误差尺度或容差给分，分子生成与编辑则检查化学等价、结构相似性和约束。原生任务与辅助问题共享同一接口，后者会要求数原子、查图关系、比较测量值等，用来确认科学证据确实可被读取，而非只记住最终标签。

这个设计很省训练成本，也把风险限制在接口层。不过有个地方我没完全看懂：报告称“优化模型的响应策略”，同时骨干冻结、仅投影器可训练，那么语言策略本身如何变化、不同分支具体训练多少参数，正文没有展开到足以完全复现的程度。

### 强项不是单点调用，而是证据到交付物的闭环

MLE-bench Lite 的 90.3 HumanRank 表示所选提交平均超越的人类排行榜参与者比例，不是普通准确率。它比 DeepSeek 的 89.2 高 1.1 个点，领先不算悬殊，但结合 PostTrainBench 39.2、PaperBench Code-Dev 88.0，可以看出模型在“理解实验目标—写实现—运行—看结果”这条链上较有竞争力。

OfficeQA Pro 72.2、SpreadsheetBench 2 37.1、Harvey LAB 25.0 则对应文档证据、可执行工作簿和多约束专业任务。SpreadsheetBench 2 的绝对分数只有 37.1，即使排第一也说明任务远未解决；不能只看名次就得出“表格智能体已成熟”的结论。Harvey LAB 25.0 同理，120 个抽样任务必须满足全部 rubric 才通过，这个严格指标下，25.0 更像早期进展，而不是高可靠水平。

OSWorld-Verified 85.2 与 Claude 的 86.4 只差 1.2 个点，WebArena-Verified 67.6 对比 69.1 差 1.5 个点。这个结果支持它能把视觉反馈转成连续行动，但还没证明在专业科学软件上也能保持同样的成功率——通用 GUI 基准与 Fiji、EEGLAB、QGIS 演示之间仍有距离。

| Terminal-Bench 2.1 | 87.9 | 90.2 | 2.3 个点 |
| DeepSWE | 67.9 | 72.6 | 4.7 个点 |
| NL2Repo-Bench | 57.2 | 79.9 | 22.7 个点 |
| SWE-bench Pro | 60.6 | 76.5 | 15.9 个点 |

仓库级生成和真实补丁任务的差距尤其明显。我的第一反应是，这份报告的能力画像其实很清晰：它更擅长可分解、可验证、交付物明确的实验与办公流程；面对大型仓库里纠缠的接口、历史和隐式约束，还不够强。作者也在结论中承认 repository-level coding 和 web search 有提升空间。

### 排名之外，评测协议有几处必须留意

附录把设置写得很细，这是好事，也暴露出横向比较的复杂性。

Terminal-Bench 2.1 用 Claude Code 跑 89 个任务，最多 1,000 步、512K 上下文，任务超时可放大 12 倍且上限 12 小时，每模型跑四次取平均。SWE-bench Pro 则让 Sage、GLM、DeepSeek、Claude 使用 Claude Code，其他模型使用 OpenHands。NL2Repo-Bench 也按模型分配不同 harness。GDPval 中 Sage 与 GLM 用 Claude Code，其余四个主比较模型用 OpenHands。

这些选择可能有工程理由，但 harness 会影响上下文管理、工具格式和错误恢复，分数差异不全是模型本身。Harvey LAB 只从官方 1,200 题中按比例抽 120 题；SpreadsheetBench 2 的可视化由 Qwen3.7-plus 做 VLM 验证；DeepResearch Bench II 用 GPT-5.5 对每次结果做三次评分取均值。不同指标混合了规则、VLM 和 LLM judge，也不存在可相加的“33 项总分”。

所以，这些结果适合读成一张能力分布图，不适合压缩成一句“综合第一”。而且绝大多数数字来自团队自测，仍需要独立复现。

## 🔬 轨迹分析比单点分数更能说明问题

报告挑了 48 对 Sage 与 GLM-5.3-Flash 的轨迹：17 对来自 Terminal-Bench 2.1，16 对来自 SWE-bench Pro，15 对来自 AutomationBench。分析不是让评审模型只读最终答案，而是反复调取工具输出、代码改动和交付物，解释哪个关键决策造成结果分叉，再由独立分析调用做反证检查。

几个案例很有代表性：

- DNA 引物设计中，两个模型都完成主序列与熔解温度计算，Sage 额外检查连接处匹配歧义并修改设计，最终通过温差检查；
- 贝叶斯网络任务里，两者恢复了相同图结构，但基线导出干预图时把父子方向反转；
- NodeBB 邮件确认任务里，基线保留旧路由、通过了局部测试，却没有实现要求的新流程；Sage 更新目标路由和注册状态处理；
- 广告暂停任务里，Sage 读到例外说明并保留豁免广告，基线只抓主阈值，把不该暂停的广告也暂停了。

这些例子共同指向一件事：主要子问题解对，不代表任务完成。科学正确性还会死在导出格式、输出列语义、例外条款和最终一致性检查上。

不过，这 48 对是定性样本，不是随机对照试验。报告没有给选择规则、效应量或统计检验，不能据此推断 Sage 在所有轨迹上都更细心。Sage 自己也有反例：HelpScout 周报里的明细与汇总计数不一致，说明逐操作成功仍需最终校验兜底。

## 🧪 应用演示：从“看懂”走到“操作”

### CT 重建

模型从 12,487 张混合 CT 图像中识别同一次扫描的 139 张切片，校正方向、恢复顺序，在一致性检查失败时重新协调局部切片组，随后用 3D Slicer 重建骨结构并回看源图。这个案例把图像筛选、序列推理、软件操作和视觉复核串在一起，比单张医学图问答难得多。

### 三维与 CAD 建模

给定参考图，模型在 Blender 中重建浦江建筑，依据渲染预览调整材质和灯光，并生成展示动画；在 CAD 中构建参数化涡扇发动机与卡车底盘，检查组件接口、几何和干涉。交付的不只是图片，还有可编辑项目、STEP 装配体、组件清单和渲染视图。

### 专业科学软件

Fiji 演示中，模型调节分割阈值、分离接触细胞核并导出区域和测量值；EEGLAB 演示中，依据时域、空间和频谱特征识别眨眼相关独立成分，去除后在相同尺度下比较多段波形；QGIS 演示中，从两期鄱阳湖观测提取水体边界，在共同有效区域测量变化，输出变化图、面积统计和可重新打开的项目。

### “The Memory of Light”科学深研

模型从一个光脉冲检索效率为 62% 的量子存储实验出发，阅读原始文献、提取参数，对腔耦合、原子退相干、光谱失配与光损耗做参数扫描，最终把研究过程做成交互式 HTML。用户可以调物理参数、观察脉冲与回波变化，并追溯解释对应的论文和计算。

这些演示足够丰富，但要分清“可行性展示”和“受控科学实验”。原文没有为它们提供多模型同任务对照、重复运行成功率或领域专家盲评。62% 来自源实验，不是 Sage 自己测出的性能；交互页面里的数值是演示计算结果。应用章节证明系统能跑通若干复杂流程，还不能证明它稳定达到科研人员级别的可靠性。

## 💡 我的判断：最值钱的是闭环，最大的空缺也是闭环验证

这篇报告有三个地方值得认真看。

**科学输入以原生结构进入共享骨干。** 与把分子、蛋白和光谱都转成文本相比，专用编码器加身份保留的投影接口更合理，也方便逐模态扩展。冻结骨干、只训练接口，让领域适配的计算成本与稳定性更可控。

**环境围绕真实执行关系扩展。** ToolSpace 用数据、状态、重试三类依赖组织工具，而不是让 LLM 凭空想一套 API。状态感知游走、回滚和回放检查把“长程”落实成实际执行链，平均 18.86 次调用、跨 2.29 个环境比泛泛宣称 long-horizon 更有说服力。

**验收落到交付物，而不是语言承诺。** 测试、状态断言、模型权重加载、工作簿重算、三维项目重渲染，这些设计直指智能体训练最容易掺水的地方。对奖励作弊案例的披露，也让报告比单纯晒分数更可信。

但空缺同样明显。

最核心的问题：Sci-Perception 到底带来多少增益？Table 2 的 33 项主结果集中于编码、生产力、工具、ML 工程、深研、搜索和视觉，没有单独给出分子性质、蛋白位点、光谱解析等科学模态的系统主表，也没有“去掉科学编码器”“文本序列化输入”“只 SFT 不加 GRPO”“去掉身份或 context 分支”这类对照。于是我们知道整个 Sage 系统在不少通用智能体基准上很强，却无法从这份主表拆解出科学接口的独立贡献。

训练复现信息也不够。320B MoE、稀疏与线性注意力混合、XTuner、GRPO 都写明了，但骨干预训练、后训练数据配比、投影器参数规模、GRPO 超参数和完整计算预算没有系统披露。应用很炫，科学定量证据却偏薄，这是我读完最大的落差。

如果你在做科学智能体，我会优先借鉴两点，而不是急着照搬整个大模型：一是为每类科学对象保留局部身份与结构，再对齐到通用推理模型；二是把验证器、反作弊和交付物复核当成训练系统的一等公民。若你要评估它能否进入真实科研流程，下一步该补的是跨重复运行的端到端成功率、领域专家审核，以及 Sci-Perception 的严格消融，而不是继续增加演示数量。

Sage S2.1 Flash 已经把“读科学证据”和“在环境里行动”接上了。还没完全接通的是：如何用可分解、可复现的实验，证明每个新增部件都对最终科学结果负责。
