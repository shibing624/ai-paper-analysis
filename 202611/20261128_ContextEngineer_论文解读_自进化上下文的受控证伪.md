# 让大模型自己给自己写提示词，怎么就不灵了？

你有没有干过这么一件事：把一个 Agent 跑出来的失败轨迹喂给模型，让它"反思一下，总结经验"，再把这段经验塞回系统提示词，期待下一轮它就变聪明了？

我做过。还挺上头的——看着 prompt 一轮比一轮写得漂亮，条目从三条涨到二十条，什么"避免冗余输出""注意格式约束""多步规划前先拆解子目标"，读起来像一份像模像样的作战手册。然后一上线，准确率纹丝不动，偶尔还倒退两个点。

当时我把它归因为"经验写得不够好"。直到看到 arXiv:2611.30494 这篇 *Revisiting LLMs as Context Engineers*，我的第一反应是：坏了，问题可能根本不在经验写得够不够好，而在**模型压根就没能力从一堆各不相同的失败里，抽象出一条真正管用的原则**。

---

## 🎯 核心摘要

这两年"让 LLM 自己当上下文工程师"（LLM Context Engineer，下文简称 LCE）特别火：不改一个参数，只让模型从离线试验里抽取指令或经验、反复改写上下文，就能自我进化。ACE 那篇报告在 AppWorld 上比 ReAct 基线涨了 17.0%，看着像白捡的性能。但这篇论文没去卷新方法，而是搭了个统一基准，把 4 类 LCE 方法、3 个 8B 模型家族、5 个推理模式各异的数据集摆到同一张桌子上做受控对照。结论挺扎心的：没有任何单一方法通吃，连 CoT 这种简单基线都常常赢；把模型从 0.6B 拉到 235B、换新世代、加生成迭代，LCE 的收益依旧不成系统。作者还挖出一条统计上成立的规律——LCE 增益与推理轨迹失败模式的多样性呈负相关（$r=-0.5,\ p\le0.05$）。机制拆解更狠：不少涨点来自"格式遵循变好"，用 LLM 答案抽取器一归一化，GEPA 在 MATH500 上的 +3.50 直接变成 -0.50。

我的判断：这不是一篇给你新工具的文章，是一篇把整条赛道的评估漏洞摊开给你看的证伪型工作。做 Agent 自进化的人值得花一小时细读，尤其后面那几组消融。

## 🤔 先聊聊这个范式为什么让人上头

训练派的路线很贵。RLHF 要堆偏好数据，GRPO 要几十万条 rollout，改的是参数。另一条路就聪明得多：参数一个不动，只在文本空间里做优化。

这个想法有个很漂亮的来历。回到 2023 年前后，Automatic Prompt Engineer 开始让模型自己搜指令候选；Optimization by Prompting（OPRO）把 LLM 当成迭代优化器；TextGrad 借了反向传播的壳，用自然语言当"文本梯度"往回传；Reflexion 让模型对失败做口头反思，下一次尝试带上这段自我批评。再往后，DSPy 把整套流程工程化，MIPROv2 和 GEPA 在里面做候选采样与反思式突变，TF-GRPO 从成功/失败 rollout 的对比里抽"语义优势"，ACE 干脆维护一份不断演进的 playbook，靠 Generator、Reflector、Curator 三个角色分工，用增量 delta 更新防止"上下文塌缩"。

说到底，这些方法的共同设定就一句话：**把优化循环里的梯度换成文本反馈，把参数更新换成上下文重写**。写成一行更直观：

$$\pi_{t+1} = \mathcal{U}\Big(\pi_t,\ \mathcal{R}\big(\{(q_i,\ \tau_i,\ y_i)\}_{i=1}^{N}\big)\Big)$$

$\pi$ 是上下文（系统提示词，或者一池子经验条目），$\mathcal{R}$ 是反思器，从离线轨迹 $\tau_i$ 和反馈 $y_i$ 里吐出文本反馈，$\mathcal{U}$ 是更新算子。跟 SGD 的骨架一模一样，只是所有运算都发生在字符串上。这行式子不是论文的编号公式，是我把作者的设定压成一句话，方便后面拆解瓶颈到底卡在哪一环。

听着确实像人类从经验里学习。但有个前提一直没人认真验证：**这些"经验"，模型真抽得出来吗？**

## 🧠 作者没提新方法，先修了一张桌子

坦率地讲，我觉得这篇最值钱的地方不是结论，是它先指出了一个场子里的混乱：大家各说各话。

ACE 那篇（arXiv:2510.04618）报的是 DeepSeek-V3.1-671B 在 AppWorld 和金融任务上的成绩，离线设置下 ReAct + ACE 比基础 ReAct 平均涨 17.0%，比 ReAct + ICL 高 12.3%、比 ReAct + GEPA 高 11.9%，在线设置还能再比 Dynamic Cheatsheet 高 7.6%。GEPA 那篇报的却是 Qwen3-8B 和 GPT-4.1-mini 在 MATH、多跳问答上的结果。

671B 对 8B，Agent 任务对数学题，连基线都不是同一个。这些数字彼此没法比，可"LCE 能自我进化"的印象就这么靠一篇篇独立报告堆起来了。看到这个对比我有点皱眉——不是怀疑谁造假，是这套评估协议天然允许挑对自己有利的场地。

于是作者干了件笨功夫：搭统一基准。

![图1：论文总览——左侧 Benchmark 汇总了 3 个 8B 模型家族（Qwen/Gemma/Ministral）、4 类 LCE 方法和 5 类任务，结论是"No clear winner among LCEs"；中间 Scaling 展示 Reflector→Generator 的上下文流、0.6B→235B-A22B 的参数缩放和 Qwen1.5→Qwen3.5 的世代缩放，结论是"Scaling may not enable LCEs"；右侧 When & How 点出低失败模式多样性更容易抽象出共享原则，而案例研究显示 LCE 改善的是指令遵循与经验抽取](https://arxiv.org/html/2611.30494v1/figs/overview3.png)

*图1（论文 Figure 1）：整篇论文的三段式路线——统一基准、缩放检验、机制拆解。右下角那两行小字其实已经把结论剧透了：LCE 能改善的是 answer format 和 conciseness，而 Experiences Extraction 才是关键瓶颈*

**数据集按推理模式分了四类**，不是随便凑几个榜单：

| 推理模式 | 数据集 | 模型得干的事 |
|---|---|---|
| 推理解答 | MATH500、HotpotQA | 一步步算出答案 / 多跳找证据 |
| 长上下文检索 | HotpotQA、MiddleMatch | 从一长串文本里定位目标 |
| 遵循未见约束的指令 | IFBench | 按训练里没见过的格式要求输出 |
| 多步规划执行的智能体任务 | AppWorld | 跟 App 环境反复交互、调工具 |

MiddleMatch 值得单独说一句：它的题目全是固定模板生成的——"给你一串名字，找出恰好夹在 X 和 Y 之间的那个名字"。同质到近乎机械。后面它会成为整篇论文的关键对照组。

模型选了三个 8B 量级的不同家族：Qwen3-8B、Gemma-4-E4B-it（文中简称 Gemma4）、Ministral-3-8B-Instruct-2512-BF16（简称 Min3）。基线是两个不迭代的朴素方法：CoT（"Solving the problem step by step"）和 ICL（用成功 rollout 当演示，还额外补了逐步推理过程，不算放水）。

四个被检验的 LCE 方法，按"上下文长什么样"分成两派：

| 方法 | 上下文 $\pi$ | 主策略 | 来源脉络 |
|---|---|---|---|
| TextGrad | 系统提示词 Sys | 文本梯度反向传播 | 借神经网络反向传播的壳 |
| GEPA | 系统提示词 Sys | 文本反思 + 突变采样 | DSPy 生态 |
| TF-GRPO | 经验池 Exp | 组相对文本优势 | 对比成功/失败 rollout |
| ACE | 经验 + 元数据 Exp + metadata | 文本反思、增量累积 | 演进式 playbook |

前两个重写 prompt，后两个往上下文里注入蒸馏出的经验条目。这个区分后面解释 ACE 为什么"不太吃失败多样性"时会用上。

## 🔬 第一记闷棍：验证集一片大好，测试集现原形

![图2：四个数据集上的验证集性能增益柱状图，TF-GRPO、GEPA、ACE、TextGrad 对比](https://arxiv.org/html/2611.30494v1/figs/benchmark/val2.png)

*图2（论文 Figure 2）：验证集增益。IFBench 上 ACE 冲到 30 点附近、GEPA 约 17 点；MiddleMatch 四个方法全为正；但 HotpotQA 上 TextGrad 直接砸下去约 16 点（红色柱），误差棒还特别长*

先看这张图，LCE 简直赢麻了。TF-GRPO、GEPA、ACE 在四个数据集上一致涨；MiddleMatch 和 IFBench 所有方法都涨，ACE 在 IFBench 涨超 20 点，GEPA 涨超 10 点；MATH500 和 HotpotQA 上三家只有边际增益，TextGrad 最惨，在 HotpotQA 掉了 15 点以上。

如果故事停在这儿，就是又一篇"自进化有效"的顺风顺水报告。

但作者的上下文是在**验证集**上挑出来的，测试集另算。转到 Table 2，画风突变。我把 Qwen3-8B 那一整块原样搬过来（单位 %，括号内是相对各方法初始上下文的变化，粗体为该行最佳）：

| 数据集 | CoT | ICL | TF-GRPO | GEPA | ACE | 最佳 LCE 减最佳基线 |
|---|---|---|---|---|---|---|
| MiddleMatch | 31.27 | **46.07** | 37.73 (+6.47) | 42.33 (+12.53) | 25.20 (+4.73) | -3.74 |
| IFBench | 32.35 | 30.54 | 32.21 (-0.14) | **33.30** (-0.37) | 32.17 (+0.64) | +0.95 |
| MATH500 | **83.20** | 79.80 | 82.10 (-1.10) | 80.60 (-0.20) | 63.80 (-7.30) | -1.10 |
| HotpotQA | **38.00** | 37.60 | **38.00** (0.00) | 32.80 (-1.54) | 33.67 (-3.26) | 0.00 |
| AppWorld | 21.55 | 23.10 | **23.69** (+2.14) | 23.33 (+0.48) | 18.93 (-3.45) | +0.59 |

*表1（论文 Table 2 的 Qwen3-8B 分块）：右边那列是"最好的 LCE 减去最好的简单基线"，星号代表统计上成立*

看到这个数我愣了一下。Qwen3 上五行里，LCE 相对 CoT/ICL 的净优势分别是 -3.74、+0.95、-1.10、0.00、+0.59。也就是说费了半天劲做反思、突变、经验蒸馏，跟一句 "step by step" 打了个平手，MiddleMatch 上还输给 ICL 近 4 个点。ACE 在 MATH500 上更是从 71 分掉到 63.80，自伤 7.30。

验证集涨 20 点、测试集归零——这股味道做过模型的人太熟了：在同一个小验证集上反复挑上下文，说到底就是在几百条样本上做选择，选中了噪声。作者把这一条写得很克制（"gains do not consistently transfer to the test set"），我觉得这是全文最该被划线的句子之一。

换个模型家族，结论又换了一副面孔。Gemma4 上 MiddleMatch 的净优势是 **12.86 个点**（带星号，GEPA 93.33 对 CoT 79.33），IFBench 是 **6.94 个点**；可同一个 Gemma4 到 MATH500 就变成 -4.10，因为 ICL 已经 77.90 了，LCE 最好的 TF-GRPO 才 73.80。Min3 上 MiddleMatch 又是 +9.40（带星号），TF-GRPO 71.40 对 CoT 62.00，而 ACE 只有 38.93。

AppWorld 上 TF-GRPO 拿 Qwen3 最好，ACE 在 Min3 上领跑；LCE 在 Gemma4 的 MATH500 上提升明显，在 Qwen3 和 Min3 上几乎不动；HotpotQA 反倒是对 Min3 帮助最大。作者自己下的词是 "no free lunch"——不同模型、不同数据集，可能就需要不同的 LCE 算法。

这就是没有单一赢家。不是"某方法还差一口气"，是这套收益本身高度依赖场地。

## 📊 第二记闷棍：堆参数、换世代、加迭代，都救不回来

我读的时候一直在等一个转折：是不是 8B 太小了，反思器不够聪明？毕竟 ACE 原论文用的是 671B。这个质疑挺自然的，作者显然也料到了，专门用两张图回应。

![图3：Reflector 与 Generator 规模的消融，上排 Generator=8B、下排 Generator=32B，四个数据集箱线图](https://arxiv.org/html/2611.30494v1/figs/scaling/gr2.png)

*图3（论文 Figure 3）：灰色是 8B 反思器、深灰是 32B 反思器，蓝色标注"32B 更好"、红色标注"32B 更差"，虚线是 CoT 均值。MiddleMatch 上出现 +18.1、+13.2、+11.7 这类大幅正向标注，而 MATH500 下排 GEPA、ACE 被标成红色往下走*

先把两个角色分清楚：Reflector 是生成反思、写上下文的那个模型，Generator 是拿这份上下文去干活的模型。作者让两者在 8B 与 32B 之间交叉组合。

结果特别有意思：**放大 Reflector 救不了原本失败的场地，只会把原本就赢的场地赢更多**。MiddleMatch 上 32B 反思器把 GEPA 推高了 18.1 个点，IFBench 上只有 +1.5、+0.3、+0.7 这种零头；MATH500 和 HotpotQA 上，更大的反思器反而把 GEPA、ACE 拖到 CoT 均值以下（图里那几个红色方块）。

这顶多算"放大器"，不是"解药"。

![图4：参数规模缩放（上排）与模型世代缩放（下排）](https://arxiv.org/html/2611.30494v1/figs/scaling/2x422.png)

*图4（论文 Figure 4）：上排横轴是 Qwen3 从 0.6B、1.7B、4B、8B、32B 到 235B-A22B 的参数刻度，橙色为 GEPA 系、蓝色为 TF-GRPO/CoT 系，虚线是各方法初始上下文；下排横轴是 Qwen1.5-7B→2-7B→2.5-7B→3-8B→3.5-9B 的世代演进*

上排把自反思模型从 Qwen3-0.6B 一路拉到 Qwen3-235B-A22B。MiddleMatch 上 GEPA 和 TF-GRPO 在各个规模都压过 CoT，235B 时差距还拉得更大；IFBench 上两者只在 235B 才勉强追平 CoT，小模型规模上完全写不出管用的上下文；MATH500 和 HotpotQA 上压根没有稳定收益，某些小规模涨了，规模一大又消失。

作者的解读我很认同：**参数变大主要强化的是底层那个干活的 solver，LCE 这一层并没有跟着变聪明**。曲线整体往上抬，是模型本来就会做题了，不是上下文写得更好了。

下排换成世代：Qwen1.5-7B 到 Qwen3.5-9B，任务表现稳步上升，LCE 的增益依旧没有一致趋势。GEPA 在 HotpotQA 上随世代推进增益反而变小，在 MiddleMatch 上却一直保持。没有证据说明"更新的模型更适合当上下文工程师"。

那会不会是优化预算不够、epoch 太少？作者把 K 从 1 拉到 128，用 Pass@K / Best@K 检验上下文到底有没有带来新知识：

$$\text{Best@}K=\mathbb{E}_{\text{problems}}\!\left[\sum_{i=K}^{128}\frac{\binom{i-1}{K-1}}{\binom{128}{K}}\,s_{(i)}\right]$$

其中 $s_{(i)}$ 是 128 个采样里第 $i$ 小的分数，Pass@K 就是分数取 0/1 的特例。思路很直白：如果上下文真塞进了新知识，整条 Pass@K 曲线该被抬起来；如果 Pass@1 的涨点在 K 变大后迅速跟初始版本重合，那点涨头就只是采样运气，学习价值有限。附录还查了优化预算、基线准确率这些因素，都没跟增益挂上钩。

排除了这么多"努力不够"的解释，剩下的可能性就有点刺眼了。

## 💡 那条负相关，才是全文的题眼

作者给失败模式打了个多样性分：让 LLM 从每条失败轨迹里抽出"失败模式"标签，再用 Vendi Score 量化这批标签有多杂（这个指标本身基于相似度矩阵特征值的熵，是通用的多样性度量，不是论文新造的）。然后拿它跟 LCE 的性能增益做相关。

![图5：LCE 性能增益与失败模式 Vendi Score 的相关性散点](https://arxiv.org/html/2611.30494v1/figs/analysis/qwen385.png)

*图5（论文 Figure 5 左）：横轴 Failure Vendi Score（约 3–11），纵轴 Performance gains (%)。图例直接给出各条回归线的相关系数——LCEs 总体 r=-0.464 (p≤0.01)、GEPA r=-0.556 (p≤0.05)、TF-GRPO r=-0.512 (p≤0.05)、ACE r=-0.372 (n.s.)、ICL r=-0.085 (n.s.)。菱形是 MiddleMatch、方块 IFBench、三角 MATH500、圆 HotpotQA、加号 AppWorld*

摘要里那个 $r=-0.5,\ p\le0.05$，是聚合后的整数近似；图上拆开看更细：GEPA 和 TF-GRPO 负相关最强且统计上成立，ACE 次之、不显著，ICL 几乎水平。标点的形状也把结论摆得很清楚——MiddleMatch、IFBench 挤在左侧低多样性区，增益动辄 5–10 点；AppWorld 的加号全堆在右侧高多样性区，围着 0 上下晃，还有掉到 -3 的。

为什么 MiddleMatch 最"纯"？前面说过，它所有题目都来自同一个固定模板，失败原因翻来覆去就那么两三种。AppWorld 最"杂"，因为要跟 App 环境多步交互，工具调错、参数填错、规划断链、状态没跟上……失败长得各不相同。

作者的猜测挺有解释力：GEPA 重写整个 prompt、TF-GRPO 合并筛过的经验，这类"覆盖式"更新在失败模式杂的时候容易把有用知识冲掉；ACE 靠增量累积，反而更能保住零散知识，所以它的增益对多样性没那么敏感——图里 ACE 那条红线确实最平。这算是对 ACE 设计的一个侧面的侧面佐证，虽然 ACE 绝对值未必最高。

![图6：经验的 Vendi Score 随 epoch 的变化](https://arxiv.org/html/2611.30494v1/figs/analysis/delta_vs_exp11.png)

*图6（论文 Figure 5 右）：横轴 epoch 1→3，纵轴是经验 Vendi Score 的变化量，TF-GRPO（绿）、ACE（红）两条线几乎贴着 0 走，置信带也窄*

这张小图我觉得比相关系数更要命。如果 LCE 真在"从经验里学原则"，随着迭代，一堆零散失败该被压缩成几条共享原则，经验的多样性应该往下掉。结果三个 epoch 过去，Vendi Score 变化量在 0 附近几乎不动。

模型没有在做归纳。它更像在**不断往清单里追加条目**，却没把清单变短、变抽象。

![图7：失败模式 Vendi Score 的方差分解](https://arxiv.org/html/2611.30494v1/figs/analysis/vs2.png)

*图7（论文 Figure 6）：纵轴是对数刻度的方差占比，Dataset 一柱接近 90%，Model 约 5%，LCE 只有约 0.3%，Residual 约 20%*

方差分解把责任划得很干净：失败模式有多杂，主要由**数据**决定，跟用哪个模型、哪个 LCE 方法关系很小。这直接堵死了"换个更强的反思器/换个算法就能搞定"的退路——瓶颈是任务本身天然会生出多少种死法。

作者还补了混合效应分析控制其他因素，负相关依然成立。相关性当然不等于因果，这点我自己也留了三分怀疑：多样性高的任务往往本身更难、基线更低、评测方差更大，可能混着没被完全剥离的混杂因素。但配上右图那个"Vendi 不随 epoch 下降"的机制证据，链条就相当完整了。

一句话概括：**LCE 擅长的是"同类错误反复犯"的场景，不擅长"每次都错得不一样"的场景。** 而现实里真正值钱的 Agent 任务，恰恰大多是后者。

## 🔧 拆开来看，涨点到底从哪来的

到这里作者做了两刀很漂亮的解剖。

**第一刀：HotpotQA 上的"假失败"。**

![图8：HotpotQA 上 LCE 行为，横轴 False Failure 率（越低越好），纵轴测试准确率](https://arxiv.org/html/2611.30494v1/figs/analysis/hp8.png)

*图8（论文 Figure 7）：蓝 Qwen3、红 Gemma4、绿 Min3，圆形 TF-GRPO、方形 GEPA、三角 ACE；空心是 Before、实心是 After，箭头从空心指向实心。Min3 从约 38% 假失败率 / 23% 准确率，被拉到约 21% / 31%*

Min3 在 HotpotQA 上有个毛病：答案其实算对了，但输出啰嗦、没按要求的格式收尾，自动判分直接判错。这类"假失败"能占到三成以上。LCE 把上下文调过之后，输出变简洁、假失败率往下掉，准确率跟着抬。

所以那几个点不是推理变强，是**模型终于肯按要求把话说完了**。

**第二刀：MATH500 上的格式遵循，以及那个致命的抽取器消融。**

![图9：MATH500 上格式遵循率与测试准确率的关系](https://arxiv.org/html/2611.30494v1/figs/analysis/math9.png)

*图9（论文 Figure 8）：横轴 Format Compliance (%)，纵轴 Test Acc (%)。Gemma4（红）从约 30% 遵循率 / 66% 准确率，被 GEPA 推到约 10% 遵循率 / 73% 那个方块（另一条推到约 45% / 74% 的圆形），箭头方向显示遵循率上升伴随准确率上升；Qwen3（蓝）在高遵循率区有升有降，Min3（绿）本就贴近 100%*

Gemma4 在 MATH500 上常犯的是格式错——没把答案放进要求的 `\boxed{}`。LCE 优化后的上下文把格式约束写得更硬，遵循率上去，准确率跟着上去。

然后作者做了我认为全文最狠的一步：请 Qwen3.8-27B 当"答案抽取器"，把所有输出里的最终答案统一抠出来再判分，等于把格式噪声整个剥掉。

| 方法 | 无抽取器：初始 → 最终 | 无抽取器增益 | 有抽取器：初始 → 最终 | 有抽取器增益 |
|---|---|---|---|---|
| GEPA（Gemma4, MATH500） | 67.70 → 71.20 | +3.50 | 91.70 → 91.20 | -0.50 |

*表2（论文 Table 10 的 GEPA 行）：加一个答案抽取器，增益直接归零还倒贴*

+3.50 变成 -0.50。那个"提升"，几乎全部来自更听话的输出格式，跟会不会做题没关系。

这一刀下去，LCE 的叙事就有点尴尬了：我们以为在教模型推理，其实很多时候只是在教它别啰嗦、别忘了加 boxed。论文原话克制得多——"instruction adherence can explain some success"，指令遵循能解释**部分**成功。但配上 Table 2 里那些归零的净优势，我倾向认为这个"部分"在实际工程里占比高得吓人。

当然也有真东西：Table 3 里作者拆了 TF-GRPO 的经验利用方式，加了 GRPO-ICL RAG（用 Qwen3-Embedding-0.6B 按语义相似度检索训练时的演示）、All-Exps Random（从所有经验里随机抽）等变体，对比固定条数与变长经验。结论是经验抽取（$E$）和整合（$\phi$）这两步确实关键，随便拿一堆经验塞进去没用。这跟 Figure 5 右图的"归纳失败"能对上。

## ⚖️ 我的判断：该给它一个什么位置

先说亮点。

**评估协议这一刀补得很及时。** 把 671B/8B、Agent/数学、ACE/GEPA 这些不可比的设置拉到同一张桌子上，本身就是贡献。搜索一圈能看到 ACE 那篇恰好主打"Reflector 是关键创新""增量更新防上下文塌缩"，而这篇的 Figure 3 直接说放大 Reflector 救不了失败、Figure 5 又说 ACE 的增量累积确实让它对失败多样性不那么敏感——两边居然能对上，不是互相打脸，是互相校准。这种对照比多刷两个点有营养。

**机制拆解做得干净。** 从"没有赢家"这个现象，追到"验证集/测试集不迁移"，再追到"缩放无效"，一路落到"多样性负相关 + 归纳失败 + 格式遵循"，层层往下剥，每一层都有独立证据。尤其答案抽取器那个消融，成本很低、杀伤力很大，属于看完就能搬回自己项目里用的那种设计。

**没硬吹。** 作者没说自己推翻了谁，标题用的是 Revisiting，结论写的是"为未来工作提供指引"。在一片"自进化""测试时学习"的热闹里，这种克制反倒让人更愿意信。

再说我觉得有问题的地方。

**8B 主战场的选择，多少有点取巧。** 全文主表锁在 8B，而 ACE 原论文的招牌结果是 671B 上的。作者用 Figure 4 缩放到 235B-A22B 做了回应，这个补得挺周到，但 235B-A22B 是 MoE，激活参数远不到 235B，跟稠密 671B 不是一回事。严格讲，"大模型上 LCE 不行"这个命题并没有被完全证死，更准确的说法是"在作者覆盖的这些规模里没看到一致收益"。这块的边界我标一下，别读成全称判断。

**基线还能更强。** CoT 和 ICL 确实朴素，但 self-consistency、ReAct 这些同样是免训练的测试时方法没进主表。如果连 CoT 都打不平，加更强的基线只会让结论更难看——方向上不影响，可少了这一档，读者不太好判断 LCE 到底处在什么位置。

**Vendi Score 是个间接代理。** 用 LLM 抽失败模式标签、再算多样性，中间隔了两层主观性。论文附录做了方差分解和混合效应分析，算相当负责了，可"高多样性任务本身更难、评测方差更大"这个混杂我还是没完全放下。说实话这块我也不是特别确定，可能得等有人换个多样性度量复现一遍才踏实。

**最该被记住的，是它划出了适用边界。** 这篇不是在说"上下文工程没用"，是在说"别指望一套自动反思流程通吃"。失败模式同质、模板化、格式敏感的任务（MiddleMatch、IFBench、格式老出错的 MATH500），LCE 能捡到实打实的分；开放式、多步、每次死法都不一样的 Agent 任务（AppWorld），这套"从失败里攒经验"的范式目前够不着。

## 🛠️ 如果你也在做自进化上下文，几条能直接用的

**上线前先量一下失败模式的多样性。** 挑 100 条失败轨迹，让模型打标签，看是集中在两三种还是散成几十种。集中在少数几类，LCE 大概率划算；散得厉害，先把力气花在别处。这一步比调 prompt 模板值钱得多。

**做一次"格式归一化"消融。** 拿个强一点的模型当答案抽取器，把输出统一抠成标准答案再判分。前后一比，就知道你的涨点是推理还是格式。我自己以前就把格式对齐的收益当成推理提升，写进周报还挺得意……现在想想挺想撤回的。

**验证集挑的上下文，别当泛化证据。** 独立测试集是底线；条件允许就多切几折，看上下文换一折还灵不灵。Figure 2 和 Table 2 的落差就是最好的警示。

**别急着堆 Reflector。** 同样的算力，换个更强的 Generator 往往更直接——Figure 3、Figure 4 都在说缩放主要喂饱了干活的那个模型。真要投入，把预算挪到经验抽取与整合那两步（Table 3 的 $E$ 和 $\phi$），或者干脆人工写几条硬约束，性价比可能更高。

**判断有没有"新知识"，用 Pass@K 而不是 Pass@1。** 单点涨了不算数，把 K 拉到 128 看曲线整体抬没抬。这个检验便宜，还能挡掉一大堆自我感觉良好的迭代。

## 📝 收个尾

这篇论文没给我一个新算法，倒是把一个我隐约觉得不对、一直没说清的直觉给摁实了：模型写出来的"经验"看着像原则，其实经常只是把这一批失败复述了一遍。它没有归纳，只有累加。

ACE 那篇的口号是上下文该成为"不断演进的作战手册"。这篇补了下半句：**手册越写越厚，不代表写手册的人真的懂了战场上为什么会输。**

再往深想一层，还有个没解决的问题悬着：让模型从异质失败里抽象共享原则，到底是能力没到，还是这个目标对纯文本空间的优化循环来说就不合适？作者给的是"limited capabilities"，我更倾向怀疑后者——归纳这件事可能天然需要某种跨样本的状态压缩，而字符串上的增量更新做不到。这部分纯属我的猜测，论文没给答案。

但至少，下次再看到一份写得漂漂亮亮的自进化 playbook，我会先问一句：这些条目，是真被抽象过的原则，还是又一批没消化完的失败？
