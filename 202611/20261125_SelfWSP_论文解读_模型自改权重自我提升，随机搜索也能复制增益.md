# 模型自己动手改自己的权重，数学分涨了五倍——可随机搜索说：这我也能

你有没有碰到过这种事：一个 0.8B 的小模型，数学题明明会做，却卡在那儿一遍遍重复同一句话，32k 的 token 预算烧光了，答案一个字都没吐出来。你盯着日志，心里清楚它不是不会，是「卡碟」了。

前阵子 MIT CSAIL 那篇《Sparks of Weight-Space Programming》传得很广：让 GPT-6 Astra 像读代码一样读一个网络的权重，定位到 Qwen3.5-0.8B 第 15、19 层 MLP 里一个「重复方向」，抹掉它，只动 0.016% 的权重，MATH-500 从 7.9% 干到 48.1%。当时圈子里有两种声音，一种说这是 AI 改 AI 的阶跃式能力，另一种嘀咕：这不就是把复读 bug 修好了吗，凭什么算「获得数学能力」？

这篇 2611.28833 接的是一个更狠的问题：**不让 GPT-6 来改，让那个 0.8B 的小模型读自己的权重、自己给自己动刀，行不行？**

我的第一反应是：这题问得漂亮，但答案八成会难看。看完之后，说实话，比我想的更有意思——不是因为它证明了「模型能自我改进」，而是因为它花了大半篇幅，认认真真地证明「你看到的自我改进，大部分不是模型理解了什么，而是搜索和筛选撞大运」。这种肯自己拆台的论文，我是真的觉得比一堆刷榜文值钱。

---

## 🎯 核心摘要

作者提出 Self-WSP：让 Qwen3.5-0.8B 读自己的权重、提出编辑、再用改过的权重同时当解题器和编辑器，外层循环按练习题正确率决定留不留这一刀。数字很唬人：GSM8K 从 11.8% 到 62.2%，MATH500 从 7.0% 到 32.2%，有时只改 16 个参数，个别 run 里一轮一轮改下去还能继续涨。可作者自己往后翻就泼了冷水：模型压根不懂自己改了啥，解释常是幻觉，编辑位置跟着目录顺序走；换个不调用任何模型的随机采样器，GSM8K 上照样拿到 32.8%（Self-WSP 是 31.9%），GPT-6 那个较简单的公开编辑重评测下来也只和「最佳单次随机编辑」打平。这不是底层突破，是一次做得很干净、也很诚实的 RSI 评测方法论示范——它最值钱的输出不是那个五倍，是一整套「别把 best-of-24 当成能力」的对照设计。

## 🤔 问题动机：RSI 的老梦，和一条一直没走通的路

递归自我改进（RSI）这个念想能追到 Good 1966、Schmidhuber 2007：一个系统提升自己的智能，顺带提升「继续提升智能」的能力，一层套一层。语言模型其实早就在「自我改进」了，只是都不直接——拿自己生成的推理链、数据、奖励去训练自己（STaR、Self-Instruct、Self-Rewarding 那一挂），重写调用自己的代码，或者学着自己写微调数据。你想想看，不管哪种，权重都是被数据、代码、训练**间接地**推动的，模型从没伸手碰过自己的参数。

WSP 把这条路掰直了：把权重视作一种可以被语言模型读、写、改的「代码」。GPT-6 Astra 那篇证明前沿模型能干这事，但留了个明晃晃的空白——**它改的是别人，不是自己**。一个模型能不能读懂自己的权重、自己改、改完用新的自己继续改？这就是 Self-WSP 要回答的。

这里有个必须先讲清的坑，也是全文的暗线。Qwen3.5-0.8B 的 model card 自己就警告：thinking 时经常陷进重复，原模型大约 90% 的题在 32k-token 预算里答不完。也就是说这个模型的「数学能力」很大一块被测的不是会不会算，是**能不能把话说完**。任何一刀只要碰巧打断复读，分数就能窜一大截。这个前提不摆出来，后面所有五倍、四倍的数字都会被读歪。

## 🏗️ 方法核心：一个模型，两个角色，一个不下场的裁判

![图1：Self-WSP 循环](https://www.mulanai.com/fs/files/1125_3715cbc8_fig_loop.jpg)

*图1：Self-WSP 循环。同一个模型分饰两角——editor 读自己当前的权重、提一个编辑；solver 拿着「应用了编辑的权重副本」去答练习题；外层 Check 只看「练习题是不是多答对了」，是就把副本扶正为当前权重，于是下一次提议来自被改过的模型。*

一句话讲清核心 idea：**模型负责提候选，外层循环负责筛选，两者都用同一份、且不断被改写的权重**。图里那个 `if yes, keep` 的箭头是整套系统的命门，后面批判部分会回到它。

### 一个模型，两个角色

模型用的是 Qwen3.5-0.8B，24 层，其中四分之三用线性注意力（linear attention）、四分之一用标准注意力。线性注意力层把读过的内容压进一个固定大小的 state，按权重设定的速率遗忘过去——记住这句，那个「只改 16 个数」的奇迹就发生在控制遗忘速率的参数上。当 editor 时把思考关掉，只负责提编辑；当 solver 时把思考打开，按 Takehi et al. 的采样设置答数学题。两个角色**始终用当前权重**，所以每保留一刀，既改变模型怎么解题，也改变它接下来怎么提刀。

### 读自己的权重：318 个张量的目录

editor 看到的是一份 318 个可编辑张量的目录，覆盖全部 24 层，给出名字和形状。它挑一两个张量后，系统才给更细的东西：形状、均值标准差这类统计量、最多 64 个具体数值连同位置、行范数列范数；外加当前模型在一批练习题上的表现，含参考答案和几条回答的结尾。

这个设定跟 GPT-6 对齐了「信息可得性」，但砍掉了最关键的一样东西：**GPT-6 能在 Python 环境里自由分析权重、从激活里算方向，这里的 editor 只能看系统预先算好的一张静态快照**。其实它更像在读一份体检报告，而不是拿着探针做实验。这个差别，后面解释「为什么模型不懂自己在干什么」时会反复咬回来。

### 写自己的权重：七个动作 + 一份语法约束

0.8B 的模型输出格式不太靠谱，所以作者用基于张量形状的语法（grammar-constrained decoding，Willard & Louf 2023、Geng et al. 2023）逼它把编辑写成 JSON。每个 proposal 含一到两个 edit，一个 edit 选中某个张量里连续的一段（若干条目、行或列），施加七种操作之一：置零、整体乘一个数、整体加一个数、填充成某个数、按该张量的均值标准差重抽样、抹掉一个方向、或者跑一小段 NumPy 表达式。

最值得一提的是「抹掉一个方向」，只对矩阵适用：editor 点名矩阵里某一列当方向 $d$，被选中的每一列都减去自己沿这个方向的分量，按系数 $\alpha$ 缩放——

$$W_{\cdot,j} \leftarrow W_{\cdot,j} - \alpha\,\frac{W_{\cdot,j}^\top d}{\lVert d\rVert^2}\,d$$

$\alpha=1$ 就是把这分量彻底抹掉。GPT-6 最奏效的那刀也是 remove direction，区别在**它的方向是从模型激活算出来的**，这里的 editor 只能从权重里随手点一列。语法只保证格式、不保证内容：重复旧编辑、把整个张量均匀缩放一刀、改完没有任何数值变化的，直接当场丢弃，剩下的才叫 valid edit。

### 保留编辑：一个不肯下场的裁判

每轮有固定预算（最多试多少个 valid edit），editor 一直提到达标；一轮也会在 24 个 proposal 之后、或连续几个 valid edit 被拒后提前收工。每一个 valid edit 先应用到**权重的副本**上，再拿两个互不重叠的练习批次检验，规则写成：

$$\text{keep} \iff \Delta_1+\Delta_2 \ge \tau \ \ \text{且}\ \ \Delta_1\ge 0,\ \Delta_2\ge 0$$

$\Delta$ 是两批各自多答对的题数，$\tau$ 是门槛（shuffled 为 1，ordered 为 3）。两批合计涨够、且任何一批都不许变差，副本才扶正为新的当前权重。伪代码大概是这样：

```python
for round in range(R):
    for _ in range(round_budget):          # 每轮固定 valid-edit 预算
        edit = editor.propose(current_weights)   # 关思考，读权重目录
        if not valid(edit):                # 重复/均匀缩放/无变化 → 丢弃
            continue
        copy = apply(current_weights, edit)
        d1, d2 = gain(copy, batch1), gain(copy, batch2)
        if d1 + d2 >= tau and d1 >= 0 and d2 >= 0:
            current_weights = copy         # 保留；下一次提议来自被改过的模型
        snapshot(current_weights, validation_questions)  # 打分，不回传给 editor
best = argmax_validation_round(snapshots)  # 验证增益最大的那轮
```

注意 `snapshot` 那行的注释：**验证集分数永远不回传给 editor**。这个隔离是整个实验设计里最讲究的一处。

### 三层数据隔离 + 两种接口

| | Shuffled（打乱） | Ordered（按层） |
|---|---|---|
| 张量目录顺序 | 随机打乱 | 按层排序 |
| editor 怎么选 | 直接挑 1~2 个张量 | 先选层，再在层内挑张量 |
| 每个练习批次 | 32 题 | 128 题 |
| 保留一刀的门槛 $\tau$ | 合计多对 1 题 | 合计至少多对 3 题 |
| 每轮预算 | 4 / 6 / 12（共 3 轮） | 8（每轮） |
| layer 0 的编辑占比 | 2.9%（目录份额 4.4%） | 62% |

问题被切成三份：practice questions 来自训练 split、带参考答案，用来判定一刀该不该留；validation questions 也来自训练 split，但**从不给 editor 看**，只在搜索结束后挑模型；GSM8K 和 MATH500 的标准 test set 只用于最终评测一次。这个 practice / validation / test 的三层切法，看着朴素，恰恰是后面 RSI 方法论那节要夸的东西。

一个 setting 是「数据集 × 接口 × 起点」的组合，跑 12 或 24 个 run；每轮结束在验证集打分，取验证增益最大那轮的当前模型作为该 run 的 best model；再把验证增益最大的三个 run 命名为 Top-1/2/3，叫 selected models，**只有它们**上完整测试集。作者自己点破了：这是 12 或 24 选 3，展示的是 best case。为了看「普通一次运行」长啥样，他们还在搜索之前按固定规则指定若干 run，不管结果好坏都测，叫 spot-check runs——这个设计我待会儿要专门夸。

continued runs 则是让 shuffled 的 selected models 换到 ordered 接口继续自我编辑，记作 $+k$，表示在 shuffled 起点之上累积了多少轮 ordered 编辑。

## 📊 实验结果：五倍是真的，但先看清是哪五倍

![图2：各方法最优模型的测试准确率](https://www.mulanai.com/fs/files/1125_a95ce6a5_fig_over.jpg)

*图2：每种方法贡献自己的 Top-1（验证增益最大的那个模型）。左 GSM8K 标了 5.27×，右 MATH500 标了 4.54×。灰色是基线与 GPT-6 的两个公开编辑，蓝色是 Self-WSP 的三种设置。注意最底下那两行灰条：GPT-6 的 Zeroing 只有 22.0% / 13.8%，而 Direction removal 是 66.9% / 49.5%——同一个模型、两个编辑，差距大到离谱。*

主实验表（Table 1）我按原样搬过来，24 个 selected models 的测试准确率，单位 %，每行内按验证增益排序：

| Setting | Original | Top-1 | Top-2 | Top-3 |
|---|---|---|---|---|
| GSM8K · Shuffled | 12.5 | 31.9 | 28.7 | 16.5 |
| GSM8K · Ordered | 11.8 | **61.0** | 59.9 | 54.0 |
| GSM8K · Continued +8 | 11.8 | **62.2** | 53.3 | 48.1 |
| MATH500 · Shuffled, batch 1 | 6.9 | 17.3 | 10.4 | 8.1† |
| MATH500 · Shuffled, batch 2 | 7.0 | 17.7 | 22.0 | 8.3† |
| MATH500 · Ordered | 7.0 | 24.2 | 21.9 | 24.7 |
| MATH500 · Continued +4 | 7.0 | 25.4 | 25.4 | 28.4 |
| MATH500 · Continued +12 | 7.0 | 31.8 | **32.2** | 28.6 |

† 表示相对原模型的增益没过统计检验。24 个 selected models 里 22 个确实优于原模型，剩下两个只涨了一个点出头。ordered 接口把 GSM8K 从 11.8 抬到 61.0、MATH500 从 7.0 抬到 24.7，continued 再推到 62.2 和 32.2。最好的自编辑 GSM8K 模型离 GPT-6 的最佳编辑（论文里重评测 66.9%）不到 5 个点；但 MATH500 上 GPT-6 的 49.5% 还遥遥领先。

看到这个数我愣了一下——**62.2 和 31.9 差了整整 30 个点，而两者唯一的差别只是目录顺序和批次大小**。同一套权重、同一个模型、同一套七种操作，只是把张量目录从随机打乱改成按层排列，结果就翻倍。这不该是「能力」该有的样子，倒像是搜索空间被悄悄调好了。

### 「只改 16 个数」到底改了什么

论文里最抓眼球的一句：24.2% 那个 MATH500 模型和原模型**只差 16 个数**——第一层线性注意力的 `A_log`，每层 16 个 head 各一个数，控制每个 head 遗忘过去的速度。一个 GSM8K 模型改同一层的 32 个数到 59.9%；某个 continued 的 MATH500 模型相对起点只差 2 个数，又涨了 6.8 个点。没有任何一个 selected model 改动超过 0.2% 的权重。

改动小到这个程度，直觉上会往两个方向想：要么模型真的找到了权重的「命门」，要么这个模型本来就有一根一碰就倒的拐杖。作者后面选了后者，而且给了很硬的证据。

### 把各方法摆在一张桌上

图2 的数值我整理成表，方便横向看：

| 方法 | 谁来提编辑 | GSM8K Top-1 | MATH500 Top-1 |
|---|---|---|---|
| 原始 Qwen3.5-0.8B | — | 11.8 | 7.0 |
| Random search（同预算） | 随机采样器 | 32.8 | 6.6 |
| 单次随机编辑 | 随机采样器 | 22.3 | 14.0 |
| Self-WSP · Shuffled | 模型自己 | 31.9 | 17.3 |

第二行就是那盆冷水：把 editor 换成一个**不调用任何模型**的随机采样器，GSM8K 上 32.8% 反超 Self-WSP 的 31.9%。

## 🔬 泼冷水的部分：模型压根不知道自己在干什么

这篇论文我最早被打动的地方，是第 4 节的标题直接叫「Does the Large Language Model Know What It Is Doing?」，然后自己答：Hardly。

### 那个 61.0% 的编辑，解释是反的

看看拿下 61.0% 的关键 proposal（Figure 3，我这里用文字复述）。两个练习批次各 128 题，原本只对 12 道和 20 道。editor 先选 layer 0，点名 `p273`（input norm）和 `p298`（`A_log`），读到 `A_log` 的均值 −1.9795、标准差 1.4477，然后写下两刀：把 `p273` 的前 16 个数乘 −1.979492，把 `p298` 的前 16 个数加 −1.979492。附的假设是：「当前权重被 −1.9795 缩放了……这是个意外的缩放，应该被移除」。

等等，这里不对。撤销一个「乘了 −1.9795」的操作，得**除以**它才对，它却又**乘**了一次。它声称要移除的缩放，恰好是它自己刚施加的那个。解释和编辑自相矛盾，但它把两个批次的正确数从 12/20 抬到 78/87，于是被保留，落到测试集 61.0%。

一个自相矛盾的推理，配上一个撞对的结果。这就是全文的缩影。

### 一万一千五百八十次提议里的真相

作者把 11,580 个 proposal 全数了一遍：

- **69% 是无效的**，哪怕语法已经保证了格式。多数是重复已试过的编辑、或把整个张量均匀缩放一刀——而 prompt 里明明白白禁止了这两件事。
- 剩下的 valid edit 里，**只有 12% 被保留**。
- 两个能表达结构化改动的操作（抹掉方向、写 NumPy 表达式），editor **一次都没用过**。它几乎只会「乘一块数」或「平移一块数」。

![图4：每个有效编辑落在哪一层](https://www.mulanai.com/fs/files/1125_5cd48f07_fig_laye.jpg)

*图4：每格是落在那一层的有效编辑占比（取整）。第一行灰色是各层在目录里的份额——假如 editor 对张量一视同仁，就该照这个比例分布。Shuffled 一行确实铺得很匀；Ordered 一行里，layer 0 独占 62%，因为它就是目录第一条。*

改哪儿跟着目录走，这条最扎心。shuffled 目录下 layer 0 拿到 2.9% 的编辑，接近它 4.4% 的目录份额；ordered 目录下一口气拿 62%。而且这个偏好**在每轮第一个 proposal 就出现**，那时 editor 还没看到这一轮任何一刀的反馈。layer 0 的前两个张量，正是上面那个 61.0% 案例里改的 `p273` 和 `p298`。ordered 的 15 个 selected models 全改了 layer 0 的 `A_log`，shuffled 的 9 个一个都没改。「调整第一层的遗忘速度」是个挺合理的目标，可模型似乎只是**从头读目录正好撞上**了它。

连写进去的数都是抄的：valid edit 里有 9% 到 28% 的数值等于 editor 刚读到的统计量（均值、标准差、范数）。那个 −1.979 的均值，单独出现在 4 个 selected models 里当缩放系数或平移量。

解释文字更靠不住。很多是空的、描述的是另一个张量块、或者跟权重毫无关系。最离谱的一条，全文是「The cost of one chair is $11.」（一把椅子 11 美元）——逐字抄自同一次调用里练习反馈中一道椅子定价题的回答结尾，跟它附着的那刀没有半点关系。作者没绕弯，直接归类为幻觉（Ji et al. 2023）。

### 被保留的刀，有四成在帮倒忙

![图5：ordered 接口下所有 run 的验证准确率轨迹](https://www.mulanai.com/fs/files/1125_e4279532_fig_traj.jpg)

*图5：每个数据集 24 个从原模型出发的 run，淡蓝细线是其余 run，虚线是原模型基线。深蓝两条被挑出来当典型：GSM8K 有「一轮跳升」和「稳步爬」，MATH 有「先跌后回升」和「一路向下」。*

在小题集上估模型能力，误差是长尾的，偶尔会离全量评测很远（作者引了自己几篇 2026 的工作）。外层循环只看练习分数，就注定会留下一批蒙对的刀：shuffled 接口下**超过 40% 的「保留了编辑」的轮次反而拉低验证准确率**；ordered 把批次放大到 128 有帮助，但 MATH 上仍有三分之一这样的轮次。GSM8K 的 24 个 run 里，11 个涨超 23 个点，另外 13 个涨不到 10 个点——同一个设置，命运分成了两半。

至于从不参与挑选的 spot-check runs：ordered 接口每个数据集 6 个，测试集上平均 GSM8K 涨 24.7 个点、MATH500 只涨 7.7 个点，比 selected models 差一大截。这个落差，才是「普通一次运行」的真实面目。

## ⚠️ 换随机搜索上场：一半江山就直接塌了

![图6：shuffled 接口下各 run 的最终验证变化](https://www.mulanai.com/fs/files/1125_8f8e7446_fig_rand.jpg)

*图6：每个点是一个 run，上方浅蓝曲线是分布，黑竖线是均值。四行依次是 Self-WSP、frozen editor（编辑器始终用原始权重、只改 solver）、Random search 同预算、Random search 大预算。左 GSM8K 右 MATH。前三行在 GSM8K 上均值几乎重合。*

第 5 节干脆把 editor 换成一个不调用模型的随机采样器：均匀抽一个张量（五分之一概率抽两个），随机定布局、起点、长度，再随机挑一个操作和数值，走**完全相同**的循环和保留规则。

- **GSM8K 上打平**：随机搜索最佳 32.8%，Self-WSP 31.9%，图6 里两组 run 的分布长得几乎一样。
- **frozen editor**（编辑器永远用原始权重，只有 solver 被改）平均表现和另外两组也差不多。也就是说，**让编辑器自己也被编辑，没带来看得见的好处**——这一条直接戳在 RSI 的那个「递归」上。
- **MATH500 不一样**：同预算下随机搜索找不到任何改进，Self-WSP 能到 17.3%；只有把预算加约 70%，随机搜索才搜出一个 13.6% 的模型（把某个线性注意力层的 256 行置零），还是够不着。

![图7：352 个单次随机编辑按增益排序](https://www.mulanai.com/fs/files/1125_7f58eb86_fig_rand.jpg)

*图7：纵轴是 screening 里的准确率变化（点），横轴是 352 个随机编辑从好到坏的排名。灰带是不做任何编辑、只换随机种子重答带来的采样噪声区间；上方实线是 shuffled 的最佳 Self-WSP 模型，虚线是 GPT-6 的 Zeroing 编辑。GSM8K 一侧 78 个编辑跌破灰带，只有 24 个爬到灰带之上。*

作者还嫌不够，把「搜索 + 累积」这两层也拆掉，只留单次随机编辑：每个数据集抽 352 刀，各自单独作用到原模型上，用 128 道既非 practice 也非 validation 的留出训练题做 screening（每题采样一次、8192-token 上限）。这里有个我很喜欢的处理——**先量出「什么都不做」的噪声**：原模型换随机种子重答一遍，分数本来就会飘几个点，取 5~95 百分位画成灰带，落在带里的编辑和「啥也没干」没法区分。

结果：GSM8K 上 78 个编辑跌破灰带（有害），只有 24 个爬上去。动辄几万到几百万权重的大编辑伤害最大，几乎每种操作平均都在帮倒忙。把每数据集最好的 8 个拿 512 道额外题复筛、再测赢家：GSM8K 22.3%（把一个卷积的 4096 个权重乘 −2），MATH500 14.0%（把一个 query projection 的 64 行乘 −2）。

然后是全文最辛辣的一句判断：**GPT-6 那个较简单的编辑，压根就是一次随机编辑**。它把 layer 15 attention output 矩阵的 256 列置零，这种操作落在单次随机编辑能生成的范围内（虽然采样器要抽约 1.3 亿次才会撞上），论文里重评测只有 22.0% / 13.8%，和「最佳单次随机编辑」的 22.3% / 14.0% 几乎一样，在 screening 里也只排在较好的随机编辑中间。而 GPT-6 **更强**的那刀（从激活算出方向再抹掉）在采样器能产生的范围之外，重评测 66.9% / 49.5%，是真本事。

回想当初「GPT-6 改 0.016% 权重让数学涨六倍」的刷屏，和「这不就是修了个复读 bug」的质疑——这篇论文等于用实验把两派各打五十大板：那个被反复转述的「简单置零」其实没那么神，真正强的是那刀有激活依据的方向移除。说实话，这个厘清比 Self-WSP 本身还解渴。

公平地讲，Self-WSP 也不是全无胜算。同一套 screening 里，shuffled 的最佳自编辑模型在两个数据集上都压过全部 352 个随机编辑；MATH500 上 selected continued +4 模型 screening 最多涨 17.2 个点，是最佳随机编辑的两倍多；同预算下也胜过随机搜索。它的 proposal 确实比乱猜好——只是好得有限，**而且不是因为模型懂它为什么管用**。

## 🔧 一轮一轮改下去，会滚雪球吗？

![图8：持续自我编辑](https://www.mulanai.com/fs/files/1125_af0b9f00_fig_chai.jpg)

*图8：横轴是原模型、shuffled 的 selected 模型，以及 +4/+8/+12 的累积 ordered 轮数。实线连的是 selected models 与各自起点，虚线是预先固定、从不挑选的 spot-check runs。GSM8K 一侧的 A、B、C 标出三个 shuffled 起点。右图 MATH500 里虚线到 +12 明显走平甚至下滑。*

让 shuffled 的 selected models 换到 ordered 接口接着改：GSM8K 的 A、B、C 各跑 8 轮到 +8，MATH500 的 6 个各跑 4 轮到 +4，其中 3 个 selected +4 再跑 8 轮到 +12。

**最好的模型确实还在爬**：GSM8K 的 B 从 28.7% 一路到 62.2%；MATH500 一个 8.3% 的 shuffled 起点长成 +4 的 25.4%~28.4%，其中一个 +12 到 32.2%，而且相对起点只差 2 个数。多数增益在切到 ordered 之后很快就来了——原因前面已经交代，就是撞上 layer-0 那刀。

**典型的 run 却停住了**。selected 是 12 个 run 里最好的 3 个，天生偏向幸运儿。spot-check 的虚线讲另一个故事：GSM8K 的 spot-check 在 +4 之后几乎不再涨，最好的还从 +4 的 53.3% 滑到 +8 的 51.6%；MATH500 三个都从 selected +4 出发，到 +12 时一个涨 3 个点、一个原地、一个从 28.4% 一路跌到 23.4%。全部 12 个 MATH 八轮 run 里，被保留的编辑让验证准确率**平均不变**。

作者的收尾句我抄在这儿，因为它把 RSI 的幻觉一刀切开了：更多轮次只是给外层循环更多次「抽到好模型」的机会，权重一直在变，**模型作为 editor 却一点没变强**。滚起来的不是智能，是抽奖次数。

## 💡 我的判断：这篇论文真正交付的是一套评测规矩

### 外层循环干了大头的活

讨论节第一句就是「The outer loop does much of the work」。模型提出每一刀、也被每一刀改变，但**决定留哪刀、什么时候停、以及测哪个 run 的，全是外层循环**，而且用的是带参考答案的练习题。作者给 Self-WSP 的定位很克制：一次搜索，模型提供 proposal；这些 proposal 在 MATH500 上胜过随机，在 GSM8K 上只是打平。

「为什么小编辑走这么远」那节把底裤也扒了：原模型约 90% 的题在 32k 预算里答不完，几乎每一道被编辑救回来的答案，都是原模型**没写完**的；所有评测模型里，准确率随「未完成回答占比」几乎线性下降。任何一刀只要打断复读，分数就窜。这也顺手解释了 GPT-6 为什么改不动 Gemma 3 270M——那个模型很少复读自己。加上少数参数能有过大影响（Yu et al. 2024）、推理时修正一小部分 thinking token 就能提分（Ling et al. 2026b）、Qwen 拿假奖励训练数学都会变好（Shao et al. 2026）这几条旁证，结论就很难回避了：**测出来的五倍，大头是「模型终于肯把话说完」，不是「模型学会了数学」**。

顺带说一句，作者自己在 Limitations 里写得很坦白：单个小模型、两个数学基准，而它的主要弱点恰好异常好修；外层循环用了参考答案，所以**这次改进是有监督的**；ordered 接口是在看过 shuffled 结果**之后**设计的；还没在 ordered 下跑随机搜索，也没通过反转目录直接验证 layer-0 偏好的来源；跟 GPT-6 的比较只是指示性的，因为工具、反馈、预算都不同。肯把这些一条条列出来，比多刷两个点更让我信这篇。

### 它撞上了 RSI 评测最要命的那根神经

说到这个，得把视野拉开一点。2026 年 10 月有一篇审计论文《Auditing the Product, Not the Recursion》（arXiv 2610.27610，Chen 等，Stevens Institute of Technology / UMass Boston）把 114 篇相关研究全文编码了一遍，其中 90 篇自称 RSI，结论挺不留情面：90% 报告了「最终产品」的评测，60% 用了没参与挑选的任务，**只有 22% 审计过两次以上完整 loop 的重跑**；26 篇声称「改进了改进过程」的，只有 4 篇在同一起点、匹配预算下比较了早期和晚期的改进器。它主张把 product claim（最终系统多强）和 process claim（改进过程本身有没有变强）分开，按 claim 去配证据——而「best-so-far 曲线按构造单调不降，不能证明逐次修改可靠有益」这句，简直就是图8 的理论版。

RSI 的评测文献里还反复点名几个混淆：extra compute（后几轮变好只是多花了搜索，得用「单轮 ×k 预算」对照）、co-designed evaluator（任务生成器和搜索过程互相拟合，几乎每刀都被采纳，得冻结 evaluator、用 loop 没选过的留出任务）、selective reporting（只报跑通的那几次，得发布全部 run）、non-recursive gain（得用一个被剥夺自我修改机制、但共享随机流的对照）。有项目记录过，一个「复利式改进」的声称后来追溯到 5× 的算力不对等被撤回，另一个 15/15 全采纳的结果被查出是任务生成器和搜索引擎一起设计的，发表前被拒。

把这张清单摊开，再看 Self-WSP 的做法，会有点恍然：

| RSI 评测的常见坑 | 这篇论文给的对照 |
|---|---|
| selective reporting（只报最好的） | spot-check runs：搜索前固定、不挑选、好坏都测 |
| extra compute / non-recursive gain | 同接口**同预算**的 random search |
| frozen improver 对照 | frozen editor：编辑器不随权重一起被改 |
| development / selection / audit 混用 | practice / validation / test 三层切分，验证分不回传 |
| 采样噪声被当成增益 | 图7 的灰带：不做编辑、只换种子的分数波动 |
| 只报最终 best | 图5、图6、图8 发布全部 run 的轨迹与分布 |

这套东西不是顺手做的，是冲着「别把 best-of-24 当成能力」去的。作者给后来者的建议也只有两句：**进展最好用同接口、同预算的随机搜索来衡量，并且和 spot-check runs 一起报告**。我觉得这才是论文最该被引用的部分。

### 那到底算不算 RSI？

我的判断：不算，差得还挺关键的一层。真正的递归自我改进要的是「改进改进能力本身」——编辑器得因为被改过而更会提刀。这里 editor 从头到尾没变强（frozen editor 打平、典型 run 停滞、layer-0 偏好只跟目录走），变的只有权重和抽奖次数。它证明的是「一个 0.8B 模型能在不作弊的信息边界内，靠搜索把自己的分数推上去」，这是 RSI 的**必要前置**，不是 RSI 本身。

不过作者指的下一步我挺认同：给 editor 配权重分析工具（GPT-6 有而它没有）、专门训练一个模型学会提编辑（Zweiger et al. 2025）、换一个失败模式比「复读」更深的 solver。这三件事都指向同一个方向——**让 proposal 的质量来自理解，而不是来自目录顺序和运气**。有个地方我没完全看懂：那 9%~28% 抄统计量的数值，究竟算「零理解」还是一种极粗糙的隐式先验？论文没拆，我也不敢替它下结论。

## 🔗 工程启发：能直接搬走的几条

- **先修解码，再谈能力**。如果你手上是个小推理模型、分数低得反常，先量一下「未完成回答占比」。这个模型 90% 的题卡在 32k 复读上，改 16 个参数就能涨 17 个点——这种「能力提升」跟训练没关系，是解码层的 bug。别急着上 RL。
- **把 WSP / 自改进当成搜索系统来设计，别当成智能体来膜拜**。一旦拆成「proposal 生成器 + 筛选器」，该问的问题就变了：生成器比随机好多少？筛选器用了多少带标签的反馈？是不是有监督的？这篇论文把这三问全答了。
- **报告 best-of-N 时，必须同时报告普通 run**。只发 Top-1/2/3 会系统性高估。spot-check 那 24.7 / 7.7 个点，和 selected 的 61.0 / 31.8，差的就是「运气」被定价之后的样子。
- **随机基线要卡死两个变量：同接口、同预算**。这篇里「同预算打平、加 70% 预算才勉强追一点」的对比，比任何显著性星号都说明问题。预算不对等的对照，等于没对照。
- **量噪声，再量增益**。不做任何改动、只换随机种子重跑一遍，画出分数波动带；落在带里的一律不许叫「提升」。图7 那条灰带，成本低得几乎没有，却能挡掉一大半自我感动。
- **给编辑器和解题器分家做消融**。frozen editor 那组是整套实验里最便宜也最致命的一刀：如果编辑器不跟着变，结果一样，那「递归」这两个字就先别写进标题。

回到最开始那个卡碟的小模型。这篇论文没造出一个会自我进化的智能体，它做的是更朴素、也更难得的事：把「模型自己改自己涨了五倍」这句话，一刀一刀拆成「目录顺序 62% 集中在 layer 0」「69% 的提案无效」「四成保留的编辑在帮倒忙」「换个随机数生成器照样拿 32.8%」。拆完你会发现，五倍还在，但神话没了。

一个更根本的问题还悬着：如果模型对权重的理解只到「抄均值、照目录第一条改」，那在这套循环里，真正在「递归」的到底是谁？权重在变，外层循环在筛，唯独那个该变聪明的编辑器，从头到尾没动过。作者把这句话留给了下一批人，我觉得留得很体面。
