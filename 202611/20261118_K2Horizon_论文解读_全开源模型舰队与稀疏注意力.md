# K2-Horizon：把模型训练的“黑箱”拆开，顺便给注意力也装上 MoE

下载一个开源模型很容易，想弄清楚它为什么强，却往往无处可查。权重拿到了，训练数据没有；技术报告写了数据配比，中间 checkpoint 没有； benchmark 分数很漂亮， reward hacking 到底占了多少，也没人知道。做研究的人面对这种发布，像是在只给可执行文件、不给源码的项目上debug。

K2-Horizon 有意思的地方，不只是又多了六个模型。它把预训练语料、数据合成管道、中间 checkpoint、训练日志、RL 代码和量化版本一起端了出来，还留下四台共享同一份 22T token 语料的模型，让“规模”和“稀疏架构”终于可以放在受控条件下比较。说实话，这比单刷一张榜单更让我兴奋。

**核心摘要**：K2-Horizon 发布从 0.9B 到 375B-A23B 的六个模型，试图同时回答开源模型的能力、效率与可复现性问题。架构上，MoVA 把专家路由搬进注意力 value 投影，36B-A4B 以约七分之一的激活参数逼近同数据训练的 32B 稠密模型；推理上，Uno 用共享主干与 KV cache 的扩散 LoRA 草稿，实现最高 2.2 倍解码加速。更稀缺的是 380 个 checkpoint、21.6TB 数据和完整管道。不过，旗舰并未越过最强闭源模型，智能体安全和 benchmark 作弊也暴露了明显短板。这是一份工程与研究资产都很厚实的开放模型报告，不是单靠新架构取胜的故事。

## 六个模型，不是六个简单缩放副本

型号里的 A 指每个 token 激活的参数规模。表中的参数采用论文对 backbone 的精确统计，不包含输入 embedding 和输出投影，所以和型号的标称数字略有差异。

| 型号 | 架构 | Backbone 总参数 | 每 token 激活参数 | 中期训练后的上下文 | 目标部署场景 |
|---|---|---:|---:|---:|---|
| 0.9B | Dense | 0.881B | 0.881B | 128K | 手机与内存受限设备 |
| 3.7B | Dense | 3.775B | 3.775B | 512K | 本地助手、消费级硬件 |
| 7B | Dense | 6.946B | 6.946B | 512K | 本地编程工具、小模型 RL 研究 |
| 32B | Dense | 32.213B | 32.213B | 512K | 自托管技术与智能体助手 |
| 36B-A4B | MoE + MoVA | 36.162B | 4.665B | 512K | 低激活成本的自托管助手 |
| 375B-A23B | MoE | 376.087B | 23.590B | 512K | 多 GPU 服务端部署 |

这六个模型覆盖端侧到服务端，但训练安排并不完全一样。3.7B、7B、32B 和 36B-A4B 使用同一份 21.92T token 预训练语料与同一套 recipe，其中还有两对模型看到完全相同的数据批次。375B-A23B 分两个阶段训练 15.1T token；0.9B 则训练 5.03T token，并使用更小的 64,256 词表。

这份设计最值钱的地方，是它把模型家族变成了一组对照实验。普通模型发布里，架构、数据、超参数往往一起变，最终只剩一句“我们的模型更好”。这里至少有一次机会，把规模和稀疏性从数据差异里剥出来。

## MoVA：专家不再只住在 FFN 里

标准 MoE 的稀疏化发生在 FFN：每个 token 只挑几个前馈专家，参数总量可以很大，单次计算量却不必同比增加。MoVA 问了一个很直接的问题——attention 里的 value 投影，能不能也这么干？

![图2：MoVA 架构，value 投影由路由选择的非线性专家生成](https://www.mulanai.com/fs/files/1118_c04d5fb4_mova.png)

*图2：输入经 RMSNorm 后仍走常规 Q、K 通路；V 通路则由 sigmoid router 从 64 个 value 专家中选 4 个，每个专家先投影再经过 SiLU，最终按路由权重加权合并。合并后的 V 才进入 GQA，因此 KV cache 形状不变。实线承载表示，虚线表示路由选择或权重。*

核心计算可以写成：

$$V(x_t)=\sum_{i\in\mathcal{V}(x_t)}p_i(x_t)\,\operatorname{SiLU}\left(x_tW_v^{(i)}\right)$$

这里 $\mathcal{V}(x_t)$ 是当前 token 被选中的专家集合，$p_i$ 是归一化路由权重。36B-A4B 每层有 100 个 routed FFN 专家，激活 8 个；value 侧则有 64 个专家，激活 4 个。前三层仍保留 dense FFN，另有一个共享 FFN 专家。

SiLU 不是随手加的装饰。如果每个 value 专家都只是线性投影，加权混合之后仍然接近一个输入相关的线性映射；非线性让不同专家真正能形成不同的 value 变换。这个细节挺漂亮，也很容易被架构图的“MoE for V”一句话盖过去。

工程上还有两个好处。attention 的 QK 计算没有改，FlashAttention、GQA 和稀疏 attention 都能继续用；每个 token 的 value 在处理时已经合并完成，cache 里只存合并结果，不需要保存 64 份专家输出。

| 方案 | 稀疏化位置 | 每次前向的额外草稿网络 | KV cache 变化 | 主要目的 |
|---|---|---|---|---|
| 常规 MoE | FFN | 无 | 不变 | 扩大模型容量 |
| MoVA | attention 的 V 投影 | 无 | 不变 | 给注意力增加稀疏容量 |
| Uno | 解码阶段的 LoRA 扩散通路 | 无独立草稿模型 | 共享主模型 cache | 一次起草多个 token |

### Softplus 门控与 Grouped RMSNorm

36B-A4B 还配了 softplus attention gate。常见 sigmoid 门控只能把输出压在 0 到 1 之间，初始化时约为 0.5，先砍掉一半 attention 输出，之后最多恢复到原始幅度，不能放大。

作者改用：

$$\operatorname{softplus}(x;\beta)=\frac{1}{\beta}\log\left(1+\exp(\beta x)\right)$$

它始终为正，但上不封顶。取 $\beta=\log 2$ 时，零输入对应的门值恰好为 1，初始化更接近恒等映射。这个改动的逻辑很干净：门控不该只会关小音量，也应该能开大。

Grouped RMSNorm 则把特征维分组，在每组内部计算 RMS。普通 RMSNorm 的单维输出上界随模型宽度 $\sqrt d$ 增长，分组后上界变成 $\sqrt{d_g}$。论文报告它改善了多个规模上的训练稳定性，但没有给出一张只改这一项、其余完全不变的独立消融表。我的态度是：机制讲得通，训练日志也有旁证，贡献大小还不能从这份报告里单独剥得很干净。

## 22T token 之外，真正难得的是训练过程也公开

预训练在 8K 上下文上完成。四个共享语料的模型都跑 1.1M steps，全局 batch 为 19,922,944 tokens；峰值学习率随规模变化，从 3.7B 和 36B-A4B 的 $4\times10^{-4}$，到 32B 的 $1.5\times10^{-4}$。除 0.9B 外，预训练末端不靠学习率衰减收尾，而是 averaging 最终的 checkpoint，再进入 mid-training。

中期训练约 1.9T token，上下文按 32K、128K、512K、512K 四阶段扩展，RoPE base 同步提高。数据也从通用文本转向长文档、推理、代码、指令跟随和智能体轨迹。智能体数据不是等 post-training 才出现，而是在上下文扩展时就进入训练流。

![图3：375B 模型两个预训练阶段交界处的 loss](https://arxiv.org/html/2611.21003v1/fig_phase_transition.png)

*图3：左侧面板是阶段一末尾的 10,000 steps，loss 稳定在约 0.88；右侧是阶段二开头，学习率重新 warmup 的 1,000 steps 用浅色标出。两阶段使用不同数据，所以 loss 的绝对高度不能直接当作能力涨跌。*

训练稳定性部分没有只展示一条漂亮曲线。作者统计 loss spike、回滚和被擦除的分支：7B 主 run 出现 403 个接受轨迹上的 spike episode，并有 43 次 rollback；375B 阶段一有 184 个位于后来被擦除分支上的 episode。这样的日志对做训练 infra 的人很有用，因为真实大模型训练不是一条从左上到右下的平滑曲线，而是监控、重启、回滚和数据排查组成的长期运维。

### 约 10T 合成 token，重点不是“多”，而是怎么造

合成数据约占预训练规模的一半，覆盖数学推理、代码推理、规划、搜索 grounded 行为、指令跟随等。稠密与 MoVA 模型采用的生产配比中，web 占 32.3%，代码占 13.6%，代码推理占 11.7%，数学推理占 14.3%，行为数据占 16.4%，多语言占 6.9%。

作者没有用“小模型上哪份 mix 分数高，就直接选哪份”的办法。小实验里 SFT-heavy mix 更强，外推到生产规模后却变成 web-heavy 更优。流程是先拟合每个验证集 loss 关于参数量和 token 数的 scaling law，再用稀疏回归把预测 loss 映射到 benchmark 分数。1.5B 实测平均分是 SFT-heavy 40.5、math-heavy 38.8、web-heavy 36.6；外推到 31.2B、20T token 后，预测顺序反转为 57.4、56.7、55.1。

看到这个反转时我停了一下。它提醒我们，小模型数据配比结论未必能原样搬到大模型；不过，预测链条也叠加了两层拟合误差，不能把这组外推数字当作实测成绩。

合成轨迹里有错误怎么办？报告给出的视角是“一篇文档就是一组 token 级标签”：一个 $2+2=5$ 的错误 token 不必让整段上下文都作废。这个想法适合保留探索过程，但它不是免死金牌。错误是否教会模型错误推理，仍取决于错误密度、后续纠正和任务类型，不能只用“其他 token 没问题”带过。

### 从公开文件到办公智能体轨迹

![图20：从公开文档合成文件操作任务与教师轨迹](https://arxiv.org/html/2611.21003v1/figures/fmp_pipeline_v1.png)

*图20：管道从 18 个行业、89 种职业出发搜索并过滤办公文件，将 PDF、表格、文档、演示稿和 CAD 文件组成输入包；随后采样任务类型、交付物、复杂度与风格，让 LLM 写工作请求；教师智能体在 OpenCode 和 Stirrup 两套 harness 中执行任务，模拟用户再发起多轮追问，最终保留教师轨迹用于训练。*

这条管道使用了 115,000 个公开种子文件，其中 PDF 占 57.7%，XLSX 占 17.0%。三个教师模型共留下 329.2K 条轨迹、28.2B token。它解释了 K2-Horizon 为什么会把办公自动化当作核心场景：不是往 SFT 里塞几条“请总结这份文件”，而是构造输入包、真实工具环境、交付物和后续修改请求。

坦率地讲，开放这些管道比再公开一份静态数据更费工夫，也更有复用价值。不过，管道可获取不等于复现便宜。教师模型调用、搜索、沙盒执行、质量审查和人工设计规则都构成真实成本，报告也没有给出一份“从零复现全家族需要多少钱”的账单。

## 后训练：先训练五个专家，再把能力合并回去

375B-A23B 没把所有领域混进一口大锅做 RL，而是分别训练 search、knowledge work、tool use、scientific reasoning、instruction following with abstention 五类专家。原因很实际：混合域 RL 可以让能力互相迁移，也会让不均衡奖励和失败模式互相传染；分开训练更容易调参，也能让不同团队并行工作。

RL 使用多轮完整轨迹上的单步 GRPO 变体。环境返回的 token 会被 mask，只在模型生成的位置上更新；每条轨迹先按自身生成长度平均，再对轨迹取平均，避免长 episode 主导梯度。全异步 rollout 最多允许 5 个 policy version 的 staleness，过旧样本直接丢弃。

RL360 把组件拆成明确的服务边界：Miles 管轨迹与奖励，Harbor 执行沙盒任务，SMG 把推理请求路由到 SGLang，Megatron-LM 负责训练。早期系统在大约 1,024 条并发轨迹处碰到 CPU 控制面瓶颈，说明长程智能体 RL 的瓶颈不总在 GPU。session 管理、tokenization、轨迹拼接和沙盒调度，同样能把训练拖慢。

专家训练完，ISO-RAM 负责合并。attention 和共享专家矩阵使用 ISO-merger，在奇异向量方向组合更新并固定基座奇异值； routed expert、router 和归一化权重使用 RAM，保留只出现在单个专家里的更新，避免直接平均把专业能力冲淡。

合并结果不是简单的“各保留一点”。BrowseComp 从 base 的 59.2、search 专家的 62.5 升到 merged 的 68.1；IFBench 从 53.0、60.7 升到 65.2；Terminal-Bench 2.1 没有专门专家，也从 base 的 37.8 升到 merged 的 46.1。反向的一面是 $\tau^3$-Banking 从专家 24.0 回落到 19.5。合并能带来迁移，也会丢东西，不是免费的能力打包。

## Uno：不用第二台草稿模型，也能做无损加速

长推理和多轮工具调用让自回归解码的串行成本很刺眼：一次 forward 只出一个 token，权重和 KV cache 却得反复读取。传统 speculative decoding 可以不改输出分布，但通常要额外维护草稿模型和另一份 cache。

Uno 把草稿器做成附着在 Q、K、V、O 与 MLP 投影上的 LoRA。干净位置走冻结的 AR 权重，噪声位置走 AR 权重加扩散 adapter；一次前向起草一个 token block，AR 通路再做验证，只接受与目标采样规则相容的最长前缀。

![图46：Uno 的训练插入位置、吞吐与质量对比](https://www.mulanai.com/fs/files/1118_f2093dc7_uno.png)

*图46：扩散蒸馏插在常规 NTP 训练之后、RL 后训练之前，作为可插入阶段；左下图显示 7B 在 batch size 64 时系统吞吐约为 AR 的 1.5 倍，batch size 1 时约 2.2 倍；右下图四项 7B benchmark 在取整后保持一致，包括 $\tau^2$-Telecom 90、AA-LCR 68、Terminal-Bench 2.1 的 39 和 SWE-bench Verified 的 70。图中 Terminal-Bench 数值来自 Uno 的独立实验面板，不应与后训练主表的 44.6 混用。*

0.9B 和 7B adapter 都是 rank 128，LoRA alpha 为 256，在 7B token 的 SFT 数据上蒸馏，AR 权重全程冻结。7B adapter 训练约耗 8 个 H200 节点、每节点 8 卡运行 60 小时。低负载用 Tree sampler 追求单请求速度，高并发用 Linear sampler 追求系统吞吐。

这里的“无损”指采样器保持 AR 模型的输出分布，不是两次运行会逐 token 产生相同文本。这个区分很重要。它也不等于每个场景都快 2.2 倍：0.9B 的 1K/8K 测试里，单请求吞吐从 576 提到 681 token/s，并发 64 时从 9,643 提到 11,848 token/s；加速受接受率、两次前向开销和 batch 大小共同约束。

## 实验：旗舰强在智能体，不是各项都站在最上面

375B-A23B 每 token 激活约 23B，与 MiniMax M3 相同，低于 Nemotron 3 Ultra 的 55B、Inkling 的 41B 和 GLM-5.2 的 40B。它在 Toolathlon 和 SWE-Atlas-QnA 上领先这些开放模型，并在另外八项上位列第二，这个效率是有分量的。

但别把“frontier”读成“超过所有闭源模型”。Terminal-Bench 上，GPT-5.6 Luna 为 80.9，Claude Sonnet 5 为 80.5，K2-Horizon 是 70.2；HLE 上，Claude Sonnet 5 为 41.3，K2-Horizon 是 32.0。它更像一个有竞争力的开放旗舰，长板在工具使用和部分智能体任务，科学推理仍有缺口。

### 36B-A4B 与 32B：七分之一的激活参数，换来多大差距？

| $\tau^3$-Banking | 26.8 | 24.1 | 2.7 |
| Terminal-Bench 2.1 | 58.6 | 62.6 | 降 4.0 |
| SciCode | 38.9 | 37.9 | 1.0 |
| HLE without tools | 25.2 | 25.2 | 0.0 |
| GPQA Diamond | 80.8 | 82.8 | 降 2.0 |
| AA-LCR | 66.3 | 68.0 | 降 1.7 |

两者使用同一预训练数据与 recipe，且这两个中模型都没有经过 RL，SFT 都从最终的 mid-training checkpoint 开始，比较比跨家族榜单干净得多。36B-A4B 并非每项都接近：Terminal-Bench 差 4 分并不小；但它还在 $\tau^3$-Banking 和 SciCode 上反超。MoVA 的潜力可信，距离“稀疏模型已经无代价替代稠密模型”还远。

小模型的结果更偏科。7B 的 SWE-bench Verified 为 72.4，Qwen3.5 9B 为 50.8；Terminal-Bench 为 44.6 对 29.2。3.7B 在 SWE-bench Verified 上是 65.6，对 Qwen3.5 4B 的 41.2。0.9B 的 HumanEval++ 达 79.9，也赢过 Qwen3.5 0.8B 的 16.5。可是同一个 0.9B 在 GPQA Diamond 只有 27.3，Qwen3.5 2B 是 54.9；BFCL v4 也只有 28.0，后者是 43.6。小模型不是通用能力一起变大，而是训练数据强推的能力特别突出。

## 两组“不太好看”的审计，反而提高了报告可信度

### 70.2 分里，有多少是作弊？

作者审计了 Terminal-Bench 2.1 的 712 次试验，其中 500 次通过 verifier。GPT-5.6 Sol 作为 judge，对照任务描述、参考解、完整轨迹和 verifier 输出，把 24 次通过判为 reward hacking，占 4.8%，集中在 89 个任务中的 10 个。

这些行为包括读取泄漏答案、复制上游项目修复、利用隐藏 oracle、下载 benchmark 自己的参考解，以及操纵 grader。把它们改判失败后，分数从 70.2 降到 **66.9**。

这段我读完反而更愿意相信其余结果。不是因为它证明分数完全干净，而是作者至少承认 verifier 通过和真正解题不是一回事。当然，审计依赖单个 LLM judge，仍可能有漏检；66.9 也不该被理解为绝对无污染的下界。

### 智能体安全在间接注入面前掉得很厉害

聊天安全评估覆盖 88 个英文任务、每模型 16,458 个评分样本。旗舰的一般有害内容拒绝分数为 0.976，0.9B 仍有 0.873；但 OR-Bench Hard-1k 和 FalseReject 上，良性难题的过度拒绝仍接近一半。

智能体安全更棘手。面对直接恶意请求，K2-Horizon 有 66.0% 的轨迹低于可行动危害阈值；遇到间接 prompt injection，这个比例降到 37.5%，完全拒绝率只剩 2.5%。同一模型的良性任务成功率为 86.0%，过度拒绝为 0，所以问题不是“它太谨慎”，而是它对不可信内容里的恶意指令识别太浅。

论文还引入 MathErrataBench，让模型审查 200 篇数学预印本中的 717 个 gold issue。375B-A23B 的总恢复率为 35.7%，严格恢复率为 15.5%，只有 5.0% 的论文做到所有问题的位置、严重度和描述都正确。GPT-6 Astra 总恢复率达到 77.4，完美审查也只有 12.0%。这项结果把“能解数学题”和“能审数学论文”拉开了距离，后者远没有被解决。

## 我的判断：最大的贡献是开放开发过程，而不是某个单独模块

K2-Horizon 同时给了很多层东西，最好把它们拆开评价。

模型能力上，它是同激活参数规模下很有竞争力的开放家族，尤其擅长工具调用、终端任务和小模型软件工程；但旗舰没有越过最强闭源模型，科学推理与长链安全仍有明显差距。架构上，MoVA 和 softplus gate 都有清晰动机，36B-A4B 与 32B 的同数据对照也有说服力；Grouped RMSNorm 和 MoVA 各自贡献多少，还需要更细的独立消融。推理上，Uno 的共享权重、共享 cache 和分布保持采样很有工程价值，但实际部署要看自己的并发、上下文和输出类型，不能直接照搬 2.2 倍。

我觉得最耐用的资产，是 **完整开发历史**。380 个 checkpoint、58 次训练 run、21.6TB 数据、17 个代码仓库，以及预训练到部署的日志和管道，让外部研究者能问许多过去无法回答的问题：能力在哪个阶段出现？一次 rollback 前发生了什么？数学 RL 怎样迁移到代码？稀疏模型和稠密模型在同数据上如何分叉？

如果你在做模型训练，这份报告值得读的不只是第二章，而是第三到第七章里那些不够光鲜的训练事故、数据质检和 RL 控制面细节。如果你只想部署模型，7B、36B-A4B 和 Uno 更值得优先试；如果要把智能体暴露给网页、文件和真实工具，间接注入结果说明外部权限控制仍然不能省。

开放权重让大家能运行模型。开放过程，才让大家有机会理解模型。K2-Horizon 真正往前推的是后者。
