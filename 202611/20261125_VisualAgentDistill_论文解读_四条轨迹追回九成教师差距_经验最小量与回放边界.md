# 四条轨迹就追回九成差距：蒸馏视觉智能体，到底要攒多少交互经验？

你有没有过这种崩溃时刻——想把一个 27B 的视觉智能体压到 4B 能跑的规模，环境 rollout 一开就是几百个 episode，模拟器实例得常驻十几个，GPU 烧着，API 计费跳着。更让人头疼的是，学生模型换一个动作，后面看到的画面就全变了，上一轮辛苦采的轨迹立刻"过期"。于是圈子里默认了一个前提：蒸馏得喂够多、够杂的任务，不然学生只是背下了几条标准答案，换个房间就现原形。

上周翻到 arXiv 2611.28618 这篇，我的第一反应是：这帮人在抬杠。

他们问的问题朴素到有点冒犯常识——**要蒸馏出一个能用的视觉智能体，究竟需要多少种交互经验**？给出的答案更冒犯：在标准 Navigation 和 Sokoban 上，四条固定轨迹，把 4B 学生的成功率从 49.17% 拉到 82.08%、从 60.16% 拉到 85.55%，跟 27B 教师之间量到的差距吃掉了九成以上。而且优化阶段一次新交互都不给，纯靠回放旧前缀。

说实话，看到这个数我愣了一下。不是因为涨得多，是因为它把一个大家默认"越多越好"的维度，直接摁到了个位数。

---

## 核心摘要

这篇论文真正较真的不是"怎么蒸馏"，而是"蒸馏需要多少经验"这个几乎没人单独拿来当主问题研究的空白。作者搭了一套两阶段框架：先让一个独立的标注模型给训练池里的轨迹打上"能力—上下文"标签和有序的视觉决策描述，再用**覆盖优先、代表性兜底**的字典序贪心挑出 K 条完整轨迹；接着用这些轨迹的原始因果前缀做 on-policy 蒸馏（OPD），或者只回放固定历史、完全不执行新动作。结果是 4 条轨迹在 Navigation 和 Sokoban 上闭合了 91.86% / 90.28% 的教师差距，一个独立评测面板上纯回放保住了同任务在线训练 91.36% 的增益，连 1 个在线任务都能往别的任务迁移。

我的判断：这是一篇**问题定义比方法更值钱**的实证论文。它没有新的蒸馏目标函数，也没有新的模型结构，价值在于把"经验预算"这条曲线量了出来，并且老老实实把边界条件摊在桌面上。但"四条轨迹"这个说法有相当大的压缩空间，下面会拆开讲——它省的并不是算力，省的是**优化阶段的环境交互**，这两件事别混。

## 🎯 为什么"四条轨迹"值得较真

先把场景落地。视觉智能体跟文本模型不一样的地方在于，它不是一次性给个答案就完了：它看一张图，输出一个动作，环境变了，再看下一张图。DAgger 那篇老论文早就点破过这件事——**学习者的动作会改变它自己接下来看到的状态分布**。你在教师轨迹上做离线监督，学生一旦偏离，后面整个观测序列就飘到了训练数据没覆盖过的地方，误差像滚雪球。

所以直觉上，蒸馏视觉智能体应该需要大量"状态覆盖"：得多跑任务、多采轨迹、最好边训边刷新历史（on-policy）。这条思路本身没错，代价是重。GUI 智能体要开浏览器，具身智能体要开模拟器，真机更别提，每一步都是钱和时间。

作者把这个问题拆成了两个可以分开测的维度：

- **任务广度**：训练时到底得接触多少个不同的任务？能不能只有一个？
- **历史新鲜度**：训练时还得继续跟环境交互、刷新轨迹吗？还是把一开始攒下的几条旧前缀反复拿出来用就够了？

这两维度以前经常搅在一起。你做 on-policy 蒸馏，既增加了任务数，也刷新了历史，涨点了，说不清是哪一半的功劳。这篇论文的做法是**把两者拆成两条对照曲线**：橙色用 K 条固定轨迹做回放，青色用 K 个任务做真实在线交互，两边锁死同样的 100 次更新、batch 64、6400 条响应，K=4 时连任务 ID 都对齐。这样"回放能不能替代在线交互"就变成了一个能直接读数的比较，而不是一句口号。

我之前在做类似的数据精简时也碰到过这个坑：把训练池砍到十分之一，效果没掉，当时很高兴，后来才发现是因为采样次数没变——少量样本被反复抽了十倍。这篇论文聪明的地方是它没躲这个坑，反而把它写成了核心机制之一，后面会讲。

## 🧠 先别急，"一条轨迹"到底算什么

这是全文最容易被误读的地方，得先掰清楚。

一条轨迹 $\tau_i=(x_i,o_{i,1},y_{i,1},\ldots,o_{i,T_i},y_{i,T_i})$ 记录的是任务 $x_i$、每一步的视觉观测与反馈 $o_{i,t}$、以及模型的原始响应 $y_{i,t}$，一共 $T_i$ 次决策。关键在第 $t$ 步喂给模型的输入：

$$h_{i,t}=(x_i,o_{i,1},y_{i,1},\ldots,y_{i,t-1},o_{i,t})$$

这个叫**因果前缀**：包含系统指令和之前所有的原始推理（包括学生自己当时的胡思乱想），但严格排除当前这一步的响应和之后的所有观测。 replay 保留的是原始 $h_{i,t}$，一个字不改。

一条轨迹能展开成 $T_i$ 个前缀。所以"四条轨迹"绝不是四条训练样本——Navigation 那四条有 16 + 8 + 30 + 12 步，合计 **66 个原始前缀**；Sokoban 四条短一些，只有 10 个；SpatialGym 是 21 个。训练时从这些前缀里均匀抽样，每次让当前学生重新生成响应，教师去打分，6400 次响应一次不少。

回放的采样分布也写得挺细：

$$p_S(i,t)=\frac{1}{|S|T_i},\quad i\in S,\ t\in\{1,\ldots,T_i\}$$

先均匀挑轨迹，再在轨迹内均匀挑轮次。分母里那个 $T_i$ 是为了防止长轨迹天然占便宜——不这么归一，一条 30 步的轨迹会被抽到三倍于 10 步轨迹的次数。这个小设计看着不起眼，但它是后面"覆盖—重复"权衡能成立的前提。

还有一点得记牢：作者明说了，$K$ 数的是**固定轨迹数**（回放）或**不同任务数**（在线），不是被监督的响应数量。减小 $K$ 未必省训练算力，甚至可能更费——同样的 6400 次抽样砸在更少的前缀上，重复度反而上去了。论文后面专门用一张表把这点标了出来，我觉得这种自我揭短比多报两个点更让人信服。

## 🏗️ 怎么挑出那四条：覆盖优先，代表性兜底

挑选发生在训练之前，而且用的是**未适配的初始学生**自己采出来的轨迹池：120 条 Navigation、128 条 Sokoban、32 条 SpatialGym。K=4 分别只占 3.3%、3.1%、12.5%。

挑选全靠一个独立于蒸馏教师的标注模型（gpt-5.6-terra）。这里有个我认为很关键的设计约束：**标注只用来选数据，绝不进入学生或教师的 prompt**。学生看到的始终是原始截图和原始历史推理，看不到任何"技能标签"或"决策描述"。这就把 selector 的偏见挡在了策略之外——不然你很难分清涨点是因为数据选得好，还是因为给模型塞了提示。

标注分两条路走，下面这张图把 Navigation 的完整流程摊开了：

![图1：Navigation 记录的选择案例——从冻结的技能—上下文清单到四条代表性历史](https://arxiv.org/html/2611.28618v1/selection-case-navigation.png)

*图1：论文 Figure 3。(a) 环境文档 + 训练轨迹经标注模型生成并冻结"能力技能 / 使用上下文"清单，图里给了两条：Inspect the egocentric scene（Route / target evidence unresolved）、Interpret feedback and recover（Action feedback available to assess）。(b) 同一段经验的两条标注路径：上面是"机会对 → 覆盖"（Skill: interpret feedback and recover；Context: action feedback available to assess），下面是"决策描述 → 序列相似度"（Sink out of view; latest movement failed. Decide how to reorient and approach the sink.）。(c) 第 2 轮的真实比较：Selected #2 与 Runner-up 的 $\Delta C$ 都是 0，$\Delta F$ 分别是 1.726 与 1.682，靠代表性增益分胜负。(d) 四条贪心选出的历史：Laptop（16 步，$\Delta C=11$，$\Delta F=4.373$）、Sink（8 步，$\Delta C=0$，$\Delta F=1.726$）、Towel（30 步，$\Delta C=0$，$\Delta F=1.379$）、Toilet paper（12 步，$\Delta C=0$，$\Delta F=1.188$），合计 66 个原始前缀，全部保留用于 OPD / matched SFT。*

**第一条路：机会覆盖。** 标注模型先从环境文档里提议任务流程和组件能力，再用训练轨迹批次细化、合并同义词，冻结成允许的能力—上下文对集合 $\mathcal{I}$。注意它描述的是**反复出现的情境**，不是具体场景或标准解法。到了第 $t$ 步，$\mathcal{O}_{i,t}\subseteq\mathcal{I}$ 是"有证据支持的机会对"，证据必须出现在该步响应之前（截图、历史动作、反馈都行，之后的不算）。一条轨迹的覆盖是不同对的并集：

$$C_i=\bigcup_{t=1}^{T_i}\mathcal{O}_{i,t},\qquad E=\{i\in V:C_i\neq\varnothing\}$$

只数**不同**的对，不数出现次数。执行状态（成功示范 / 失败 / 不确定）单独记一个字段，明确不参与排序。这个选择我挺欣赏：挑数据时不看"这条轨迹跑成功了没"，只看"它有没有覆盖到某种需要能力的情境"。失败轨迹里往往藏着最有价值的纠错决策，按成功率筛会把它直接扔掉。

**第二条路：有序决策相似度。** 光看覆盖会漏东西——两条轨迹可以覆盖完全一样的能力对，但决策展开的顺序天差地别，而视觉智能体偏偏对顺序敏感。于是另起一套标注 $\mathcal{A}$，只看 $\bar h_{i,t}$（截图、观测、已解析的历史动作、反馈），当前响应、未来观测、最终结果一律屏蔽，产出：

$$d_{i,t}=\mathcal{A}(\bar h_{i,t}),\qquad \mathcal{D}_i=(d_{i,1},\ldots,d_{i,T_i})$$

每条描述记录目标、视觉状态、当前需要的决策、相关历史、变化和不确定性，还要过 schema / 证据检查和部分语义复核。

具体怎么算"像"？用带字段标签的 unigram/bigram TF-IDF 向量编码每条描述，对数词频 + $\ell_2$ 归一化。图像是通过**文字描述**进入计算的，不是 learned visual embedding——这点挺务实，省掉了额外训一个视觉编码器的麻烦，也让整个过程可审计。两条长度分别为 $m,n$ 的轨迹，先算任意两步描述的余弦相似度 $c_{pq}$，再做一个保序的软匹配动态规划：

$$D_{pq}=\max\{D_{p-1,q},\ D_{p,q-1},\ D_{p-1,q-1}+c_{pq}\},\qquad s(i,j)=\frac{D_{mn}}{\max(m,n)}$$

熟悉序列比对的话一眼就认出来了，这是个带跳过的最长公共子序列式打分，除以 $\max(m,n)$ 做长度归一。它跟"把两条轨迹的所有描述扔进集合比相似度"的差别就在于**顺序**——第 3 步的决策不能跟第 12 步的决策随便配对。后面消融里那个 "unordered matching" 对照，就是把这段动态规划换成一对一匹配，用来验证顺序到底有没有用。

有了 $s(i,j)$，用 facility location 给每个候选轨迹等权：

$$F(S)=\sum_{i\in E}\max_{j\in S}s(i,j),\qquad F(\varnothing)=0$$

直观讲就是"整个池子里的每条轨迹，都能在选出的集合里找到一个最像的代表，把这些相似度加起来"。最后一步是字典序贪心：

$$j^*=\operatorname*{arg\,max}_{j\in E(S)}^{\mathrm{lex}}\bigl(\Delta_C(j\mid S),\ \Delta_F(j\mid S)\bigr)$$

$\Delta_C$ 是新增的不同机会对数，$\Delta_F$ 是加入后的代表性增益。**先比覆盖，覆盖打平才比代表性**；覆盖一旦饱和，剩下的名额全由代表性说了算。$E(S)$ 里排除了跟已选轨迹同 task ID 的候选，避免四条全来自同一个任务。剩下的平局用不可变 ID 破，明确不按成功率、长度、执行状态排序。

Sokoban 的案例图把这套流程演得更清楚，尤其能看到"覆盖饱和之后"发生什么：

![图2：Sokoban 的第二个选择案例——128 条轨迹选出 4 条](https://arxiv.org/html/2611.28618v1/selection-case-sokoban.png)

*图2：论文 Figure S2。顶部 (a) 是视觉证据到因果决策描述的转换：Goal「Push the box onto the target」、State「Player below box; target upper-left」、Decision「Reposition and push toward the upper-left target」。(b) 第 2 轮比较：Selected #2 与 Runner-up 的 $\Delta C$ 都是 1，$\Delta F$ 为 2.646 对 2.514，仍是覆盖打平后由代表性决定。(c) 贪心顺序：S1（5 步，$\Delta C=6$、$\Delta F=9.184$，「Reposition before pushing → Avoid trapping the box」）、S2（2 步，$\Delta C=1$、$\Delta F=2.646$，「Approach a viable pushing side → Keep the target reachable」）、S3（1 步，$\Delta C=0$、$\Delta F=3.345$，「Push toward the adjacent target → Respect push-only dynamics」）、S4（2 步，$\Delta C=0$、$\Delta F=1.892$）。最后两条一条新机会都不加，纯粹是代表性补位；四条合计 10 个原始前缀。图里特意说明展示的是冻结记录，不是理想化的成功解法。*

## 🔧 训练：固定历史 OPD 和 matched SFT

选完轨迹，两条训练路径共用同一批冻结前缀和同一串抽样顺序。

**固定历史 OPD**。冻结的更新前学生 $\pi_{\mathrm{old}}$ 在 $h_b$ 上重新生成响应 $y_b$（这一步是"on-policy"的含义：响应来自学生自己，不是教师写的），教师 $q$ 逐 token 打分。记 $u_{b\ell}=(h_b,y_{b,\lt \ell})$，token 信号和策略比是：

$$a_{b\ell}=\operatorname{sg}\!\left[\log q(y_{b\ell}\mid u_{b\ell})-\log \pi_{\mathrm{old}}(y_{b\ell}\mid u_{b\ell})\right],\qquad r_{b\ell}(\theta)=\frac{\pi_\theta(y_{b\ell}\mid u_{b\ell})}{\pi_{\mathrm{old}}(y_{b\ell}\mid u_{b\ell})}$$

$\operatorname{sg}$ 是 stop-gradient，信号是教师与更新前学生的对数概率差，不归一化、detach 掉。实现里用原生策略目标，clipping 区间 $[0.8,1.2]$，没有 dual clip，没有额外的 reward、参考策略 KL 或熵正则。作者补了一句挺诚实的注解：这个目标在更新前策略处的局部梯度等价于 token 级 log-ratio 蒸馏信号，但**不宣称它是完整自回归序列 KL 梯度的精确估计**。说实话这种措辞在现在的论文里不多见，多数人会直接把"等价于 KL 最小化"写上去。

**matched SFT**。同一批前缀，让教师生成 $z_b\sim q(\cdot\mid h_b)$，只在这些响应上做 response-only 交叉熵，标签是教师原生的推理和动作，不是标注描述，不做成功过滤也不做格式过滤，连被截断的输出都留着。两边匹配的是抽样顺序、更新次数和响应数——作者反复强调，这**不等于**匹配了 token 数或算力，OPD 数的是学生生成的 token，SFT 数的是教师标签的 token，前缀处理、教师打分、采集、标注、评估统统不在账上。

**在线对照**。选中任务 ID 组成一个受限任务目录，学生的响应真的丢进环境执行，产生新观测、刷新历史。K=4 时回放和在线用的是同一批任务身份，所以差异可以比较干净地归因到"要不要新交互"。

配置上，学生是 Qwen3.5-4B 和 Qwen3.5-9B，教师是冻结的 Qwen3.5-27B，开 native thinking，训练框架 Slime 0.4。100 次更新、batch 64、学习率 $10^{-6}$、fresh Adam、32768 响应 token 上限；训练时温度 1、top_p 1、关掉 top-k；环境奖励完全不进训练。三个环境沿用 VAGEN 的接口：AI2-THOR Navigation、Sokoban、Theory-of-Space 的 SpatialGym 制图。

## 🧪 评测怎么摆的

| 维度 | 设置 |
|---|---|
| 候选池 | 初始 4B 学生采集，120 / 128 / 32 条轨迹（Navigation / Sokoban / SpatialGym）|
| 训练预算 | 100 updates × batch 64 = 6400 条响应，所有方法一致；token 与算力不等 |
| Navigation | 60 个标准任务 + 60 个 long-horizon（同样场景目标，初始朝向旋转 180°），每个任务评 4 次，30 个模型轮次、每轮最多 5 个动作，距目标 ≤1 m 算成功 |
| Sokoban | 64 个 6×6 单箱地图，最短解 1–5 步，每任务评 4 次 |
| SpatialGym | 16 个训练单房间 / 4 个 held-out 单房间 + 20 个双房间场景；10 轮探索后交图 |
| 指标 | Navigation / Sokoban 为平均成功率；SpatialGym 为连续 cogmap_score（位置精度、探索覆盖、direction − 1/8、facing − 1/4 四项均值，后两项 clamp 到 0）|
| 评测协议 | 各模型共享任务、repeat seed、prompt 与预算，分数取 4 次重复均值；只用 update 100，不取曲线峰值 |

这里有个细节值得停一下：**原始评测面板在开发过程中被检视过**（论文原文 "Original panels were inspected during development"）。作者没藏着，还额外补了一个独立的 Navigation 面板和四次训练重复来兜底。这个诚实度我认，但它确实意味着主表数字不能当成完全干净的 held-out，后面聊批判时会再拎出来。

## 📊 主表：四条轨迹到底拿回了多少

先看最核心的 Table 1（4B 部分，成功率为 %，SpatialGym 为 0–1 的制图分）：

| 方法 | Nav 标准 | Nav 长程 | Sokoban 64 图 | SpatialGym held-out | SpatialGym 双房间 |
|---|---|---|---|---|---|
| Teacher 27B（共享）| 85.00 | 25.00 | 88.28 | 0.4566 | 0.3777 |
| 原始 4B 学生 | 49.17 | 13.33 | 60.16 | 0.2553 | 0.1157 |
| 全任务在线 OPD | 78.75 | 21.25 | 85.94 | 0.4763 | 0.3051 |
| K4 离线 SFT | 74.17 | 20.42 | 76.17 | 0.3996 | 0.2413 |
| **K4 离线 OPD** | **82.08** | **22.08** | **85.55** | **0.4112** | **0.2700** |

4B 上，四条固定轨迹把标准 Navigation 抬了 32.92 个点、Sokoban 抬了 25.39 个点，分别闭合了 91.86% 和 90.28% 的"教师差距"（分母是教师减原始学生）。更反直觉的是对照行：**全任务在线 OPD 只有 78.75 / 85.94**，K4 离线 OPD 在标准 Navigation 上反而更高，论文算出来 K4 保住了全任务在线增益的 111.27% / 98.48%。

等等，离线回放比全量在线还好？

作者给的解释是覆盖—重复权衡：全池有 1840 / 402 / 236 个前缀，K4 只有 66 / 10 / 21 个，6400 次抽样砸下去，小集合把选中的决策反复监督了很多遍，大集合则把次数摊薄到大量没那么有代表性的前缀上。这个解释我觉得站得住，而且论文自己给出了离线 K4 超过全池 OPD（77.50 / 83.59）的旁证。但坦率讲，这里也埋着一个公平性问题：全池方法用的是同一套 100 updates / 6400 响应的超参，没有为更大的数据池重新调 epoch 或学习率。数据多了却不加训练步数，本来就容易吃亏。作者没做等 token / 等算力的对照，Table S6 和 S11 里也明说了"不是 equal-compute 或端到端 GPU 小时比较"。所以这一行我会打个问号，不会拿它当"少数据优于大数据"的证据。

**格式合规不是全部。** 这是我很喜欢的一组对照。K4 OPD 和 K4 SFT 在 Navigation 上的格式正确率是 97.99% / 98.00%，几乎一模一样；但成功率是 82.08% / 74.17%，差了近 8 个点。Sokoban 同样：格式 93.05% / 93.44%，成功率 85.55% / 76.17%。也就是说学生把"该怎么输出动作"这套接口学得一样好，真正拉开差距的是**决策质量**。OPD 让学生在自己采的响应上被教师纠偏，SFT 只是模仿教师写好的答案——这个差别在只看格式指标的评测里会被完全抹平。做智能体落地的人应该把这条抄进 checklist：别拿 valid-action rate 当能力指标。

**迁移的广度也量了。** K4 OPD 改善了 60 个标准 Navigation 任务里的 45 个（3 个退步）、64 张 Sokoban 图里的 31 张（1 个退步）；长程 Navigation 是 20 改善 / 32 持平 / 8 退步；4 个 held-out 单房间和 20 个双房间场景**全部改善**。这些评测任务 ID 都不在候选池里。SpatialGym 两房间的分项也拆开看了：探索覆盖 0.413 → 0.806、direction 0.012 → 0.078、facing 0.032 → 0.156、position 0.042 → 0.233，涨的不是单一维度。

## 🔬 回放能不能替代在线交互

这是标题里我最想看的一半，也是论文做得最细的一块。

**同任务、同预算的硬碰硬。** 用同样的四个任务，在线 OPD 拿到 82.50% / 22.50%（标准 / 长程 Navigation）和 84.38%（Sokoban）；固定历史回放是 82.08% / 22.08% / 85.55%。换成 episode 数就是 197/240 vs 198/240、53/240 vs 54/240、219/256 vs 216/256——**差 1、1、3 个成功 episode**。优化阶段零新交互，几乎打平。

但 SpatialGym 双房间上在线明显更好：0.2998 对 0.2700。作者的解读是"在需要持续交互的场景下，历史刷新更有用"。我觉得这个边界恰恰是全文最有价值的发现之一：回放不是万能替代品，它在短程、决策结构稳定的任务上够用，在需要长程探索和地图构建的任务上会露怯。

**独立面板。** 主表面板被开发时看过，所以作者又补了一个 collaborator-reported 的独立标准 Navigation 面板，每个模型 240 个 episode：

| 模型 / 方法 | 成功数 | 成功率 |
|---|---|---|
| 原始 4B | 110/240 | 45.83% |
| Teacher 27B | 205/240 | 85.42% |
| 完整选择器 K4 离线 OPD | 184/240 | 76.67% |
| 仅代表性 K4 OPD | 170/240 | 70.83% |
| 同任务 K4 在线 OPD | 191/240 | 79.58% |

这里两个比率要分清：教师差距恢复 $(184-110)/(205-110)=77.89\%$，在线增益恢复 $(184-110)/(191-110)=91.36\%$。摘要里那句"retaining 91.36% of the same-task online gain"指的后者，不是"追回教师九成"。主表上的 91.86% 是另一个面板、另一个分母。**同一个 91% 在论文里出现了两次，含义完全不同**，读的时候别串。

**一条任务也够。** 在线 K1（只在一个任务上真实交互）拿到 80.42% / 80.47%（标准 Navigation / Sokoban）和 0.4057 / 0.2878 的 held-out / 双房间制图分，比原始学生的 49.17% / 60.16% 高出一大截。离线 K1 也有 73.75% / 80.47%。所以"经验最小充分量"这个问题的答案，在作者的三套环境里大概是：**决策情境覆盖够了，一条到四条就够；覆盖不够，堆任务数也补不齐**。K16 在长程 Navigation（23.75%）和制图（0.46 / 0.31）上确实更好，说明更宽的池子对某些维度仍有收益。

## 📊 选择器到底有没有用：消融与重复

四条轨迹能work，是"随便挑四条都行"，还是"必须这么挑"？论文给了两层对照。

Table 2 的单次运行消融（4B，K4 OPD，成功率 %）：

| K4 OPD 选择器 | Nav 标准 | Nav 长程 | Sokoban |
|---|---|---|---|
| 完整（参考）| 82.08 | 22.08 | 85.55 |
| 仅代表性 | 77.92 | 17.92 | 80.47 |
| 仅覆盖 | 79.17 | 19.17 | 82.42 |
| 无序匹配 | 81.25 | 21.25 | 85.55† |

† 表示 Sokoban 复用了同一次选择结果，没多跑一次训练。去掉任一准则都掉点，无序匹配在两个 Navigation 面板各低 0.83 个点——顺序相似度确实有贡献，虽然幅度不大。

Table S5 的原始随机子集对照更能说明问题：

| K4 OPD 选择器 | Nav 标准 | Nav 长程 | Sokoban |
|---|---|---|---|
| 完整选择器 | 82.08 | 22.08 | 85.55 |
| 随机子集 1 | 74.17 | 18.75 | 78.52 |
| 随机子集 2 | 76.25 | 19.58 | 80.08 |
| 随机子集 3 | 77.08 | 20.42 | 82.03 |
| 仅覆盖 | 78.75 | 20.00 | 81.25 |
| 仅代表性 | 79.17 | 20.42 | 82.03 |
| 无序匹配 | 76.67 | 18.75 | 85.55† |

完整选择器比三个随机子集的均值高 6.25 个点（标准 Navigation）、2.50 个点（长程）、5.34 个点（Sokoban）；在 held-out 单房间 SpatialGym 上恢复了 77.4% 的初始学生到教师差距。随机挑四条不是不行，但平均要掉五六个点，这个差距在这类任务上不算小。

单次运行结果容易是噪声，所以作者又补了四次训练重复：完整选择平均 81.98% / 23.75%，仅代表性 80.73% / 23.54%，固定随机 K4 是 76.88% / 21.67%。完整选择对固定随机 K4 的平均优势是 5.10 个点（标准）和 2.08 个点（长程）。但作者也老实写了：**完整选择与仅代表性之间的排序在四次重复里并不一致**（差值 1.25 和 0.21 个点，忽上忽下）。也就是说，"覆盖 + 代表性 > 随机"这个结论稳，"覆盖优先 > 仅代表性"这个结论没那么稳。这种自曝其短挺难得的，比把消融全写成单调下降可信多了。

## 📊 9B 扩展：换个学生规模还成立吗

同一批 K4 历史、同一个 27B 教师、同样的 100 次更新，直接拿去训 Qwen3.5-9B，选择过程不重跑：

| 方法 | Nav 标准 | Nav 长程 | Sokoban | held-out 单房间 | 双房间 |
|---|---|---|---|---|---|
| 原始 9B | 67.08 | 25.83 | 64.06 | 0.2790 | 0.2023 |
| 全任务在线 OPD | 86.25 | 20.00 | 87.50 | 0.4881 | 0.3212 |
| K4 离线 SFT | 72.92 | 23.75 | 83.20 | 0.4274 | 0.2555 |
| K4 离线 OPD | 74.17 | 24.58 | 87.50 | 0.4255 | 0.2976 |

Sokoban 上 K4 OPD 涨了 23.44 个点到 87.50%，追平在线 OPD，还压过 K4 SFT 的 83.20%。标准 Navigation 只涨 7.08 个点到 74.17%，在线 OPD 是 86.25%，差得挺远。长程 Navigation 更尴尬：原始 9B 是 25.83%，K4 OPD / SFT / 在线分别 24.58 / 23.75 / 20.00，**全都没超过不训**，而且原始 9B 本身已经比教师量到的 25.00% 还高。

这块我读到的时候有点皱眉。它说明选出来的"好经验"是跟学生规模耦合的——用 4B 的初始轨迹挑出来的前缀，对 9B 未必是最需要补的情境。作者把这称为"不重新选择也能支持更大学生"，但数据其实只支持一半：Sokoban 和制图成立，Navigation 两块不成立。而且"原始学生超过教师"这件事，直接把教师差距恢复这个指标的分母打成了负数或接近零——论文也识趣地说这个面板上该比率"不具信息量"。

## 🔬 覆盖饱和长什么样

补一张诊断图，它比任何文字都直观地解释了"为什么四条就够"：

![图3：训练池机会出现热力图——前 16 个冻结选择排名中各上下文的观测情况](https://arxiv.org/html/2611.28618v1/analysis_context_heatmap.png)

*图3：论文 Figure S4。三栏分别是 Navigation（Context ID 1–11）、Sokoban（1–7）、SpatialGym（1–12），横轴是冻结的选择排名 1–16，紫色表示 Context observed、浅色表示 Not observed，橙色竖框圈出 First four trajectories（正好落在 rank 4 处）。可以清楚看到，前四条轨迹之后新增的紫色格子非常少——Navigation 尤其明显，第一条历史就把 11 个观测对全覆盖，后面基本只是在补代表性。图注特意提醒：填充格子表示"有机会标注"，不代表执行成功，也不代表独立的视觉状态覆盖。*

这张图我需要配一句冷水：它证明的是**标注空间里的机会覆盖**饱和得快，不是策略能力饱和。作者在论文里也把这两个分开讲了——"annotation-space diagnostics"和"trained-policy outcomes"是两码事。一个情境被"覆盖"了，跟学生在这个情境上做对决策了，中间还隔着整段训练。

不过它确实给出了覆盖率—重复度权衡的机制解释。K4 保留 66/10/21 个前缀，全池是 1840/402/236；6400 次均匀抽样下，每个前缀的期望抽取次数 $\mathbb{E}[n_{i,t}]=R/(|S|T_i)$，小集合里的每个决策被反复看见，大集合里的决策大多只被瞥一眼。论文把这称为 coverage–repetition tradeoff，并明说它"可能解释"数据量结果——用的是"may"，没有当成定论。这种措辞我给加分。

## 🤔 我的判断：哪些能拿走，哪些要打折

聊了这么多数据，该下判断了。

**最值钱的是问题定义，不是方法。** OPD、prefix replay、facility location、TF-IDF + 保序匹配，这些件件都不是新东西。论文自己在 Related Work 里把家底摊得很清楚：GKD、MiniLLM、DistiLLM 做学生生成序列上的蒸馏，DAgger 讲动作引起的状态漂移，ReOPD 和 WAM-OPD 做固定轨迹的前缀加权回放，LIMA 和 1-example RLVR 讲少样本适配，CRAIG / DSIR / DEITA / LESS 讲数据选择，Voyager / ExpeL 讲技能和经验复用。这篇的增量在于：把"经验预算"单独拎出来做成主变量，把任务广度和历史新鲜度拆成两条可对照的曲线，然后在三个环境、两个学生规模上把曲线量出来，还配了随机子集、组件消融、matched SFT、全池和在线一整套对照。这属于扎实的实证研究，不是底层突破。想找新 loss、新架构的人可以不用细读；想给自己的智能体训练砍数据预算的人，值得全文看一遍。

**四条轨迹这个说法得拆开理解。** 它省的是优化阶段的环境交互，不是全流程成本。摊开算：先要采 120 / 128 / 32 条初始学生轨迹，再要用 gpt-5.6-terra 做能力清单构建、机会标注、决策描述、schema 检查、部分人工语义复核；训练时 6400 次响应一次不少，教师 27B 逐 token 打分也一次不少，标注模型和教师的推理费用全在账外。Table S6 / S11 里"offline zero excludes prior candidate acquisition"这句话就是作者自己划的红线。所以正确的读法是：**在交互昂贵、离线算力相对便宜的场景里，把在线 rollout 换成固定前缀回放是划算的**；如果你的瓶颈本来就是 GPU 小时，这套方法未必省钱。

**教师差距恢复这个指标对分母很敏感。** 标准 Navigation 教师 85.00、学生 49.17，分母 35.83；Sokoban 教师 88.28、学生 60.16，分母 28.12——这两个还算健康。但长程 Navigation 教师只有 25.00、学生 13.33，教师自己都快不会做，这个面板上压根没人报恢复率；9B 长程更是原始学生 25.83 反超教师 25.00。作者在 Appendix F 里专门写了"scores with small denominators require particular care"、"neither ratio treats measured teacher/online performance as an upper bound"、比率可以超过 100%、描述的是分数增益不是能力比例。这些免责声明写得比多数论文诚实，但也提醒我们：拿一个本身不太行的教师当上界，恢复率天然容易好看。真要评估，还是得看绝对成功率和独立面板。

**单 run 端点 + 1 个 episode 的差距，别过度解读。** 主表是单次训练运行的 update 100 端点；回放与在线在 K4 上差 1、1、3 个成功 episode（197/240 vs 198/240 这种量级）。论文自己写了"small differences are not evidence of statistical equivalence"，四次训练重复和独立面板补了一些，但独立面板上教师差距恢复只有 77.89%，比主表 91.86% 低了十几个点；11 个 selector-control 和 12 个 K1/K16 端点是合作者报告的聚合值，原始训练日志、逐 episode 记录、精确子集 ID 映射**没有本地审计**，离线 K1/K16 与在线的 task pairing 也标成"unverified"。我的看法：结论方向（少量经验可迁移）可信，具体点位（91.86%、6.25 个点）应当当作点估计而非定值。这块我也不是特别确定，因为缺配对置信区间的原始记录，只能按作者的措辞保守处理。

**环境偏简单，别急着外推到真实 GUI 智能体。** Sokoban 是 6×6 单箱、最短解 1–5 步；Navigation 最多 30 个模型轮次、每轮最多 5 个动作、判定是水平距离 ≤1 m；SpatialGym 是 10 轮探索后静态交图，指标是四项连续分的平均。全部是短程、确定性、反馈清晰、格式明确的任务，而且**环境奖励完全不进训练**，纯靠教师 token 级信号。OSWorld、WebArena、真实手机 GUI 那种几十步、页面随时变、还有弹窗干扰的长程任务，跟这里的设定差着一个量级。作者把 Scope and limitations 写得很短，只说了"collection and annotation remain necessary"和"single training runs、development-inspected panels"，没有正面讨论外推边界——这算是这篇论文我觉得稍稍不够的地方。

**一个容易被忽略的不公平：全池 baseline 没调超参。** 前面提过，100 updates / 6400 响应锁死对 K4 有利、对全池不利。既然论文自己都说了"匹配 draws 和 updates 不等于匹配 token 或算力"，那全池 OPD 反而更低这个结果，更像是在说"固定更新预算下小池子收敛更快"，而不是"数据越少越好"。要坐实后者，得给全池加一组按 token 对齐、或调到收敛的对照。这个缺口不影响主结论，但影响"K4 超过全池"这句话的分量。

**还有一个小细节值得记：** 论文的 9B 实验直接复用了 4B 选出的轨迹，选择过程没重跑。这既是卖点（选一次多处用）也是局限（情境跟学生规模耦合）。长程 Navigation 上 9B 全军覆没，我怀疑就跟这有关，但论文没做"为 9B 重新选择"的对照，所以只能算猜测。

## 💡 工程上能拿走什么

顺着上面的判断，给几条我觉得真能用的：

**选数据别只按成功率筛，按"决策情境覆盖"筛。** 这套框架里最反直觉也最实用的一条：失败轨迹、不确定轨迹里的机会对，跟成功轨迹一样算覆盖；执行状态单独记、不参与排序。做智能体 SFT 时我们习惯先过滤掉失败 episode，其实纠偏决策往往就藏在那些轨迹里。哪怕不实现整套 TF-IDF + 保序匹配，光是"给轨迹打上能力—情境标签、贪心补覆盖、去重"这一步，就比随机采样稳。

**标注物只用于选数据，别灌进 prompt。** 作者反复强调 annotations 既不进学生也不进蒸馏教师的输入。这条纪律在工程上特别容易被破坏——一旦把"这段需要重新定位"之类的描述塞进上下文，涨点就说不清是数据选得好还是提示加得好，线上还多一份标注成本。保持训练输入是原始因果前缀，可审计、可复现。

**在线 rollout 贵的时候，先试 prefix replay。** GUI 智能体、真机、按调用付费的 API 环境，优先攒一小批初始策略的完整轨迹，展开成因果前缀做 OPD。按这篇的数据，短程任务上有机会拿到在线增益的九成。但记得同时盯两个信号：一是格式正确率和任务成功率是否背离（背离说明涨的是决策质量，同涨可能只是学会了接口）；二是需要长程探索的任务上，回放大概率打不过在线，别硬替。

**别把 teacher-gap recovery 当唯一 KPI。** 分母小、教师弱、学生反超教师的面板都会让这个比率失真。落地时把绝对成功率、独立面板、以及逐任务的改善/退步数一起摆出来。这篇论文给的 "45/60 改善、3 退步"、"4 个 held-out 房间全改善" 这类分布信息，比一个 91.86% 更能说明迁移是否真的发生了。

**重复监督要配监控。** 少量前缀 + 固定 6400 次抽样，本质是让模型把同一批决策看很多遍。作者的防护是覆盖优先保证前缀多样性。你自己做的时候，建议把每个前缀的期望抽取次数 $\mathbb{E}[n_{i,t}]=R/(|S|T_i)$ 打进日志，配合训练曲线看有没有过拟合到那几条轨迹——这篇论文报了 300 个 4B 观测点、180 个 9B 观测点，都是每 5 次更新采一次、不平滑，最终分只取 update 100 不取峰值，这个记录习惯值得抄。

**一个还没被回答的问题：** 覆盖饱和的判据是标注模型给的机会对，而标注模型本身也是个大模型。如果换成更弱的标注器，或者干脆无标注（纯视觉 embedding 聚类），这条"四条就够"的曲线还成立吗？论文没做这个消融。我是真的觉得，这个方向下一步该问的是"选择质量对标注器有多敏感"，而不是继续把 K 往下压。

---

坦率讲，这篇论文不会改变谁的技术路线，但它会让人重新算一遍自己的数据预算。把一个"越多越好"的默认前提摁到个位数，还把边界、免责声明、未审计的聚合值一条条摊开——这种做法比多刷两三个点更让我愿意信它。

如果你也在给视觉智能体砍 rollout 成本，那套"覆盖优先 + 保序代表性 + 原始因果前缀回放"值得先在小环境里复现一遍。至于能不能直接搬到几十步的真实 GUI 任务上，我持保留态度，得等有人把长程、噪声反馈、动态页面的曲线也量出来。
