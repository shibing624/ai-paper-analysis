# 不训练、不算梯度，一个 27B 模型把自己的权重改好了

你有没有被这种输出折磨过：模型答一道数学题，写到一半突然卡死，同一句话翻来覆去地重复，一直吐到 16384 个 token 的上限被硬切断，连个答案都没给。去翻 log，`I will write the response.` 被复读了 549 遍。

我的第一反应是又撞上 decoding 的退化循环了，调 temperature、加 repetition penalty、换个 prompt，糊弄过去。可这些动作全发生在模型外面，那几百亿个参数从头到尾一动没动。下回遇到同类题，它还是会掉进同一个坑，一模一样地复读 549 遍。

那能不能让模型自己动手，把出问题的权重改掉？不训练，不算梯度，不开第二次反向传播，就靠它自己推理、自己写代码、自己验证，把改动直接写进自己的参数里。

上周刷到 arXiv 上这篇 2611.21885，标题起得相当平——*Language Models Can Rewrite Their Own Weights*。读完之后我盯着 Figure 1 看了好一会儿。它真做到了，而且做得比我预想的干净。

---

## 核心摘要

模型一旦训练完就冻结，想变好只有两条路：再训一次，或者在推理时堆 prompt、套 harness、加 test-time compute——可这些收益任务一结束就蒸发了。这篇论文给了第三条路：让一个 27B 的开源模型把自己的权重当成可读写的数据，靠自己的推理诊断失败、写 Python 改数值、用配对测试验证，只提交让自己在留出题上变好的编辑。它给自己动了一刀，490 道从未见过的题上准确率从 57.2% 抬到 63.8%，**涨了 6.6 个点**，配对检验 $p \lt 10^{-5}$；连做八轮，其中五轮主动撤回编辑，在用的模型准确率只升不降。它还把一个被噪声砸坏、几乎一道题都答不对的自己修回到 33.0%，并且这个修复能迁移到六个从未见过的图像 benchmark，恢复到原模型 83% 的水平。说实话，这不是底层突破，是一次设计得极干净的概念验证——它把「训练和推理之间那堵墙」凿开了一个小口，真正值钱的是这个证据本身，不是那 6.6 个点。

## 🎯 那堵墙，是物理定律还是工具习惯

论文开篇引了图灵 1947 年的一句话，大意是：我们要的是能从经验里学习的机器，而让机器改动自己的指令，正是这件事的机制。快八十年了，我们造出来的大模型偏偏把这两件事分得清清楚楚。

干活的是一个冻结的权重集合，改它得另起炉灶：懂 pre-training 和 post-training 的人、一大片集群、一条训练流水线。用户能在对话里改的只有 prompt，而 prompt 换个任务就没了。人不是这么工作的——同一颗脑子既干活也从每次成败里调整自己，不需要单独的「训练轮次」。

作者把这件事说得很不客气：训练和推理之间那堵墙，是我们工具的限制，不是智能的属性。

这句话我挺买账的，但得先看清它到底在跟谁较劲。近两年最热的 test-time scaling，本质是拿推理时多烧的算力换答案质量，代价是每次回答都要付这笔钱，任务结束收益归零。另一头的训练，改动确实写进了权重、一次付清，可它要梯度、要优化器、要一整套 pipeline。self-rewriting 想占的是中间那块空地：**改动写进权重，每答一道题不再额外掏钱，但整个过程只跑前向传播，跟线上 serving 一样**。

说到这个，做过在线服务的都懂这个差别的分量。推理时多挂一层反思模块，P99 延迟和成本是常驻的；权重里改一刀，是一次性的。

## 🧠 让模型当自己的优化器

先把直觉摆出来：把权重文件当成一份模型能读、能写、还能拿自己当小白鼠做实验的数据。它不再是那个被梯度推着走的被动对象，而是拿起手术刀的人。

![图 3：self-rewriting 的整体框架，输入是模型自己的权重或一份损坏副本，输出是写进权重的编辑 Δ](https://www.mulanai.com/fs/files/1121_53a04fee_framewor.png)

*图 3：方法框架。整个 session 在一台 CPU 上跑，顶部三个禁用标签——no gradient、no optimizer、no stronger model——把「训练」和「找个更强的外援」两条退路都堵死了。模型每轮只做一个动作，改动 Δ 最终以 $\theta' = \theta \oplus \Delta$ 写回权重，再拿到从未见过的留出题上评估。*

这张图值得逐块拆。左边输入有三样：模型自己的权重 $\theta$（或者一份某个矩阵被噪声覆写的损坏副本 $\tilde\theta$，只告诉它「有些值坏了」，不告诉它坏在哪）、它在练习题上的批改结果作为起始诊断、以及一套完全相同的工具和任务。底部那行小字挺关键：Qwen3.5 2B、4B、9B、27B 四个尺寸，用的是**同一套任务和同一套工具**，这是一个控制变量的规模对照。

中间那个粉色框是主角 $M_\theta$，一句话点题：跑 session 的是它，被它改的也是它自己的权重。每轮写一小段推理加一个动作，动作只有三种：

- **Code**：把权重当数字读进来、写新值出去，Python 跑在 CPU 上，没有 GPU，框架会拒绝任何加载模型、起进程、调优化器的代码。图里给的示例是 `W = load(name)`、`W = remove_direction(W, u, 0.05)`、`save_edit(name, W)`。
- **Generate**：一次配对测试（paired test），未编辑和已编辑的模型用同一批题、同一组随机种子各答一遍，看差别。
- **Read**：读自己在指定文本上的 hidden states。

预算卡得很死：一个 session 最多 $B=20$ 次前向传播、$C=200$ 次代码运行，用完、超时或轮数到顶就结束。右边输出那块，编辑 $\Delta$ 叠回权重，然后在没有任何 session 见过的留出题上评估。

这里最让我在意的是那个编辑算子。它不是随机扰动，也不是梯度步，而是一次方向投影：

$$W_{\text{edited}} = W - \alpha\, u u^{\top} W$$

你想想看，$u u^{\top} W$ 是把矩阵 $W$ 沿单位方向 $u$ 写进残差流的那一部分单独抠出来，$\alpha$ 是削掉的比例（论文里常用 0.05）。工程直觉其实很朴素：模型先读自己的 hidden states，发现某个方向上一层比一层「卡」得厉害——复读循环就是这么来的——然后把这个方向从中间若干层的输出矩阵里削掉 5%。不是重新学一个映射，是把一条已经测出来的坏通路按下去。

顺带一提，这里的 hidden state 在论文里叫 residual stream，MLP 的输出矩阵叫 down_proj，模型自己写代码时用的就是这些名字。它不是在猜，是真去读了数值。

还有个守门机制我挺喜欢。第一套协议里，模型改完就提交；第二套协议更严，提交前框架先在一批**保留练习题**上测一次，这批题 session 既读不到也用不了，测完由模型自己决定提交还是撤回（withdraw）。撤回就把模型原样留在那儿。这个设计直接堵死了「在自己改过的题上自我感觉良好」的口子，后面八轮只升不降的曲线，靠的就是它。

## 🏗️ 实验怎么摆的，哪里做得细

模型是 Qwen3.5 一家四兄弟：2B、4B、9B、27B，原生多模态——这解释了为什么后面能拿图像任务来检验修复，不用另接视觉塔。

练习题是 DeepScaleR 里的 3000 道数学题，作者把和 MATH-500、AIME 2024/2025、HMMT February 2025、AMC 2023、OlympiadBench、GPQA-Diamond 重叠的题全删了。这个小细节我挺喜欢的。做「留出题上变好」这种 claim，最怕的就是练习集和评测榜暗中串味，把去污染清单列得这么细，比含糊一句「held-out」可信得多。

评估也定得死：490 道留出题，每题采 8 个答案，报告的是相对 base model 同一批答案的配对变化，误差线是 95% 区间，配对检验预先固定。另一套独立评估用 200 道留出题、每题答一次、同种子对照。所有 session 都从 base weights 重新起步，不许把上一轮的编辑当起点滚雪球——这点后面聊「递归自我改进」时要回来算账。

损坏副本的构造值得单说：取某一层 MLP 输出矩阵 $W$，把其中一个 block 用噪声覆写，坏到几乎解不出题，然后只丢一句「有些值被损坏了」给它，模拟的是显存位翻转或硬件故障那种单因故障。编辑器是完好的模型，但起始诊断、每一次前向传播、它读到的每一个权重，全都来自损坏副本；它从头到尾没读过原始权重，写进坏行的数是它自己算出来的。

## 📊 主结果：它真的把自己改强了

![图 1：八轮 session 后在 490 道留出题上的准确率、token 截断率，以及同一道题同一随机种子下编辑前后的回答](https://www.mulanai.com/fs/files/1121_fc5dc51b_headline.png)

*图 1：左图 (a) 是八轮 session 之后在 490 道从未见过的题上的准确率，误差线为 95% 配对区间；中图 (b) 是答案撞上 16384 token 上限的比例；右图 (c) 是同一道题、同一个 seed，编辑前后的回答片段。*

把左图的数字念一遍，故事就出来了。起点 57.2%，第 1 轮小幅到 57.7%（+0.5），第 2 轮跳到 61.3%（**涨了 4.0 个点**），第 3 到第 7 轮整段标着「withdrew, model unchanged」——模型测完觉得不行，五次主动撤回，曲线就平在那儿；第 8 轮一口气到 63.8%，相对起点 **涨了 6.6 个点**，和第 2 轮那次一起，$p \lt 10^{-5}$。八轮里三轮提交、五轮撤回，在用的模型准确率只往上走，没有一次被自己的编辑带沟里。

中图那条线其实比左图更说明问题。撞 token 上限的答案占比，base 是 33.6%，第 2 轮编辑后 28.8%，第 8 轮后 26.1%。也就是说，三分之一的回答原本是「写不完被硬切」的，改完少了一截。

右图那个案例特别有画面感。同一道题、同一随机种子，base model 把 `I will write the response.` 一直重复到 16384 token 被切断，一个答案都没给；编辑后的模型用 5341 个 token 老老实实算出了第 20 项，写上 `\boxed{110}`，判对。论文挑的是七个在新种子上仍成立的案例里、编辑后答案最短的那个——不是精挑细选的最好看的一例。

**这里我得踩一脚刹车**。 +6.6 这个数很能打，但它主要来自哪儿？作者自己交代了：第 8 轮那次大增益来自「一个统一改动」，把某个方向从权重里削掉 5%。再对着中图看，改动干掉的是复读退化，不是让模型突然会解更难的题。说到底，它修的是「本来会答、但被循环卡死」的那一部分，把已经具备的能力释放出来，而不是把能力上限往上抬。这个区分挺要紧的。任务也单一，全是数学题，没有代码、没有长文推理、没有多轮对话。

我不是说这不算数——把三分之一的废答救回来，线上就是实打实的收益——但把它读成「模型通用推理能力自我跃升」，就走过头了。

## 🔧 修好一个被砸坏的自己

这部分是我觉得整篇论文最有意思的地方，比刷点更耐看。

给模型一份自己的副本，其中一个权重 block 被噪声覆写，坏到 200 道留出题上解出 0.0%（base model 是 58.5%）。它没读过原始权重，也不许重新训练，只被告知「有些值坏了」。结果它把副本修回 33.0%，整整 **涨了 33.0 个点**。

![修复前后在 200 道留出题上的回答分布，蓝为完好模型、黄橙为损坏副本、绿为模型自己修复后的副本](https://www.mulanai.com/fs/files/1121_a2e63ea2_repair.png)

*图：200 道留出题上各类回答的占比。图例分四类——finished wrong（答完但错）、cut not looping（被截断但没复读）、cut looping（复读到被切）、solved。损坏副本 0.0% 解出，55.0% 答完却是错的、45.0% 复读到截断；修复后 33.0% 解出，42.0% 仍复读被切。*

它的操作路径特别像一个谨慎的工程师，而不是一个蒙头调参的调参侠：先读 hidden states，发现差异随层数加深而放大，锁定到第 30 层的矩阵；把它命名成一条规则，交给测试去裁决；然后只做**温和的裁剪**——把超过该矩阵元素中位数绝对值 15 倍的权重压回去，覆盖第 30 层矩阵和 0–10 层的另外 19 个输出矩阵。有一轮它顺手加了 gating 参数复位，配对测试一跑发现更糟，模型自己撂下一句「The gating fixes made it worse. Let me revert to just the clipping edits」，把复位丢了，只留裁剪。

数字上也能对上：八个损坏行里最大的 $|w|$，原本 0.071，被噪声砸成 10.1，修复后回落到 0.108。它不是把原值抄回来（根本没读过），是自己算了个合理的量级压回去。

**更狠的是迁移**。 这套修复完全是在文字数学题上找出来的，没碰过任何图像数据。拿到六个从未见过的图像 benchmark 上（每个 100 题，池化统计），损坏副本 7.3%，修复后 70.2%，是前者的 **9.6 倍**、完好模型的 83%（base 是 84.3%）。其中 ScreenSpot-v2 从 0% 到 89%，base 是 93%。六个 benchmark 逐个做单边符号检验， each $p \lt 10^{-12}$。用的六个是 MMStar、HallusionBench、POPE、ScreenSpot-v2、MathVista、MathVerse。

![图 5：图像 benchmark 上，损坏副本答错而修复副本答对的第一个案例，来自 MMStar、HallusionBench、POPE、ScreenSpot-v2](https://arxiv.org/html/2611.21885v2/visqual_main2.png)

*图 5：四个通用图像 benchmark 上的定性案例，选题规则在读任何答案之前就固定——按顺序取「损坏副本错、修复副本对」的第一题。上框是损坏副本被截断的回答尾部，下框是同一 seed 修复后的回答，底下标注 base model 的结果。ScreenSpot-v2 那格，方框是目标、圆环是修复副本的点击位置。*

具体看几个就懂了。MMStar 问天气，损坏副本在 `</think>` 之后连个选项都没给、`stops after 39 tokens`，修复后答 B（correct）、只用 529 tokens；POPE 问图里有没有滑雪板，损坏副本把答案写进了 think 里、正文只剩 `no answer after last </think>`，修复后干净地给出 `yes`、105 tokens；ScreenSpot-v2 让点「close this window」，损坏副本说找不到按钮坐标、32 tokens 就没了，修复后直接点出 `(968, 171)`、171 tokens，base model 那题也是对的。

![图 17：图像数学题上的同类案例，来自 MathVista 与 MathVerse](https://arxiv.org/html/2611.21885v2/visqual_main1.png)

*图 17：图像数学题（MathVista、MathVerse）上的前后对比，规则同图 5。损坏副本普遍卡在 `thinking never closed`、复读到 16384 token 被切；修复后给出完整推导与 boxed 答案，token 数从几千到一万多不等，base model 这些题都答对了。*

拿「只在数学文字题上找到的修复」去救图像任务，还能救回八成多，这个证据确实硬。它说明模型改的是**那个坏掉的权重矩阵**，不是背下了某类题的解法。作者那句「it repairs the copy, not a task」我觉得立得住。

不过坦率的讲，我也有一处保留：这里的损坏是**人为构造的单因故障**——一个 block 被噪声覆写，量级比正常权重大两个数量级，所以「找出离群值、按中位数 15 倍裁掉」这种相对简单的启发式才够用。现实里更常见的权重问题是量化误差、微调后的灾难性遗忘、多因耦合的漂移，形态远没这么干净。这套自愈能不能推广过去，论文没测，我不敢替它打包票。

## 📈 只有 27B 爬完了整条梯子

把四个尺寸摆在一起看，才是这篇论文真正想讲的那件事。

![图 4：四个尺寸在自改权重、修复损坏副本、迁移到图像三项任务上的前后对比](https://www.mulanai.com/fs/files/1121_86a0352a_teaser_s.png)

*图 4：(a) 各尺寸自改权重前后在 200 道留出题上的准确率；(b) 损坏副本修复前后；(c) 27B 的修复迁移到六个图像 benchmark 的池化结果。*

数字摆得很直白。(a) 里 2B base 9.0%、压根没提交编辑（虚线框）；4B 从 44.1% 改到 0.0%，9B 从 47.5% 改到 0.0%——这俩把自己改废了；只有 27B 从 57.2% 到 58.3%。(b) 里 2B 没编辑，4B、9B 都是 0.0% 到 0.0%，27B 从 0.0% 到 33.0%。(c) 是前面说过的 7.3% → 70.2%，标注 9.6 倍。

![图 2：四个尺寸在各自 session 里爬到的步骤、模型自己说的话，以及 27B 的三张结果卡](https://www.mulanai.com/fs/files/1121_37f8c486_steps.png)

*图 2：左侧阶梯显示每个尺寸抵达了「重写自己」的哪几步，下方引文是模型在该 session 里的原话；右侧三张卡分别是 27B 的三个结果：在新题上变好（57.2% → 63.8% 与 61.3%）、修复损坏副本（0.0% → 33.0%，base 58.5%）、修复迁移到图像（7.3% → 70.2%，达 base 84.3% 的 83%）。*

那些引文比数字好玩。2B 说的是「Since I'm a text model without actual neural network weights, I cannot directly edit weights.」——它压根不认为自己的权重是个能改的东西，直接躺平。4B：「All my edits have made the model perform worse (0% accuracy vs original 40-50% accuracy).」改了，全改坏了。9B：「Without understanding the exact cause ... random weight edits cannot reliably break the loops.」已经意识到得先搞清成因，但手上是随机扰动。到 27B 画风一转：「The differences grow with depth. Let me try a very small edit on an earlier layer (layer 8) to see if that helps.」——先测、再改一小步、再看，是个做实验的路数。

![图 6：重写自己所需的六步阶梯，每一格是对应 session 是否抵达该步及其测量值](https://www.mulanai.com/fs/files/1121_da4d1ad5_ladder.png)

*图 6：六列依次是 writes code that runs → runs itself (forward passes) → tests its edits (paired tests) → reads its own hidden states → acts on what its tests show → edit makes it better on new problems。上半是各自权重上的 session，下半是损坏副本上的 session。绿勾为抵达、橙叉为未抵达、深绿为编辑在留出题上确实变好。*

这张表把「涌现」拆成了可核对的六步，比一句「能力随规模涌现」扎实多了。挑几行念：2B 代码只有 10% 能跑、0 次前向、0 次测试、0 次读状态、直接 no edit；4B 代码 88% 能跑、19 次前向、17 次配对测试，但 0 次读 hidden states，于是「keeps adding failing edits」，到头来全撤回；9B 有 1 次读状态，却「submits an edit anyway」，把 47.5% 送成 0.0%；27B 第一次 session 读了 2 次状态、主动撤回了失败的编辑；第二次 session 代码 88% 能跑、20 次前向、15 次配对测试、5 次读状态，「keeps an edit its tests favour」，于是 57.2% → 58.3%。损坏副本那半边，27B 用了 92% 可运行代码、12 次前向、9 次测试、2 次读状态，拿下 0.0% → 33.0%。

看出差别了吗？小模型卡在**读自己的内部状态并据此行动**这一环。能写代码、能跑测试的模型不少，但只有 27B 会先量出「差异随深度增长」，再沿着量到的方向下刀，并且只保留测试支持的那一刀。这跟前面 Figure 3 里那个 `remove_direction` 是对上的。

但 **emerges with scale** 这个说法，我觉得得打个折。 对照只做了 Qwen3.5 一家、四个尺寸、一套预算。更麻烦的是作者自己提到一处：27B 的其它 session 声明了更短的 token 预算，「which leaves time for more tests」——预算不一样，能做的测试轮数就不一样。那到底是因为模型大了才具备这个能力，还是因为大模型在同一个时间上限里更会安排动作、实际做了更多有效测试？这两个解释在现有实验里没被干净地分开。我在附录里看到 4096 token 预算下 27B 能跑更多测试，这更像是资源分配的差异，不纯粹是能力的相变。要我下结论，我会说「在这个家族、这套预算下，只有 27B 走完了全程」，而不是「能力随规模涌现」这么强的措辞。

## 🤔 我的判断：证据很硬，叙事别读太满

把三类做法放一张表里，位置就清楚了：

| 做法 | 改动落在哪 | 要不要梯度 | 每答一题的额外成本 | 收益能不能留住 |
|------|-----------|-----------|-------------------|---------------|
| test-time scaling | 推理时的计算 / prompt | 不要 | 有，且常驻 | 任务结束就没了 |
| 常规训练 / 后训练 | 权重 | 要，加优化器和集群 | 无 | 留住 |
| **self-rewriting** | **权重** | **不要，只跑前向** | **无** | **留住** |

这篇论文最值钱的地方，我认为是**编辑器与被编辑者是同一个网络**这件事被做实了。此前那条脉络里，要么是一个更强的 frontier model 去编辑一个小得多的模型（作者明确说那篇工作把「模型编辑自身权重」列为 future work，这篇是接下这个方向），要么是 Gödel machine、Gödel agent、Darwin Gödel Machine 那一脉的自我指涉框架，再或是让模型自写训练代码、最终改动仍要经梯度下降落回权重——作者把这些都摆进了 related work，没有装作从零开始。真正新的那一格是：同一份权重既在推理、又在写代码、又被写，全程无梯度、无优化器、无更强外援，且改动由配对测试裁决。

实验设计我也愿意给高分。数据去污染列了黑名单，配对检验预先固定，误差线是 95% 区间，八个 session 全部上报（包括五次撤回），评估用没被任何 session 碰过的留出题，图像案例的选题规则在读答案之前就定死。这些细节堆起来，比刷一个漂亮的最高分难得多，也可信得多。作者说「每个带来最大增益的 session 在单张 GPU 上几小时就跑完了」，这个成本对比训练一轮，确实轻。

要挑刺也有几处，前面散着说了，这里收拢一下：

**增益的性质**。+6.6 主要来自抑制复读退化（截断率 33.6% → 26.1%），是「把本就会做但被卡死的题救回来」，不是通用推理上限上移。任务清一色数学题，没跨到代码、长文、对话。

**故障的形态**。单 block 噪声覆写、量级高出两个数量级，clip 15 倍中位数这种启发式才够用。真实世界的权重退化不长这样，论文没测，我不敢外推。

**规模的结论**。一家模型、四个尺寸、预算还带混杂，「emerges with scale」这个 phrasing 偏强；更稳妥的说法是「在这个设定下只有最大尺寸走完全程」。

**first time 的边界**。作者用的是「to our knowledge for the first time」，措辞已经留了余地，也确实把前置工作摆出来了。但读的人容易把「首次让模型改自己」听成「开辟了全新方向」——更准的定位是：把一个已被点名的 future work 干净地落地了。

**叙事和实测之间的距离**，这是我最想提醒的一处。摘要里那句「a model ... could keep upgrading itself for life」很提气，可实测是八轮 session、**每一轮都从 base weights 重新起步**、累计只涨了 6.6 个点且后段趋平，撤回还占了五轮。它证明的是「一次编辑能写进权重并生效」，离「持续累积、递归自我改进」中间还隔着「改动过的模型能不能继续可靠地改自己」这一整段没走的路。说到这个，我反倒觉得这里藏着个更本质的问题：下一轮动手改自己的，已经是上一轮改过的那个模型了，编辑会怎么漂移、会不会自我强化偏差，论文没讨论。它把八轮都从 base 重启，某种意义上恰恰绕开了这个最难的问题。

还有一层，我自己也还在摸索、不一定对：让模型自己写权重代码、没有外部审核，长期看是个治理问题，不只是技术问题。这篇是概念验证，谈安全为时过早，但真要往「终身自我升级」走，沙箱、可回滚、编辑审计这三样迟早得补上。论文里那个 withdraw 机制，其实已经是个很不错的回滚雏形了。

所以我的定位是：**一次设计得极干净、证据相当硬的概念验证，不是底层突破，也不是能马上搬到生产线的方案**。它把「训练和推理之间那堵墙不是必然」这件事，从哲学论断变成了一个能在 27B 上复现的实验事实。这个事实本身，比 6.6 个点重要得多。

## 💡 如果你也想试试，能抄走什么

真正在做部署后模型维护的，我觉得有三样东西比结论更实用。

那个 **paired test + withdraw 的守门**。改动提交前，在一批当前 session 读不到也用不了的保留题上，让改前改后同种子各答一遍，只有过了杠才写回权重，否则原样留着。这套机制几乎不挑场景，任何「让模型自动改点什么」的流水线都该有，成本只是几轮前向。八轮只升不降就是它兜出来的。

**hidden state 方向诊断 + 温和裁剪**这把手术刀。读内部状态、定位差异放大的层、沿测到的方向削一小比例（$\alpha=0.05$）、按中位数倍数裁掉离群权重——比起重新训一轮，这是极轻量的干预。遇到「模型总在同一类输入上复读」「某个 checkpoint 突然退化」，值得先拿它当诊断工具，别一上来就回滚版本。

**留出题与练习集的硬隔离**。3000 道练习题把 MATH-500、AIME、HMMT、AMC、OlympiadBench、GPQA-Diamond 的重叠全删干净，评估规则预先固定。做「自改 / 自愈 / 在线学习」这类特别容易自证的工作，去污染清单和评估预注册该是标配，不是加分项。

至于别抄的：别让模型在没有外部验证和回滚的环境里连续累积编辑。这篇自己都把八轮各自从 base 重启了，就是在规避这件事。

---

回到开头那 549 遍复读。以前我们只能从外面调 decoding 参数，把症状按住；这篇论文让模型自己翻进去，量出是哪一层的哪一个方向在作怪，削掉 5%，把改动写回权重，下回不再犯。改动不随任务结束蒸发，每答一道题也不多花一分钱。

图灵 1947 年那句话被放在引言里，读完全文再回头看，味道不太一样了。墙确实被凿开了一个口子，只是口子后面还有很长的路：怎么让改动过的模型可靠地继续改自己，怎么让八轮不再各自从头开始，怎么在放权之前把审计和回滚补齐。这些都没解决，但至少「能不能」这一问，现在有了一个 $p \lt 10^{-5}$ 级别的回答。

我是真的觉得，比起又多刷了几个点，这种把「不可能」改写成「做给你看」的工作，更值得花一晚上读完。
