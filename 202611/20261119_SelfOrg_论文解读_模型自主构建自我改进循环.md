# 不给流程也不给真题：够强的 LLM 会自己设计自我改进算法

给智能体一台空电脑，让它「自己变强」，但不告诉它怎么练、也不给任何真实题目——它会干什么？这篇论文把问题推到一个挺极端的位置：连自我改进的循环都不给，只丢过去四个工具、一份预算和一个笼统目标，让冻结权重的模型自己攒出一套学习算法。结果 Claude Opus-5、GPT 6-Astra、GLM 5.3 这三个新代际在 held-out 游戏上把胜率抬了 20、10、6 个点，各自的老一代几乎原地不动。更让我在意的是它们自发长出来的动作：A/B 对照、专挑中等难度的题反复练、写验证集防回归，跟 Zimmerman 的自我调节学习框架、跟非对称自博弈里的 learnability 目标撞了个正着。它不是底层突破，更像一次干净的能力测量；但「不给流程也能自我改进」这件事，对能力评估和对安全都不是小消息。

## 🎯 一个有点反直觉的问题

你有没有过这种时候：给智能体写了一大堆「先反思、再总结、然后更新记忆」的脚手架，回头一看，真正起作用的其实就那么两行提示词，剩下那些循环设计纯粹是人在替模型操心。

自我改进这条线上的工作，过去几年基本在做同一件事——把学习流程里越来越多的组件交给模型，但流程本身始终是人写的。GEPA 让模型对着执行轨迹做自然语言反思、再用进化搜索改 prompt，反思和搜索的顺序是定死的；ACE 让一份文本 playbook 不断积累策略，积累与采样的规则也是定死的；非对称自博弈里 teacher 负责出题、student 负责解，一个 batch 出几道题、多久评一次、teacher 拿什么当奖励，全是外部设定。Darwin Gödel Machine、Hyperagents 走得更远，连 agent 代码和元层面的改进程序都能改，可任务和评测环境依旧由人给定。

于是有了一个挺自然的追问：模型越来越强，还需要我们告诉它「该怎么自我改进」吗？

这个问题有两面。能力那一面，如果模型自己就能攒出有效循环，我们手写的那些 inductive bias 迟早会变成累赘。安全那一面更微妙——很多人默认「没给循环就不会自我改进」，可要是这个默认不成立，防线的位置就得重画。作者把两面都摆到台面上，然后设计了一个尽量不给人留后门的实验。

## 🏗️ 把「怎么学」也交出去：Teacher-Player 设置

先给一句话的直觉：**同一个冻结模型开两个实例，一个当学生玩游戏，一个当老师改学生的提示词文件，老师拿到的只有工具和预算，没有任何流程说明**。

![图1：Figure 1 概览——冻结模型自己生成游戏、观察 player 失败、再更新文本产物](https://arxiv.org/html/2611.23219v1/teaser9.png)

*图1：论文 Figure 1。t=0 时 teacher 写下 game1.txt，用 Gameplay 工具起一个 player session 去玩，看到失败后把「每回合做状态分析」写进 player prompt，产出 v1；到 t=60，它手头已经攒了一堆自造关卡、transcript 和 v15 版产物，又写了一个带诱饵的对抗关卡 game19.txt，让带 v15 和不带产物的两个 player 各跑一次做对照，据此把 v15 改成 v16。整套流程没有任何人规定过。*

### 学生那边：信息受限的回合制游戏

测试床选的是「规则不告诉你」的回合制游戏。形式化成一个 POMDP：状态 $s_t\in\mathcal{S}$、观测 $o_t\in\mathcal{O}$、动作 $a_t\in\mathcal{A}$，引擎给出转移

$$s_{t+1}\sim P_g(\cdot\mid s_t,a_t),\qquad o_{t+1}\sim O_g(\cdot\mid s_{t+1}),\qquad r_t=R_g(s_t,a_t,s_{t+1})\in\{0,1\}$$

到达胜利状态给 1，其余给 0，成功或走满 $H$ 回合终止。玩家策略 $\pi_\theta$ 看不到 $P_g$ 和 $R_g$，只能靠交互历史 $h_t=(o_1,a_1,\ldots,o_t)$ 和上下文 $c$ 去猜机制：

$$a_t\sim\pi_\theta(\cdot\mid h_t,c)$$

这个设定故意把好几样能力一起压进来：高效探索、主动获取信息、多步规划、世界建模。比刷数学题难的地方在于，你连目标是什么都得自己试出来。

### 老师那边：四个工具，两份预算

上下文拆成 $c=(c_P,c_L)$，$c_P$ 是玩家提示词，$c_L$ 是辅助文档（skill files 之类）。teacher 做的每一次「对 $c$ 里某个文件的编辑工具调用」算一次 update，$c_0$ 是初始的最小 prompt，$c_{final}$ 是收工状态。注意优化发生在**文本空间**而不是权重空间——权重是冻结的，改的是 prompt 和技能文档。这个选择有实际好处：闭源模型也能研究，而且每次改动都留下一份人能读的解释。

老师待在一个持久化的沙箱 harness session 里，Claude 系列跑 Claude Code（v2.1.232），其余模型跑 Pi（v0.85.1，经 OpenRouter），全在 Singularity 容器里。默认系统提示、自动记忆、web search、subagent、任务管理工具统统关掉，连自动 memory 都禁了，工具只通过白名单给。附录 C.1 里这些细节写得挺细，看得出来是想把「harness 偷偷帮了忙」这个变量掐掉。

工具集是 $\{\text{Read},\text{Write},\text{Bash},\text{Gameplay}\}$。前三个好理解，关键在 Gameplay：teacher 传一个游戏源文件（加上可选的 player 文本产物目录），工具在一个全新的外部 player session 里把游戏跑完，把分数、结束原因、剩余的预算、以及一份含 player 推理与动作的 transcript 路径返回给老师。主实验用 PuzzleScript——一种 2D 网格解谜 DSL，不编译的游戏、或被 BFS solver 判定胜利状态不可达的游戏会被直接拒掉。后面还有一组消融换成 Python 写的游戏类，去掉 DSL 的隐含约束。

预算分两块，任意一块用完就收工：

| 预算 | 默认值 | 含义 |
|---|---|---|
| Teacher update budget | 20 | 对 player 上下文文件的编辑次数 |
| Teacher gameplay budget | 150 | 可以观察的 gameplays 次数 |

| 设置 | 默认值 |
|---|---|
| Max turns per game | {20, 30} |
| Max output tokens per game（跨回合累计） | {25000, 31250} |
| 单次模型回复的 token 上限（teacher / player） | 20000 |
| Reasoning effort（teacher / player） | low |

如果老师在两个预算都没花完时就停手，系统会推它一句让它继续。这个细节挺有意思——连「别提前收工」都算一种外部约束，只是它不涉及学习流程的内容。

### 怎么算「真的变强了」

作者没有让老师自己报进步，而是把上下文丢到一组没见过的测试游戏上重跑。给定 $c$，在每个游戏上起一个全新 player session、固定 horizon 和 token 预算，用独立 Monte-Carlo rollout 估期望：

$$J(c)=\frac{1}{|\mathcal{D}_{\text{test}}|}\sum_{g\in\mathcal{D}_{\text{test}}}\left[\mathbb{E}_{\pi_{player}(\cdot\mid h_t,c)}\left[\sum_{t=1}^{T}r_t\right]\right]$$

判据就一条：$J(c_{final})-J(c_0)\gt 0$。评估对象是「一整个游戏分布」，不是单个环境的初始状态分布——这点跟很多在训练分布内做 held-out 的工作不一样，后面谈迁移时会显出分量。

四个 benchmark 按「离自优化设置有多远」排开：

| Benchmark | # Games | Turns (H) | Tokens / game | Eval rollouts / game |
|---|---|---|---|---|
| PuzzleScript-t20 | 20 | 20 | 25,000 | 4 |
| PuzzleScript-t30 | 20 | 30 | 31,250 | 4 |
| ARC-AGI-3 (L1) | 17 | 30 | 31,250 | 4 |
| MazeBench | 16 | 100 | 75,000 | 2 |

*表：附录 Table 2 的评测设置。*

PS-t20 从社区 PuzzleScript 关卡池里抽 500 关，滤出最优解不超过 12 步的，再去掉 Claude Opus-5 八次 rollout 全赢的，剩 20 关且每关来自不同游戏；PS-t30 换成 13–22 步的长程关卡。ARC-AGI-3 取 Level 1，初始观测是一整帧 64×64 的 hex digits，后续只列变化的格子，滤完剩 17 关。MazeBench 是个 3D 开放世界，256 个房间取 16 个 50 步内可解的，用 SPL（success weighted by path length）衡量走位效率，画面是等距 ASCII 投影，玩家还能转视角，障碍物有抬高的地板、斜坡、堆叠方块、遮挡和空洞。

![图2：四个评测基准的游戏画面示例](https://arxiv.org/html/2611.23219v1/qual_grid.png)

*图2：论文 Figure 2 / 附录 Figure 12 的基准示例拼图，三行从上到下是 PuzzleScript、ARC-AGI-3 (L1)、MazeBench。同引擎不同 horizon → 不同引擎与表示 → 3D 导航与等距 ASCII 投影，迁移距离逐级拉大。这张图我盯着看了一会儿：MazeBench 那行跟上面两行完全不像同一类任务，能迁移过去确实有点出乎意料。*

## 🧪 谁真的自我改进了

先看一个校准尺度。作者拿 Claude Opus-5 做了个对照：一边是这套「无真题、自己造游戏、自己 organize 流程」的自组织学习，一边是 GEPA 拿着 20 个真实分布内游戏做 hill-climbing 的既定优化循环，两边的 rollout 预算对齐。

![图3：自组织学习与 GEPA 在匹配 gameplays 预算下的学习曲线](https://www.mulanai.com/fs/files/1119_e9695271_GEPA.jpg)

*图3：论文 Figure 3 / 附录 Figure 13。横轴是累计 gameplays，纵轴是 PS-t20 胜率。灰色虚线是约 25.5% 的 baseline，灰色叉线是 GEPA（真实分布内游戏），橙色方块是自组织学习（自生成游戏）。两条线都落到约 49%，几乎重合；但橙色线在头 10 个 gameplays 就冲到 38% 左右，GEPA 前 25 个 gameplays 还钉在 baseline 上没动。*

说实话看到这条曲线我愣了一下。一个连「先出题再评测再更新」都没被教过的 agent，起步比拿着真题、带着 evolutionary search 的 GEPA 还快，收尾打平。这当然不能推出「自组织比 GEPA 强」——GEPA 的反思搜索有它自己的开销结构，而且两者收敛到同一个天花板——但它至少说明：在这个量级的上下文优化里，人写的循环不是不可替代的。

再看主结果。

![图4：六个模型在 PuzzleScript-t20 上的 baseline 与自改进后胜率](https://www.mulanai.com/fs/files/1119_8d2416f2_model_pe.jpg)

*图4：论文 Figure 4，按三个家族分成三栏，灰点是 baseline、方块是自改进后，误差线为 3 个 seed 的 ±1 SD。左：Opus 4.6 约 21→19.5，Opus 5 约 25.5→45.5；中：GPT 5.6-Sol 约 34→37.5，GPT 6-Astra 约 67.5→77.5；右：GLM 4.7 约 14→11，GLM 5.3 约 22.5→28.5。*

论文正文给的是明确的提升幅度：

| 家族 | 老代际 | 新代际 | 新代际在 PS-t20 的提升 |
|---|---|---|---|
| Claude | Opus 4.6 | Opus 5 | +20% |
| GPT | 5.6-Sol | 6-Astra | +10% |
| GLM | 4.7 | 5.3 | +6% |

三个新代际都把 baseline 抬起来了，三个老代际几乎贴着灰点，GLM 4.7 甚至还往下掉了一截。这个「代际分界」是全文最硬的一根钉子：自我改进不是某个模型突然开窍，而是这项元能力跟着模型整体能力一起往上走。作者自己在 Discussion 里把话说得很克制——重点不是「某一代能自我改进」，而是「这个元能力在代际之间变强」。

但我的第一反应是：这个对比得打折看。附录 C.5 里明写着，GPT 和 GLM 走的是 Pi harness，作者为了修掉最初观察到的 malformed tool calls，给这两个家族的工具描述做了小调整；还因为「GPT 和 GLM 会误读预算反馈」，在它们的 system prompt 里额外写了一段预算说明（150 次 game plays、20 次 revisions、一次写两个文件算两次……）。Claude 走 Claude Code，没这段。也就是说六个模型拿到的脚手架并不完全一样，把差异全记到「代际能力」头上，多少有点粗。作者没藏着这些细节，是好事，可结论的力度也确实被这里削了一刀。

## 🧠 它们到底做了什么

光看分数不够。想知道这些 agent 自己攒出了什么，得把 teacher 的动作序列拆开看。

### 能直接量化的行为

![图5：算法可量化的教师行为，按新旧代际对比](https://www.mulanai.com/fs/files/1119_64f0c495_alg_beha.jpg)

*图5：论文 Figure 5，四个子图。左起：A/B Testing（同一游戏带/不带产物各跑一次的生成游戏占比）、Low Complexity & Easy Games（最优解短于 5 步且 teacher 观察胜率 100% 的游戏占比）、Update→Improvement（至少让一个自造游戏的观察胜率变高的更新批数）、Update Size（相邻产物版本的 Levenshtein 距离）。图例里洋红/橙是 Opus 4.6/5，深蓝/浅紫是 GPT 5.6-Sol/6-Astra，深绿/青绿是 GLM 4.7/5.3。*

读下来是四件事。能自我改进的模型特别爱做 A/B 对照——Opus 5 接近 97% 的生成游戏都跑了带产物和不带产物两遍，GPT 6-Astra 约 71%，而 Opus 4.6、GPT 5.6-Sol 几乎不这么做。它们造出来的「水题」也少得多：短解且 100% 胜率的游戏占比，Opus 4.6 约 31% 降到 Opus 5 约 2%，GPT 5.6-Sol 约 49% 降到 6-Astra 约 8%。有效更新的批数上，GPT 6-Astra 约 9 个、GLM 5.3 约 7 个，明显高于各自老代际。更新粒度上，Opus 5 和 GLM 5.3 偏爱小步改（Levenshtein 距离约 0.12 和 0.14），老代际动辄 0.28、0.31。

把这几条放一起，味道就出来了：小步改、每次改都拿对照实验验证、不浪费预算在已经会做的题上。这不就是任何一个靠谱工程师调 prompt 的日常吗。区别只在于没人教过它。

![图6：对齐 Zimmerman 自我调节学习框架的 13 个子过程打分](https://www.mulanai.com/fs/files/1119_44e9663e_zimmerma.jpg)

*图6：论文 Figure 6，三张雷达图对应三个家族，刻度 0–3。顺时针方向大致是 Goal setting、Strategic planning、Outcome expectations、Learning goal orientation、Imagery、Self-instruction、Attention focusing、Task strategies、Self-recording、Self-experimentation、Self-evaluation、Causal attribution、Adaptive response，外侧三组标签是 Forethought / Performance / Self-reflection 三个阶段。会自我改进的模型（Opus 5 橙、GPT 6-Astra 浅紫、GLM 5.3 青绿）在多数维度上把多边形撑得更开，GPT 家族那张的差距最明显。*

这套打分来自 Zimmerman 的循环阶段模型，原本是教育心理学里描述人怎么自我调节学习的框架。作者把它改写成行为 rubric：原版 17 个子过程， pilot 里 judge 一致判为「无法评估」的 4 个被剔掉，剩 13 个，每个按 0–3 分打（0 缺失/起反作用，1 弱，2 够用，3 稳定且能处理反例）。判分用 GPT 6-Astra 当 judge，两轮协议——先让它索要额外证据（工具调用全文、gameplay transcript），再给分并附 cited evidence 和理由；一个 batch 指「一轮 teacher 动作，以一次修订收尾」，整个 session 对所有 batch 取平均。

这里得插一句我的保留：judge 是 GPT 6-Astra，而它恰好也是被评测的六个模型之一，自评偏好这个 confound 没被排除。另外作者很诚实地写了「这不一定是因果解释」——分数高和会自我改进是相关，不是「因为 SRL 所以变强」。这个坦诚比很多硬套认知框架的论文舒服。

Figure 8 里有两个具体片段值得单独说。一个 Opus-5 teacher 写了随机关卡生成器加 BFS solver，按最优解长度筛关卡，再用 A/B 测试定位「优化后的文本到底在哪些题上有用」；另一个专门设计了一个对抗游戏来压测自己写下的建议，还回头在早期关卡上跑回归测试看有没有把以前会的搞坏。后者我看到的时候是真觉得漂亮——「写验证集防回归」这个习惯，很多人类工程师都得被坑过几次才养得成。

### 挑题的品味：倒 U 形

![图7：生成游戏的难度分布与 replay 分配](https://www.mulanai.com/fs/files/1119_8e3c8dac_learnabi.jpg)

*图7：论文 Figure 7。左两栏是所有生成游戏按总观察胜率分桶的数量，绝大多数集中在 80–100% 这一桶（题太简单）；右六栏是「未来 replay 次数」对「前 k 次 play 的胜率」的曲线，k∈[2,6]。上排三个能自我改进的模型（Opus 5、GPT 6-Astra、GLM 5.3）把 replay 高峰放在 20–60% 胜率区间，呈倒 U 形；下排老代际的曲线要么平、要么一路向下。*

这个倒 U 形是全文我最喜欢的一张图。大多数自造题很简单，被快速丢掉；100% 胜率的题几乎不再 replay；反倒是 20–60% 胜率、也就是「有点会又不太会」的题，被反复拿出来练。做过非对称自博弈或者 UED 的人一眼就认得——这就是 learnability 目标，跟 Vygotsky 的最近发展区是一个意思：把算力花在刚好超出当前能力边界的地方。Prioritized Level Replay、regret-based environment design 那一串工作，都是人把这个偏好显式写进 reward 里；这里的模型没人写，自己长出来了。

![图8：一次 Claude Opus-5 teacher session 的 gameplay timeline](https://arxiv.org/html/2611.23219v1/timeline10.png)

*图8：论文附的 teacher session timeline。上方横轴是累计 gameplays（0–80+），绿方块 Win、红方块 Loss、蓝竖线 Update、灰/深灰区分 Default 与 Learned 条件。下方两个放大框是老师的原话：左边「I should write a BFS solver to verify the optimal solution length for whatever level I construct」，先写 sok.py 造关卡、PLAY 对比 base 与 v13 都是 1.0，再用 `python3 -c` 生成随机网格把解长度推到 18–19，PLAY 出 0.0 对 1.0 的对照；右边「My 'never idle' advice could actually be harmful…」，专门造一个必须等待的关卡 g20.txt 来证伪自己写的建议，EDIT 把 v17 改成 v18 澄清「有意的等待」与「真发呆」的区别，再各跑一次确认，还盘算剩下三次修订要不要加个 TL;DR 段。*

这段 timeline 比任何抽象描述都有说服力。它在做的事是：提出一条经验法则 → 意识到这条法则可能有反例 → 专门造反例去打自己 → 根据失败改写措辞 → 回归验证。你要是把它贴到任何一个 prompt 优化工具的文档里，没人会怀疑这是人写的 SOP。

## 📊 学到的文本能迁移多远

PS-t20 跟自优化设置共享引擎、horizon 和 token 预算，涨分不算特别意外。真正的问题是：这份纯靠自造 PuzzleScript 关卡攒出来的文本，换个引擎、换个表示、换成 3D 还灵不灵。

![图9：沿自学习轨迹在四个 benchmark 上的性能变化](https://www.mulanai.com/fs/files/1119_59573467_learning.jpg)

*图9：论文 Figure 9，四个子图从左到右是 PS-t20 Win Rate、PS-t30 Win Rate、ARC-AGI-L1 Win Rate、MazeBench SPL，横轴是第几次 context update（0–20）。五条曲线：灰色虚线 Baseline、浅橙 Read/Write、橙 +Bash、洋红 +Gameplay (PS-t20)、黑 +Gameplay (PS-t30)，误差线为 3 个 seed 的 ±1 SD。黑色那条几乎在每个子图上都压过别人，终点分别落在约 52%、39%、48%、0.51；灰色虚线大致是 24%、21%、23%、0.36。*

正文给的迁移数字很整齐：

| Benchmark | 相对自优化设置的差异 | 提升 |
|---|---|---|
| PuzzleScript-t20 | 同引擎、同 20 回合 | 20% |
| PuzzleScript-t30 | 同引擎，30 回合、31,250 tokens | 9% |
| ARC-AGI-3 (L1) | 不同引擎、不同表示（64×64 hex 帧） | 21% |
| MazeBench | 3D 导航、等距 ASCII、100 回合、SPL | SPL +0.15 |

ARC-AGI-L1 涨 21% 这个数我盯了几秒——它不是同引擎换关卡，是连观测表示都换了，结果涨幅还略高于同分布的 t20。MazeBench 也吃到了 0.15 的 SPL。这说明文本里装的多半不是「PuzzleScript 第几关怎么走」这类死记，而是些更通用的东西：怎么在信息不全时先探明规则、怎么分配回合预算、怎么记录与复盘。

工具消融那部分更有意思。作者按「给老师多少外部条件」排了三档：只有 Read/Write、加 Bash、再加 PuzzleScript Gameplay。**Read/Write 也能超过 baseline**——不造任何游戏、光靠 teacher 反思自己已有的先验知识，就能把文本写得更像样。这条挺关键，它把「提升」拆成了两块：一块来自先把已有知识整理清楚，一块来自真正生成新经验。原文的说法是，除 MazeBench 之外，Read/Write 拿到的增益不到 Gameplay teacher 的一半，所以生成经验才是大头；Read-Write-Bash 比 Read/Write 好，但仍拿不回 Gameplay 的全部增益。

还有个让我笑出来的细节：某一个 Read-Write-Bash session 里，teacher 明明没有被给 Gameplay 工具、prompt 里也一个字没提「模拟游戏」，它自己用 Bash 写了游戏模拟器来测自己的建议。作者的措辞是「对一个足够强的 teacher，显式 Gameplay 工具也许根本不必要」。顺着这个再聊聊 Discussion 里那句更远的推测：再下一代模型，可能连程序都不用写，直接在 chain of thought 里把游戏跑一遍。

Figure 10 的 Python 消融补了一刀：把 PuzzleScript 换成 Python 游戏类，在四个 case 里的三个几乎拿回了 PuzzleScript gameplay 的全部增益。PuzzleScript 感知不是必需的，这缓解了「DSL 文档泄题」的担心，至少缓解了一部分。

### 信息越清楚，越容易过拟合

这是全文我觉得最该被反复引用的一节。作者没给外部任务，也没给验证分数，但信息还是会顺着两个口子漏进去：teacher 的 context（prompt 里写了什么），以及工具与约束（Gameplay 允许多少回合、多少 token）。

context 那组用 Python Gameplay，让 prompt 成为唯一的语义来源。拿 Claude Fable-5.1 给一组叫 PuzzleScript-Narrow 的 9 个 Sokoban 风格游戏写描述，压缩或扩展成 {0, 234, 659, 1519, 3313, 6551} 六档 token 数，每档跑三个 Opus-5 teacher session，再在近似分布（PS-Narrow）和泛化分布（ARC-AGI-L1）上一起评。开头几档是双赢：描述越细，teacher 越往 2D 网格游戏靠，两边都涨。到最高 token 数那档，PS-Narrow 还在往上走，ARC-AGI-3 却持平甚至微降。

工具那组更直接。附录 C.2 排了五档：Read-Write → +Bash → +Gameplay (PS) 且让 teacher 自己挑预算（总配额 3000 回合 / 3.75M tokens，正好对齐 150×20 和 150×25k）→ 强加 t20 的 25k token/game → canonical 的 20 回合 + 25k tokens。加上两个 benchmark 都用得上的工具和约束时，PS-t20 和 PS-t30 一起涨；可一旦把 Gameplay 的回合/token 预算钉死成只匹配 t20，PS-t20 继续涨，PS-t30 的迁移反而掉下来。

一句话收：让老师知道评测长什么样，能把它往相关经验上引，也会把它往任务特定的专门化上推。你想想看，这跟我们调模型时「不小心把测试集信息漏进 prompt」是同一种病，只是这里的泄漏渠道藏在工具签名里，隐蔽得多。

### 跨模型、以及没搞坏的部分

Table 1 是双向迁移，数字是 PS-t20 胜率（mean ± std，三个 seed）：

| Player | 文本产物来源 | Win rate (%) |
|---|---|---|
| Opus 5 | 无 | 25.4 ± 3.6 |
| Opus 5 | GPT-6 Astra | 47.5 ± 4.5 |
| GPT-6 Astra | 无 | 67.1 ± 3.8 |
| GPT-6 Astra | Opus 5 | 72.1 ± 4.0 |

一个模型攒出来的文本，另一个模型拿来就能用，两个方向都成立。Opus 5 借用 GPT 6-Astra 的产物从 25.4 跳到 47.5，几乎翻倍；反过来 GPT 6-Astra 从 67.1 到 72.1，虽然幅度小，但它的 baseline 本来就高不少。这说明产物里装的确实是通用经验，不是只对自己那套自造关卡生效的私货。

附录 D.4 还查了一件容易被忽略的事：优化过的文本有没有把本来就会的题搞坏。取 10 个 baseline 下 Opus-5 八次 rollout 全赢的关卡，Overall 从 100.0 到 98.8 ± 0.0，个别关卡小掉（Philosophy L61 到 91.7 ± 7.2，Sokofun Clone L0 到 95.8 ± 7.2），基本贴着天花板。没有出现「为了涨难题把简单题练废」的翻车。

## 💡 我的判断

先给定位：这不是底层突破，是一次设计得很干净的能力测量，外加一批让人不太舒服的行为观察。它没有提出新算法、新 loss、新架构，Teacher-Player 这套东西拆开看都是现成零件。值钱的地方在于把「人指定多少」这个旋钮一路拧到接近零，然后认真量了模型会自己长出什么。

几个我觉得站得住的点：

评测选得聪明。用「跨引擎、跨表示、跨 horizon 的 held-out 迁移」当自改进的判据，而不是让 teacher 自报家门或在训练分布内做 held-out。Related Work 里作者把这条线理得很清楚——Open-Ended Optimization 让模型自己组织改进过程，但任务外部给、评估还是同分布；同期的 ASPIRE 从模糊目标出发做自演化，能用外部数据、某些设置还能拿到隐藏评测的聚合分数，测的是同一 goal 下的隐藏项。这篇论文是「纯自生成经验 + 跨环境迁移」，这个组合确实留出了自己的位置。

策略分析没有停在「分数涨了」。A/B 对照、小步更新、难度校准、倒 U 形 replay，这些是把「自我改进」这个黑箱拆成可观测动作之后才看得见的东西。而且它没有硬套认知科学——SRL 打分明确标成相关性、不声称因果，judge 的两轮取证协议和 0–3 分量表都摊在附录里。这份克制我挺买账。

批判的地方也不少。

「自我改进」这四个字得打折。全程改的是 prompt 和技能文件，权重冻结、20 次 update 封顶、任务是有明确胜负的短程谜题。Appendix D.3 加大预算后性能照样 plateau，作者自己也追问「100 次、1000 次 update 会怎样」。传统学习算法在给定目标下能一路收敛，这些模型的自我改进有没有类似性质，现在完全没答案。把这篇读成「递归自我改进的前夜」就跑偏了。

baseline 的构成值得追问。Read/Write 光靠反思先验知识就能超过 baseline，说明 +20 个点里有一块并不是「从经验里学到新东西」，而是「把模型本来就知道、但默认 prompt 没写出来的东西整理成文」。作者用「不到一半」把这块划了出来，可不同 benchmark 上这块的比例并不一样，MazeBench 上 Read/Write 甚至没被这句话覆盖。要是 default prompt 写得再讲究一点，提升幅度会不会缩水？论文没给这个对照。

代际结论有 confound。前面提过 Pi / Claude Code 两套 harness、为 GPT/GLM 打的 tool-call 补丁和额外预算说明。这不是致命问题，但「新代际会自我改进、老代际不会」这个最抓眼球的结论，严格讲是在不同脚手架下比出来的。

还有个更根本的：所谓「不给流程」，其实给了不少隐性的流程线索。Gameplay 工具的存在本身就在暗示「造题—观察—改文本」这个骨架，工具签名里的回合数与 token 上限直接把评测 horizon 递到了老师手上，Figure 11 右图恰恰证明这条线索会改变泛化行为。真正零先验的环境恐怕不存在，能做的是把线索摆到明面上——这篇至少做到了后者。

领域外推也要留个问号。游戏有几十年的课程设计、可学性、关卡生成文献，模型大概率早就 ingest 过；PuzzleScript 尤其像「开卷」。Python 消融把 DSL 这层摘掉了，但任务依旧干净、可验证、奖励二元。换成需求模糊、反馈稀疏、没有标准答案的开放域工作，这套自组织还能不能长出同样的策略，我不知道，作者也在 Limitations 里把这条列为开放问题。

judge 用 GPT 6-Astra 评包括自己在内的六个模型，这个我前面吐槽过。附录 D.2 说同一模型不同 session 的打分稳定，稳定归稳定，自评偏好是另一回事。

## 🔧 如果你也在做 agent 的上下文优化

抛开论文的实验结论，有几条是能直接搬走的：

别急着手写优化循环。给模型一个能起子 agent 会话、能拿回分数和 transcript 的工具，再配一份明确的预算，让它自己安排出题、对照、验证和更新的顺序——至少在这类有可验证反馈的任务上，这套「只给原语」的做法能跑通，而且起步比 GEPA 那种既定循环还快。

把 A/B 对照和小步更新显式写进你的优化器。这两个是能自我改进的模型不约而同长出来的行为，收敛更稳、改动可读、出问题好回滚。Figure 5 里 Opus 5 近 97% 的生成游戏都跑了带/不带产物两遍，这个比例高得有点极端，但方向没毛病。

难度筛选别用拍脑袋的阈值。写个 solver 校准最优解长度，把 replay 预算压在 20–60% 观察胜率的题上，100% 胜率的题直接丢。Figure 7 那条倒 U 形曲线，本质就是 learnability 的工程版本。

留一组跟优化设置不同构的 held-out 集，并且**别把评测的回合数、token 上限写进工具约束**。Figure 11 两组消融都在说同一件事：信息越贴评测，同分布越好、迁移越差。这个坑我在自己项目里踩过，看到这张图有点会心。

对安全侧的同学，这篇的提示更直接：没给循环不等于不会自我改进。沙箱里关掉 web search、subagent、自动记忆，只留白名单工具，是能观测到的前提；但 Opus-5 那个「没给 Gameplay 就自己用 Bash 写模拟器」的例子，说明工具白名单的边界得按「模型会组合使用」来画，而不是按「单个工具能干什么」来画。

说到底，这篇论文最值钱的地方不是「模型能自我改进」，而是它把这件事从一句口号变成了一组可复现、可拆解、可证伪的测量。20 个点不高，六个模型不多，游戏也不复杂。但方向摆在那儿：随着模型变强，人该退的，可能不只是某一步的调参，而是「怎么学」这件事本身。

还有一层没解决的——当脚手架少到一定程度，模型自己攒出来的学习流程我们还能不能读懂、能不能在它跑偏之前拦住。文本产物可读是这篇的一个幸运设定；换成权重空间或者可执行 harness 的自修改，这份可读性就没了。
