# 答错了，到底怪没找到证据，还是怪没用好证据？

你有没有碰到过这种事：把一篇论文整本塞进多模态大模型，问它某个结论是怎么来的。它答得头头是道，语气笃定，还顺手引了两个数字。你回头去核对，发现关键那条曲线在 Figure 10 里，它压根没看；或者它看了图，也看了正文第 4.5 节，但就是没把"传感器事件的时间顺序"和混淆矩阵里那两个数字对上。

答案不算全错，就是差那么一口气。

我之前调文档 RAG 的时候有个挺别扭的体验：训练曲线上的 reward 一路往上走，人工抽检却觉得回答越来越"滑"，该给的解释被悄悄略过。当时想了很久才反应过来——答案级别的反馈太粗了。它只会告诉你"这题答得不行"，不会告诉你，是那张表根本没被检索进来，还是检索进来了但模型没能把它和文字接起来。这两种失败，处理方式完全是反的，可 reward 把它们压成了同一个数。

所以翻到 arXiv:2611.22837 的时候我停了一下。这篇来自山东大学的工作，想干的就是把这两种失败分开，然后让"找证据的"和"用证据的"一起进化。说实话，这个命题我挺买账的，虽然读完觉得它有几处包装得比实际漂亮。

---

## 核心摘要

科学文档问答里，"检索到了相关来源"和"把散落在文字、图、表里的互补证据拼成一条完整论证"，是两件事。更麻烦的是，答案级别的 reward 分不清一次失败究竟是没找全，还是找到了没用好。作者给出的解法是一个 Retriever–Perceiver–Reasoner 三组件框架：检索器按预算顺序挑证据，感知器在隐状态空间里构建一个"问题条件的潜在本体"，推理器把这个潜在引导和原始证据一起用。三个组件通过诊断引导的协同演化一起训练——交替更新共享一个答题 reward，再用 RPF 和 LEF 两个诊断信号判断"这题该补检索"还是"该修引导"，据此定向重采样。四个 benchmark、七个设置下，7B 和 8B 骨干拿到 69.9 和 75.0 的平均分，比全局最强 baseline 高 4.0 和 9.1 个点。我的判断是：这不是底层架构突破，是一次想得挺清楚的系统整合，最值钱的地方是把"错在哪"做成了可计算、能接进训练闭环的信号；但 "Self-Improving" 这个词，用得有点松。

## 🎯 问题动机：一条单向流水线，说不清锅在谁头上

科学文档推理的难，不在读字，在"接关系"。一个问题的支撑材料往往散在正文的某句话、某张图的曲线、某个表格的格子里。你得先把它们都找齐，还得把它们对上——比如"Leave Home 识别率从 70% 涨到 87%"这个数字在图里，而"为什么涨"的解释藏在正文 4.5 节，说是因为 GNN 能捕捉传感器事件的时间顺序。只拿到其中一半，答案就是残的。

传统的 retrieve-then-reason 是条单向流水线：检索器吐出一批相关来源，推理器照着答。Figure 1 上半部分把它的毛病画得很直白——检索到的 Figure 和 Text 中间是个断开的链接图标，旁边标着 "Disconnected Evidence"，底下还有个红叉写着 "Missing Complementary Evidence"（表格没进来），落到答案那一栏，是个 "Incomplete Answer"。作者给了一句挺到位的总结：Relevant Sources, fragmented evidence integration，来源是相关的，整合是碎的。

![图 1：动机与框架总览。上半部分是传统 retrieve-then-reason 流水线，检索到 Figure 和 Text 却彼此断开、缺了表格这类互补证据，最终只得到不完整答案；下半部分是这套协同演化框架，Retriever 之后多了 Perceiver 做"问题条件感知"，把 Table、Figure、Text 连成 Question-Conditioned Latent Ontology，Reasoner 同时拿到原始证据和潜在本体，输出有据可依的答案，底部是"下一轮"的协同演化回路](https://arxiv.org/html/2611.22837v1/intro.png)

*图 1：动机与框架总览（论文 Figure 1）*

但真正打动我的不是"检索会漏"这个观察，而是接下来那层追问：**答案不完整的时候，你分不清是没检索到，还是检索到了没用好。**这两件事还互相咬着——再强的解读能力也补不回从来没被检索进来的证据；反过来，一个来源到底有没有价值，又取决于当前模型能不能读懂它。作者管这个叫 reciprocal dependence，互相依赖。

这句话其实把整篇论文的合法性立住了。既然两种能力互相定义，那单独优化哪一个都是半截工程，得让它们一起学。

顺着这个再聊聊现有工作，能看出作者想卡的那个位置。Related Work 里把前人都摆得很清楚：

| 路线 | 代表工作 | 管什么 | 不管什么 |
|---|---|---|---|
| 多模态证据检索 | MIRAGE、VisRAG、M3DocRAG | 把图文表找出来 | 找到之后怎么跨模态拼起来 |
| 证据定位与迭代推理 | DocSeeker、VisRAG2.0、ViDoRAG | 定位、grounding、多轮找证据 | 检索与利用的联合训练信号 |
| 检索—生成联合优化 | CLaRa | 检索器和生成器一起调 | 没有细粒度的失败归因 |
| 感知—推理协同演化 | PRCO | 感知与推理 co-evolve | 没有把"检索"纳入同一个闭环 |

（这张表是我按论文 Related Work 归纳的，不是原文表格。）

你会发现，一边是"只管找"，一边是"粗粒度地一起调"，中间空着一块：能不能先诊断出这次到底该怪谁，再决定练哪个模块？这就是 RPR 想填的坑。

## 🏗️ 方法核心：三个组件，加一个会"问诊"的训练回路

一句话讲清核心 idea：**找证据的和用证据的一起学，而且学之前先搞清楚这次该怪谁。**

### 先把任务摆成一个三段式决策过程

给定完整文档 $D=(X,V)$（$X$ 是正文，$V$ 是带 caption 的图和表）和问题 $q$，智能体要产出一条带推理轨迹的回答 $y \sim p_{\Omega}(\cdot \mid D, q)$。参数被拆成三块：$\phi$ 管 Retriever、$\psi$ 管 Perceiver、$\theta$ 管 Reasoner。

流程是三个相位 $\xi_t \in \{\mathrm{s}, \mathrm{p}, \mathrm{r}\}$。检索相位里，动作空间是"从候选池挑一个来源"或者"喊停"：

$$\mathcal{A}_{\mathrm{s}}(s_t) = \{a_e : e \in \mathcal{C}_t\} \cup \{a_{\mathrm{stop}}\}$$

检索一旦终止，选中的来源被打包成证据 $E$，感知器造出潜在本体 $Z$，推理器拿两者一起生成：

$$E = \operatorname{Pack}(S_T), \quad Z = C_{\psi}(E, q), \quad y \sim p_{\theta}(\cdot \mid E, q, Z)$$

这里有个我觉得挺克制的设计：**原始证据 $E$ 始终直接喂给 Reasoner，潜在本体 $Z$ 只是补充，不是替代。**很多工作喜欢把多模态信息压缩成一段文本摘要再交给 LLM，省事是省事，但摘要本身就是一层有损编码，还会自带幻觉。作者选择让 $Z$ 提供紧凑的跨模态"组织关系"，把细节的读取权留给原始 $E$。后面的 Table 4 会证明这个决定不是白做的。

### Retriever：带结构感知的顺序选择

候选池 $\mathcal{C}(D)$ 由一个固定规则先构造好，跟问题、跟标注都无关——每个候选保留自己的来源身份，文本还保留在原文中的区间位置。训练和推理用同一套构造与打包逻辑，这点对可复现很重要。

挑证据不是一次性 Top-K，而是一步一步来，受两个预算约束：$K_{\max}$ 个来源单位、$B_E$ 个证据 token。每一步状态里都带着问题、已选来源、剩余预算。一个**冻结**的多模态 reranker 给出问题—候选的相关性表示，再和候选特征、选择特征、预算特征融合。

为了不把文档当成一袋互不相干的碎片，作者叠了两层结构建模：

- 一张 source-relation graph：同 section 里重叠的文本块相连，文本连到它引用的图和表，再加自环保留候选自身信息；上面跑一层 message passing。
- 一个 candidate-level Transformer，捕捉候选之间的全局交互。

再由选择头和停止头给出动作分数 $u_{\phi}(a, s_t)$，套一个带温度 $\tau_r$ 的 softmax 就是策略：

$$\pi_{\phi}(a \mid s_t) = \frac{\exp(u_{\phi}(a, s_t) / \tau_r)}{\sum_{b \in \mathcal{A}_{\mathrm{s}}(s_t)} \exp(u_{\phi}(b, s_t) / \tau_r)}$$

每一步的 eligible set 会剔掉已选的、不兼容的、超预算的候选；喊停、到达来源上限、或者没候选可选，三种情况任一都终止。打包时合并重叠的文本区间，视觉内容原样保留。

### Perceiver：在隐状态空间里"组织"，不写摘要

这是全文我最喜欢的一块。给定 $E$ 和 $q$，Perceiver 要造出一个"问题条件的潜在本体" $Z$ —— 作者把它定义成多模态证据在共享连续空间里的**隐式组织结构**，注意是隐式的，不是一棵显式的知识图谱，也不是一段文字。

它由两个部件组成：

**QueryBuilder** 先做 question-evidence query induction。用 $N_q$ 个可学习 query slots，同时 attend 到证据特征 $H_E$ 和问题特征 $H_q$（都从冻结的多模态 backbone 里抽），生成 evidence-aware 的查询 $Q$。这一步的意义是：接下来该关注什么，既取决于问什么，也取决于手里有什么。

**Latent Evidence Consolidator** 做跨模态整合。把证据特征 $H_E$、查询 $Q$、还有 $M$ 个可学习输出槽 $U$ 拼起来，喂进一个 backbone-specific 的 Former——它直接复用预训练语言模型的 decoder，挂一个专门的 Perceiver LoRA adapter。取输出槽位置的隐状态，投影到 Reasoner 的嵌入空间：

$$Q = \operatorname{QB}_{\psi}(H_E, H_q), \quad H_U = \operatorname{Former}_{\psi}([H_E; Q; U])\big|_{U}, \quad Z = H_U W_Z + b_Z \in \mathbb{R}^{M \times d}$$

关键就在 "directly in hidden-state space, without an intermediate textual summary" 这句。$Z$ 是一组连续的、固定长度的向量槽位，不是可读文本。你想想看，这等于把"跨模态对齐"这件事从生成任务挪回了表示任务，少了一步离散化，也就少了那一步的信息瓶颈。

Reasoner 那头，把 $Z$ 追加到 evidence–question prompt 的原生多模态 embedding 后面，一起 prefill，再自回归生成推理轨迹和答案。$Z$ 管"关系怎么组织"，$E$ 管"具体数字和原文是什么"。

### 训练：交替更新 + 两个诊断信号

![图 2：诊断引导协同演化总览。三大块——(1) 左下的诊断引导重采样：RPF Pool、LEF Pool 与常规问题混合成训练 batch，RPF 指向 Retriever、LEF 指向 Perceiver+Reasoner，重采样的是问题而非轨迹；(2) 上方的交替组件协同适配：依次 Perceiver Update → Retriever Update → Reasoner Update，每次只更新一个组件、另外两个冻结，监督信号是 Answer Quality / Evidence Agreement / Latent Gain 三方面；(3) 右下的成对诊断反馈：RPF 固定 Perceiver+Reasoner，比较"检索证据 E"与"标注证据 E*"下的 rubric 打分差；LEF 固定证据+Reasoner，比较 with Z 与 without Z 的打分差；正向 gap 决定下一轮的反馈池。左侧 Fresh Rollouts、右侧 Updated Model、底部 Next Cycle 构成闭环](https://arxiv.org/html/2611.22837v1/main_method.png)

*图 2：诊断引导协同演化总览（论文 Figure 2）*

先说初始化，两步都很干净，用的是 SciMDR 训练集里的 7000 条（含问题、标注证据 $E^*$、参考回答）。

**Perceiver 初始化**：绕过 Retriever，直接把标注证据 $E^*$ 递进去，Reasoner 冻结，用 teacher forcing 算参考回答（含推理轨迹）的 per-token 负对数似然，只更新 $\psi$，梯度穿过冻结的 Reasoner 回传。$\mathcal{L}_{\mathrm{I}} = \ell_Z$。这么做的意图很直白：先把"感知"练到对下游推理有用，别让它一上来就被检索错误带偏。

**Retriever 初始化**：同样 7000 条，把 $E^*$ 对齐到自动构造的候选池，拿到 source-level 监督。有意思的是它不规定固定的选择顺序——同一组有效证据，先挑哪个都行。于是用 set-valued supervision：在状态 $s_t$ 下，动作 $a$ 的分数由选完之后那组证据的质量决定，$v_{t,a} = F_{\mathrm{ret}}(S_t \oplus a, E^*)$，其中 $F_{\mathrm{ret}}$ 把活跃模态上的文本 F1 和视觉 F1 等权平均。给个容差 $\delta$，把分数接近最优的动作都算进近优集：

$$\mathcal{A}^{+}(s_t) = \{a \in \mathcal{A}_{\mathrm{s}}(s_t) : v_{t,a} \geq \max_{b \in \mathcal{A}_{\mathrm{s}}(s_t)} v_{t,b} - \delta\}$$

目标是动作分数回归，加上对近优集的概率质量做对数监督。这个"不强定顺序"的处理我觉得比强制一条 gold 路径合理，检索本来就没有唯一正确顺序。

**交替组件协同适配**是主训练阶段，写成一行是：

$$\Omega^{k+1} = \bigl(\mathcal{U}_{\theta} \circ \mathcal{U}_{\phi} \circ \mathcal{U}_{\psi}\bigr)(\Omega^{k})$$

按右到左执行，也就是依次更新 Perceiver、Retriever、Reasoner；每次只动一个参数块，另两个冻结；每轮都用当前模型的 fresh rollouts。这里插一句我自己的经验：多模块一起上 RL 的时候，credit assignment 特别容易糊，几个可学习模块同时动，谁也分不清 reward 该记在谁头上。后面 Table 2 里 "Joint updates (no alternation)" 比交替更新低了 6 个点多，算是给这个直觉补了个实验证据。

**共享 reward** 分三项。先让一个 LM compiler 把参考答案拆成若干带权重 $w_j$ 和部分给分锚点的可独立评判 claims，judge 打分：

$$S(y \mid q) = \frac{\sum_{j=1}^{J_q} w_j g_j(y)}{\sum_{j=1}^{J_q} w_j}$$

每个问题采 $G$ 条检索轨迹，每条轨迹让 Reasoner 成对生成 with $Z$ 和 without $Z$ 的响应（证据、问题、解码设置全同），得到 $S_i^Z$ 和 $S_i^0$。共享 reward：

$$R_i = S_i^Z + \lambda_{\mathrm{ret}} F_{\mathrm{ret}}(E_i, E^*) + \lambda_{\mathrm{gain}} (S_i^Z - S_i^0)$$

三项分别是答案质量、与标注证据的一致性、潜在引导的贡献。三个组件轮流用 GRPO 更新，$\lambda_{\mathrm{ret}} = \lambda_{\mathrm{gain}} = 0.5$ 全程固定。训练配置是 3 个协同演化 cycle，每 cycle 每组件 20 步，batch 32，最大输入 128K；reranker 用 Qwen3-VL-Reranker-2B 全程冻结；首轮纯常规采样，之后每 batch 是 24 条常规题 + 8 条从相关反馈池抽的题（不够就常规补齐）。

**现在到了我觉得全篇最值钱的地方——RPF 和 LEF。**共享 reward 只说"答得好不好"，不说"该练谁"。两个诊断信号就是来补这一刀的，做法都是"固定住其余部分，换一个输入，看分数差"：

- **RPF（Retrieval Potential Feedback）**：固定 Perceiver 和 Reasoner，把检索来的 $E$ 换成标注证据 $E^*$，重算 $Z^*$，比较两次 rubric 分数：

$$d_{\mathrm{ret}}(q) = \bigl[S^{\mathrm{gold}}(q) - S^{Z}(q)\bigr]_{+}$$

正 gap 说明"给更全的证据就能答得更好"——那这题的瓶颈在检索，进 RPF pool，下一轮定向喂给 Retriever 更新。

- **LEF（Latent Efficacy Feedback）**：固定证据和问题，比较 with $Z$ 和 without $Z$：

$$d_{\mathrm{use}}(q) = \bigl[S^{0}(q) - S^{Z}(q)\bigr]_{+}$$

正 gap 说明"加了潜在引导反而更差"——引导本身、或者 Reasoner 用引导的方式有问题，进 LEF pool，喂给 Perceiver 和 Reasoner。

图里那行小字我特意看了一眼：**Resample questions, not trajectories**。选中的是问题，不是旧轨迹，下一轮用当前模型对这些题重新 rollout。这个细节挺关键的，否则拿旧策略的轨迹去训新策略，分布就歪了。

## 🧪 实验结果：涨在哪，没涨在哪

### 设置

先说结论：7B 的 Ours 拿到 69.9，8B 拿到 75.0，全文那两个 "4.0 / 9.1 个点" 都是跟**同一个全局最强 baseline**比的，也就是 Avg 65.9 的 Qwen3-VL-8B + SFT + GRPO。$69.9 - 65.9 = 4.0$，$75.0 - 65.9 = 9.1$。这个细节我核对了一下才敢写，因为很容易被读成"各自同骨干对比"。要是按同骨干比，7B 的 Ours 对 Vision-R1-7B + SFT + GRPO 是 69.9 对 59.6，涨了 **10.3 个点**，其实更狠。

说实话，看到这张表我第一反应不是"哇涨了好多"，而是去盯 SciMDR-Eval 那一列。你看：

- ChartQA 一栏，从 85 到 90，所有模型挤在 5 分以内，Ours 也就 89.8 / 90.4。
- SciMDR-Eval 一栏，Qwen2.5-VL-7B 是 19.8，Qwen3-VL-8B 是 34.2，连做过 SFT+GRPO 的任务适配 8B 也只有 45.6；而 Ours 是 75.8 / 79.7。

差了三四十个点。也就是说，**这套方法的收益几乎全压在"长文档里跨模态找齐证据并整合"这一类题上，单图理解题基本没动。**这其实是个挺诚实的定位——它解决的本来就是证据整合，不是视觉理解。但也提醒一句：别把 9.1 分脑补成模型全面变强了，换个以单图问答为主的业务场景，这套东西大概率给不了你同样的惊喜。

还有个值得留意的对照：Table 1 里 Keye-VL-1.5-8B 在 SciMDR-Eval 上有 65.2，比一堆更大模型都高，但 ChartQA/CharXiv 又偏低。说明这个 benchmark 的分数分布本身就很"偏科"，Avg 是把七个性格完全不同的设置等权平均出来的，跨列比较要小心。

几点我想聊的：

"**w/o Perceiver**" 掉 9.1 是最大单项，但这个归因不干净。Table 2 的脚注自己写了：拿掉 Perceiver 的同时也一并省掉了它的监督初始化。所以这 9.1 里混着"没有潜在本体"和"没有那步初始化"两件事。要真想证明 $Z$ 的价值，更该看 Table 4。这块消融设计我觉得有点含糊。

**QueryBuilder 三种变体**很说明问题：完整 69.9、只用问题 64.7、只用证据 64.4、去掉 62.5。感知阶段该关注什么，确实得同时看问题和手里已有的证据，偏哪头都不行。

### 三条支撑证据链

**Retriever 不是靠"多塞证据"涨分**（Table 3，Vision-R1-7B）：六个检索指标从训练前 → 初始化后 → 协同演化后全程上行。举两个数，SciMDR-Eval 的 Visual F1 是 48.30 → 72.02 → 79.74，SPIQA 的 Text F1 是 22.46 → 33.10 → 39.01。附录里还提到，训练后的检索器平均来源数和 token 用量都还在预算以下——是定位更准了，不是堆得更多了。这条证据挺关键，否则"涨分"很容易被解释成"反正上下文塞得满"。

**$Z$ 是真被用上了，不是凑数的 token**（Table 4，latent-input 干预）：

| 条件 | SPIQA-A | SPIQA-B | SPIQA-C | SciMDR-Eval | Avg. |
|---|---|---|---|---|---|
| Full $Z$ | 74.6 | 66.2 | 62.7 | 75.8 | 69.8 |
| No $Z$ | 68.5 | 59.2 | 54.6 | 62.1 | 61.1 |
| Random $Z$ | 50.2 | 41.7 | 36.5 | 45.3 | 43.4 |
| Mismatched $Z$ | 52.6 | 43.9 | 40.3 | 47.6 | 46.1 |

这个实验我挺喜欢。随机 $Z$（43.4）比干脆不给 $Z$（61.1）还低了快 18 个点，错配的 $Z$ 也掉到 46.1。说明 Reasoner 是真的在读这组向量，给错了会主动把答案带沟里——反过来说，正确的 $Z$ 里确实编码了对当前问题有用的组织信息。比单纯"去掉某模块看掉多少分"有说服力得多。Table 5 在 SciMDR-Eval 上还拆了输入模态：Full $Z$ 75.8、只给文本 65.8、只给视觉 67.3、不给 62.1，哪怕 Reasoner 本来就能看到两种模态，Perceiver 少接一路输入照样掉分。

**训练动态不单调，作者自己写出来了**（Table 6，SciMDR-Eval）：

| Cycle | w/o $Z$ | w/ $Z$ | $\Delta$ Score | Text F1 | Visual F1 |
|---|---|---|---|---|---|
| 0（初始化） | 57.3 | 63.5 | 6.2 | 34.57 | 72.02 |
| 1 | 58.8 | 70.3 | 11.5 | 36.14 | 74.39 |
| 2 | 62.7 | 72.5 | 9.8 | 38.27 | 77.06 |
| 3 | 62.1 | 75.8 | 13.7 | 40.14 | 79.74 |
| 4 | 64.9 | 74.2 | 9.3 | 41.55 | 78.33 |

从 0 到 3，with-$Z$ 从 63.5 走到 75.8，文本和视觉 F1 一起涨，$\Delta$（潜在引导的贡献）从 6.2 拉到 13.7，协同演化确实在起作用。但 Cycle 4 翻车了：文本 F1 还在涨（40.14 → 41.55），no-$Z$ 也在涨（62.1 → 64.9），可 visual F1 掉了（79.74 → 78.33），with-$Z$ 反而回落到 74.2。

作者对这个分叉的解释，正好回扣了开头的 reciprocal dependence：单个组件继续变好，不代表端到端会跟着变好。这段我是真觉得写得诚实——多数论文会把第 4 个 checkpoint 悄悄藏进附录，或者干脆只报最好的那轮。它敢把非单调摆到正文，反而让我更信前面那些数。顺带也说明"3 个 cycle"这个数是调出来的，不是自然收敛点，换个数据分布未必还是 3。

## 💡 我的判断

**最值钱的地方，是把"错在哪"做成了可操作的信号。**RPF 和 LEF 的思路一点都不玄：固定住其余模块，换一个输入，重跑一遍打分，看差值。但它把训练里那个模糊的"这题怎么又错了"转成了两个可计算、能直接接进采样策略的标量，而且分别指向不同的待更新模块。这个迁移性很强——你做检索+重排+生成的多模块 agent，或者任何几个可学习模块共享一个稀疏 reward 的系统，都能照着搭一套反事实诊断。成本也就是多跑几次前向，不算贵。

**几个设计上的克制我也认。**潜在本体直接在隐状态空间做、不生成中间摘要；Reasoner 始终保留原始证据、$Z$ 只做补充；检索初始化不强定唯一顺序，改用近优动作集。这些都不是炫技，Table 4 和 Table 5 也确实验证到位了。实验链条从主表、消融、检索指标、latent 干预一路铺到训练动态，层层把"为什么涨"拆开，比只甩一张 SOTA 表扎实。

**但 "Self-Improving" 这个词，我觉得用得松了。**整套闭环从头到尾都依赖标注证据 $E^*$ 和参考回答：rubric 要拿参考答案去拆 claims，$F_{\mathrm{ret}}$ 要拿 $E^*$ 算覆盖，RPF 更是直接把 $E$ 换成 $E^*$ 才得到参照分数。也就是说，这个 "self" 是有监督信号兜底的，推理时虽然没有 $E^*$，训练时的诊断参照物却一刻没离。更准确的说法大概是"带诊断信号的联合 RL 微调"，而不是真的无监督自进化。名字起大了一号，不影响方法本身的含金量，但读的时候心里得有数。

**收益边界清楚，也窄。**涨分集中在 SciMDR-Eval、SPIQA-C 这类需要长文档跨模态整合的设置，ChartQA 几乎纹丝不动。这不是缺点，是定位，但别拿 9.1 分去讲故事说"多模态推理全面跃迁"。

**还有几处我没完全被说服的地方：**

- reward 是 LM compiler + judge 打出来的分，本身是模型判的。judge 偏好、rubric 拆得稳不稳、跟人工一致性如何，正文没给分析（附录 A.5 可能有，我没细看，这块不敢下结论）。用模型当裁判的 RL，reward hacking 的空间总归在那儿。
- baseline 的对比口径对作者有利：4.0 和 9.1 都拿 8B 的全局最强 baseline 65.9 做参照，7B 的 Ours 等于是跨了骨干尺寸去比。不过同骨干的 59.6 摆在那儿，10.3 个点的差距也是实打实的，算不上注水。
- PRCO 在 Related Work 里被一句话带过（"co-evolves perception and reasoning"），但正文没把它作为协同演化的核心对照做直接消融。想判断"交替更新 + 双诊断"相对"单纯的感知推理协同演化"到底增量多少，缺一个正面比较。
- 系统不轻：三个组件、两个诊断池、三个 cycle 的交替更新、冻结 reranker、LoRA adapter，工程链路不短。正文只说推理成本分析放在附录 A.3，没在正文给数字。7B/8B 跑得动，换更大骨干时 Perceiver 那份额外前向开销值不值，还得自己算。

**定位上，我不把它当底层突破。**GRPO、rubric judge、LoRA、reranker、source-relation graph，全是现成积木，作者垒得挺巧，但没动地基。真正有原创味道的是 RPF/LEF 这套"把失败归因做成训练信号"的机制，以及把检索、感知、推理三个组件放进同一个交替更新闭环的系统决断。想读一篇论文拿一个能迁移到自己系统里的 idea，这篇够了；想找架构级的新东西，可能会失望。

**落到工程上，我会记这么几条：**

- 多模块 agent 别只用一个答案级 reward。试试"固定其余模块、换一个输入看分数差"这种反事实诊断，实现不复杂，直接能接进下一轮的采样权重。
- 多模块一起上 RL 之前，先想想能不能轮流更新。Table 2 那个 69.9 对 63.8 值得抄进笔记。
- 要给 LLM 喂跨模态的"组织信息"，尽量在隐状态层面对齐，别绕一道文本摘要，少一层有损编码就少一层幻觉。
- 想复刻这套 self-improving，先确认你手上有标注证据，或者能自动构造出可信的 gold 参照。没有参照物，RPF 那类诊断就无从算起——这是前提，不是细节。

## 🔗 收尾

还有个更根上的问题没解决。RPF 和 LEF 都是"换输入、重跑、比分数"的事后诊断，等于在训练回路外面挂了一个评估模块。模型自己能不能在前向过程里就判断"这题我还得再找一张表"还是"证据够了，该停下来推理"？那才是把归因真正内化进策略，而不是外挂一个裁判。作者用三个 cycle 让组件彼此适应，走的是"系统层面协同"这条路；"单次推理层面的自我诊断"是另一条路，两篇论文的距离。

顺带说一句，Figure 3 那个 Cycle 3 结尾写着 "No positive RPF / LEF gap"——诊断信号归零，训练就停了。拿"没有改进空间"当收敛判据，比拍脑袋定 epoch 数优雅，这个小心思我挺喜欢。

如果你也在做检索增强或者多模态文档问答，这篇别只看那张 SOTA 表，把 3.3 节和两个诊断公式单独抠出来读一遍，大概率比 9.1 这个数字更有用。
