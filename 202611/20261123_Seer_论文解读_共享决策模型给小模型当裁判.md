# 让 9B 的裁判去指挥 4B 的选手：Seer 把深度研究的决策权拆了出来

上周调一个本地跑的 research agent，4B 的小模型，让它查「某年 NBA 总决赛收官战的分差」。第一次搜索的关键词就偏了，后面十几轮全在追一条错线索，工具调用数冲到三位数，答案还是错的。当时我盯着日志想了很久：要是能在它点下「搜索」之前，先有人把几个候选动作在脑子里过一遍、说一句「这条大概率没戏」，能省下多少冤枉调用？

麻烦在于，你没法真去试。真去试就是四次真实的搜索加四次页面抓取，费用和延迟都翻倍。你也没法让这个 4B 模型自己打分——它连题都答不对，凭什么判断自己哪一步走对了？更别提换一个 backbone 就得把整套引导逻辑重训一遍，端侧部署根本扛不住这种重复投入。

Seer 给的答案挺干脆：找两个「外人」来当裁判，一个负责想象「这个动作会搜回来什么」，一个负责判断「带着这个结果往下走，到头来能不能答对」。这两个裁判跟选手是谁没关系，离线训练一次，丢给一堆不同尺寸、不同家族的 agent 直接用。选手只管提动作，裁判只管打分，选中的那一个才真正去调工具。

---

## 🎯 核心摘要

深度研究（deep research）的 agent 每一步都要决定搜什么、读什么、验证什么，小模型一步走歪，后面全盘跑偏。推理时引导有三道坎：真去试错要烧工具调用、让模型自我评价受限于它本身的能力、模型专属的引导换个模型就得重训。Seer 把「动作提议」从「后果预测」和「价值估计」里剥开，用一份共享的真实研究轨迹语料离线训出两个可复用模型——工具响应模拟器和历史价值估计器，推理时在想象出来的历史上做搜索，只把选中的动作真正执行，而且写回上下文的证据一律用真实响应。效果很直观：GAIA 准确率在 Qwen3.5-4B 上从 13.6% 抬到 41.7%，9B 上从 22.3% 抬到 50.5%；在 BrowseComp-200 上，4B 用大约 7 次工具调用拿到 7.0%，而 BoN@4 烧掉约 26 次调用只有 4.5%。我的判断是：这是一次干净、诚实、验证量很足的工程整合，把「共享决策模型」这个部署形态立住了，但它不是新的底层机制，而且论文主打的端侧叙事跟它自己那两个 9B 裁判之间，有一道没算清楚的账。

## 🤔 问题动机：三道坎，和一个更根本的矛盾

论文把深度研究的形式化写得很规矩。冻结的 agent 在历史 $s_t$ 上按策略采样动作，$o_t$ 是真实工具响应，然后拼成新历史：

$$a_t \sim \pi_{\mathcal{G}}(\cdot \mid s_t), \quad o_t = \mathcal{E}(a_t), \quad s_{t+1} = s_t \oplus (a_t, o_t)$$

优化目标是终端答案质量 $R_{\mathrm{term}}$，但要被一个二维资源向量卡住：

$$\mathbf{c}(\mathcal{G},\xi) = \big(c_{\mathrm{param}}(\mathcal{G}),\, c_{\mathrm{tool}}(\xi)\big)^{\top}, \qquad \max_{\mathcal{G}}\ \mathbb{E}_{q,\xi}\big[R_{\mathrm{term}}(\xi;q)\big] \ \text{s.t.}\ \mathbf{c}(\mathcal{G},\xi) \preceq \mathbf{B}$$

$c_{\mathrm{param}}$ 是本地部署的总参数量，$c_{\mathrm{tool}} = \sum_t |\operatorname{calls}(a_t)|$ 是真实工具调用数，批量调用也按个算，被丢弃的候选只要真执行了照样计入。这个约束设定很关键，后面所有的批判都得回到它。

作者用 Figure 1 的四张小图把现有方案为什么不 work 摆了一遍。

![Figure 1(a)：端侧小模型单条链路的高错误率](https://arxiv.org/html/2611.26423v1/figs/motivation_sub_1.png)

*Figure 1(a)。Edge Model 经过 Tools / Environments 直接到 Conclusion，一条链走到底。小模型选错一次搜索词，后面没有任何纠偏机会，错误率就这么堆上去了。*

![Figure 1(b)：让模型自我修订带来的偏置](https://arxiv.org/html/2611.26423v1/figs/motivation_sub_2.png)

*Figure 1(b)。在出结论之前多插了一步 Revise，把结果再喂回同一个 Edge Model。问题是打分的人和犯错的人是同一个，自我修订天然带偏，论文称之为 Biased revision。*

![Figure 1(c)：多分支真实执行的工具成本](https://arxiv.org/html/2611.26423v1/figs/motivation_sub_3.png)

*Figure 1(c)。为了让 agent 比较几个候选，直接分出两条并行的 Tools / Environments 分支。设想是好的，但每条分支都要真的去调工具，被放弃的那条钱已经花掉了，收不回来。*

![Figure 1(d)：模型绑定的模拟难以跨 agent 复用](https://arxiv.org/html/2611.26423v1/figs/motivation_sub_4.png)

*Figure 1(d)。把后果预测做成模型内嵌的 Simulation，图中两个红叉点出了要害：换个 agent 模型，这套模拟和打分就得重做，泛化不过去。*

四张图对应摘要里的三道障碍：真实试错的工具开销、prompt 式自我评价的能力天花板、模型专属引导的重复适配成本。说实话这个拆解我认，尤其第三点常被忽略——很多推理时增强方法把成本从「训练」挪到了「配套组件」上，换个 base model 又得重来一遍，账其实没省。

但这里有个更根本的矛盾，论文自己埋了伏笔却没在动机里挑明：**端侧部署最紧的资源是内存和算力，而工具调用是要付给外部服务的钱**。Seer 后面所有的设计都在省后者、花前者。这个取舍在云侧很合理，在端侧就未必。等看到训练配置我再回来算这笔账。

## 🏗️ 方法核心：把「提动作」和「判动作」拆成两家人

先看架构图，整篇论文的骨架都在这张图里。

![Figure 2：Seer 整体框架](https://arxiv.org/html/2611.26423v1/figs/seer-arch.png)

*Figure 2。左栏是轨迹采集：QA Bank 经真实工具执行、Monte Carlo 分支展开，配合 Model Bank 收集跨模型跨任务的真实轨迹。中栏是两个离线训练流水线：上半训练模拟器（Tool-calls Normalization → 去错误 → 去重复 → 0.7M 工具调用/响应对 → LoRA 微调），下半训练估计器（Format → Cleaning → Dedup → Judge → 折扣奖励赋值 $G_{\xi,t}=\gamma^{T_\xi-t}R_{\mathrm{term}}(\xi;q_\xi)$ → 1.0M 价值样本 → LoRA 微调）。右栏是推理：从 History Messages 展开 K 个候选，浅蓝圆点是模拟器、浅绿圆点是估计器，层层收敛到 Determined Action，只对这一个动作做 Real Tool Execution，收尾是 Answer Retrieved。*

一句话讲清核心想法：**agent 只负责「有哪些动作可以做」，两个共享模型负责「做了会看到什么」和「看到之后有多大戏」，然后只把票最高的那一个真正执行**。

### 4.1 两个模型，两种互补的监督信号

**工具响应模拟器** $W_\phi$ 学的是条件分布：给定一次工具调用 $c$（工具名加参数），预测响应 $o$。训练损失是 response-only 的负对数似然，指令和调用参数只当上下文，不产生目标 token：

$$\mathcal{L}_{W}(\phi) = -\mathbb{E}_{(c,o)\sim\mathcal{D}_{W}} \sum_{\ell=1}^{|o|} \log W_{\phi}\big(o_{\ell} \mid c,\, o_{\lt \ell}\big)$$

候选动作 $a^{(i)}$ 里往往含多次调用，按调用顺序逐个采样再拼起来：$\hat{o}_c \sim W_\phi(\cdot\mid c)$，$\widehat{\mathcal{E}}(a) = (\hat{o}_c)_{c\in\operatorname{calls}(a)}$，于是得到想象历史：

$$\hat{s}^{(i)} = s_t \oplus \big(a^{(i)},\, \widehat{\mathcal{E}}(a^{(i)})\big), \qquad v^{(i)} = V_{\theta}\big(\hat{s}^{(i)}\big)$$

这个设计有个我很喜欢的细节：模拟器只学「工具会返回什么」，不学「该选哪个动作」，也不学「题目做完没有」。职责切得干净，才谈得上跨 agent 复用。数据采集时也刻意不按最终答案对错过滤——一条失败轨迹照样能提供「这个调用到底返回了什么」的有效观察。论文的措辞是，这些清洗步骤只消除采集基础设施带来的噪声，不按答案正确性筛样本。

**价值估计器** $V_\theta$ 的输入是完整历史前缀，标签是折扣后的终端正确性：

$$\mathcal{D}_{V} = \{(s_{\xi,t},\, G_{\xi,t})\}_{\xi,t}, \qquad G_{\xi,t} = \gamma^{T_{\xi}-t} R_{\mathrm{term}}(\xi;q_{\xi}), \quad \gamma = 0.95$$

这里 $T_\xi - t$ 数的是**剩余交互轮数**，不是 token 数、也不是动作内部拆出来的单次工具调用。答对的轨迹越接近终点目标越靠近 1，答错的提交整条轨迹目标恒为 0；超时和报错的未完成轨迹直接从训练集里剔除。标签由 judge 拿提交答案跟 gold answer 比对得出，是二元的，gold answer 和 judge 输出都不会被塞进估计器的输入历史。

估计器的输出头用了 HL-Gauss：把 $[-1, 1]$ 均分成 201 个 bin，用高斯平滑把标量目标摊成软标签 $y_b(G)$，再按期望解码出分值：

$$V_{\theta}(s) = \sum_{b=1}^{K} z_b\, p_{\theta}(b\mid s)$$

为什么要把回归改成软分类？我的理解是，终端正确性是个 0/1 的稀疏信号，直接回归方差大、容易塌，摊成相邻 bin 的分布后训练稳得多。$\sigma$ 取 0.75 个 bin 宽，属于「稍微糊一点、不糊到分不清」的取值。这块我自己也还在摸索更优的设定，可能理解有偏差，但方向是对的。

### 4.2 想象搜索与真实执行

每个真实轮次，Seer 以已提交历史 $s_t$ 为根新建一棵树，跑 $N_{\mathrm{sim}}$ 次 PUCT 模拟。扩节点时从冻结策略 $\pi(\cdot\mid\bar{s})$ 独立采 $m$ 个合法动作（$1 \le m \le k$），把它们的工具调用打包喂给模拟器，生成的想象历史挂成子节点，新兄弟节点的先验一律 $P(e)=1/m$，提交最终答案的子节点直接当终点。

选择用经典的 PUCT：

$$\operatorname{score}(e) = Q(e) + c_{\mathrm{puct}}\, P(e)\, \frac{\sqrt{N(u)+1}}{1 + N(e)}$$

每次模拟把端点交给 $V_\theta$ 打分并沿路径回传。注意一个措辞：论文特别区分了「一次 search simulation」（一次树遍历加价值回传）和「用模拟器预测单个工具响应」，别混了。还有个诚实的自白——因为 $V_\theta$ 是在真实历史上训的，模拟误差会扭曲它的排序，所以他们设了深度上限 $d_{\max}$，主实验干脆用 **depth-one** 的单层想象搜索。等于主动承认：多步想象不靠谱，先只做一步。

搜完之后提交访问次数最多的根边：

$$e^{*} \in \arg\max_{e \in \mathrm{root\ edges}} N(e), \qquad a_t = \operatorname{action}(e^{*})$$

然后才是真正的重点：**只对这一个动作做真实执行，并且只把真实响应写回已提交历史**。想象出来的东西用完就扔，绝不污染证据链。我看到这条的时候愣了一下，随即觉得挺漂亮——很多做世界模型的工作会顺手把模拟状态留在上下文里往后推，误差一层层叠上去，几轮之后 agent 就在自己编的世界里自洽了。Seer 把「想象」严格隔离在决策阶段，证据仍然是网上真实抓回来的原文，这个边界划得很专业。

### 4.3 训练配置：把账摊开

- 语料来自 DeepDive、MiroVerse、Nemotron RL、OpenSeeker、REDSearcher 五个数据集，按轮次轮询采样问题，**排除所有评测题**，冻结的 agent 真实执行并用 Monte Carlo 分支展开轨迹。最终得到 **0.7M 条工具调用/响应对**给模拟器，**1M 条价值样本**给估计器。
- 两个模型都从 **Qwen3.5-9B** 初始化，LoRA 微调，学习率 $10^{-4}$，rank 分别 64 / 32，上下文上限 16k / 128k tokens。估计器用可全训练的 HL-Gauss 头，201 个 bin 覆盖 $[-1,1]$，高斯标准差 0.75 个 bin 宽。两个 checkpoint 跨所有 agent **原样复用，不再更新**。
- 两个外部工具：`search` 返回标题、链接、摘要；`visit` 抓页面并抽取与目标相关的证据，抽取环节由一个共享的 **Qwen3.5-397B-A17B 服务**完成，作者说明这项开销对所有对比方法一致。
- 评测：GAIA、BrowseComp-200（BC-200）、BrowseComp-ZH（BC-ZH）、SEAL-0、XBench-DeepSearch（XBench-DS）五个基准，报最终答案准确率。主对比覆盖 Qwen3.5-4B / 9B / 35B-A3B、Qwen3.6-35B-A3B、Gemma-4-e2b-it / e4b-it，另测 Qwen3.5-122B-A10B 和 397B-A17B 两个大 agent。
- Baseline：Base Agent 跑一条 ReAct 轨迹；BoN@4 跑四条，用归一化答案多数投票选；AV@4 跑四条，用 prompted outcome verification（非对称验证那条线）选，都不接触 gold answer；另外实现了 RAP@4。每条轨迹限 100 个已提交轮次、128k 输入 token、9000 秒，触顶就强制直答，投机性的候选提议不占轮次预算。
- Seer 用单层想象搜索，候选宽度 $k \in \{4, 8, 16, 32\}$，主表报告 $k=4$ 和 $k=32$。

## 🧪 实验结果：数字很好看，但有个地方让我皱眉

### 先看预备实验：prompt 式世界模型在小模型上根本不 work

Table 1 报的是跨基准平均准确率：

| 模型 | Base | RAP@4 | Seer ($k=4$) |
|---|---|---|---|
| Qwen3.5-4B | 8.3 | 8.0 | **18.8** |
| Qwen3.5-9B | 14.2 | 13.9 | **25.2** |

RAP@4 是「让同一个 LLM 既当世界模型又当决策者」的那条经典路线，在 4B / 9B 上几乎不动，甚至略降。作者因此把它从后面的主表拿掉了。这个结果我一点都不意外——4B 模型连题都做不明白，你让它凭空想象「搜这个关键词会返回什么」，想象出来的东西只能是它自己的幻觉。这也正是 Seer 要引入外部裁判的最强理由：**能力不能凭空自举**。

### 主实验：跨八个模型复用同一对 checkpoint

Table 2 是主表，我把三个 Qwen3.5 型号在三个代表性基准上的数值摘出来（单位 %，BoN / AV 均为 @4）：

| 基准 | 4B Base | 4B BoN | 4B AV | 4B $S_4$ | 4B $S_{32}$ | 9B Base | 9B $S_4$ | 9B $S_{32}$ | 35B-A3B Base | 35B-A3B $S_4$ | 35B-A3B $S_{32}$ |
|---|---|---|---|---|---|---|---|---|---|---|---|
| GAIA | 13.6 | 21.4 | 26.2 | 29.1 | **41.7** | 22.3 | 35.9 | **50.5** | 57.3 | **62.1** | 57.3 |
| BC-200 | 1.0 | 4.5 | 3.5 | 5.0 | **7.0** | 2.5 | 5.5 | **9.5** | 22.0 | 24.5 | 22.0 |
| XBench-DS | 20.0 | 36.0 | 35.0 | 41.0 | **43.0** | 28.0 | **47.0** | **60.0** | 64.0 | 66.0 | **69.0** |
| BC-ZH | 2.4 | 7.6 | 5.2 | 8.0 | **9.7** | 7.6 | 15.2 | **16.3** | 36.3 | 36.0 | **43.3** |
| SEAL-0 | 4.5 | 9.9 | 8.1 | 10.8 | **16.2** | 10.8 | 22.5 | **26.1** | 27.0 | 31.5 | **34.2** |

$S_4$ 在 4B 上五个基准全部压过两个四轨迹 baseline；9B 的 XBench-DS 到 47.0%，而 BoN 和 AV 都卡在 38.0%。放大到 $S_{32}$，GAIA 的 4B / 9B 分别冲到 41.7% / 50.5%，也就是摘要里那两个数字。Gemma-4 那边同样吃到红利，e2b-it 的 GAIA 从 20.4% 到 31.1%，e4b-it 从 21.4% 到 36.9%。$S_{32}$ 在 30 个 setting 里有 26 个超过 Base。

Table 3 更值得看：122B 和 397B 的大 agent 上，同一对 9B 裁判不重训直接挂上去，$S_{32}$ 在所有组合里都赢过 Base。397B 的 GAIA 从 68.9% 到 72.8%，BC-200 从 34.5% 到 42.5%，XBench-DS 从 75.0% 到 80.0%。一个 9B 的模型能给 397B 的选手提供增量，这件事本身比涨点更有意思——它说明价值判断这个活儿，未必需要跟生成能力同 scale。

不过看到 35B-A3B 的 GAIA 那行我停了一下：$S_4$ 是 62.1%，$S_{32}$ 反而是 57.3%，还低于 Base 的 57.3%（打平）。**候选变多，效果变差**。这不是个例，后面会专门讲。

### 工具调用：这才是 Seer 真正的卖点

Figure 3 把「准确率 vs 真实工具调用数」画成散点，三张图分别对应 4B / 9B / 35B-A3B 在 BrowseComp-200 上的表现。

![Figure 3(a)：Qwen3.5-4B 在 BC-200 上的准确率与工具调用数](https://arxiv.org/html/2611.26423v1/figs/Qwen3.5-4B_at_BC-200.png)

*Figure 3(a)。横轴 Tool Calls，纵轴 Performance（准确率 %）。Base 在约 7 次调用处只有 1.0%；Seer@4 / @8 / @16 / @32 挤在 6 到 8 次调用之间，准确率从 5.0% 一路到 7.0%；而 BoN@4 用了约 26 次调用拿到 4.5%，AV@4 约 25 次拿到 3.5%。左上角那一簇粉点就是「省调用还更准」的帕累托前沿。*

![Figure 3(b)：Qwen3.5-9B 在 BC-200 上的准确率与工具调用数](https://arxiv.org/html/2611.26423v1/figs/Qwen3.5-9B_at_BC-200.png)

*Figure 3(b)。9B 上差距更夸张：Seer@32 / @16 落在约 10 次调用、9 到 9.5% 的位置，Base 是 10 次调用 2.5%，BoN@4 和 AV@4 各自烧掉约 40 次调用，分别只有 5.5% 和 6.5%。*

![Figure 3(c)：Qwen3.5-35B-A3B 在 BC-200 上的准确率与工具调用数](https://arxiv.org/html/2611.26423v1/figs/Qwen3.5-35B_at_BC-200.png)

*Figure 3(c)。35B-A3B 上 Seer@8 / @16 约 45 次调用拿到 27.5% / 27.0%，Seer@4 约 45 次拿 24.5%，而 BoN@4 和 AV@4 都要约 160 次调用且只有 24.0%。有意思的是 Seer@32 在这里掉到 22.0%，跟 Base 持平——大模型上把候选铺太宽反而不划算。*

| 案例 | Base | BoN | AV | $S_{32}$ |

| 1. OpenCV 贡献者 | 11 (I) | 39 (I) | 50 (I) | 3 (C) |
| 2. 徒步地点 | 54 (I) | 178 (I) | 124 (I) | 17 (C) |

| 6. 电梯事故报道 | — | 21 (C) | — | 2 (C) |

第 4 个案例就是我开头调的那个类型。178 次调用答错、17 次调用答对，这个对比比任何平均值都更有说服力。**坦率的讲，我觉得这篇论文最值钱的地方不在涨了多少点，而在它把「推理时引导」的成本结构摆到了台面上**：省的是被调用方收的钱，花的是本地多跑几次前向的电。

### 消融：一个被轻描淡写、但很要紧的下降

Table 4 在 GAIA 上逐层加组件（$k=4$，单位 %）：

| 变体 | 4B | 9B | 35B-A3B | 122B | 397B | Qwen3.6-35B | Gemma e2b | Gemma e4b |
|---|---|---|---|---|---|---|---|---|
| Base + search ($k=4$) | 16.5 | 44.7 | 62.1 | 71.8 | 73.8 | 74.8 | 26.2 | 19.4 |
| + estimator | 38.8 | 45.6 | 66.0 | 72.8 | 71.8 | 75.7 | 31.1 | 29.1 |
| + simulator（完整 Seer） | 29.1 | 35.9 | 62.1 | 68.0 | 76.7 | 78.6 | 30.1 | 24.3 |
| Direct scoring | 23.3 | 31.1 | 61.2 | 68.0 | 72.8 | 76.7 | 28.2 | 21.4 |

先看好的一面：把「prompt 打分」换成训练出来的估计器，4B 从 16.5% 直接到 38.8%，Gemma e4b 从 19.4% 到 29.1%。**价值估计器是这套方案里真正出力的那个零件**。

再看让我皱眉的一面：接着把模拟器加进来（也就是不用真实调用去试被丢弃的候选），八个模型里有六个准确率往下掉——4B 从 38.8% 到 29.1%，9B 从 45.6% 到 35.9%，35B-A3B 从 66.0% 到 62.1%，122B 从 72.8% 到 68.0%，Gemma e2b 31.1% 到 30.1%，e4b 29.1% 到 24.3%。只有 397B（71.8 → 76.7）和 Qwen3.6-35B（75.7 → 78.6）在涨。

论文 Table 4 的 caption 自己写得明明白白：加模拟器「avoids real calls for discarded candidates at an accuracy cost」。诚实，加分。但这个代价在主表和摘要里几乎不出现。你想想看，完整 Seer 相对「真实试错 + 估计器」这个上界，在 4B 上少了快 10 个点；它赢的是工具调用数，不是准确率。这不叫缺陷，叫取舍，只是宣传口径容易让人误会成「又省又准」。

### 候选宽度与「裁判也会看走眼」

Table 5 把 $k \in \{4,8,16,32\}$ 在五个基准上全跑了一遍，结论是**更大的 $k$ 并不稳定带来更好的结果**。举几个例子：35B-A3B 的 GAIA 是 62.1 → 64.1 → 59.2 → 57.3，397B 的 GAIA 是 76.7 → 76.7 → 71.8 → 72.8，122B 的 XBench-DS 是 71.0 → 68.0 → 71.0 → 72.0，全都不是单调的。小模型倒是常吃这一套，4B 的 GAIA 29.1 → 35.9 → 39.8 → 41.7 一路向上。作者的解释是「更宽的候选覆盖可以补偿不完美的模拟，但预测和打分误差会限制更宽想象搜索的收益」，并提醒要按 agent 和任务挑宽度。

Table 6 给了更硬的证据，统计估计器与 oracle 选中同一个候选动作的比例：

| 模型 / 数据集 | $k=4$ | $k=8$ | $k=16$ | $k=32$ |
|---|---|---|---|---|
| 397B / GAIA | 25.0 | 21.1 | 11.8 | 10.0 |
| 122B / BC-200 | 40.9 | 21.4 | 17.6 | 22.5 |
| 397B / XBench-DS | 30.8 | 7.9 | 0.0 | 0.0 |

$k=32$ 时，397B 在 XBench-DS 上跟 oracle 的一致率是 0.0%。等等，这个数得琢磨一下：候选越多，估计器越挑不准，这跟「模拟误差会随想象深度累积」是同一件事的两个侧面。也解释了他们为什么把搜索压在 depth-one——不是不想往深里搜，是深了就崩。

## 💡 我的判断：立住了一个部署形态，但没立住端侧叙事

### 亮点在哪

**解耦这件事本身很干净**。 把动作提议留给冻结的 agent，把后果预测和价值判断交给两个独立模型，部署时一个权重都不用改。这比「把引导逻辑塞进 agent 自身」的路线在工程上友好太多，换 backbone 的边际成本几乎为零。

**证据链只用真实响应**，这个边界我上文夸过了，值得再夸一次。想象归想象，写回上下文的必须是网上真抓回来的原文，避免了模拟状态在长轨迹里滚雪球。

**验证量够足**。 八个不同尺寸、三个家族的 agent，五个基准，加两个百 B 级模型，全程复用同一对 checkpoint。同类的推理时引导工作常常只在一两个 backbone 上验一验，这个覆盖度不多见。

**不藏拙**。 RAP@4 不 work、加模拟器掉点、$k$ 不单调、oracle 一致率归零，全写进表里了。说实话，读到 Table 6 那两个 0.0 的时候，我对这篇论文的好感反而上来了。

### 但有几笔账没算

**第一笔，也是最大的一笔：裁判比选手大得多**。 两个决策模型都从 Qwen3.5-9B 初始化，本地部署意味着除了 4B 的 agent，还得额外加载两座 9B 的基座（LoRA 再轻，基座权重也省不掉）。论文符号表里把 $c_{\mathrm{param}}$ 明确定义成「agent 模型加两个决策模型的总参数」，然后……实验部分就再没提过显存、内存占用或首 token 延迟。

这就是我开头说的那个矛盾。端侧设备最缺的是内存和算力，工具调用反而是要付给外部 API 的钱。Seer 精确地省下了后者，把成本搬到了前者。对一个跑 4B 都费劲的设备，额外 18B 参数这道门槛直接把主打动机削掉一半。我不是说方案不成立，我是说「端侧 / 隐私 / 本地控制」这个叙事，跟它自己的配置之间需要更多解释。

**第二笔，实验里其实有个 397B 在背后**。 `visit` 工具的证据抽取由共享的 Qwen3.5-397B-A17B 服务完成。作者说这项开销对所有方法一致、因此对比公平——这个辩护在「方法间比公平」上成立，但在「整套系统是不是端侧闭环」上不成立。至少在这套评测里，云侧依赖还在。

**第三笔，算力没有对齐**。 实验设置里有一句很关键的自白：$k$ 这些宽度「are not compute-matched to four full trajectories」。BoN@4 / AV@4 的四条轨迹每条都真实执行，工具调用全计入；Seer 只执行选中动作，但每个真实轮次要采 $k$ 个候选、跑 $k$ 次模拟器生成、多次估计器打分、外加 $N_{\mathrm{sim}}$ 次树遍历。论文只报工具调用数，没报 FLOPs、wall-clock 或显存。省的是钱，花的是电和本地算力——端侧恰恰更缺后者。这不是作弊，是口径选择，但读者得自己补上这一栏。

**第四笔，绝对值别被相对涨幅带跑**。 BC-200 上 4B 从 1.0% 到 7.0%、9B 从 2.5% 到 9.5%，相对倍数好看，绝对仍是「十题错九题」。GAIA 的 41.7% 放在今天的前沿系统里也不算高。论文的定位本来就是「强化小 agent」，这个我不苛责，但把「small agent」读成「可用的深度研究助手」就过了。

**第五笔，价值标签依赖离线黄金答案**。 估计器的监督来自 judge 拿提交答案跟 gold answer 比对出的二元正确性，还要剔除超时和报错轨迹。这套流水线在有标注的数据集上很好使，换到没有标准答案的开放任务怎么定义 $R_{\mathrm{term}}$，论文没展开。有个地方我没完全看懂：如果任务答案本身是开放式的，折扣终端正确性这个信号还成不成立？

### 跟前置工作比，它站在哪

搜了一圈同期和前置的方案，把几条线放在一张表里更清楚。下表中 WebDreamer、RAP、LATS、AgentRM 的描述与数值来自各自公开工作，不是 Seer 论文里的结果，别混在一起看。

| 方案 | 后果从哪来 | 打分从哪来 | 被丢弃候选要真执行吗 | 换 agent 要重训吗 | 提交用真实响应吗 |
|---|---|---|---|---|---|
| Base / ReAct | 无 | 无 | — | — | 是 |
| BoN@4 / AV@4 | 真实执行四条完整轨迹 | 多数投票 / prompt 验证 | 是，钱花了收不回 | 否 | 是 |
| RAP | 同一个 LLM 兼作世界模型 | LLM 自评 | 否 | 否，但受限于 agent 自身能力 | 否（想象） |
| LATS | 真实环境交互的树搜索 | 自评 + 反思 | 是 | 否 | 是 |
| WebDreamer | LLM 或专门训练的 Dreamer-7B | LLM 兼作价值函数 | 否 | 训练专用世界模型 | 否（模拟） |
| AgentRM | 真实交互 | 可迁移的奖励模型 | 部分 | 部分 | 是 |
| **Seer** | **离线训练的共享模拟器** | **离线训练的共享估计器** | **否，只执行选中动作** | **否，checkpoint 原样复用** | **是，严格只用真实响应** |

WebDreamer 那条线值得多说两句。它同样主张「先在想象里评估候选动作、只执行最优的一个」，同样训练了专门的小世界模型（Dreamer-7B，用 Qwen2-VL-72B 标注的 3.1M 交互实例训练），在 VisualWebArena / Online-Mind2Web 上相对 reactive baseline 提升 34.1% 到 42.3%，并报告比树搜索快 4 到 5 倍；它自己也承认多步想象存在「幻觉墙」，超过 3 步误差累积就不可靠。这些数值是 WebDreamer 论文及其公开仓库的口径，跟 Seer 的五个基准不可直接比较，我列在这里只是为了定位。

我的判断是：**Seer 不是新的底层机制，是一次定位非常清楚的工程整合**。世界模型加价值函数加树搜索的零件都是现成的，RAP、WMA、WebDreamer、AgentRM 各自做过一段。Seer 的增量在三个地方——把「跨 agent 复用、不绑定 backbone」当成第一设计目标并真的用八个模型验证；把「只执行选中动作且证据链不掺模拟结果」写死成硬约束；以及用 Monte Carlo 分支攒出 0.7M + 1M 规模的共享语料，配上折扣终端正确性和 HL-Gauss 这套稳住训练的标签工艺。这三样合在一起，构成了一个可交付的部署形态，而不是一个新算法。值不值得细读？我觉得做 agent 推理时引导、端侧部署或者 test-time scaling 的人值得，尤其是数据构造和消融那两节；想找机制层面突破的人可能会失望。

## 🔧 工程上能拿走什么

如果你手上有类似的项目，这几条我会先试：

**把策略和价值与世界模型拆开部署**。 换 backbone 不用重训配套组件，这个收益在需要同时维护多个 agent 规格的团队里会被放大。共享 checkpoint 的做法比「每个模型配一套 critic」省太多事。

**先算清楚你缺的是钱还是显存**。 如果工具调用便宜、本地显存紧张，BoN@4 反而可能更划算；如果调用按次收费且延迟敏感，Seer 这条路才成立。别照搬论文的结论，先填自己的 $\mathbf{B}$。

**别急着上 9B 的裁判**。 更现实的路径是把模拟器和估计器蒸馏或量化到 1 到 3B，再测一遍复用性是否还在。论文没做这个消融，但端侧落地绕不开。

**只在关键决策点开想象搜索**。 既然 depth-one 就够、$k$ 大了还会掉点，那就别每一轮都铺 32 个候选。第一次搜索、或者从「搜」切到「读」的那一步，价值密度最高，值得多花几次前向；后面顺着证据链推进时收窄到 $k=4$。Table 5 的数据支持按任务挑宽度，不支持一路拉满。

**数据构造那套可以单独复用**。 Monte Carlo 分支展开真实轨迹、不按答案对错过滤调用/响应对、用剩余交互轮数（不是 token）做折扣、把 0/1 正确性摊成高斯软标签——这一整套工艺跟 Seer 的框架是解耦的，拿去训任何过程奖励模型都合适。

**给候选宽度配一个监控**。 Table 6 的 oracle 一致率是个很实用的在线指标：如果估计器在宽候选下开始跟「事后看最优」严重脱节，就该主动收窄，而不是继续堆算力。

## 📝 收尾

回到开头那个查 NBA 分差的小模型。Seer 给它的不是更强的脑子，是两个不归它管、也不会被它带偏的裁判：一个想象搜索结果，一个判断这条历史有没有戏。只执行被选中的那一次调用，剩下的全部留在想象里。这个思路我是真的觉得漂亮，尤其「证据链只用真实响应」那一刀切得利落。

但还有一个更根本的问题没解决：当设备连 4B 都跑得吃力，你往哪儿再塞两座 9B？论文把「共享」这件事做到了极致，却把「共享的代价」留给了读者自己算。也许下一步该问的不是「裁判能不能更强」，而是「裁判能不能小到和选手一起住进同一块内存」。那才是端侧深度研究真正要过的坎。
