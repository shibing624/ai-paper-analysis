# 视频还没渲染，怎么给搜索的每一步打分？Loupe 把评分表前移成步骤级过程奖励

你有没有碰到过这种憋屈事：让视频模型画「基督城那座纸板教堂」，出来的画面光影漂亮、镜头高级，可仔细一数，纸板管的数量是错的，管径标注也是编的。再让它画「2023–24 赛季 Hart 纪念奖得主捧杯、对手队名要写对」，模型给你一个金灿灿的奖杯，球员球衣上的字全是糊的，队名纯属幻觉。

问题不在渲染，在知识。这些请求要的是某个具体实体、某个确切数字、某个事件顺序，而用户给的 prompt 里往往把这些关键信息全省了。你把解码器调得再好、把运动一致性做得再稳，模型也变不出它压根不知道的事实。

上周读到这篇叫 Loupe 的论文（arXiv:2611.31895），我的第一反应是：这题我熟，之前做检索增强生成的时候被同类问题折磨过——给智能体装了搜索工具，可怎么教它「什么时候该搜、搜到什么算够」一直是个玄学。更头疼的是，训练这种多轮智能体，奖励信号要么贵得离谱，要么粗得没法用。这篇论文给了一个我觉得挺漂亮的思路：既然最终视频太贵、轨迹级奖励太糊，那就干脆把「评分表」前移，在视频渲染之前，直接给每一次搜索和规划打分。

---

## 🎯 核心摘要

一句话讲清楚：Loupe 提出 Rubric-Based Credit（RBC），从用户请求本身派生出「这条视频必须验证哪些事实、哪些外观、哪些时间关系」的评分表，让一个过程裁判在**视频还没生成之前**就对每个中间决策打分，把昂贵的视频级终局反馈 + 粗粒度轨迹级信用，拆成可计算的步骤级过程奖励。往下衍生出 RBC-SFT（按步骤质量重加权 assistant token）和 RBC-GRPO（步骤级信用叠加最终规划奖励，RL 全程不渲染视频）。配上自建的 Search-VBench，MiniMax-H3 总分从 32.80 拉到 70.67，完整 RBC 训练比「标准 SFT 接轨迹级 GRPO」高 5.27 分。

说到底，这不是底层算法的突破，是一次相当聪明的工程整合——把过程监督（process supervision）那套思路，搬到了一个连标准答案都没有的领域里。值得细读，但里面的数字得带着点怀疑看，后面我会讲为什么。

## 🤔 为什么非得另起炉灶：三个卡在一起的问题

先别急着看方法，把动机捋清楚，后面所有的设计才说得通。

给视频智能体装上搜索工具，思路很自然：缺什么知识就去查什么，查到证据再写进 prompt。论文里 Loupe 用的就是这套 ReAct 循环，配三个工具——Text Search 查事实、实体关系、科学机制和流程步骤，Image Search 找实体和场景的视觉参考，Browse Page 打开检索到的页面去核实细节或消歧。同一个智能体自己决定搜什么词、怎么读工具返回的结果、怎么一轮一轮改计划，末尾吐出一个带时间结构的 video prompt 和一组参考图，交给下游生成器渲染成片。

麻烦从「怎么训练」开始，而且三个坑是叠在一起的。

第一个坑，SFT 一视同仁。标准监督微调把一条轨迹里所有 assistant token 当成同等重要的样本去模仿，可教师轨迹本身是脏的：这一步检索精准到位，下一步可能就是重复搜一个早就查到的数字。论文 Figure 4 专门画了这个现象——RBC 分数在轨迹的每一个位置上都有高有低，也就是说「好决策」和「坏决策」在任何步数都可能冒出来。你整条照抄，就把那些冗余搜索一起学进去了；你要不放心把整条丢掉，又浪费了里面真正值钱的取证行为。

第二个坑，视频级终局反馈太贵、太脏。用最终视频质量做 RL 奖励，成本是一回事，更要命的是它把「智能体的决策」和「生成器的渲染能力」死死缠在一起。视频烂，可能是智能体没查到关键事实，也可能只是生成器今天手抖把字画糊了。这个信号没法干净地归到某一步决策头上。

第三个坑，轨迹级信用太粗。就算你绕开渲染，只给整条轨迹一个 outcome 分，一个 10 轮的交互也只拿到 1 个奖励数字。哪一轮是关键的、哪一轮是废的，模型根本分不出来。说到这个，做过 GRPO 的都懂：结果奖励稀疏得像期末只告诉你总分、不告诉你哪道题错了，你知道考砸了，却不知道该复习哪章。

而且这里还有个更隐蔽的死结。近两年过程监督的经典做法——比如 ABSeeker 从已知正确答案往回回溯出「监督线索」，SRaR 从答案验证过的对错推理轨迹里提炼 rubric——都默认你手里**有标准答案**。可知识密集型视频生成压根没有：用户要「一条 2010 年代末某欧洲化学周刊封面报道过的、水做唯一溶剂的过渡金属催化 domino 反应」，你上哪去找标注好的事实答案或目标视频？没有答案，那些从答案回溯的过程监督就全断了。

这篇论文最值钱的地方，恰恰是绕开这个死结的那一步。作者的观察特别朴素：一个请求哪怕没给答案，它也**规定了必须验证什么**。「得认出这个实体」「得搞清楚事实细节」「得把外观坐实」「事件顺序不能乱」——这些是评价准则（criteria），不是事实答案（answers）。答案得靠外部证据去找，但准则，从请求本身就能抠出来。

这就是 Loupe 的立足点：把「评分表」从事后、从视频级，前移到事前、到每一个中间步骤上。

![图1：Loupe 帮助多个视频主干模型应对知识密集型生成](https://arxiv.org/html/2611.31895v1/teaser.png)

*图1（论文 Figure 1）：上半部分对比直接生成与 Loupe 的多跳搜索——直接生成遇到知识缺口容易编造实体和外观，Loupe 靠检索拿到特定实体外观和长尾事实；下半部分是 Search-VBench、Sci-VBench、KIVI-Bench 上的分数柱状图，深色段是 Loupe 带来的增益。注意那个 2028 Tesla Roadster「会飞」的例子，就是典型的 prompt 里埋了陷阱、模型照单全收的幻觉。*

## 🏗️ 方法核心：把评分表搬进训练回路

![图2：Loupe 整体框架](https://arxiv.org/html/2611.31895v1/overview.png)

*图2（论文 Figure 2）：(A) 推理——同一个智能体走 ReAct，认知识缺口 → 迭代检索文本/视觉证据 → 时间规划（Context/Action/Ending）→ 输出带证据的 video prompt 和参考图；(B) 训练数据构造——从 prompt 池生成「prompt 专属 rubric」并采集教师轨迹；(C) RBC 打分——裁判对每个 assistant turn 给分；(D) 信用感知学习——RBC-SFT 加权 token loss、RBC-GRPO 步骤级 GRPO。右上角那句 One Agent across all four stages 值得留意，全流程复用同一个 8B 模型。*

框架图里的四个阶段（A→D）其实是一条因果链，我按自己的理解把它讲成一句人话：**先让模型学会「搜得对」，再让它在不渲染视频的前提下，用打分表把「哪一步搜得好」量化成奖励。**

### 3.1 评分表长什么样：只有准则，没有答案

对每个请求 $x$，RBC 构造一张 rubric $q$，两个字段：

- **reference requirements（参考要求）**：这条视频必须满足的实体、事实、视觉属性、时间关系。
- **grounding type（知识类型）**：对应的知识需求是什么，比如实体发现、科学机制、流程顺序、多跳关系。

关键的一句作者写得很明白：**没有任何 rubric 里预置答案**，它们只规定「评估搜索进展时该检查哪些方面」。论文附录 Table S2 列了 13 种 grounding type，从「文本/数字标签」「实体外观」到「科学机制」「因果效应」「时序」，基本把知识密集型视频会踩的坑分了类。

### 3.2 打分：一个「中性起点 + 行为加减」的裁判

有了 rubric，一个过程裁判（论文用 GLM-5.3-Flash）对每个 assistant 轮次 $a_t$ 打分，输入是 $(x, q, h_t, a_t)$——请求、评分表、到这轮为止的交互历史、这轮的动作。有个细节挺讲究：当前轮的工具返回值不喂给裁判，留到下一轮再用来判断「证据有没有被用上」，这样防止裁判用结果倒推动作。

分数公式干净得有点可爱，从 1 这个中性值起步，按命中的行为条目加减 $\Delta$，再 clip 到 $[0,2]$：

$$r_{t}=\operatorname{clip}\left(1+\sum_{j\in\mathcal{A}_{t}}\Delta_{j},\,0,\,2\right)$$

$\mathcal{A}_t$ 是这轮命中的评分条目集合，$\Delta_j$ 是每条的调整量。具体加减表（论文 Table 1）：

| 行为 | 调整量 $\Delta$ |
|------|--------------|
| 聚焦的文本搜索 / 推理 | $[+0.2, +0.4]$ |
| 定向图片搜索 | $[+0.2, +0.4]$ |
| 浏览核实事实 / 消歧 | $[+0.2, +0.4]$ |
| 正确的证据综合 | $[+0.3, +0.6]$ |
| 完整、有据的最终答案 | $[+0.3, +0.7]$ |
| 模糊或无关的tool use | $[-0.5, -0.2]$ |
| 无依据事实 / 自相矛盾 | $[-0.9, -0.4]$ |
| 漏要求 / 引用无效 | $[-0.9, -0.4]$ |
| 有害、欺骗、不可用输出 | $\leq -1.0$ |

这里我停一下说两句。第一，一次搜索调用**本身不等于取证成功**，但只要 query 合理，不会因为工具恰好没返回有用结果就被扣分——这个设计挺照顾真实检索的随机性，我之前做类似的东西时吃过「因为检索空结果误罚好 query」的亏。第二，最终计划那轮，「文笔流畅」不能拿来抵「事实无依据或漏要求」。这两条其实都是冲着 reward hacking 去的，能看出作者踩过坑。

![图3：RBC 打分的一个完整例子](https://arxiv.org/html/2611.31895v1/score_details.png)

*图3（论文 Figure 3）：左边把一句「2010 年代末欧洲化学周刊封面的、水相 domino 反应」拆成 3 条带优先级的参考要求（R1 认论文身份、R2 催化体系与 domino 序列、R3 杂环产物类别），配 6 类 grounding type；右边是裁判给各轮打分：S1 定向搜 EurJOC/domino/水 得 1.30，S5 重复一个畸形失败的期刊归档浏览得 0.50，S9 查到具体 DOI 把论文与机制和产物需求连起来得 1.60，S12 补图片搜结构式得 1.25，最终 S13 交出 5 阶段、机制与外观都齐的计划得 1.65。一张图把「好步骤涨分、重复/无进展步骤掉分」讲透了。*

### 3.3 RBC-SFT：不丢轨迹，改权重

SFT 这边的处理很务实：整条轨迹留着，但把监督强度按步骤质量重新分配。先把每条轨迹内的步骤信用归一化成 $w_t$，再算加权 assistant-token loss：

$$\mathcal{L}_{\mathrm{SFT}}(\theta)=-\frac{\sum_{t=1}^{T}w_{t}\sum_{j=1}^{n_{t}}\log\pi_{\theta}(a_{t,j}\mid h_{t},a_{t,\lt j})}{\sum_{t=1}^{T}n_{t}w_{t}},\qquad w_{t}=\frac{r_{t}}{\sum_{s=1}^{T}r_{s}}$$

$n_t$ 是第 $t$ 轮被监督的 assistant token 数；工具返回值永远只当上下文，既不进监督也不进归一化。同一轮里所有 token 共享一个权重，高信用轮次的每个 token 因此更有话语权。当所有信用相等且为正时，这个式子就退化成普通 SFT loss。

其实吧，它没发明新的损失函数，只是在 SFT 的 token 上加了一个从裁判那儿来的权重。工程上便宜到几乎不增加成本，消融里也确实换来了 62.00 → 64.47 的 **2.47 个点**。等等，这个 loss 真能稳住吗？后面消融会告诉我们，它确实 work，而且和 RL 是叠加的。

### 3.4 RBC-GRPO：按「轮次位置」做相对比较，全程不渲染

RL 从 RBC-SFT 的 checkpoint 起步。每个 prompt 采一组 rollout，同一个 RBC 裁判给每个 assistant 轮打过程分 $r_{g,t}$（范围 $[0,2]$）。但光有过程分不够——有用的搜索、够用的证据，仍可能写砸计划——所以另有一个 outcome 裁判单独评最终的 video prompt 和参考图，打 $o_g$（范围 $[0,1]$，输出乘 2 对齐两个量纲）。

到收尾那轮把两者混合，中间轮只留过程分：

$$R_{g,t}=\begin{cases}r_{g,t}, & t \lt T_{g}\\ \lambda r_{g,T_{g}}+(1-\lambda)o_{g}, & t=T_{g}\end{cases}$$

$\lambda$ 默认 0.3。接着是这套方法里我觉得最巧的一处：**按「同一个 prompt、同一个 assistant 轮次位置」跨 rollout 做归一化**，算相对优势：

$$A_{g,t}=\frac{R_{g,t}-\mu_{t}}{\sigma_{t}+\epsilon}$$

$\mu_t,\sigma_t$ 是位置 $t$ 上所有 rollout 的 $R_{g,t}$ 的均值和标准差。作者特意澄清：这不假设不同轨迹在第 $t$ 轮做的是同一语义的动作，只是把「交互了相同轮数之后、面对同一个请求」的决策放到一把尺子上比。于是「继续再搜一轮」和「就此收工交计划」这两个异质动作，就能作为「还需不需要更多证据」的两个候选被直接比较。某个位置上只剩 1 条 rollout 时优势置零（实测这类轮次不到 1%）。

还有个反直觉但被消融证实的取舍：作者**故意用即时 RBC 奖励，不做回报回传**。理由说得通——把下游的终局奖励往回传，会把「一次有用的搜索」和「后面规划写砸了」搅在一起，或者反过来把「恰好排在成功之前的冗余动作」也给奖励了。附录那个 discounted return（$\gamma=0.9$）的变体只有 67.60，比默认的即时版 70.67 低了 3 个点，算是给这个判断盖了章。

最关键的卖点藏在一句轻描淡写的话里：**过程分和结果分都不需要生成视频**。整个 RL 阶段，一个像素都不渲染，奖励里因此不会被生成器的随机性污染，也省掉了天量的采样成本。这一条是双刃剑，先记着，批判那节要还回来。

## 🧪 Search-VBench：给「会搜」这件事专门造把尺子

以前没有专门考「检索能力」的知识密集视频基准，作者就自己造了一个。

![图5：Search-VBench 概览](https://arxiv.org/html/2611.31895v1/benchmark.png)

*图5（论文 Figure 5）：150 个留出 prompt、7 个类别，配 339 张评估参考图和 566 条评估 rubric。七类分别是长尾实体运动、多跳实体发现、知识动态可视化、最新事件新闻、时间事件锚定、文化仪式与运动动作、流程 how-to；难度分布 Medium 56（37.3%）、Hard 79（52.7%）、Expert 15（10%）。底部给出四个评分维度和加权公式 Overall = 0.2F + 0.4V + 0.2A + 0.2T。*

四个维度：Faithfulness（内容保真）、Visual Correctness（依赖知识的视觉正确性）、Temporal Dynamics（动作与事件顺序）、Aesthetics（画质）。用 Gemini 3.1 Pro 打分，每维三档 $\{0, 0.5, 1\}$，每条视频独立评三次取平均，再缩放到 $[0,100]$。

请把那个加权公式再盯一眼：$\mathrm{Overall}=0.2F+0.4V+0.2T+0.2A$。**Visual Correctness 独占 0.4，是其它三项的两倍。** 而且按 4.1 节的说明，没有有效参考图时 V 会被省略、其余权重重新归一——你想想看，V 是唯一跟「参考图」强绑定的维度。这个设定，等下看主表涨幅的时候会变得非常要紧。

训练配置也一并交代（附录 Table S3）：主干 Qwen3-VL-8B-Instruct，16K 条教师轨迹做 SFT、2K 个与 SFT 不相交的 prompt 做 RL，过程/结果裁判都是 GLM-5.3-Flash，AdamW，SFT/RL 学习率 $10^{-5}$ / $10^{-6}$，batch 16，每个 prompt 6 条 rollout，最多 10 轮交互、每轮最多返 5 张图，16 张 A100、BF16，种子 42。全流程约 135 小时（5.6 天），其中 RBC 打分的额外开销只有 13 小时（9.6%）。

| Loupe + Seedance 2.0 | 80.33 | 61.33 | 74.33 | 70.67 | 69.60 |

MiniMax-H3 从 32.80 到 70.67，涨了 37.87；Wan 3.0 涨 34.20；Seedance 2.0 涨 20.67。 gemini 3.1 Pro 当教师参照拿到 72.13，一个 8B 智能体做到 70.67，追得很近。

我的第一反应是先把涨幅拆开看：**Visual Correctness 从 8.00 蹦到 63.33，涨了 55.33**，三个主干分别涨 55.33 / 52.66 / 41.33，是四个维度里最猛的。可 Overall 里 V 的权重恰好是 0.4——光这一项就贡献了约 $0.4\times55\approx22$ 分，占了 37.87 总涨幅的近六成。这个 benchmark 的打分公式，跟 Loupe「检索参考图 + 图生视频」的强项，对齐得有点太严丝合缝了。我不是说这数造假，而是说：**换一套把 V 权重压到 0.2 的评分，这条翻倍叙事会缩水不少。** 看到这个数我愣了一下，然后去翻了权重，果然。

还有个对照挺说明问题：Workflow（同一套搜索壳，但不训练）拿到 49.40，Loupe 70.67，差 21.27；Prompt Rewriting 只有 35.40，差 35.27。这两个 baseline 是作者自己拿 Qwen3-VL-8B 搭的，选得有点巧妙——它们干净地证明了「训练有用、不只是搜索有用」，但也都是偏弱的对手。真正最接近的 learned 竞品 VideoGen-Agent，论文里一句「闭源实现，无法直接比较」就带过了。坦率地讲，这块对比我是有点不满足的。

### 外部基准与人类评估

跨基准的迁移也做了。Sci-VBench（Table 3，5 分制）上，MiniMax-H3 的 SCC（科学与因果正确性）从 1.75 涨到 2.97，涨了 1.22，Avg 从 2.74 到 3.37；Loupe + Seedance 2.0 拿到 Avg 3.67，压过了 Veo-3.1（3.14）和 Gemini-Omni-Flash（3.39）。KIVI-Bench（Table 4）上，FactP 从 74.1 到 83.1、HelpS 从 50.9 到 63.5，涨 12.6，而人类参照上限分别是 97.8 和 81.9——离人还有距离，但方向对。

人类评估（附录 Table S5） pooled Overall 偏好率 82.33%，分主干 89.00（MM-H3）/ 85.00（Wan 3.0）/ 73.00（Seedance 2.0），每个主干 500 次选择、合计 1500 次。裁判可靠性也核了：1K 条轨迹让裁判独立打三次，自洽率 93.6%；100 个步骤、5 位标注员的 judge–human agreement 达到 91.8%。Gemini 与人类多数偏好的一致率 87.67%。这些旁证做得算扎实，把「LLM 裁判自说自话」的质疑往前挡了一层。

### 消融：5.27 分到底从哪来

这张 Table 5 是全文信息密度最高的地方，也是「RBC 到底有没有用」的正面回答：

| 训练配置 | Overall |
|---------|---------|
| Base | 32.80 |
| Vanilla SFT | 62.00 |
| Vanilla SFT + Traj-GRPO | 65.40 |
| Vanilla SFT + RBC-GRPO（λ=0.3） | 67.13 |
| RBC-SFT | 64.47 |
| RBC-SFT + Traj-GRPO | 66.13 |
| RBC-SFT + RBC-GRPO（discounted return γ=0.9） | 67.60 |
| RBC-SFT + RBC-GRPO（group normalization） | 67.93 |
| RBC-SFT + RBC-GRPO（λ=0.7） | 68.53 |
| RBC-SFT + RBC-GRPO（λ=1.0） | 68.87 |
| **RBC-SFT + RBC-GRPO（λ=0.3，完整系统）** | **70.67** |

三层结论，作者自己拆得很清楚：示范加权（RBC-SFT 比 Vanilla SFT +2.47）、步骤级信用（RBC-GRPO 在两种初始化下分别比 Traj-GRPO 高 1.73 和 4.54）、完整系统（70.67 对 65.40，**高 5.27**）。看到 Table 5 我才意识到两个 RBC 组件是叠加而非替代的，λ=0.3 这个混合系数是关键：λ 一路调到 0.7、1.0，分数反而掉到 68 出头，说明「别太信过程分、给最终规划奖励留 0.7 的话语权」这一步调得挺细。

Table 6 的 rubric 消融则回答了「随便一张评分表行不行」：No Rubric 65.27、Fixed Rubric（所有 prompt 共用一张通用表）66.93、Prompt-Specific Rubric 70.67。定制表比通用表高 3.74，比没表高 5.40。这链条算是把「从请求派生准则」这个核心洞察的贡献单独钉死了，我觉得是全文最漂亮的一组实验。

## 💡 我的判断：聪明的工程整合，但别被 70.67 晃了眼

把情绪收一收，说几句实在的。

**真正值钱的，是那个「准则 ≠ 答案」的转念。** 过程监督卡在知识密集视频上，卡了好几年，症结就是没标准答案没法做回溯。ABSeeker、SRaR 那一脉都得先有答案或答案验证过的轨迹；Loupe 直接承认「答案不给，准则自带」，于是过程监督第一次能落到一个连 ground truth 都没有的场景里。这不是新算法，是把旧思路换了个锚点，但换得确实漂亮。RBC-SFT 的加权 loss、RBC-GRPO 的同位置归一化，都是「便宜、讲得通、消融也认」的务实设计，没有为了花哨而花哨。

**但「RL 全程不渲染视频」这个卖点，得翻过来看。** 省成本、去噪声，都是真的；可代价是奖励从头到尾优化的是一个 proxy——搜索与规划文本的质量——和最终视频像素之间**没有任何反馈闭环**。论文自己在 Limitations 里也认了：「well-grounded plans 不保证下游生成器忠实渲染」。那么问题来了：proxy 和真目标之间的 gap 有多大？论文没量。一个把计划写得满分、却被生成器画糊的作品，在这套训练里是拿不到惩罚的。说实话这块我也不是特别确定该不该算硬伤，但它至少说明 70.67 衡量的是「喂给生成器的输入有多好」，不是「视频本身有多好」——这两者被标题里的「Video Generation」悄悄划了等号。

**评分基准和方法的对齐度偏高。** 前面算过，V 权重 0.4 且只有它绑参考图，涨幅近六成来自这一项。再加上评测用 Gemini 3.1 Pro、教师轨迹也用 Gemini 3.1 Pro 采集、RL 奖励用 GLM 系裁判、过程分来自一张人为设定 $\Delta$ 区间的行为表，整条链路里 LLM judge 的影子很重。做了 91.8% 的 judge–human agreement 和 300 对视频的人类偏好是加分项，但样本规模说不上大。更要紧的是，那张行为加减表（Table 1）是 hand-crafted 的：$\Delta$ 给到 $[0.2,0.4]$ 还是 $[0.3,0.6]$，全凭作者定，模型理论上完全可能学会「表演」出 focused search / correct synthesis 的样子去哄裁判。论文没讨论这类 reward hacking，是个缺口。

**收益上限明显受基座钳制。** Seedance 2.0 本身 48.93 已经不弱，加 Loupe 只涨 20.67，Temporal Dynamics 只涨 5.00、Aesthetics 只涨 1.00，几乎顶到天花板。这符合直觉：越强的生成器、越接近满分的维度，检索能补的越少。所以「32.80 → 70.67、分数翻倍」的漂亮叙事，主要发生在一个较弱的基座上，迁移到强模型时得把预期调低。

**复现门槛不低。** 16 张 A100、5.6 天、135 小时全流程，还要 Gemini 3.1 Pro 造数据和教师轨迹、GLM-5.3-Flash 逐步打分。RBC 打分只占 9.6% 听着很省，可那是在已经铺好一整套采集管线之后算的边际成本。

放到同期工作里看，它处在一个清晰的位置：GenArtist、GEMS 是纯手工工作流的图像生成；Gen-Searcher 把检索增强做到图文反馈；VideoGen-Agent 学工具协同但奖励里掺了生成视频质量、且闭源；ABSeeker / SRaR 做过程监督但离不开答案。Loupe 的差异点，是「视频 + 无答案 + 渲染前监督」这个交集，加上把过程监督 SFT/RL 两头都打通。是微创新加工程整合，不是底层突破——但这不丢人，这类「把成熟零件重新组合到一个卡住的场景」的工作，往往才是真正推动落地的那批。

## 🔧 写在收尾：如果你也在做类似的事

几个我觉得可以直接搬走的启发：

- 当你被「终局反馈太贵」卡住时，先别急着换 RL 算法，问一句：**这个任务的评价准则，能不能从输入本身派生出来？** Loupe 的全部机巧都压在这一问上。数学、代码有可验证答案，可一旦任务没有 ground truth，「准则化」几乎是过程监督唯一能走的路。
- 脏教师轨迹别整条丢，也别整条照抄。按步骤质量重加权是个几乎零成本的中间选项，RBC-SFT 那 2.47 分就是这么来的。
- 多轮 agent 做 GRPO，归一化分组不一定非得按语义对齐动作，**按轮次位置对齐「交互进度」**也成立，还能顺带把「继续搜」和「收工」放一起比。
- 密集过程奖励别想当然地做 return 回传。消融里 discounted return 反而更差，这个反直觉结论值得记下来。

还有一个更根本的问题没解决，也是我自己还在摸索的：当评审者本身是个 LLM、评分准则是人写的，我们到底在优化「把事做对」，还是在优化「让裁判觉得做对了」？Loupe 用 human agreement 挡了一层，但挡不住根上的追问。这类「评分表前移」的方法大概率会成为知识密集 agent 训练的标配，可评分表谁来校准、怎么防止被 co-design 出来刷分，恐怕是下一批论文要还的债。

如果你也在做检索增强的智能体、被信用分配折腾得够呛，这篇的思路真值得试试——但记得先把你 benchmark 的权重公式摊开看一眼，别让一个维度替你把涨幅撑起来。
