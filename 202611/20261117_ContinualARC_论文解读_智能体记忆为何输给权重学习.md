# 会写笔记不等于会学习：Continual-ARC 把智能体的记忆与权重放上同一张考卷

一个智能体今天解出一道难题，兴奋地把经验写进 `memory.md`。三天后，同类问题换了个输入再次到来，它是真的掌握了规则，还是只会重新翻笔记、重新试错、重新付一遍学费？

更扎心的是，就算它存了几百条经验，我们也很难回答：这些文字究竟带来了多少能力提升？

arXiv:2611.14505 提出的 **Continual-ARC**，就是冲着这个含糊地带去的。它不再只问 Agent“这次能不能做对”，而是把任务放进一条会持续回归的工作流：同一规则隔一段时间换个新输入回来，新规则又不断插入；看示例、答错都要花钱。工作流结束后，再分别考旧任务的新实例和从未见过的新任务。

结果挺打脸。现成 Agent harness 的持久化记忆，大多连“把买过的示例缓存起来”这种朴素基线都打不过；明确教它保存、验证并复用 Python 程序后，旧任务表现立刻好转，但新任务依然几乎不涨。真正带来可测泛化的是权重学习：Qwen3.5-9B 用 DAgger 模仿 GLM-5.3 Flash，在单用户设置下把 held-out 解题率从 **19.2% 提升至 49.0% 的水平**。

我的判断是：这篇论文最有价值的不是又造了一个 ARC 榜单，而是把“记住了旧技能”和“长出了新能力”拆成两个可独立测量的轴。它给 Agent 记忆泼了一盆冷水，却没有证明记忆无用；它真正暴露的是，很多系统连**该存什么、何时取回、怎样验证**都没想清楚。

## 核心摘要

Continual-ARC 用三代 ARC-AGI 构建终身任务流，让同一规则带着全新输入反复出现，并为示例和错误尝试计费，从而让笔记、程序库、提示词与权重更新接受同一套反馈预算考核。默认 harness 的持久化收益通常接近零，甚至落后于简单的示例缓存；加入专家指导后，GLM-5.3 Flash 在旧任务上的预算节省率达到 **74% 的水平**，但新任务仍没有可靠提升。DAgger 则在旧任务和新任务上分别节省 57% 与 29% 的 reset 预算。它是扎实的测量协议与实验研究，不是“权重必然战胜记忆”的终局证明；主实验集中在 ARC-AGI-1、少量模型和较短任务流，训练成本也不计入反馈分数。

## ARC 少考了什么：一次学会，不等于以后还会

ARC 题通常给几组输入、输出网格，让系统归纳变换规则，再处理一个新输入。它不太依赖百科知识，重点考查物体性、计数、空间关系等核心先验如何组合成新技能。

传统 ARC 的计分停在“这一回是否答对”。一个测试时训练方法可以在每道题上临时调整权重，交卷后把适配器扔掉；一个 Agent 也可以现场试错，下次遇到同规则时从零开始。单次分数看不出两者的差别。

真实工作却不是这样。你今天学会处理某类工单，下周相似工单再出现，理想状态当然是少问用户、少犯错、直接完成。这里其实有两件不同的事：

| 能力 | 论文中的对应测试 | 要排除的假阳性 |
|---|---|---|
| 记住旧规则 | seen test：流中出现过的任务，换全新输入 | 不能只缓存旧答案，否则新网格马上露馅 |
| 从经历中泛化 | held-out test：任务流从未出现过的 100 个任务 | 不能只复用某道题的程序或示例 |
| 基础解题能力 | reset 对照：每个实例前清空状态 | 不能把模型本来就强的部分算成“学习” |

Continual-ARC 的设计漂亮之处，在于把这三者放到同一个协议里，而不是给每种学习器各写一套对自己有利的评测。

## 一条会“回头”的任务流

ARC-AGI-1 主轨道从 400 个公开训练任务中抽取 25 个，用 Re-ARC 生成器提供 200 个全新且经过验证的实例。每个任务总共出现 8 次；同一时刻约有 4 个任务活跃，活跃期平均约 3 个实例，休眠期平均约 30 个实例，新任务平均约每 4 个实例到来一次。末个新任务在第 97 轮进入。

![图2：Continual-ARC 的 ARC-AGI-1 任务流](https://arxiv.org/html/2611.14505v3/modes.png)

*图 2：横轴是实例顺序，纵轴按首次出现顺序排列 25 个任务。彩色细线表示任务处于活跃期，离散标记是实际到访；线断开的地方就是休眠。可以看到前期新任务密集进入，后期主要是旧任务带着新输入回归。所有系统使用 seed 0 的同一任务、同一顺序和同一实例。*

每次回归都换输入，所以“记住上次的输出网格”没有用处。系统真正值得保留的是规则、经过验证的程序，或者已经内化规则的参数。

任务 id 也会以匿名别名暴露给学习者。这个细节不能省：同一个输入网格可能合法地对应多条 ARC 规则，仅靠输入本身无法判断当前该执行哪一种。给 id 不是泄题，而是让跨实例索引成为可能。

## 反馈不是免费的：看示例和答错都计费

单个实例里，学习者看到任务 id、一个新输入网格，以及当前已经消耗的尝试和示例次数。它可以在 Agent harness 内行动，也可以直接提交答案或购买一条新的输入—输出示例。

![图1：单实例交互与计费协议](https://www.mulanai.com/fs/files/1117_60324540_protocol.jpg)

*图 1：环境提供任务 id 与新输入。提交错误答案花费 1，购买示例也花费 1；正确答案结束实例。学习器可以在实例之间保留状态。每个实例最多 8 次错误提交、8 次付费示例，未解出直接扣完 16 点预算。*

形式化地，单实例费用和一组实例的平均预算使用率为：

$$
c_i=\begin{cases}
w_i+d_i, & s_i=1\\
16, & s_i=0
\end{cases},\qquad
U(\mathcal I)=\frac{1}{|\mathcal I|}\sum_{i\in\mathcal I}100\frac{c_i}{16}
$$

其中 $w_i$ 是错误提交次数，$d_i$ 是购买的示例数，$s_i$ 表示是否解出。$U$ 越低越好，论文同时报告解题率 $P$，因为“少花钱”和“真的解出来”不能互相替代。

失败一律扣 16 点，是在堵住一个明显漏洞：如果放弃只按已消耗量计费，系统可能通过摆烂省钱。这里的钱不是 GPU 账单，而是**监督反馈预算**。计算量、token 和记忆大小会记录，但不进入 $U$。

## 两项冻结测试：记忆与泛化不再混为一谈

任务流结束后，学习者被冻结，接受两个各含 100 个实例的测试：

- seen test 给 25 个旧任务各 4 个新实例，测记忆；
- held-out test 给 100 个从未进入任务流的 ARC-AGI-1 evaluation 任务各 1 个实例，测泛化；
- 每个测试实例都从任务流结束时的同一份状态出发，测试内部不能互相学习。

只看学习器的绝对预算仍不公平：强模型本来就花得少。于是论文加入 reset——同一个模型、同一个 harness、同一批实例，但每个实例前清空可携带状态。测试上的相对节省率为：

$$
S=\frac{U_0-U}{U_0}
$$

$U_0$ 是 reset 的预算，$U$ 是保留学习状态后的预算。$S=0$ 表示没有学到可用东西，$S=0.5$ 表示省掉 reset 一半的反馈支出，负值则代表越学越差。seen 上记作 $S_{\mathrm{seen}}$，held-out 上记作 $S_{\mathrm{held}}$。

任务流内部还有 $L=(U_0-U)/(U_0-U^*)$，其中 $U^*$ 是“首次遇到按 reset 付费、之后回归零费用”的完美记忆上界。它回答的是：在理论上可省的那部分预算里，系统实际学到了多少。

这个归一化很聪明，但也不能只看百分比。reset 从 2% 降到 1%，同样节省了 50%，绝对收益却只有 1 个预算点。所以读结果时必须同时看 $U$ 和解题率，不能拿一个相对比例就宣布胜利。

## 参赛学习器：从缓存示例到更新权重

论文没有只拿几个花哨 Agent 互相比，而是放了几级很有诊断价值的参照。

| 类别 | 缩写 | 状态如何保存 | 它负责检验什么 |
|---|---|---|---|
| 无状态提示 | $C_0$ | 不保留 | 基础交互与模型能力 |
| 示例缓存 | C | 按任务保存买过的示例，回归时自动重放 | 只记住监督信息能值多少 |
| 程序库 | P | 生成 Python 规则，验证通过后按任务保存并优先执行 | 明确的程序归纳能做到什么 |
| 默认 harness | Q / G | prime-agent 自己决定写什么 | 现成持久化机制是否自觉有用 |
| 要求多存 | QA / GA 等 | 每次结果后尽量保存未来有用的信息 | 不写东西是不是提示词的问题 |
| 专家指导 | QE / GE 等 | 明确写程序、验证、按任务存储与复用 | 工具具备时，策略指导能否补齐能力 |
| 教师笔记 | QT / QTE / QETE | GLM 玩任务流并写状态，Qwen 读取 | 强教师能否通过文字把技能交给学生 |
| 权重学习 | QDE | DAgger 更新 Qwen 的 LoRA | 同一教师的轨迹进入权重后能否泛化 |

Q 表示 Qwen3.5-9B，G 表示 GLM-5.3 Flash。主实验使用 prime-agent，每个实例开启新对话，只有写入的状态能够跨实例携带。这样设计把“上下文还在”与“经验真的被保存”分开了。

DAgger 的关键不是普通离线蒸馏。学生在 prime-agent 中遇到真实状态，教师 GLM-5.3 Flash 对这些状态给出含推理过程的回复，学生再在自己的上下文上模仿教师动作。单用户实验积累了 **21,047 条教师回复、约 2,130 万个学生 token**；LoRA rank 和 alpha 都是 128，学习率为 $10^{-4}$，从基础模型玩完 24 局后开始逐轮训练。

## 主结果：默认记忆近乎没有学会，程序库却一直在赢

![图3：记忆与泛化平面上的主实验结果](https://arxiv.org/html/2611.14505v3/tests.png)

*图 3：颜色区分“学生自己写笔记”“教师写笔记”“教师直接操作”“教师训练权重”，菱形表示专家指导，空心点是 reset。左上看绝对解题率，左下看预算；右下是论文最核心的 $S_{\mathrm{seen}}$—$S_{\mathrm{held}}$ 平面，越靠右代表旧技能保留越好，越靠上代表新任务泛化越好。紫色 DAgger 明显向右上角移动，而多数笔记方法挤在原点附近。*

下表把论文 Table 1 的关键结果放在一起。数值是相对各自 reset 的节省比例，不是解题率；括号是 95% 区间。

| 方法 | $L$：流内学习比例 | $S_{\mathrm{seen}}$：记忆 | $S_{\mathrm{held}}$：泛化 |
|---|---:|---:|---:|
| Q：Qwen 默认 harness | -0.02 [-0.09, 0.04] | -0.01 [-0.04, 0.03] | -0.01 [-0.05, 0.03] |
| QC：Qwen 示例缓存 | 0.31 [0.19, 0.45] | 0.37 [0.26, 0.51] | -0.01 [-0.05, 0.03] |
| QP：Qwen 程序库 | 0.43 [0.25, 0.64] | 0.65 [0.46, 0.86] | 0.03 [-0.02, 0.09] |
| QETE：教师与学生均获专家指导 | 0.29 [0.19, 0.40] | 0.34 [0.26, 0.42] | -0.05 [-0.10, 0.00] |
| QDE：Qwen 权重学习 | 0.43 [0.33, 0.54] | 0.57 [0.48, 0.67] | 0.29 [0.23, 0.35] |
| G：GLM 默认 harness，单次主运行 | 0.12 [-0.16, 0.36] | 0.12 [-0.03, 0.27] | 0.00 [-0.11, 0.10] |
| GC：GLM 示例缓存 | 0.41 [0.29, 0.53] | 0.44 [0.34, 0.57] | -0.02 [-0.11, 0.06] |
| GP：GLM 程序库 | 0.68 [0.49, 0.87] | 0.81 [0.59, 1.00] | 0.05 [-0.06, 0.14] |
| GE：GLM 专家指导 | 0.62 [0.49, 0.75] | 0.74 [0.64, 0.84] | 0.07 [-0.02, 0.16] |

### 默认 harness 输给了最笨的缓存

Qwen 的默认持久化在两个测试上都约为零；GLM 的单次主运行区间也跨过零。把 GLM 的三次完整运行合并后，默认 harness 的 $S_{\mathrm{seen}}$ 为 0.25 [0.17, 0.33]，说明它不是绝对一点没存到，但仍明显低于自己的示例缓存与程序库。

示例缓存做的事非常朴素：买过的示例按任务放好，下次免费重放。它不会抽象规则，也不会解新任务，却可靠地省掉了重复购买示例的钱。Qwen 和 GLM 在 seen 上分别节省 37% 和 44%，held-out 则都接近零。这个“地板”设得很值——一个复杂记忆系统若连它都赢不了，谈论长期智能就有点悬。

### 不是存不下来，而是不知道该存什么

GLM 默认运行时其实为每个任务都留下了文字规则，但 prime-agent 每次只展示 6 条，并且在知道当前任务之前就完成选择。于是相关规则只在 **154 次回归中的 40 次**真正进入模型视野。

看到这段，我对“记忆无效”的结论就要踩一脚刹车。这里至少有写入策略、任务索引和检索时机三层问题，不是简单一句“模型没记住”能够概括的。

GPT-6 Luna 驱动三种 harness 时也出现了不同形态的失效：prime-agent 没把条目标成跨会话全局记忆；hermes-agent 每次都会加载技能，但内容多是通用建议；openclaw 没有完成记忆晋升，旧答案也未在回归时复现。三者还都没有保留买过的示例，平均每实例购买 2.3 到 3.9 对，而缓存基线只需 1.4 到 2.6 对。

### 专家指导一上，旧任务立刻改观

明确告诉系统“写 Python、用示例验证、按任务保存、回归时先运行”，GE 的 seen 节省率达到 74%，接近程序库 GP 的 81%。这证明工具链本来就能完成学习动作，缺口更多在默认提示与模型判断，而不是文件系统没有记忆能力。

Qwen 更弱一些。教师写笔记、学生单方面拿指导都不够；只有教师和学生都拿到专家指导的 QETE，才在 seen 上可靠节省 34%。可它在 held-out 上是 -0.05：即使教师带着指导解出任务流中 **98% 的实例**，留下的程序与笔记仍没让 Qwen 更会做新题。

![图4：不同方法随任务访问次数的变化](https://www.mulanai.com/fs/files/1117_21c5be1e_notes-we.jpg)

*图 4：左侧是 Qwen，右侧是 GLM；上排为解题率，下排为每个已解实例的预算，横轴是同一任务的第几次访问，阴影为任务重采样的 95% 区间。GLM 的程序库 GP 很快降到接近零成本，GE 也随回归持续下降，而默认 G 的下降有限。Qwen 侧曲线更嘈杂，DAgger 的预算整体向下，但默认笔记和教师笔记没有同样稳定的收益。*

在任务流第 100 轮以后，也就是所有任务都已露面时，GLM 默认 harness 每解一题仍花 13.6% 预算，reset 为 17.5%；GE 降到 4.6%，GP 只剩 1.4%。完美记忆在回归任务上应该是零。这个差距把“存了一些东西”和“形成可靠技能”分得很清楚。

## 真正的分水岭出现在新任务上

程序库非常适合旧任务，却天然不太会泛化：某个任务验证通过的变换程序，通常不适用于另一个任务。Qwen 和 GLM 的程序库在 held-out 上分别只节省 3% 和 5%，区间都跨过零。

但新任务并非完全没有可迁移结构。Re-ARC 的 400 条 ARC-AGI-1 训练规则共享一个包含 160 个原语函数的库。理论上，系统完全可以从经历中抽象出可组合的概念，再用于新规则。ArcMemo 等相关工作就在研究自然语言概念记忆的抽象与检索，不过它是单次固定遍历设置，不能直接替代当前协议下的证据。Continual-ARC 测到的现成笔记与程序方法，没有把这种潜在共享结构变成可靠收益。

DAgger 做到了。单用户 QDE 的绝对数字是：

| 指标 | reset | DAgger 学习器 | 变化 |
|---|---:|---:|---:|
| seen 预算 $U_{\mathrm{seen}}$ | 84.0 | 36.0 | 少 48.0 个预算点 |
| held-out 预算 $U_{\mathrm{held}}$ | 84.7 | 60.4 | 少 24.3 个预算点 |
| held-out 解题率 $P_{\mathrm{held}}$ | 19.2% | 49.0% | 提高 29.8 个点 |

这里不能只解释为“学会操作 harness”。未训练 Qwen 在 prime-agent 的 held-out 上只解出约 18/100，在无状态交互环里反而能解出 31/100，说明 harness 一开始确实妨碍了它。只给未训练学生教师的操作规则，解题数可升到每次测试 22 到 33；DAgger 则达到 47 到 52。多出来的部分表明，它还学到了 ARC 解题本身的一些东西。

多用户设置更有意思。2 个用户带来 50 个不重叠任务，4 个用户带来 100 个；DAgger 的 $S_{\mathrm{held}}$ 从单用户 0.29 升到两用户 **0.40**，四用户为 **0.39**。看起来两用户后进入平台期，不过作者追加实验发现，四用户的阶段式训练没有充分吃完数据：用最终标签重新做普通打乱训练，$S_{\mathrm{held}}$ 可到 0.46，$S_{\mathrm{seen}}$ 可到 0.59。

所以，用户数同时改变数据量与任务多样性，不能简单归因为“集体学习更好”。训练日程也在其中搅局。这个自我拆检挺加分。

## 换到强商业模型，结论并没有轻松翻转

![图5：GPT-6 Luna 驱动三种 Agent harness 的结果](https://arxiv.org/html/2611.14505v3/plane-luna.png)

*图 5：红色是 prime-agent，蓝色是 hermes-agent，绿色是 openclaw；方块表示被要求广泛存储，菱形表示专家指导。默认状态下，多数点围绕零收益波动；要求存储后只有 prime-agent 的 seen 改善较明确。专家指导把三种 harness 的 seen 节省率推到 0.62 至 0.72，但 held-out 仍没有一致的可测提升。*

在 GPT-6 Luna high effort 下，明确要求保存后，prime-agent 的 $S_{\mathrm{seen}}$ 为 0.42 [0.29, 0.55]；hermes-agent 为 0.18 [-0.01, 0.39]，openclaw 为 0.07 [-0.02, 0.17]，后两者仍与零相容。专家指导则让三种 harness 都获得约 62% 到 72% 的旧任务预算节省。

这组结果削弱了“只是小模型太笨”的解释，却仍不能覆盖所有强模型和所有领域。它支持的是更窄、更扎实的判断：**默认持久化策略不会因为底层模型变强就自动变成有效的学习算法。**

## 更难的两条轨道：有初步信号，还谈不上定论

ARC-AGI-2 与 ARC-AGI-3 也实现了同一类协议。ARC-AGI-2 从第二版新增任务中筛出 117 个有可靠生成器的任务，再抽 25 个进入任务流；ARC-AGI-3 把 25 个公开游戏的首层规则做成生成环境，15 个进入流、10 个留作 held-out。

目前这里主要是 Kimi K3.1 Pro 的轻量实验。ARC-AGI-2 上，程序库和专家指导的 $S_{\mathrm{seen}}$ 分别为 0.92 和 0.66，$S_{\mathrm{held}}$ 分别为 -0.02 和 -0.01；默认 harness 仍没有可靠记忆收益。ARC-AGI-3 上，示例缓存的 seen 节省率为 0.13，默认 harness 的 seen 为 0.03，而 held-out 的点估计 0.10 经多重比较校正后不再可靠。

这与主轨道的“旧任务能靠明确程序记忆，新任务仍难”方向一致，但论文还没有在更难轨道上跑权重学习。把它当成开放性研究地图可以，当成已完成的跨领域结论不行。

## 我认可的地方，也是我皱眉的地方

### 这套基准真正补齐了评测缺口

过去不少持续学习基准固定在编码、办公等单一应用领域，模型可能只是在唤醒预训练知识；固定实例只出现一次，又无法区分缓存答案与抽象规则；不同评测还分别偏向提示记忆或梯度更新。Continual-ARC 把“新实例、可变间隔回归、任务集合增长、收费二元反馈、任意状态载体”五件事组合起来，测量对象一下子清楚了。

reset 对照也很重要。没有它，一个强模型即使什么都不学，也可能靠绝对解题率碾压一个认真学习的小模型。论文把基础能力和经验增益拆开，这是设计上的硬功夫。

代码仓库公开了环境、调度器、学习器、训练代码、实验命令、逐实例 JSON 记录与轨迹；论文图表可以从运行目录重算。外部提交还会在私有新规则上验证，降低对公开任务和固定 seed 的过拟合。可复现性不是一句口号，确实给了材料。

### 权重学习赢下的不是一场完全同成本的比赛

QDE 得到的是强教师在学生真实状态上的完整回复，包括推理 token；单用户训练用了约 2,130 万 token、177 个训练阶段，训练耗时 84.7 小时，约 263 H100 GPU-hours，估算训练费 1,182 美元，教师标注另花约 71 美元。学生推理服务成本还不在这笔账里。

反馈预算 $U$ 有意不计训练算力、存储和 token，所以它对“为学会规则消耗了多少监督”很敏感，却不代表总拥有成本。程序库存一个文件几乎不要训练，DAgger 要一台 8×H100 节点。工程选型若只按 $S$ 排名，会漏掉非常现实的一笔账。

而且教师笔记实验与权重实验虽然共享教师，信息载体和优化过程仍不同。结论应是“在这套教师轨迹与训练设置下，权重路径表现出了泛化”，不是“任何权重更新都优于任何外部记忆”。论文尝试的策略梯度和自蒸馏就没有稳定学起来：前者在早期少量成功后停滞，后者会把工具输出里的教师动作误当自己已经做过的动作。

### 主实验覆盖仍然偏窄

多数深度结果来自 ARC-AGI-1、25 个流任务、200 个实例和 seed 0。Qwen3.5-9B、GLM-5.3 Flash 都不是这个任务分布上最强的可能学习器；三种商业 harness 的失败也部分指向特定默认提示和检索策略。程序库很适合网格变换，却不该被当成所有记忆表示的上限。

还有一个值得记住的评估细节：DAgger 配置搜索用过的 100 个 evaluation 任务中，有 23 个与最终 held-out 测试重叠。排除这 23 个后，单用户 $S_{\mathrm{held}}$ 为 0.27 [0.20, 0.34]，两用户为 0.39 [0.32, 0.46]，相比全量 0.29 和 0.40 变化不大。这个结果缓解了泄漏担忧，但最好的做法仍是看私有集和更多独立 seed。

### “没有统计显著收益”不等于“证明收益为零”

不少区间很宽，尤其是任务级 bootstrap 只有 25 个流任务时。作者大体克制，会把区间跨零称为不可测，而不是硬说负数或零。不过部分方法只跑一条任务流，测试重复四次只能平滑模型采样，不能替代完整的任务流种子重复。两用户、四用户的 DAgger 也主要各是一条运行轨迹。

坦率地讲，我现在最好奇的不是默认 harness 还能被吐槽多少，而是抽象概念记忆加上任务感知检索，能否在 $S_{\mathrm{held}}$ 上走出原点。论文没有给出这条路的答案，但它终于提供了一把能量出答案的尺子。

## 对工程实践的直接启发

如果你正在做一个号称“越用越聪明”的 Agent，这套协议可以直接改造成回归测试，不必照搬 ARC 网格：

1. 选一批可生成新实例的规则型任务，固定首次学习与后续回访的间隔，不能只重放同一条样本。
2. 给用户示例、人工纠错和错误尝试定价，并记录解题率，防止系统靠放弃任务来省预算。
3. 保留同模型、同 harness 的逐实例 reset，对照测出经验本身的净收益。
4. 把 seen 与 held-out 分开报告。旧任务省钱而新品类不涨，说明只是记忆；两边都改善，才有迁移证据。
5. 对记忆系统再拆成写入、索引、检索、执行四个仪表。GLM 的“40/154”比一句“记忆效果不好”有用得多，因为它直接指出该修哪里。
6. 把训练算力、教师调用、存储和推理 token 单独列账。反馈效率和总成本是两个目标，不要藏在一个总分里。

最小可行实现甚至可以很朴素：先自动缓存付费示例，再存经过环境验证的程序或结构化经验；任务到来后按任务 id 精确取回，执行失败才调用模型修复。这个基线不性感，却能逼得复杂记忆架构拿出真本事。

## 我的判断

Continual-ARC 是一篇测量设计比单个方法更值钱的论文。它没有证明 Agent 不需要记忆，反而用专家指导和程序库证明：**正确表示、验证和检索的记忆，对旧任务极有威力。**它也没有给出权重持续学习的通用算法；DAgger 依赖强教师、推理轨迹和可观训练算力，失败变体同样不少。

它真正改变的是提问方式。别再问“你的 Agent 有没有 memory”，而要问：同一规则换个输入回来时，它比清空状态少花多少反馈？遇到没见过的规则时，它又比清空状态强多少？这两个数，一个测记忆，一个测成长。

未来的理想形态可能不是无限膨胀的笔记目录，也不是每小时重训一次的大模型，而是两者各司其职：外部状态负责精确保留可执行技能，权重逐步吸收跨任务的通用模式，harness 则负责产生、验证和蒸馏经验。Continual-ARC 把这个设想变成了一张可以持续填点的二维考卷——右上角还空着，值得做。
