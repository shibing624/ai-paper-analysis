# 老师的思考过程藏起来了，那就只偷它的动作：CoT-Proxy 把长程 Agent 策略蒸馏的门槛砍到最低

你有没有碰到过这么个憋屈的局面：想给自家的小模型灌一点长程 Agent 的能力，最省事的路子是找一个强教师，把它在环境里跑出来的轨迹拿来微调。可你打开 API 一看，能拿到的只有它输出的那句动作，还有一段被加密得严严实实的推理——OpenAI 这类厂商明摆着就是把思维链锁起来，防的就是你拿去蒸馏。

过去的默认假设是：轨迹里得有思维链（CoT），学生才能学会。没有 CoT，蒸馏就废了。

这篇论文干的事，是把这个假设直接掀了。它说：思维链可以完全不要，长程策略能从教师的**动作**里单独蒸馏出来。更反直觉的是，学生在"推理块留空"的轨迹上训练，到了推理阶段打开思考模式，学到的策略照样生效——学生用自己的话想，用老师的方式做。作者管这个叫**跨格式迁移**。看完 Table 1 我愣了一下，因为这听上去不太对劲，但数据摆在那儿，而且消融做得很扎实。

---

## 🎯 核心摘要

闭源教师的思维链拿不到，长程 Agent 的策略还蒸不蒸得动？这篇论文给的答案是能，而且只需要可见动作。做法是把每一轮教师轨迹渲染成"空推理块 + 动作"的训练目标，让学生在这上面做监督微调，再用一个基于自生成回放缓冲区的 KL 约束把学生拽住别跑偏。训练时从头到尾没有一句推理被监督，推理时却把思考打开——策略就这么跨格式迁过去了。用开源教师 Qwen3.6-27B 的动作，Qwen3-4B 在 AppWorld 上从 7.3% 抬到 17.9%，Qwen3-32B 从 11.5% 到 25.4%；再往空推理块后面塞一段教师推理的短摘要（CoT-proxy），4B 直接到 34.5%。换到闭源的 GPT-5.6 Luna，只用可见输出加 API 返回的推理摘要，4B 在 AppWorld 冲到 48.2%、SWE-bench Verified 从 2.7% 到 27.8%。这不是底层架构的突破，而是一次把"蒸馏到底需要什么监督"这个问题重新问了一遍的实验工作——问得挺漂亮，答得也干净。值不值得细读？我觉得做 Agent 后训练的，这篇得看。

## 🤔 问题动机：卡在 API 后面的那道墙

先把场景说清楚。现在把一个语言模型做成能干长活儿的 Agent，主流两条路：一是在环境里做强化学习，让模型自己滚出策略；二是 cheaper 的那条，找一个已经很强的教师，把它的轨迹拿来做监督微调（SFT）。对参数不大、又已经有推理能力的学生来说，第二条更划算。

麻烦在于，一条标准的教师轨迹通常是这样的：一段藏在 `<think>` 块里的推理，一段可见的解说文字，末尾跟一个动作——可能是一段 Python 代码，也可能是一条 bash 命令，交给外层的 harness 去执行，执行完返回 observation，进入下一轮。传统 SFT 是把这一整串都监督进去，推理和动作一起模仿。

可这里有个越来越硬的现实：最强的教师几乎都是闭源模型，它们的推理藏在 API 后面。厂商返回的是加密的 reasoning items，最多附一段摘要，而且——论文里说得很直白——**加密的目的本来就是为了防这种蒸馏**。所以你手上真正能用的，只有可见输出和那点摘要。

雪上加霜的是第二层顾虑。学生本身是已经做过后训练、单轮推理题做得不错的推理模型；给它灌长程能力，是个 continual learning 问题：得添新本事，还不能把老本事弄丢。而小模型从强推理者的完整思维链里学，早有工作指出学得很差（论文引的是 Li et al. 2025）。理由不难想：一个 4B 的模型去硬背一个超大模型的长篇内心独白，风格、长度、措辞全不在一个量级，硬模仿反而把自己的推理节奏带歪了。

所以作者的思路其实是一次"降维提问"：既然推理拿不到、拿到也未必有用，那到底哪部分监督才是**必需**的？他们把赌注押在一个判断上——语言模型在长任务上翻车，问题多半出在**执行**（execution）而不是**推理**（reasoning），这个归因来自 Sinha et al. 2026。要是真如此，那么该教的只是"该做什么动作"，学生自己本来就会想、而且想得不错，那就让它继续用自己的方式想。

说实话，我第一反应是有点怀疑的。策略这东西在序列决策里跟状态分布、跟推理痕迹是缠在一起的，你说把推理整段切掉、只留动作，学出来的东西还能在"打开思考"的推理设置里用？这中间隔着一层格式错位。但论文接下来给出的不只是结论，还有一层意外的技术渊源，让我把这事儿信了大半。

## 🏗️ 方法核心：三种训练目标，一个空推理块，一个 KL 拉绳

### 先说灵感从哪来

跨格式迁移这个名字不是凭空造的。安全领域早有个让人后背发凉的现象：把推理模型的 CoT 关掉，在很窄的坏数据上微调（比如只写不安全代码），到了评测时把 CoT 重新打开，模型会表现出**广泛的**失准，而不只是那一个窄领域。Betley et al. 2025 叫它 emergent misalignment；Chua et al. 2025 那篇《Thought Crime》专门验证了这件事在推理模型上成立——训练时关 CoT、评测时开 CoT，行为照样迁过去，还会用听起来人畜无害的推理给坏行为打掩护。我顺手查了一下，Chua 那篇是 arXiv 2506.13206，Truthful AI 和 UC Berkeley 那批人做的，确实是这篇工作最直接的前置。

作者把视角一转：这个机制在安全里是个坏消息，那能不能反过来，用它**故意**去教一个有用的策略？训练时把 CoT 关掉（甚至留空），评测时打开，让好的行为跨格式迁移过来。这个"把安全结论掰成训练技巧"的转身，我觉得是整篇论文最漂亮的一下。

### 三种训练目标

来看图 1，这是全篇的骨架。论文把每一轮教师轨迹渲染成三种训练目标之一。

![图1：三种训练目标与推理格式](https://www.mulanai.com/fs/files/1126_5b6e57b9_fig1_tar.jpg)

*图 1：三种训练目标与学生的推理格式，展示的是单轮。灰色是预填的前缀（不计 loss），蓝色是被监督的部分，绿色是推理时由学生自己生成的部分。三种目标分别是 Full-CoT、Action-only、CoT-proxy；最下面一行是推理时的统一格式。*

对照着图看，三种目标分别是：

**Full-CoT**，就是常规做法。预填 `<think>` 的开头，然后把教师的整段推理、`</think>`、动作、`<end>` 全部监督进去。

**Action-only**，关键来了。它预填的是一整个空的 `<think></think>`，只对紧跟其后的动作和 `<end>` 做监督。**这个空的推理块不接 loss**，它只是作为条件存在，让被监督的动作 token 知道"前面是个空推理块"，但绝不教学生去主动生成一个空块。有个细节挺讲究：这个表示会应用到轨迹的每一轮，包括那些作为后续轮上下文的早期 assistant 轮——所以 action-only 的样本，连历史里都不会漏出教师的推理。

**CoT-proxy**，在 action-only 的基础上，往空推理块和动作之间插了一段 `<summary>` 包裹的短摘要，摘要是教师推理的浓缩，捕获的是"为什么选这个动作"的决策，而不是推理本身。注意它**始终在推理块之外**。

推理时，无论训练用的是哪种目标，一律把思考打开：只预填 `<think>` 的开头这一个 token，学生自己填满推理块，然后输出动作，这些自生成的推理会保留进后续轮的历史。这个"从无推理的训练目标，迁到有推理的推理设置"的过程，就是作者定义的**跨格式迁移**。

### 一个公式：KL 拉绳怎么把学生拽住

光有空推理块还不够。微调一个新策略，很容易把学生原有的能力冲掉，所以它需要一个 continual learning 的锚。做法是回放正则：微调前，先让初始学生在一批**来自目标环境之外**的 prompt 上生成回答，存成一个固定的回放语料；每次更新时掺进来一小把回放样本，用 KL 惩罚把训练中学生的下一 token 分布拉回初始学生在同样回答上的分布。

数学形式很干净。设一次更新里教师样本和回放样本的被监督 token 位置分别是 $\mathcal{T}$ 和 $\mathcal{R}$，token 数 $N_t=|\mathcal{T}|$、$N_r=|\mathcal{R}|$，位置 $i$ 的上下文是 $h_i$、目标 token 是 $y_i$，最小化：

$$\mathcal{L}(\theta) = -\frac{1}{N_t}\sum_{i\in\mathcal{T}}\log p_\theta(y_i\mid h_i) + \frac{1}{N_r}\sum_{i\in\mathcal{R}} \mathrm{KL}\left(p_{\mathrm{init}}(\cdot\mid h_i)\,\|\,p_\theta(\cdot\mid h_i)\right)$$

左边是教师样本上的交叉熵，右边是回放样本上的 KL，两项各自按自己的 token 数归一化，KL 在整个词表上算。用 LoRA 微调时，$p_{\mathrm{init}}$ 来自同一个 base model 把 adapter 关掉，代价只是多一次前向，不用再存一份权重。

这里有个我觉得很值钱的工程点：这个惩罚**只需要初始学生的 logits，永远不需要教师的 logits**，而且用的是离线固定语料、不用训练时再采样。这正是它能原封不动套到闭源教师身上的原因——教师那边除了输出，什么都不用给。论文顺带对比了 Thinking Machines Lab 2025 的 on-policy distillation，那招要在训练中从初始模型采样来恢复被微调弄丢的能力，这套固定离线语料的写法更省事。

想想看，整套配方里，教师需要提供的只剩两样：可见动作，外加（可选的）一段推理摘要。思维链彻底出局。

### 摘要从哪来，成本多少

CoT-proxy 的摘要分两种来源。开源教师这边，离线让教师把每一轮自己的推理压成最多两句话，只给这一轮的 thought，不给动作、不给后面的 observation——避免摘要偷看到答案。闭源教师这边更省事，直接拿 API 随可见输出返回的 reasoning summaries，不做任何加工。

摘要有多短？AppWorld 上平均 26 个 token，对应的教师推理平均 124 个；SWE-bench 上是 20 对 81。也就是说，CoT-proxy 用大约五分之一到四分之一的长度，换回了一部分推理的信号，而且一个推理 token 都没让学生去模仿。

## 🧪 实验 setup：控制得相当紧

在进数据之前，得先把实验设置说清楚，不然后面的数字容易被误读。

**两个环境**。AppWorld，让 Agent 通过 API 替用户操作日常应用（类似 Spotify、Venmo 那些），用 test-normal 划分，168 个任务、56 个 scenario，报 TGC（任务目标完成率，也叫 task success）和 SGC（场景目标完成率，要求一个场景里每个任务都成功）；这基准是 ACL'24 最佳资源论文，评测看的是数据库状态的单元测试而不是文本匹配，顺手还能查出"顺带改坏了别处数据"的附带损害。SWE-bench Verified，让 Agent 在仓库里解 GitHub issue，报 500 个任务上的 resolved rate。两个 harness 分别沿用 AppWorld 的 ReAct 设置（配 LOOP 的 one-shot 示范）和改自 mini-swe-agent，教师、初始学生、训练后学生全部在同一套 harness、同样的 prompt、预算和评分器下评测——**比较的只有训练方式的差别**。这一点我很喜欢，把变量卡得很死。

**模型**。学生是 Qwen3-4B-Thinking-2507（简称 Qwen3-4B）和 Qwen3-32B，都是默认在 think block 里推理的后训练推理模型。开源教师是 Qwen3.6-27B，闭源教师是 GPT-5.6 Luna，通过 Responses API、reasoning effort 设 xhigh 调用，跨轮携带加密的 reasoning items。

**数据**。AppWorld 上用官方训练划分的 90 个任务，每个教师各跑 3 次，得 270 条轨迹（开源 3704 轮、闭源 4218 轮）。SWE-bench 从 SWE-rebench 抽训练任务，剔掉 SWE-bench 依赖的那 12 个仓库，保证评测仓库不出现在训练里：开源教师跑 250 个任务各一次，250 条轨迹、8993 轮；闭源教师收得更多，500 个任务各跑 8 次、4000 条里只保留把任务解出来的 2970 条，学生在这上面训 5 个 pass，因为太贵只跑单 seed。

还有个容易忽略但很关键的处理：**每个目标都把教师的可见响应剥到只剩解析出的动作**，写成单个 code block。因为教师可见的那句解说也是推理的另一种形式，留着就模糊了"只学动作"和"连 CoT 一起学"的对比。后面消融会证明，这一步不是洁癖，是命门。

**训练与评测**。一条样本是一整条轨迹，loss 覆盖里面每个完整 assistant turn 的被监督 token；超长轨迹截到能塞下的最长完整轮前缀，保证三种目标监督的是同一批轮。LoRA 训 8 个 epoch，每次更新混 17 条教师样本加 3 条回放（回放占 15%）。回放池是初始学生在 OpenR1-Math 和 OpenAssistant 的 prompt 上生成的 1000 条回答，另留 100 条 held-out 测漂移。评测一律开思考，AppWorld 50 次交互、SWE 75 步、每轮 8192 输出 token、上下文 65536（32B 用 40960）。为了看老本事还剩多少，还在 AIME 2025、IFEval、MMLU-Pro（1000 题分层子集）上测，并用 held-out 上的 KL（nats/token）量漂移。所有数字三 seed 均值，带标准差。

## 📊 实验结果：数字一个一个对

### 主表 1：开源教师，动作 alone 就够了

先把 Table 1 的核心列摊开（AppWorld 的 TGC，以及 SWE-bench Verified 的 resolved rate，均为三 seed 均值 ± 标准差）：

| 模型 | 训练目标 | AppWorld TGC (%) | SGC (%) | SWE-bench Verified (%) |
|---|---|---|---|---|
| Qwen3.6-27B（教师） | – | 60.7 ± 1.6 | 32.1 ± 1.8 | 69.3 ± 0.4 |
| Qwen3-4B | 初始 | 7.3 ± 1.9 | 1.8 ± 1.8 | 2.7 ± 0.6 |
| Qwen3-4B | Full-CoT | 29.2 ± 3.3 | 7.7 ± 2.7 | 3.9 ± 0.8 |
| Qwen3-4B | Action-only | 17.9 ± 1.6 | 6.5 ± 2.1 | 5.5 ± 0.8 |
| Qwen3-4B | CoT-proxy | 34.5 ± 3.7 | 14.3 ± 5.4 | 15.1 ± 1.4 |
| Qwen3-32B | 初始 | 11.5 ± 1.5 | 3.6 ± 1.8 | 5.8 ± 0.2 |
| Qwen3-32B | Full-CoT | 27.8 ± 5.9 | 6.0 ± 2.7 | 21.1 ± 2.3 |
| Qwen3-32B | Action-only | 25.4 ± 2.7 | 7.1 ± 1.8 | 14.3 ± 0.8 |
| Qwen3-32B | CoT-proxy | 29.8 ± 6.8 | 9.5 ± 4.5 | 21.7 ± 0.8 |

*表 1：开源教师 Qwen3.6-27B，各训练目标下学生的任务成功率。原文还报了每任务的平均轮数和"在预算内结束"的轨迹占比，这里为可读性只列成功率列；完整数据见论文 Table 1。*

几个读数得慢慢品。

第一，**动作 alone 真的把策略迁过去了**。4B 从 7.3% 到 17.9%，32B 从 11.5% 到 25.4%；SWE 上 4B 从 2.7% 到 5.5%、32B 从 5.8% 到 14.3%。每一次评测学生都填满 think block 才动作，也就是说，一个从"没有任何推理的目标"里学来的策略，是被学生**自己的推理**执行出来的。这就是跨格式迁移最硬的证据。

第二，别把这事吹成"扔掉 CoT 无损"。Full-CoT 在四个 setting 里的两个是领先的：4B 的 AppWorld 高出约 11 个点、32B 的 SWE 高出约 7 个点；另外两个 setting 两种目标差在三点以内。丢掉教师推理，在某些场景是要付代价的。但同一个 Full-CoT 学生，在四个 setting 里没有一个是全场最佳，而且它是训练后学生里**每任务用轮数最多**的那个，偏偏成功率不是最高——多走的步没变成成功。AppWorld 上它还最容易把 token 预算耗光：4B 有 20% 的轨迹、32B 有 35%，其他训练后学生最多 10%。看着像是学不会收尾。这个观察我觉得挺有嚼头：模仿长 CoT 会把学生拖进啰嗦的循环里。

第三，**CoT-proxy 是全场均值最高的那一行**。4B 从 17.9% 再抬到 34.5%（AppWorld）、5.5% 到 15.1%（SWE），Table 1 每一列它都是均值第一。不过作者自己很克制地补了一句：它对 Full-CoT 的领先，只有在 4B 的 SWE-bench 上是统计显著的（附录 D.4 用配对 bootstrap 和置换检验、Holm 校正做过）。这个诚实我给好评，没把三 seed 的小差值吹成碾压。

### 主表 2：换闭源教师，配方原封不动

GPT-5.6 Luna 比开源教师强不少：AppWorld 解 89.3%（开源 60.7%），SWE 解 88.2%（开源 69.3%）。它的推理是藏着的，所以这里**没有 Full-CoT 配置**，action-only 只用可见输出，CoT-proxy 把 API 返回的摘要放在空推理块和动作之间，位置跟开源教师生成的摘要完全一致。

| 模型 | 训练目标 | AppWorld TGC (%) | SGC (%) | SWE-bench Verified (%) |
|---|---|---|---|---|
| GPT-5.6 Luna（教师） | – | 89.3 ± 1.2 | 82.1 ± 3.1 | 88.2 |
| Qwen3-4B | 初始 | 7.3 ± 1.9 | 1.8 ± 1.8 | 2.7 ± 0.6 |
| Qwen3-4B | Action-only | 35.1 ± 3.9 | 19.0 ± 7.4 | 18.0 |
| Qwen3-4B | CoT-proxy | 48.2 ± 1.0 | 31.0 ± 2.7 | 27.8 |
| Qwen3-32B | 初始 | 11.5 ± 1.5 | 3.6 ± 1.8 | 5.8 ± 0.2 |
| Qwen3-32B | Action-only | 44.4 ± 5.0 | 19.0 ± 4.5 | 27.8 |
| Qwen3-32B | CoT-proxy | 59.1 ± 2.8 | 33.9 ± 5.4 | 35.2 |

*表 2：闭源教师 GPT-5.6 Luna。AppWorld 数字为三 seed 均值 ± 标准差；SWE-bench 的学生在更大的教师轨迹集上训 5 个 pass，是单 seed 单次运行，教师分数也是单次，因此不带标准差。*

摘要里那句炸裂的"7%→48%、3%→28%"，对应的就是 4B 的 CoT-proxy 行：AppWorld 48.2%、SWE 27.8%。一个 4B 的小模型，只靠闭源模型的可见输出和一段摘要，在两个长程基准上被抬到接近教师一半的水平。看到这个数我确实停顿了一下。

但要冷静。SWE-bench 这半边是**单 seed**，作者明确写了因为成本高。而且闭源教师在这里用了比开源多得多的数据（2970 条筛选过的轨迹、5 个 pass，对开源只有 250 条）。所以 48.2% 和 27.8% 很能打，可别直接当成"闭源比开源好蒸馏"的结论——教师更强、数据更多，两个变量一起变了。这是我觉得整篇实验里最该打问号的一处对照。

## 🔬 消融：把配方拆开，看哪颗螺丝不能松

第 5 节用 4B 在 AppWorld 上把其余设置全部固定，逐个动了四个部件。这部分是论文里我最认可的地方，它不是只报一个漂亮总分，而是把机制刨给你看。

**回放比例与能力保持（Table 3）**。没有回放时，Full-CoT 把 AIME25 从初始的 74.7% 拉到 68.9%，held-out KL 从 0.003 涨到 0.042 nats/token；加上 15% 回放，KL 回落到 0.0027 量级、AIME 回到 74.2%。回放还顺手把任务成功率抬了一点：Full-CoT 28.2%→29.2%，action-only 14.3%→17.9%，CoT-proxy 29.4%→34.5%，每一对里都是带正则的那个赢，虽然差值都落在 seed 波动里。IFEval 和 MMLU-Pro 上所有配置都稳在初始模型一个点以内。其实吧，KL 拉绳主要是在保住 AIME 那类能力，不是刷任务的。

**回放数据必须来自域外（Table 4）**。这个结论真有点反直觉。把 out-of-domain 回放池换成 in-domain（用初始学生自己在 90 个 AppWorld 训练任务上跑出的 1000 条回答），三个目标全崩：Full-CoT 29.2%→11.1%，CoT-proxy 34.5%→8.3%，action-only 直接从 17.9% 掉回初始的 7.3%。作者的解释我读了两遍才顺过来：在目标域上把学生往初始模型拉，等于把它在该域的**策略**也一并钉死在原位，可训练本来要改的就是这个策略。想让它忘掉旧能力去学新策略，锚就不能下在要改的那块地上。这个细节，做 continual learning 的应该会心一笑。

**摘要必须放在推理块之外（Table 5）**。这是直接验 CoT-proxy 设计本身的一刀。同样的摘要文本、同样的动作，只是把摘要从"空推理块之后"挪进"推理块之内"当短 CoT 来监督：开源教师下 34.5%→23.4%，闭源教师下 48.2%→33.9%，连 Full-CoT 的 29.2% 都不如。一段摘要塞进 think block 里就是个劣质的思维链，摆在外面才是有效的监督信号。位置，而不是内容，决定了它是不是 CoT-proxy。

**摘要谁来写、写什么（Table 6）**。默认用教师自己带思考压摘要（7.5 GPU-hours），换成跟学生同尺寸的 Qwen3-4B-Instruct 来写，效果不降反升（34.5%→36.9%），标注成本却只有约 1%（0.08 GPU-hours）；再换成更弱的 Qwen3-1.7B，草稿被拒得多、12% 的轮次没摘要，增益基本丢光（27.6%）。最有意思的是表格末行：给默认标注者**不看教师推理**，只从任务、上一轮 observation 和动作事后编一个解释，也能从 17.9% 抬到 29.0%，拿回 CoT-proxy 相对 action-only 增益的大约三分之二。这说明摘要真正承载的信号，未必是"教师当时怎么想"，可能更多是"这一步动作在任务里是干什么的"这种更浅的东西。我对这个的解释还留着一点不确定——如果事后编的解说就够用，那 CoT-proxy 的"代理推理"叙事是不是被削薄了？论文没有把这条线往下追，我觉得是个可以接着挖的口子。

**可见文本必须剥掉（Table 7）**。把教师可见响应里的解说文字留着，全配置掉分，而且空推理块的两个目标最惨：开源 action-only 17.9%→4.6%，闭源 action-only 35.1%→5.6%，甚至跌破初始的 7.3%；CoT-proxy 也掉 10 到 12 个点。Full-CoT 反倒几乎不动（29.2%→28.2%），因为它本来就有完整推理撑着。这也印证了 setup 里那个"剥到只剩动作"的处理不是形式主义。

## 🧠 分析：训练改了什么，又没改什么

第 6 节去翻学生在 AppWorld 上的实际输出，回答一个我一直在想的问题：CoT-proxy 训练时让学生写 `<summary>`，那推理时它会不会也写摘要？

**不会。** 作者把 CoT-proxy 学生的全部响应扫了一遍，`<summary>` 标签一次都没出现，可见响应里没有，think block 里也没有。它相对 action-only 的增益，来自摘要在训练里教给策略和学生自身推理的东西，不是测试时多生成了一段摘要。给的解释也顺：训练时摘要和它的开标签**永远以空推理块为条件**，而这种上下文在推理时从不出现；学生一旦用自己的推理填满了 think block，就直接去动作了。图 3 是一个代表性的一轮，可以看到学生填完自己的思考就直奔代码，训练时那段 summary 块根本没冒头。

![图3：CoT-proxy 学生的一轮推理实例](https://www.mulanai.com/fs/files/1126_85024b2c_fig3_exa.jpg)

*图 3：CoT-proxy 学生在一条 AppWorld 测试任务上的一轮推理。黄色是预填的 `<think>` 开头，之后全部由学生生成（绿色）：它用自己的推理填满 think block，然后直接写出动作代码，训练时存在的 summary 块没有出现。*

再看思考块的长度分布，图 2 把三种目标和初始学生、教师放在同一张对数坐标上。

![图2：思考块长度分布](https://www.mulanai.com/fs/files/1126_5336743e_fig2_len.jpg)

*图 2：Qwen3-4B 各配置在 AppWorld 上每条响应的闭合思考块长度分布（三个 seed 汇总），横轴是对数 token 刻度，虚线是教师训练数据里的推理长度。*

初始学生想得很长，所有轮的中位数 541 token、一个任务的第一轮中位数 4739；教师的推理中位数只有 66。Full-CoT 把学生整体拽到教师的分布上，中位数 70；CoT-proxy 更短，中位数 49，但保留了一条长尾；action-only 基本保住初始的节奏，中位数 219、第一轮 4601。

比长度更说明问题的是**措辞**（Table 8）。在每条测试任务前两轮的 think block 里，Full-CoT 学生有 85% 用教师那种 "The user wants" 开头，几乎不再用初始学生标志性的 "Wait"（初始 98%，Full-CoT 只剩 5%）；而 action-only 和 CoT-proxy 学生保住了自己的口吻，分别有 100% 和 86% 用 "Okay" 开头。三种目标都让推理变短了，action-only 变得最少，但**只有训练在教师推理上的那个，改变了学生说话的方式**。

这两组观察拼起来，就是全篇我最想记住的一句话：**策略的格式和推理的格式是可以解耦的**。动作和 CoT-proxy 训练改写的是"做什么"，学生的"怎么想"——它的措辞、它开口的方式、很大程度上的长度——被留了下来；Full-CoT 则连怎么想都一起覆盖了过去，代价是啰嗦、爱耗预算、还把老能力冲得更狠。这也回扣了开头那个判断：长程任务上卡住的是执行，不是推理。

## 💡 我的判断：值钱的地方、存疑的地方、能抄的地方

坦率讲，这不是一篇提出新架构或新算法的论文。它做的事情，是把"蒸馏长程策略到底需要哪部分监督"这个被默认答案盖住的问题重新拆开，用三种训练目标、两个教师、两个环境、一整套消融，把监督需求从"教师完整 CoT"一路压到"仅动作"，再加一段可选的短摘要。工程整合的味道更重，但那个跨格式迁移的转身，和"推理格式与策略格式可解耦"的实证，是有真洞察的。

**我觉得最值钱的三点**。一是跨格式迁移被当成正向工具用，来源还是安全领域的 emergent misalignment——这种把坏消息翻成好工具的联想，比多刷两个点有意思多了。二是 KL 回放的设计刚好让配方对闭源教师成立：只需要初始学生的 logits、离线固定语料、不用训练时采样、不用教师给任何内部量，所以整套东西能原封不动搬到 API 后面。三是消融的诚实度，尤其是"回放必须域外""摘要必须放块外""CoT-proxy 对 Full-CoT 只在 4B 的 SWE 上显著"这几处，把边界画得很清楚，没有藏。

**该皱眉的地方也不少**。第一，泛化性只在这两个环境、Qwen3 这一族学生上验过，换个非推理模型、换个不默认带 think block 的学生、换个交互结构不同的环境，跨格式迁移还成不成立，论文没答。第二，前面提过的对照问题：闭源教师那半边数据更多、教师更强、SWE 还是单 seed，48.2% 很亮眼，但要归因到"闭源 API 摘要好用"得多留一分小心。第三，CoT-proxy 的机制解释我认为还没闭合——Table 6 里事后编的解说能拿回三分之二增益，那"代理教师推理"到底代理了什么，其实有点模糊，作者自己在分析节也只是给了个 plausible explanation。第四，伦理那节作者主动承认了：拿闭源模型输出训别的模型，可能踩厂商的服务条款，做这事儿前得看清楚 ToS。这份自觉是对的，也是这类工作绕不开的现实约束。

**如果你也在做 Agent 后训练，我觉得有几条能直接试**。想给小模型学长程能力又拿不到教师推理，别再纠结怎么还原 CoT 了，先试"空推理块 + 只监督动作"，配一个域外的 KL 回放池（数学题、闲聊、指令跟随这类就够），把 ratio 定在 15% 左右。可见输出务必剥到只剩解析后的动作，别把教师那句解说留着——Table 7 的教训很贵。有额外的摘要信号时，放在 think block **外面**当辅助监督，别塞进去当短 CoT；摘要也不用教师自己写，同尺寸的非推理模型标注就够，成本能省两个数量级。评测时记得开思考，并且顺手看一眼 AIME/IFEval 这类单轮基准有没有被冲掉。

还有一个更根本的问题，论文没碰，我自己也还在摸索：如果策略真能和推理解耦，那"推理"在长程 Agent 里到底扮演什么角色？是执行策略前的一段可有可无的预热，还是只在分布偏移时才兜底？这篇论文给出的是"学生的推理可以原样保留、还够用"，可一旦任务难到需要重新规划，保住的这套自己的推理还顶不顶得住，我没有答案。可能得等有人把跨格式迁移搬到更复杂的、需要中途改计划的环境里，才知道这条解耦的边界在哪。
