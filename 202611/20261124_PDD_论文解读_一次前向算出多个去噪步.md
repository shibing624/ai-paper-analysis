# 4 步出视频，还不用 GAN：把去噪轨迹并行算完的 PDD

上周在调一个视频蒸馏的活儿，碰到个特别熟悉的场面：VBench 分数一点点往上爬，生成出来的片子却越来越"乖"。同一个 prompt 换五个随机种子，出来的五段视频像是一个模子里刻出来的，人物姿势几乎不动，镜头也懒得推。指标很漂亮，片子很死。

做过少步视频蒸馏的人大概都见过这一幕。质量涨了，多样性没了，运动也没了。

所以看到 arXiv:2607.26004 这篇 *Parallel Decoding Distillation for Fast Image and Video Generation* 的时候，我的第一反应不是"又一个 SOTA"，而是——终于有人不打算在 loss 上继续叠补丁了。

---

## 🎯 核心摘要

这篇论文想解决的是扩散/流模型采样太慢，而主流加速方案（VSD + 对抗损失）在视频上会把多样性炼没的问题。作者给的答案是 **PDD**：不再把几十个小步压成一个大步，而是让网络**一次前向同时预测一整个块里每个小区间的平均速度**，然后一次性把这 L 步走完；训练目标只有一个纯 MSE 回归，不用 JVP、不用有限差分、不用判别器、不用多阶段训练。结果是在 Wan2.1 14B、Qwen-Image 20B、LTX-2.3 22B 上用 4–8 NFE 就能出图出片，VBench 84.94（1.3B）和 OneIG 0.541（8 NFE）都站在第一梯队，多样性指标比 DMD2 高出一大截。

一针见血地说：这不是底层数学突破，是一次参数化方式的重新收拾——把"学 flow map 的导数"换成"学一组并行的线性输出头"。但正是这个换法，让训练复杂度塌下来一个数量级，还顺手把 mode collapse 躲开了。值不值得细读？我觉得值，尤其是你正被 GAN/VSD 训练不稳定折磨的时候。

## 🧠 为什么这件事值得做：两条路线的旧账

少步生成这些年基本分成两派。

**轨迹派**（trajectory-based）盯着老师模型那条 ODE 采样路径，让学生用几步把老师几十步走过的路复刻出来。一致性蒸馏、flow map、Pi-Flow 都在这条线上。好处是监督信号干净，坏处是在视频这种高维、长时序的场景里，一步跨太远容易糊，训练算法还贵。

**分布派**（distribution-based）想得更开：不管老师怎么走，只要学生输出的边缘分布跟老师对齐就行。DMD、DMD2 是代表，视频少步生成现在几乎是它们的天下。代价也很清楚——reverse-KL 是 mode-seeking 的，它只惩罚"学生采到的模式"，学生漏掉的模式它不管。说到这个，MIT 那篇关于 DMD2 的博士论文和后续的综述都点得很明白：DMD2 靠 TTUR（双时间尺度更新）+ GAN 判别器稳住训练，但反向 KL 天然的收窄倾向并没被消掉，视频上表现出来就是动作变得保守、画面发糊或者过饱和。

我顺手查了下同期的工作，有个挺有意思的对照：Data-Forcing Distillation（arXiv:2606.18478）声称只要在 DMD2 上改一行代码——把 teacher score 算在真实视频而不是学生生成样本上——再用 50–100 步后训练，就能把多样性和运动捞回来。另有综述把这类失败归成一张账单：多样性塌缩、运动抑制、架构错配。这些都说明 mode collapse 不是训练不够久的问题，是目标函数里长出来的。

于是 PDD 的问题设定就很清楚了：**能不能回到轨迹派，但把训练成本压到跟普通回归一样低，同时不碰分布匹配？**

作者自己在结论里放了句 "first pure trajectory-based distillation method for few-step, high-resolution video generation"。看到"首个"我一般会先皱眉——rCM 那边早就把连续时间一致性蒸馏推到 10B+ 视频 DiT 了，两派其实在收敛。不过把"纯轨迹 + 高分辨率视频 + 无 VSD/GAN"这个组合单独拎出来，确实没太多前人完整跑通。这句我按"作者自称"来读，不当结论。

## 🏗️ 方法核心：不是迈大步，是一次算完一串小步

### 先给一句直觉

传统加速是把 4 步并成一个大步，PDD 是**一次前向，把接下来 4 个小步各自该往哪走，全写在一张纸上，然后按顺序走完**。网络的 backbone 只跑一次，多出来的只是末端几个线性层。

这句话看着平平无奇，但它是整篇论文的支点。

### 从 flow matching 的平均速度说起

把扩散和流模型统一看成 ODE：

$$\frac{d}{dt}X_t = v_t(X_t),\quad X_0\sim p_0$$

采样就是把 $[0,1]$ 切成 $N$ 个区间 $0=t_0 \lt t_1 \lt \dots \lt t_N=1$，一步步积分。第 $n$ 步真正需要的是这个区间上的**平均速度**：

$$u_n(X_n)=\frac{1}{t_{n+1}-t_n}\int_{t_n}^{t_{n+1}} v_t(X_t)\,dt$$

$$X_{n+1}=X_n+(t_{n+1}-t_n)\,u_n(X_n)$$

Euler 拿区间起点速度近似 $u_n$，Midpoint 拿中点速度近似，都是对这个积分的数值逼近。PDD 抓的就是这个 $u_n$——它管这叫 mean velocity，是个**离散时间、有限区间**的量，不是瞬时速度 $v_t$。

这个区分挺要紧。Pi-Flow 蒸馏的是连续时间的瞬时速度 $v$，PDD 蒸馏的是数值求解器里的平均速度 $u$。后者跟实际采样器对齐得更紧。

![图 1：PDD 把 N=12 个时间区间按 L=4 分组，两个 Parallel Decoder 分别从 X̄0 和 X̄4 出发，一次前向输出块内 4 个平均速度箭头](https://www.mulanai.com/fs/files/1124_70ed912e_illustra.png)

*图 1（论文 Figure 2）：轨迹被切成 N=12 个区间，浅蓝色块是大小为 L=4 的当前块。灰色的方块是还没预测到的后续区间。注意看图里有两个 Parallel Decoder，各自只吃一个输入状态，就吐出 4 个方向箭头。*

### 并行解码器与块步更新

固定一个长度为 $N$ 的时间网格，大小为 $L$ 的块就是索引集合 $\{n,\dots,n+L-1\}$。并行解码器 $\bar u_n^\theta(\cdot\mid X_n)\in\mathcal X^L$ 一次前向，输出块内每个区间的平均速度：

$$\bar u_n^\theta(k\mid X_n)\approx u_k(X_k),\quad k=n,\dots,n+L-1$$

作者特意论证了它 well-defined：块内的状态序列由初值 $X_n$ 和精确解完全决定，所以"只看 $X_n$ 就能预测后面 L 个速度"在数学上站得住。这句话其实是整篇论文敢把 L 步并行化的许可证。

训练时定义一个"并行化过程"（论文叫 parallelized process），把这 L 个预测速度在块内依次累加，得到块内状态 $\bar X_k$；而推理时把递归直接求和展开，一步跨过整个块：

$$\bar X_{n+L}=X_n+\sum_{k=n}^{n+L-1}(t_{k+1}-t_k)\,\bar u_n^\theta(k\mid X_n)$$

重复 $N/L$ 次就得到样本。所以 NFE 就是 $N/L$：网格 $N$ 固定，块 $L$ 越大步数越少。

![图 2：学生一次输出 4 个平均速度，教师配 ODE 求解器只输出单个区间的平均速度](https://www.mulanai.com/fs/files/1124_dfa319b2_student_.png)

*图 2（论文 Figure 3 左）：左边 Student 从 $X_n$ 一次吐出 4 个 $\bar u_n(\cdot\mid X_n)$ 箭头；右边是绿色框里的 Teacher + ODE Step，从 $\bar X_k$ 只算出一个绿色箭头 $u_k(\bar X_k)$。一个前向换一个前向，信息量差了 L 倍。*

### 那个让我愣了一下的 loss

$$\mathcal L_{\text{PD}}(\theta)=\mathbb E\left[\left\|\bar u_n^\theta(k\mid X_n)-u_k\big(\mathrm{sg}(\bar X_k)\big)\right\|^2\right]$$

就这。一个 MSE。

$n$ 从块的起点里均匀采，$k$ 在块内均匀采，$X_n$ 用插值过程 $X_t=(1-t)X_0+tX_1$ 采出来（有数据的情况），$\bar X_k$ 是学生自己滚出来的状态，$\mathrm{sg}$ 是 stop-gradient，右边的 $u_k$ 是老师用**一步 Euler 或一步 Midpoint** 算出来的平均速度。

等等，这个 loss 真的会收敛吗？毕竟监督信号是老师在自己学生走偏的状态上算的，还带 stop-gradient。作者给了 Proposition 1：在 Runge-Kutta 逼近误差可控的前提下，PD loss 的最优解满足上面的并行解码器条件，学生轨迹与老师轨迹一致（$\bar X_n=X_n$）。证明放附录 D。说实话这个结论我读了两遍才顺过来——它成立的关键在于 on-policy：老师不是在数据集分布上给答案，而是在**学生自己会走到的状态**上给答案，这跟 DMD2 里 backward simulation 想解决的 train-inference mismatch 是同一类问题，只是用回归直接绕开了。

代价也算得很清楚：$\bar u_n^\theta$ 和 $\bar X_k$ 共用**一次**学生前向；老师那边 Euler 要 1 次评估，Midpoint 要 2 次。没有 JVP，没有有限差分，没有判别器，没有 fake score network，也没有交替更新。这跟 DMD2 那套"生成器 + 在线 critic + 判别器 + TTUR"比起来，工程复杂度基本是断崖式下降。

![图 3：PD loss 的估计方式，红色虚线是学生状态与教师一步到达位置之间的差异](https://www.mulanai.com/fs/files/1124_b16e4661_illustra.png)

*图 3（论文 Figure 3 右）：蓝色箭头是学生串起的 $\bar X_{n+1}\to\bar X_{n+2}\to\bar X_{n+3}\to\bar X_{n+4}$，绿色箭头是 Teacher mean velocity，浅蓝色弧线是 Teacher trajectory，红色虚线就是被回归的那一项。图例里四种颜色的分工标得很清楚。*

把训练逻辑写成伪代码，大概就是这样（论文 Algorithm 2 的精简版）：

```python
# student: 并行解码器   teacher: 预训练流模型   t: 时间网格
N = len(t) - 1
n = L_min * randint(0, N // L_min)          # 随机块起点
x_n = (1 - t[n]) * randn_like(x) + t[n] * x  # 插值过程采样
u = student(x_n, t[n])                      # 一次前向，输出 N 个速度
h = diff(t, dim=0)
k = randint(n, clip(n + L_max, max=N))      # 块内随机挑一个区间
x_k = x_n + einsum('l,l...', h[n:k], u[n:k])   # 学生自己滚到 X̄_k
u_k = runge_kutta(teacher, x_k, t[k], h[k])    # 老师在这算平均速度
loss = mse_loss(u[k], u_k.detach())         # 纯 MSE
```

推理侧更短（Algorithm 1）：

```python
x_n = randn(*shape)
h = diff(t, dim=0)
for n in range(0, len(t) - 1, step=L):
    u = student(x_n, t[n])                  # 一次前向
    u_n, h_n = u[n:n+L], h[n:n+L]
    x_n = x_n + einsum('k,k...', h_n, u_n) # 一步跨过 L 个区间
return x_n
```

### 架构：只动末端线性层

![图 4：预训练流模型的架构，backbone 后接单个 Linear 层输出瞬时速度](https://www.mulanai.com/fs/files/1124_12660dc9_teacher_.png)

*图 4（论文 Figure 4a）：老师模型的标准形态，$x_n$ 和 $t_n$ 进 Backbone，过一个 Linear 输出 $v_n$。*

假设老师是 $v_t(x)=W\,H_t(x)$，$H_t$ 是 backbone，$W$ 是末端线性层。PDD 保留同一个 backbone，把 $W$ **复制成 $N$ 份**（$N$ 是整个网格大小，不是块大小 $L$）：

$$\bar u_n^\theta(k\mid x_n)=W_k^\theta\,H_{t_n}^\theta(x_n)$$

![图 5：并行解码器训练时的架构，backbone 后接 N 个 Linear W_0…W_{N-1}](https://www.mulanai.com/fs/files/1124_b6299cd7_student_.png)

*图 5（论文 Figure 4b）：Backbone 的输出同时喂给 $W_0$ 到 $W_{N-1}$，每个头产出一个区间的平均速度。所有头都从老师那一个 $W$ 初始化，改动量小到有点可爱。*

这里有个我觉得挺精巧的取舍：用 $N$ 个头而不是 $L$ 个头，是为了让**同一个模型支持任意块大小**，不用像 flow map 那样再引入第二个时间坐标。训练时设 $L_{\min}\le L_{\max}$，块起点取 $L_{\min}$ 的倍数，$k$ 在 $[n, n+L_{\max}-1]$ 里采，一个 checkpoint 就能在推理时选 2/4/8 NFE。

更妙的是推理时的**层融合**。既然块步只用到速度的加权和，那 $N$ 个线性层可以在部署前先加权平均成一个：

$$W^\theta_{n:n+L}=\sum_{k=n}^{n+L-1}\Delta_k W^\theta_k,\quad \Delta_k=\frac{t_{k+1}-t_k}{t_{n+L}-t_n}$$

$$\bar X_{n+L}=\bar X_n+(t_{n+L}-t_n)\,W^\theta_{n:n+L}H^\theta_{t_n}(\bar X_n)$$

![图 6：推理时把多个线性层融合成单个 W_{n:n+L}，直接输出整块的加权平均速度](https://www.mulanai.com/fs/files/1124_af1d5879_student_.png)

*图 6（论文 Figure 4c）：红色的输出框写着 $\Delta_n\bar u_n(n|X_n)+\dots+\Delta_{n+L-1}\bar u_n(n+L-1|X_n)$，就是融合后一步跨整块的意思。也就是说放大末端层只发生在训练期，线上服务每个块只需常驻一个线性层。*

### 为什么不需要 JVP

这段是论文里我认为最值钱的理论直觉，得单独聊。

Flow map 类方法要学"从 $t_n$ 一步跳到 $t_{n+L}$"的映射，训练时得对这个映射求导，于是离不开 Jacobian-vector product 或者有限差分——贵，而且在 14B、22B 这种规模上显存很痛。

PDD 的观察是：共享 backbone $H^\theta_{t_n}$ 其实已经在学 $[t_n,t_{n+L}]$ 区间的平均速度表示了，只是我们**用 $L$ 个可学习的线性映射 $W_k^\theta$ 把这个平均速度拆成了 L 个并行子区间预测**。训练时梯度穿过共享 backbone，在期望意义上就把"学整段平均速度"的信号还回来了。于是 JVP 被一组线性头替掉了，有限差分也不需要。

作者还专门用 Figure 17 验证了学生不是只学到一条直线：把 PDD 的块内轨迹曲率跟老师轨迹曲率放一起比，两条曲线形状相似，都在 $t\approx0.05$ 之后快速衰减到接近 0，说明学生在块内确实学到了弯曲的、非平凡的路径。我看到这张图才把"并行"这两个字理解到位——并行的是预测，不是把轨迹压平。

![图 7：PDD 与 Teacher 的平均曲率随时间变化，两条曲线形状相似](https://www.mulanai.com/fs/files/1124_460108c9_pdd_vs_t.png)

*图 7（论文 Figure 17）：横轴 Time 0–1，纵轴 Average Curvature。红色 Teacher 起始接近 0.095，蓝色 PDD-Midpoint 约 0.048，两者都在前段陡降、尾段略微回升。PDD 只统计块内曲率，作者想证明的是"块内不是直线"。*

### 三条路线的横向对比

论文 Table 1 给了一张很干净的对照表，我照着整理一下：

| 维度 | Eulerian/Lagrangian Flow Maps | Pi-Flow | PDD |
|---|---|---|---|
| 推理 NFE | 可变 | 固定 | 可变 |
| JVP / 有限差分 | 需要 | 不需要 | 不需要 |
| 推理时的输出头 | Linear | Gaussian mixture | Fused-linear |
| 蒸馏对象 | 连续 flow map | 瞬时速度 $v$ | 离散平均速度 $u$ |
| 额外时间坐标 | 需要 | 不需要 | 不需要 |

说实话，PDD 跟 Pi-Flow 的血缘关系比作者写的还要近一点：两者都注意到"给定初值，块内轨迹完全确定"，Pi-Flow 拿这个观察去设计一个小的策略头做积分，PDD 拿它去做并行预测 + 更硬的监督。差别落在"表达力换成训练简洁度"这个取舍上，属于同一条脉络上的重新参数化，不是另起炉灶。这点我后面还会提。

### 没有数据怎么办

大规模文生图/文生视频那几个实验，作者用的是 data-free 训练：不采样真实数据，直接从噪声 $X_0\sim p_0$ 出发，边用学生自己的输出往前滚、边在这些状态上算 PD loss，推状态的时候加 stop-gradient，不多花显存。论文 Algorithm 3 是这版伪代码。

这个设计挺务实——高质量视频数据集本来就难搞，能不依赖数据就把 22B 模型蒸出来，工程上省掉一整套数据管线。但后面我会说，它同时也是这篇文章最大的一个未验证前提。

## 🧪 实验：数字好看，但得会看

实验铺了四块：ImageNet-256 类条件生成（SiT-XL+REPA）、Qwen-Image 20B 文生图、Wan2.1 1.3B/14B 文生视频、LTX-2.3 22B 文生视频+音频。训练上统一的三个旋钮是时间网格 $N$、Runge-Kutta 近似方式（Euler / Midpoint）、以及 $L_{\min},L_{\max}$ 决定的可用 NFE 集合。ImageNet 用 $N=128$（Euler）/ $N=64$（Midpoint），NFE 覆盖 1/2/4/8；文生图与视频用 $N=256$（Euler）/ $N=128$（Midpoint）加 shift 时间重参数化，Qwen-Image 和 Wan2.1 支持 2/4/8 NFE，LTX-2.3 支持 4/8。为保证公平，Midpoint 需要两次老师评估，作者就让 Euler 在每个块内累积两个区间的 loss。

这个表我盯了一会儿。PDD 单步 2.69，比 Pi-Flow 的 2.85 好，但离 FreeFlow 的 1.45 差了一大截——差不多是 1.24 个 FID 点。作者的说法是"很有竞争力，同时目标更简单、还能多 NFE 推理"，这个辩护成立，但别把"单步 SOTA"记到它头上。

还有个细节值得吐槽：8 NFE 的 FID 比 4 NFE 还差。作者自己的解释是可以用更低的 guidance scale 缓解，代价是低 NFE 时 FID 变高（附录 Figure 8）。说到底，**一个 checkpoint 共享所有 NFE 是要有折衷的**，权重共享不是免费的。这跟很多"可变步数"方法的通病一样，只是作者比较坦诚，把曲线摆出来了。

### Qwen-Image：整体分赢，人类偏好输

论文 Table 3 / Table 4 把 2/4/8 NFE 都跑了，我挑关键行整理（OneIG-EN / DPG-Bench / GenEval 都是 overall，越高越好；$*$ 是作者对官方 checkpoint 的复评）：

| 方法 | NFE | OneIG-EN | DPG-Bench | GenEval | HPSv2 | PickScore | OneIG diversity |
|---|---|---|---|---|---|---|---|
| Euler 老师 | 50×2 | 0.537 | 88.30 | 0.86 | 30.83 | 22.78 | 0.200 |
| DMD2 (Lightning-step4-v2) | 4 | 0.524 | 88.25 | 0.85 | **32.34** | **22.98** | 0.095 |
| Pi-Flow | 4 | 0.533 | 88.11 | 0.85 | 30.94 | 22.67 | 0.182 |
| PDD - Midpoint | 4 | **0.538** | **88.66** | **0.86** | 31.33 | 22.86 | 0.174 |

三个"对齐/质量"类 benchmark 上 PDD 都拿到最好或并列最好：4 NFE 的 DPG-Bench 88.66、8 NFE 的 OneIG 0.541，GenEval 全程 0.86，跟 50×2 步的老师持平。这部分没水分。

但 Table 4 翻过来就有意思了：HPSv2 和 PickScore 这两个人类偏好指标，PDD 全程输给 DMD2（4 NFE 时 31.33 对 32.34，8 NFE 时 31.56 对 32.35）。作者的解释是 DMD2 有 mode collapse，所以 diversity 掉得厉害——OneIG diversity 0.095 / 0.109，PDD-Euler 8 NFE 是 0.198，差不多翻倍，几乎追平老师的 0.200。

这个对比我想多说两句。人类偏好指标偏爱对比度高、细节锐利的图，而 DMD 系蒸馏出来的过饱和输出恰恰在这类打分器上占便宜。所以"偏好输、多样性赢"不一定是缺陷，反而可能是论文最想让你看见的那件事。但反过来说，**多样性是拿 V-JEPA / 特征距离这类代理指标量的**，这跟人眼觉得花样多不是一回事。作者没有做大规模人工多样性评测，这块我觉得还留着口子。

### LTX-2.3：22B、带音频、250 次迭代

压轴实验是把 22B 的 LTX-2.3 蒸到 8 NFE，生成 10 秒 720p 带音频的视频。老师这边用了三重引导（视频 CFG 4.5、音频 CFG 7、跨模态引导 3、还有第 29 层的时空 skip guidance 2），一次生成要 $4\times30$ NFE；学生只跑 $N=256$ 的 Euler、8 NFE，训练 250 次迭代，而且完全 data-free。PD loss 对音频和视频 latent 分别算再取平均。

定量对比是拿 Gemini 3.1 Pro Preview 当裁判：从 ViMix 和 VidProm 抽 100 个 prompt，每个 3 个种子、每段 2 次打分，共 300 对配对比较，四个维度（prompt 对齐、视觉质量、运动质量、音频质量）按 1–4 分打。结果是 PDD 赢 142、平 35、输 123，平均分 2.62 对 2.59。

142 比 123。这个差距我得诚实说：**基本算打平**，说"on par or better"可以，说"明显更好"就过了。不过考虑到 PDD 没有用任何训练数据、只训了 250 次迭代就能跟官方蒸馏模型站到同一条线上，工程含义比这个分数本身更重。

### 消融与训练配置里藏的信息

- **Midpoint 稳赢 Euler**：作者明说 Tables 3/4/5 里 Midpoint 一致更好，图 8 的曲线也印证。多花一次老师评估换更准的平均速度，划算。
- **两个最敏感的超参**：时间重参数化和 batch size，batch 越大越好。Qwen-Image 用 AdamW、lr 1e-5、weight decay 0、batch 2048、无 EMA、训 3k 迭代，每 250 次评一次三个 benchmark 取平均最好的那次（Euler 选 1250，Midpoint 选 2250，shift $s=5$，CFG $w=4$）。
- **Wan 的 checkpoint 挑法很碎**：1.3B 训 250 次，Euler 在第 25 次最好、Midpoint 在第 225 次；14B short 训 250 次取第 200 次，long 训 3.5k 次带 EMA 0.99 取第 3k 次。这种"每 25 次评一次 VBench 挑最好"的操作，其实吧就是在跟评测噪声共舞，复现时得留神。
- **CFG 的小 trick**：作者发现在 CFG 的无条件项里跳过 backbone 的某一层能涨分，1.3B 跳第 10 层、14B 跳第 12 层。这类经验性修补让我对"方法完全不挑工程"的说法保留一点余地。
- **公平性的一处瑕疵**：rCM 那行标了 $\dagger$，是在专有 prompt 上的报告数字、没有 diversity 评测，因为没放 checkpoint；DMD2 那行是作者自己复现的。把不同来源的数字放进同一张表，作者用脚注交代了，但读表时还是得自己降权。

## 💡 我的判断

**最值钱的地方，是 loss 的极简和它带来的连锁反应。** 一个 MSE，一次学生前向 + 1–2 次老师前向，没有判别器、没有在线 critic、没有交替更新、没有 JVP。训练稳定性这件事在论文里没被大书特书，但对做过 DMD2 调参的人来讲，光"不用同时盯三个优化器"就够有说服力了。再加上末端线性层从老师直接复制初始化、推理时融合成单层、一个 checkpoint 覆盖 2/4/8 NFE —— 这套组合的工程落地成本低得反常。线上按延迟预算动态切 NFE，不用换模型，这条我觉得会被很多团队直接抄走。

**但它不是底层突破，得把位置摆正。** 把 JVP 换成一组可学习线性头、把瞬时速度换成离散平均速度、把 policy head 换成并行输出——每一步都是在同一条轨迹蒸馏脉络上做减法。Pi-Flow 的影子很明显，作者也承认 conceptually related；flow map 的 Lagrangian  formulation 在附录 C 里专门做了连接。这是漂亮的重新参数化 + 扎实的系统整合，不是新范式。我个人挺吃这一卦，但别指望它改朝换代。

**几个我认为没解决或者没说清的点：**

1. **单步能力并不强**。ImageNet NFE=1 的 FID 2.69 对 FreeFlow 1.45，差 1.24。PDD 的甜区是 4–8 NFE，1 步场景别指望它。
2. **多样性是相对 baseline 赢，不是绝对恢复**。Wan 1.3B 的 V-JEPA cosine 0.1032 对老师 0.1254，还差一截；而且这个指标是特征距离代理，不是人评。
3. **14B 上 Overall 没赢 AnyFlow**，4 NFE 差 0.03、8 NFE 差 0.12。摘要里的 SOTA 需要按"Quality 子项 + 多样性"来理解。
4. **共享权重跨 NFE 有折衷**，8 NFE 的 FID 反而比 4 NFE 高，作者靠调 guidance scale 打补丁。
5. **大规模实验全靠 data-free**。作者在结论里自己列为 future work：数据依赖设置下 PDD 会怎样，除了 ImageNet-256 之外没验证。"缺高质量数据集"是合理理由，但也可能掩盖了"有数据时这个方法是否还最优"这个问题。
6. **baseline 选择有点巧妙**：对比对象清一色是带 VSD 的方法，这恰好是 PDD 最容易显出多样性优势的一组。跟纯轨迹派在统一 prompt、统一 checkpoint 可得性下硬碰硬的比较，表里没有。
7. **CFG skip layer**、**每 25 次迭代挑 checkpoint** 这些细节说明它对工程调参仍有依赖，不是开箱即用。

**作者自己列的三条后续方向**我倒是挺认同：按置信度自适应选块大小（推理时先跑一次并行解码器，再决定这一步跨多远）、把并行解码推广到离散自回归模型、以及补上 data-dependent 的大规模实验。第一条尤其顺理成章——既然模型一次能吐出整个块的速度，那"看一眼再决定跨几步"几乎不加成本，这可能会变成后续一堆论文的起点。

**给工程同学的一句话**：如果你在做视频/图像少步蒸馏，且被 VSD+GAN 的训练抖动、显存和模式塌缩折腾过，arXiv:2607.26004 这套"复制末端层 + 纯 MSE + 层融合"值得花一个下午复现；它的复现门槛比 DMD2 低太多，LTX-2.3 那种 22B 规模 250 次迭代就能出结果，很能说明训练效率。但如果你要的是 1 步生图、或者要绝对追平老师的多样性，先把上面那几条折扣算进去再决定。

坦率讲，我读完最强烈的感受不是"这方法多强"，而是"原来那堆复杂的东西可以整个拿掉"。有时候一个方向往前走，靠的不是加东西，是敢减。
