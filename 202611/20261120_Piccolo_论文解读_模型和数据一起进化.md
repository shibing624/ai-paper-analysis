# Loss 降了，决策却错了：Piccolo 把模型和数据放进同一个进化循环

上周调一个路由模型的时候，我又碰到那个老毛病：训练集上的 loss 一路往下掉，曲线漂亮得像教科书，结果上线一测，正确率反而掉了两个点。当时我盯着监控面板愣了半天，第一反应是数据脏了，翻了一圈标注又没发现问题。后来才发现，是某一类样本被反复喂了太多遍，模型在"总分布"上越来越自信，在"具体该选哪个"上却开始犯糊涂。

所以当我翻到 arXiv:2611.24651 这篇 Piccolo，看到 Table 1 里那组数字的时候，说实话有点被戳中：目标—预测 KL 从 2.19 降到 0.66 再降到 0.64，单调下降，一点没反弹；同一批 341 道题上的净正确数却先涨了 78 道，紧接着又倒退 13 道。作者没把这个当成噪声划掉，而是顺着它把那一桶数据的配比从 5.36% 压回 5.14%。

这篇论文真正让我坐直身子的，不是它刷了个榜，是它把"这种说不清的倒退"变成了能被记录、能被复用、能被下一轮实验直接拿去用的东西。

## 核心摘要

Piccolo 是一族 0.8B 到 27B 的多模态决策模型，不给状态生成文字，只在一组候选答案上读出概率。它的做法是把模型能力和训练数据放进同一个递归自改进循环（RSI）：研究智能体分析模型行为、构造数据、跑实验，再用结果修正下一轮提案，语义切片和共享研究记忆把这些动作串成一条 lineage。27B 版本在 Decision Index Vision Full 拿到 75.59 登顶，9B 和 4B 分别是 68.35 和 67.46，三个尺寸都在各自参数档的 Private 榜排第一。整套探索跑了约 600 次实验、归档 647 次 27B 训练尝试、约 6300 个加速器小时，并从中提炼出三条反直觉结论：老 backbone 配好配方能赢新 backbone、定向数据能让 4B–9B 在特定工作流上逼近 27B、loss 持续下降可以和离散决策准确率脱钩甚至反过来伤害它。我的判断是，这篇的价值不在模型结构，也不在某个新算法，而在它把"怎么组织一轮又一轮的后训练实验"这件事做成了可复用的工程系统——是一次很扎实的规模化实证，不是底层突破，但比很多号称底层突破的论文更值得工程团队细读。

## 🎯 生成模型很会写，但真实系统卡在"做决定"

你有没有注意过，一个 Agent 系统里最贵、最慢、最容易出事的环节，往往不是"生成"，而是"判断"。

工具要不要调？这段上下文该不该压缩？这条数据该过滤还是保留？权限够不够？游戏里这一帧该跳还是该躲？这些都不是开放式的写作题，而是给你一个状态、一个问题、一组候选，让你在几十毫秒内给出一个可靠的选择。用生成式大模型干这活儿其实挺别扭：你得让它吐一段 JSON，再写解析器，再处理它偶尔自由发挥的格式，延迟和不确定性都堆在这一层。

Piccolo 走的是另一条路。它把一个训练样本定义成 $(s, u, C, q)$——$s$ 是状态（文本、图片或结构化观测），$u$ 是问题，$C=(c_1,\dots,c_K)$ 是有序候选集，$q$ 是候选上的目标分布。三种接口共用这套表示：**Choice** 在备选之间比较，**Noul** 用 yes/no 二选一，**Score** 在有序等级上打分。调用方拿到的是一个概率分布，可以直接选动作、卡置信度阈值，或者把没把握的样本升级给更慢的系统处理。

![图1：Piccolo 概览与 Decision Index Vision Private 榜单](https://arxiv.org/html/2611.24651v1/fig01_piccolo-overview.png)

*图1：左上是自改进闭环——研究智能体读决策反馈、改数据与训练、产出更新后的模型，再回到反馈；左下是推理时的"直接候选读出"，游戏、Agent harness、数据处理三类输入进 Piccolo，出来的是 A 0.12 / B 0.81 / C 0.07 这样的候选概率，直接选 B。右侧是 Decision Index Vision Private 榜：Overall 前十里 Piccolo-27B 以 70.97 居首，JDI-Decision V1 70.52、WeMM-JEV-27B 69.70 紧随；Below 27B 里 Piccolo-9B 65.04、Piccolo-4B 63.49 分列第一和第三。*

这套接口落到四个场景里，论文给了很具体的例子。

![图2：Piccolo 的四大应用域](https://arxiv.org/html/2611.24651v1/fig02_applications.png)

*图2：顶部是统一流水线——状态、问题、候选进 Piccolo，出来 Choice / score / noul 三类结构化响应。(a) 通用决策：判断"圆是否在方块左边"、读柱状图选最大类、从发票里读 Total $42。(b) 低延迟交互：Mario 的起跳时机、2048 的合并方向、绝区零的走位与战斗。(c) Agent harness：查订单时选 Web 还是 Email、草稿权限下能否保存、8 个完成 2 个待办时检查剩余文件。(d) 数据处理：丢空记录、先清洗再去重、Sales 120 / Costs 80 时请求税额。*

我喜欢这张图的地方在于，它没把"决策模型"包装成一个玄乎的新范式，就是把 Agent 里那些反复出现、又懒得为每题单独训一个分类头的小判断，统一成了一个接口。企业场景里敏感数据留在本地、游戏里要求几十毫秒响应、数据处理流水线里要求确定性输出——这三类需求凑在一起，确实不是生成式模型舒服的工位。

## 🧠 不生成文字，只读候选 token 的 logit

技术上怎么做到"一次 forward 就给概率"？论文第 2 节讲得挺干净。

Piccolo 由视觉编码器、connector、语言 backbone 加原生的语言模型头组成。全注意力块对 prompt 用双向注意力，混合架构里的线性注意力块保留原来的因果计算。构造输入 $x=\operatorname{compile}(s,u,C)$ 时，每个候选 $c_k$ 被分配一个单 token 标签 $\tau(k)$，连同描述一起摆进 prompt；图片经视觉编码器、connector 送进 backbone，可选的旁挂 OCR 模型把提取出的文字当成额外的图像关联观测。

关键在答案位置。backbone 产出隐状态 $h_\theta(x)$，原生 LM 头 $W_{\mathrm{LM}}$ 把它投影到词表 logits，Piccolo 只取每个候选标签对应的那几个 logit，在 $K$ 个值上做 softmax：

$$z_{\theta,k}(x)=[W_{\mathrm{LM}}h_\theta(x)]_{\tau(k)},\qquad p_{\theta,k}(x)=\frac{\exp z_{\theta,k}(x)}{\sum_{j=1}^{K}\exp z_{\theta,j}(x)}$$

训练目标是候选分布上的交叉熵，硬标签和软标签都能用：

$$\ell_{\mathrm{CE}}(q,p_\theta)=-\sum_{k=1}^{K}q_k\log p_{\theta,k},\qquad \ell_{\mathrm{CE}}-H(q)=D_{\mathrm{KL}}(q\|p_\theta)$$

第二条等号值得停一下。硬标签时它就是"正确答案的负对数概率"；软标签时减掉目标熵 $H(q)$，剩下的正好是目标与预测之间的 KL，把"监督本身有多不确定"和"模型猜得有多偏"拆开了。交叉熵是个 proper scoring rule，这给校准型监督留了口子。准确率另记一件事：正确候选有没有排到第一。

这两个信号后来成了整个 RSI 循环的眼睛。loss 看分布怎么变，accuracy 看离散决策对不对，两者不总是一伙的——Table 1 那个反转就是这么被抓出来的。

有监督之后还有两层精修：候选级强化学习用 correctness 奖励、group-relative 更新加监督回放来拧准确率；权重空间优化则直接改参数，靠 checkpoint 插值、参数投影缩放、从历史更新里抽方向来找更好的组合，不用每试一个候选就重跑一遍梯度训练。后者思路跟进化式模型合并那一路很接近，论文引了 Akiba 等人 2025 的工作。

## 🏗️ 663K 样本、43 个来源、551 个语义标签：先把数据变成地图

如果只把 Piccolo 理解成"一个读 logit 的模型"，那就漏掉大半了。它真正花力气的地方，是把数据池做成一张能按切片查询的地图。

![图3：数据准备、语义标注与组合](https://www.mulanai.com/fs/files/1120_7802f965_fig03_da.jpg)

*图3：(a) 数据准备——文本源池 6.65M 条记录、43 个来源（SNLI、ESCI、BoolQ、GoEmotions、ARC、AQuA-RAT 等），图文源（Geo170K、TextVQA、TQA 等），以及 Seed→Synthesis→Verifier 产出的 26 万条合成候选；下面统一走去重、审计去污、过滤整合、准入。(b) 语义标注——统一 schema 交给 Qwen 系列标注再校验，词表是 13 条轴、551 个可选值、334 个领域叶类、144 个能力叶标签，覆盖领域、能力、难度与价值 Lv1–5、以及 Choice / Noul / Score 三种任务形式。(c) 组合——池里 Text 47%、Image-text 53%；某个文本配方的领域分布是日常生活 54.7%、计算与技术 13.6%、数学与科学 12.7%、人文艺术社会 5.8%、其他 13.2%，能力上信息处理占 51.5%、推理 22.8%，难度 Lv2–3 合计约 77%，任务形式 Choice 58.8% / Noul 24.6% / Score 16.2%。底部给出训练池 663K 条：311K 文本 + 352K 图文。*

数字得对上：附录 C.1 列了 43 个初始文本来源集合，分成语言理解与检索对话 10 个、知识与推理 10 个、偏好与质量判断 5 个、动作与工作流 4 个、转换与合成决策 14 个。转成 $(s,u,C,q)$ 格式时，动作前提、相关性区分、图文对齐、原始监督分布都得留着，Data-Juicer 负责归一化、过滤、审计，重复项去掉，任务级审计把不完整和错误的数据修掉或剔除，覆盖不够的地方用 CuES 做合成。

标注这层是全篇的地基。13 条轴里，领域 334 个叶类挂在 26 个父组下，能力 144 个叶标签挂在 14 个父组下，另有任务功能 20 项、输入质量 3 档、验证方式 4 类、决策关系 4 类、挑战因素 11 项、输入缺陷 7 项、决策依据 6 类、目标结构 5 类、知识需求 3 档、难度 5 级、学习价值 5 级。约 210K 条样本进了这个语义视图。每条样本保留身份和来源，智能体顺着一个切片上的异常，能一路查回底层数据去检查、修订或定向合成。

我的第一反应是：这不就是给数据建了套"可观测性"嘛。以前我们看训练只有一个总 loss，现在每个领域×能力的桶都有 loss 轨迹、净正确数变化、样本曝光量。没有这张图，后面所有"按切片调配比"的动作都无从谈起。

顺带交代一下算力，免得对"600 次实验"没概念：附录 E 说归档的 27B 探索是 647 次训练尝试、约 6300 个 PPU-ZW810E 加速器小时，按每设备 123 TFLOP/s 的 BF16 参考峰值折算约 $2.8\times10^{21}$ FLOP、差不多 32 PFLOP/s-days。代表 curriculum 用 38 万或 70 万条样本，每套配方不到一百万条。这个量级不是"堆参数堆数据"，是"堆实验次数"。

## 🔧 RSI：把失败的实验当资产存起来

常规开发里，跑挂的训练就是沉没成本，删掉日志、清掉 checkpoint，当没发生过。Piccolo 第 3 节开头那句话我挺认同：把每次成功或倒退的实验都当成结构化的认知资本存下来。

目标写得很像一个有预算的搜索问题：

$$\max_{\psi_{1:T}}\;S_{\mathrm{dev}}(m_T^{\mathrm{best}};\mathcal{V})\quad\text{subject to}\quad\sum_{t=1}^{T}c_t\le B$$

$\psi_t$ 是一次实验提案，$B$ 是加速器小时预算，$m_T^{\mathrm{best}}$ 是 $T$ 次实验后（含起点）最好的模型。原子循环写成一串状态转移：

$$\mathcal{R}_{t-1}\xrightarrow{\mathrm{Propose}}\psi_t\xrightarrow{\mathrm{Experiment}}(m_t,\mathbf{f}_t,c_t)\xrightarrow{\text{Diagnose \& Update}}\mathcal{R}_t$$

$\mathcal{R}_t$ 里装着可用模型、带标注的数据资产、已完成的比较、研究记忆和剩余预算；$\mathbf{f}_t$ 是按语义切片汇总的学习动态、推理结果和数据统计。诊断把涨跌挂回切片和本次配置，更新把资产和结论写进共享记忆，并重新排提案优先级。

![图4：RSI 编排器](https://www.mulanai.com/fs/files/1120_5815d803_fig04_re.jpg)

*图4：左侧 Feedback signals——按"领域×能力"切成桶（例子是 Computing × Numerical calculation），同一个桶里能看到三种截然不同的学习曲线：A 快速下降（查冗余和采样）、B 持续高位（查难度和标签质量）、C 来回波动（查倒退和冲突）；Tags / Loss / Outcome 靠 sample ID 串起来，可回捞对应样本。中间是 Agent-led research loop 四步：找问题 → 定下一次试验 → 构建并跑 → 复盘涨跌，人类设目标与预算、研究智能体提并跑试验、Audit 查数据与结果。下方 Data-Juicer Sandbox 把发现落成四类数据动作：去冗余、再平衡、修样本、补缺口。右侧在同一 held-out set 上比较候选，A 有涨就留、B 证据不足再比、C 某些能力倒退就改；Research memory 记下管用的数据与方法、待修任务、下一步实验。底部 Data-Juicer Panel 管着五类共享资产：反馈、数据与标签、方法与配方、评测规则、lineage 与经验。*

这张图我看了两遍。它把"研究"这件事拆成了可编排的组件，而不是一句"让 Agent 自己做实验"就完事。四个数据动作——downsample 冗余样本、rebalance 配比、revise 冲突标签、synthesize 覆盖不足的能力——都挂在具体的反馈信号上，不是拍脑袋。

最硬的证据是 Table 1，就是开头让我坐直的那组数：

| 阶段 | Mean KL 变化 | 341 道题净正确数变化 | 混合配比变化 |
|---|---|---|---|
| 前段 | 2.19 → 0.66 | +78 | 4.69% → 5.36% |
| 后段 | 0.66 → 0.64 | −13 | 5.36% → 5.14% |

KL 一路降，正确率先猛涨后回吐。只盯训练 loss 的人会以为还在变好，编排器却据此把这一桶的权重往下压。论文里那句"Relying solely on training loss can blindside data allocation"说得一点不客气，我认。

再给个完整案例，Figure 5 追踪的是真实训练里的一次再平衡：

![图5：数据再平衡的一次真实迭代](https://www.mulanai.com/fs/files/1120_a91e2768_fig05_it.jpg)

*图5：P1 用 80% replay + 20% 检索补充从父模型 M0 训出 M1，艺术类分数从 55.19 掉到 52.66；回捞选中数据发现艺术题只占 3.1%，诊断 K1 就把"艺术覆盖"定为下一轮目标。P2 从同一个 M0 出发，共享 replay 组、学习率和种子，比了两条路：D2a 只补知识（512 组、5824 题，Arts 占比 3.4%）得 M2，D2b 知识艺术各补 256 组（6720 题，Arts 占比 20.6%）得 M3。底部柱状图能看到 D2b 里 Arts 那一块明显变宽。结果 M3 比 M2 整体高 0.30 分、艺术高 0.70 分，K2 记下结论并保留与 M0 仍存的差距，留给后续提案。*

这个案例好看在"可比"两个字上：共享父权重、共享 replay 组、共享学习率和种子，只动数据配比，0.30 和 0.70 才敢归到数据头上。Table 2 把这种可比性写成了规矩：

| 组件 | 一次比较内固定 | 不同提案间可变 |
|---|---|---|
| 数据 | 池版本、组 ID、准入规则 | 选择、配比、合成、新来源 |
| 训练 | 父权重、目标、优化器、schedule | 父模型、目标、学习率、合并 |
| 评测 | 题目、评分、推理设置 | 输入排布、诊断队列 |
| 研究 | 目标、对照组、设备与时间 | 分析工具、优先级、后续动作 |

提案不是随便排的，按预期提升、保留技能、信息价值、成本四项打分，短诊断先消歧，长跑留给有苗头的方向；人类研究者设优先级、审重大变更、引入新方法和数据源。验证分三层：开发集看涨没涨、不相交确认集看迁移、广泛评测看整体，审计再查样本有效性、输入版本和评测完整性。

## 🔬 数据和模型是怎么一起进化的

第 4 节那句定调我挺喜欢：后训练通常被当成"在静态数据配方上优化一个动态模型"，Piccolo 把它改写成耦合动力系统——模型的能力边界一移动，最优数据分布和配方就得跟着移。某个配方在早期 checkpoint 或某一代 backbone 上加速学习，换到另一处可能直接引发倒退。

数据侧分三步走，论文标成 D1、D2、D3。

**D1 覆盖**。留出集反馈加语义标签定位缺口，替换掉早期配方里 10% 的数据，开发分 56.56，对照的等量随机替换只有 54.45，差 2.11 分。后来补回覆盖不足的偏好类，arts/preference 从 48.91 抬到 53.42。稀疏切片走两条路：自动采集加去重脱敏，或从已验证种子做模型引导合成。合成完还得验难度——Table 10 里状态跟踪通过率 63.43%、参数校验 100%、预算分配只有 15.38%，后面这个明显还是硬骨头，留给下一轮加难例。

**D2 分配**。结构化反馈给的是目标—预测 KL 和留出题上的正确数变化，据此做 Filter & Rebalance。固定配方 Public Text 是 67.36，再平衡后 67.93；再加过滤，Harness 84.58、Data 82.20，但 Text 回落到 66.98。三种数据动作长出三种能力画像，没有哪一套通吃。

**D3 联合配方**。把通用决策、依赖图像的任务、工作流补充和既有技能回放合到一起训，OCR-aware SFT 让监督对齐推理时能拿到的图像文字。一个 Qwen3.6-27B 后代从 Vision 71.89 到 79.59、Harness 68.64 到 81.36、Data 73.20 到 81.40，涨幅都在 7 到 13 分这个量级。

![图8：配方—模型交互](https://www.mulanai.com/fs/files/1120_16e9c8dd_fig08_re.jpg)

*图8（论文 Figure 9）：(a) 联合配方训练前后，Vision +7.70、Harness +12.71、Data +8.20，弧线标出每一项的位移。(b) 同一套配方、同一数据顺序，三个 27B 初始化横向比：Qwen3.5（圆点）在 Vision 上最靠右、约 79.97，Qwen3.6（方块）79.59，Qwen3.8（三角）77.86；Harness 那一行反过来，Qwen3.8 冲到约 85.93，把 80.85 和 81.36 甩在后面。横轴是"同一配方之后的分数"。*

这张图是三条反直觉里第一条的直接证据。新 backbone 不等于样样更强，视觉任务和 Agent harness 任务给出的排序几乎是反的。模型和配方得成对选，按部署目标来定，而不是按发布年份来定。

模型侧对应 M1、M2、M3。

**M1 训练选择要配得上监督**。双向注意力得训练和推理一起改：Text 开发分 69.01，全因果是 68.20，只在推理时改双向 68.14——单独改一头基本白费。目标和数据权重也一起进化，同一个父模型、同一批样本、同一更新预算下，固定权重 GRPO 到 77.13 Public Vision，候选 CE 到 77.31，置信度/进展加权的 GRPO 到 77.35。

**M2 组合把互补能力捏起来**。Table 4(a) 的跨模态合并：文本向父模型 68.53 / 73.16，图文父 67.89 / 77.29，保留视觉模块、把语言参数按 25% 混进去得 67.94 / 76.92，混 50% 得 68.15 / 75.70——Text 涨了 0.26，Vision 赔了 1.59。Table 4(b) 走另一条路，用参考候选分布补监督：

| 训练目标 | Vision | Harness | Data |
|---|---|---|---|
| Parent | 77.38 | 84.24 | 82.60 |
| 原始目标续训 | 77.09 | 84.92 | 82.20 |
| + 精确匹配 | 77.07 | 84.92 | **82.80** |
| + 采样匹配 | 77.07 | 84.92 | 82.40 |

*表3：Table 4(b) 候选分布整合，精确匹配把 Data 抬了 0.60，Harness 不动，Vision 几乎不动。*

权重空间编辑也进了搜索：把 9–17 块的视觉注意力投影调强约 5%、8–23 层 FFN 输出稍作衰减、后段门控注意力块加对数衰减偏移、30–31 层输出投影加 rank-8 更新，合起来 Public Vision 从 70.10 到 70.75，代价是 Harness 掉 0.68。另外把五个数据专精后代合并，Public Text 从单支最好的 62.78 到 63.11。

**M3 推理侧的两类增益**。输入排布上，自适应重读 68.56 Public Text、输入量 1.02 倍；全量重读 68.64；两视图聚合 68.69 但要 1.90 倍输入，三视图 68.71 要 2.08 倍。层复用那边更有意思：两段相邻层各走两个半步，Text 开发分 69.15 到 69.75、Harness 80.85 到 87.12；只复用一段是 69.58，把步长砍到四分之一反而掉到 67.41。2B 的 Public Vision 靠另一套复发配置从 65.85 到 66.64。

我是真的觉得 M3 这组数比主表更有嚼头：涨分几乎都伴随代价，输入翻倍、跨任务回吐、步长敏感，没有免费午餐。

## ⚠️ 三条反直觉，以及它们到底有多"反直觉"

摘要里那三条是整篇论文最想让人记住的东西，第 5 节给了展开。

![图11：跨任务响应](https://www.mulanai.com/fs/files/1120_5ce8dff5_fig09_tr.jpg)

*图11（论文 Figure 11）：(a) 权重不变、只重排输入布局，两个 case 里 Text 分别 +1.14 和 +0.90，Data 却是 −2.00 和 −3.00，虚线是零基线。(b) 固定数据池上重复训练，横轴累计样本曝光到 1.00M（正文说 11 个 checkpoint、1.024M 次曝光），Data 慢慢爬到 +0.60，Text 掉到 −1.29、Harness 掉到 −1.69。涨和跌同时存在。*

**第一条，backbone 与配方共适应压过模型新旧**。同一套数据顺序下 Qwen3.5 的 Vision 79.97 高过 Qwen3.6 的 79.59 和 Qwen3.8 的 77.86，Harness 上 Qwen3.8 又以 85.93 反超。买新不如配得对。

**第二条，定向数据整理让 4B–9B 在特定工作流上逼近 27B**。这句得小心读。9B 的 Harness 71.53、Data 72.40，4B 是 66.10 / 70.20，而 27B 是 84.41 / 82.60——同尺寸横向比确实把 D3、Valen 拉开了，但离 27B 还有十几分。论文自己在摘要里用的词是 "rival 27B baselines on specialized workflows"，限定在专门工作流，不是全面追平。要是有人把这句读成"4B 干翻 27B"，那是读岔了。

**第三条，loss 持续下降可以和离散决策准确率脱钩，甚至反过来伤害它**。Table 1 的 +78 后 −13 是最扎眼的证据，5.2 节那组更系统：固定池上堆到 1.024M 次曝光，Data +0.60，Text −1.29，Harness −1.69。动态整理数据比延长静态训练更省算力，这句我信，因为我开头那个线上事故就是静态喂太多遍喂出来的。

再说 5.1 那个"单基准优化掩盖跨任务退化"：只改输入布局、权重一个字没动，Public Text +1.14，DataJevBench 掉 3.00。这里我得承认一处没完全看懂——图 11(a) 两个 case 标的是 Text +1.14 / +0.90、Data −2.00 / −3.00，正文 5.1 却把 +1.14 和 −3.00 并在一句话里，可能引的是不同 case，也可能我理解有偏差。但结论不受影响：跨任务验证不是可选项，是提案筛选的必选项。

还有个我挺喜欢的点，5.3 里那句"失败分支藏着可用性"：有一条续训分支在开发集上比父模型还差，把它参数更新里的某些分量抽出来、乘个负系数，反而拼出了一个赢的权重合并。这要求把父 checkpoint、参数 delta、切片级响应全留着——也就是整篇一直强调的 lineage。

老实说，这三条对做过后训练的人都不算陌生。loss 和准确率脱钩、多任务互相拖、老模型配好数据能翻盘，工程里多少都撞过。Piccolo 的贡献不是"首次发现"，而是用 600 次实验、带切片证据和具体数字，把这些散落的经验钉成了规律，还配了一套能自动执行它们的系统。这个定位我觉得比硬蹭"底层突破"要诚实。

## 💡 我的判断

**这篇值钱的地方在哪？** 不在模型结构。候选 logit 读出、双向注意力、GRPO、模型合并、层复发，单拎出来都不是新东西，论文自己第 5.4 节也把 Mammoth / Elephant、Drex、StartLux、进化式合并、MOPD、Agentic Data Engineering、Darwin Gödel Machine 挨个列了。它做的是把这些缝成一条能自己转的流水线，再用五个尺寸、六百多次实验把"缝法"验了一遍。

| 工作 | 侧重 | 与 Piccolo 的关系 |
|---|---|---|
| Mammoth / Elephant（Kirkby 等 2026） | 数据配方 + 双向注意力 | 决策模型前置工作，Piccolo 沿用接口思路 |
| Drex（Dhankhar 等 2026） | 监督 + 强化学习 | 同样是基础决策模型，未做数据—模型协同进化闭环 |
| StartLux（Zhuang 等 2026） | 置信度引导的审慎决策 | 偏推理侧，JevBench 上 93.94 高于 Piccolo |
| MOPD（Ma 等 2026） | 多教师 on-policy 蒸馏做能力整合 | 启发了 Table 4(b) 的候选分布整合 |
| Agentic Data Engineering（Ding 等 2026） | 反馈驱动的智能体数据工程 | Piccolo 编排器的方法来源 |
| Darwin Gödel Machine（Zhang 等 2026） | 开放式自改进智能体 | 更偏"改代码"，Piccolo 偏"改数据与配方" |

放在这张表里看，Piccolo 更像一次**工程整合 + 规模化实证**：把研究循环本身当成可扩展对象，而不是把某个模块做到极致。论文结论里那句 "it requires scaling the research loop itself" 是这个意思，我认这个自我定位。

**几个让我皱眉的地方，也得说。**

榜单可比性得留个心眼。Full 是 Public 和 Private 等权平均，Private 不公开，各家 Public 与 Private 的落差又差得很大（Valen 1.5 27B 是 82.90 对 63.68，Piccolo-27B 是 80.22 对 70.97）。Public 那 11 个任务的权重也不是均分——R-Bench-M 0.5、MMMU-Pro Vision 0.25，其余单位权重，权重怎么定的正文没展开。再加上榜单快照 11 月 17 日、投稿 11 月 18 日，只差一天，86 个参赛者里还有 "pending submission" 的标记。75.59 对 75.05 的 0.54 分优势，放在这套计分规则里，我不太愿意当成鸿沟。

因果归因没那么干净。附录 D.4 自己承认，Figure 8 那几条分支"起始参数状态不同、且同时改了多个数据配比"，展示的是完整研究路径的结果，不是单变量消融。所以"再平衡让 Text 到 67.93、加过滤让 Harness 到 84.58"这类结论，严格讲是路径级观察，不能当成一个数据动作的净效应。Table 4 和 Figure 5 那种共享父权重、共享种子、只动一处的设计就干净得多，两相对比反而显出前者的粗糙。

复现门槛是另一个现实问题。13 轴 551 值的标注体系、43 个来源的数据池、647 次训练尝试、6300 加速器小时、还有贯穿全程的共享研究记忆——权重和工具开源了，但中间实验资产和记忆库是否公开，正文没讲清。对大多数团队来说，"actionable blueprint" 更像是读方法论，不是照着跑一遍。这不是缺点，是这类工作的天然边界，但读的时候得有数。

还有个偏产品视角的疑问：0.8B 和 2B 只报了 Public 分，没进 Full 排名，Harness 也只有 51.19 / 56.10。真要塞进端侧做工具审核或权限判断，这个水平离可用还差一截。尺寸—质量前沿画到了 0.3B，但那里没有 Piccolo 的点。

## 📝 落到工程上，能带走什么

如果你也在做 Agent 系统，我觉得这几条是能直接挪过去的：

路由、权限、工具审核、上下文压缩这类高频小判断，别再让生成式模型吐 JSON 再解析了。一次 forward 读候选 logit 拿概率，延迟、确定性、可校准性都更好，还能顺手用置信度阈值把没把握的样本升级给慢系统。Piccolo 把这套接口做成了 `/v1/systemone` 式的原生调用，思路比具体权重更值得抄。

训练监控别只挂一条总 loss。按"领域×能力"切片记两条线：目标—预测 KL，和留出题上的净正确数。Table 1 那个 +78 转 −13 的反转，只靠总 loss 是看不见的。这个改动成本很低，收益很直接。

单基准涨分先做跨任务回归再合入。Figure 11(a) 那组里权重没动、只换个输入排布就敢让 Data 掉 3 分，这种坑在真实系统里通常会以"上线后某个下游指标莫名变差"的形式出现。把跨任务验证做成提案筛选的硬门槛，比事后回滚便宜。

失败实验别急着删。父 checkpoint、参数 delta、切片级响应留全，某些倒退分支的更新方向乘个负系数就能拼出赢的合并。这条我在自己项目里没试过，看着有点反直觉，但论文给了具体 lineage，值得找个周末验一下。

还有一条选型经验：数据与 backbone 要成对评估，别默认新 backbone 一定更好。同一套配方下 Qwen3.5 / 3.6 / 3.8 在视觉和 Harness 上给出了近乎相反的排序，按部署目标定组合，比按发布时间定组合靠谱。

收尾前再留个没解决的问题。Piccolo 把"研究循环"自动化到了 600 次实验的规模，但提案的排序标准——预期提升、保留技能、信息价值、成本——里，"信息价值"怎么量化、研究记忆怎么避免把早期偶然结论固化成教条，正文没给答案。循环转得越快，这个偏差放大的风险越高。快速 System-1 决策模型配上审慎 System-2 推理，论文在展望里提了这个方向，我觉得真正的难点不在模型怎么合，而在"谁来判断这一轮该不该继续沿着老经验走"。

这篇我会留着当后训练工程的手册翻，不当成新范式的宣言读。它没改变什么底层规则，但它把一堆大家隐约知道、又懒得系统记录的工程直觉，变成了有数字、有切片、有 lineage 的东西。对天天跟数据和 checkpoint 打交道的人来说，这个比一个漂亮的榜首有用。
