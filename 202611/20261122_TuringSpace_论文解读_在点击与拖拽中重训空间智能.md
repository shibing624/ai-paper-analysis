# 看错一张截图，几万 token 都在替它圆谎

把一张 3D 渲染的房间图丢给多模态模型，问它「沙发要怎么绕过走廊拐角」，它能给你写一段相当体面的分析：先退半步，再转个方向，注意别蹭到门框。读起来像个搬家老手。

然后你让它真的上手。

在浏览器里给它一张截图，让它用鼠标把沙发拖过去。第一下拖进墙里，截图刷新，它看了一眼，接着又往同一个方向拖了一下。再刷新，再拖。你盯着屏幕会有点恍惚：刚才那段头头是道的分析去哪了？

我做截图理解相关的调参时，对这个场面不陌生。模型能把画面描述得花团锦簇，一旦要它根据画面决定「下一个动作点在哪」，输出就飘了。更邪门的是，你让它多想一会儿，它往往不是把错改掉，而是把错的理由写得更完整。

arXiv 上这篇 2611.25387 让我停下来的原因就在这儿。它没有再去刷一个更漂亮的分数，而是把这件有点尴尬的事摆到台面上，量了量尴尬到底有多深，还顺手给了个能批量制造训练数据的解法。

---

## 🎯 先把结论摆这儿

多模态模型在 2D 感知上已经很像样，但「从一张平面图里恢复 3D 结构、预判一个动作会怎么改变它、看到结果再纠正自己」这条闭环，一直是塌的。现有的空间基准基本是选择题，模型可以靠排除法蒙对；允许动手的那些，动作又退化成「turn left」这样的文本命令，或者直接把网页 DOM 摊开让模型挑一个带标签的元素。

TuringSpace 的做法是把每个任务写成一个**程序**：125 个交互式空间 CAPTCHA，覆盖五类空间能力，必须靠点击、拖拽、逐帧推进来解，每个程序自带检查器和标准答案，换个随机种子就能生成一道全新且自动可判分的题。于是这套东西既是榜单（TuringSpace-Bench），又是能无限产出带标注轨迹的训练场（TuringSpace-Gym）。

数字挺扎眼。人类解出 94.1%，最强模型 GPT-6 Astra 解出 74.1%（也就是仍失败 25.9%），最好的开源模型 Kimi K3 只解出 32.0%（失败 68.0%），专门训练来操作 GUI 的 Agent 几乎全军覆没，最好的也只有 3.5%。作者把 Qwen3.5-9B 放进这个训练场微调，成功率从 1.6% 拉到 33.1%，反超 Kimi K3；更关键的是七个分布外基准全部上涨，连真实室内视频的 VSI-Bench 都涨了 9.9 个点。

但我觉得这篇论文最值钱的不是那 31.5 个点。是它把失败拆开看了一遍：多数错误来自**读错截图**，而模型随后的长篇推理很少纠正这个错误信念，反而会编造画面里根本不存在的细节去替它辩护。这个发现比刷分有意思得多。定位上它不是底层架构突破，是把「可验证的环境生成」和「失败行为分析」这两件事缝得相当利落的一篇工程整合；值得细读，但别当成空间智能被解决了。

## 🤔 为什么这事值得较真

CAPTCHA 这个东西的命门，是它必须永远卡在「人轻松、机器不行」的那条线上。扭曲文字、九宫格选图、拖滑块，这些老题型早被自动化 Agent 刷穿了，于是验证码得往新能力上挪。空间理解是个自然的去处：把一张立方体展开图折起来会变成哪个方块、场景里那个人能看见什么，人类扫一眼就有答案，模型却经常翻车。

问题是挪过去之后，测法没跟上。

作者把现有工作的毛病归得很清楚，我用自己的话捋一遍。其一是**选择题化**：Spatial CAPTCHA 也好，多数空间基准也好，答案是 A/B/C/D，模型可以猜、可以排除，答对不等于真看懂了场景。其二是**动作符号化**：少数允许交互的基准，动作是文本命令「turn left」，或者干脆把页面 DOM 暴露出来，Agent 只是在一堆带标签的元素里点一个——这测的是检索，不是空间推理。其三是**GUI 题被刷穿**：真支持鼠标交互的那几个，谜题本身太简单，CUA 已经能高成功率通过。

这三条的共同的毛病，是把空间认知当成了一次性判断。可人不是这么干活的。你搬沙发过拐角，是看一眼场景、预判这一推会怎样、推、看到卡住了、退回来转个角度、再推。每一步动作都暴露了你此刻对场景的信念，每一张新截图都是一次纠正机会。一个点击指定了位置，一次拖拽指定了方向和距离，一串动作指定了场景该怎么演化——选项表达不了这些。

说实话，这个论证我认。我之前调 GUI Agent 时也碰过类似的坑：给模型一张截图让它输出坐标，它答得挺像回事，可一旦把「上一次点错之后的新截图」喂回去，它经常假装没看见，继续按原来的假设走。当时的归因是「视觉反馈没进上下文」，看完这篇我怀疑更根本的原因是信念一旦形成就很难被推翻。

于是 TuringSpace 的立题就很直白了：造一批**必须靠连续动作、且每一步都能看到反馈**的空间谜题，看看模型到底差在哪。

## 🏗️ 把「一道题」写成「一个程序」

一句话讲清核心想法：每个任务不是一张固定的图加一个固定答案，而是一个生成器程序。喂进去一个随机种子和一组素材，吐出来一整套东西——网页初始状态、指令、检查器、标准答案动作序列。

用论文里的记号写就是：

$$x = G_{\tau}(z,\mathcal{M}) = (s_0,\ q,\ C,\ a^{\star}_{1:L})$$

这里 $\tau$ 是种子任务，$z$ 是随机种子，$\mathcal{M}$ 是素材池，$s_0$ 是页面初始状态，$q$ 是指令，$C$ 是检查器（终局状态对了返回 1，否则 0），$a^{\star}_{1:L}$ 是从初始状态走到 $C(s_L)=1$ 的标准动作序列。换个种子，布局、物体、视角、答案全变，但这道题考的那项空间能力不变。

这个设计的连带好处特别实在：既然标准答案是程序算出来的，那把它在页面上重放一遍，就自动得到一条**每一步动作都配着执行后截图**的轨迹 $\xi=(q,o_0,a^{\star}_1,o_1,\dots,a^{\star}_L,o_L)$，而且只有检查器判通过的轨迹才留下。标注成本为零，数据量没有上限，格式还和评测时模型看到的一模一样。Benchmark 和 Gym 是同一套程序的两种用法，这件事想通了，后面所有实验就都顺了。

![论文 Figure 2：TuringSpace 总览](https://arxiv.org/html/2611.25387v1/teaser.png)

*论文 Figure 2，整篇论文的地图。上半部分是五类任务各两个例子，每个都给出指令、起始态、解出态和动作类型标签（tap / drag / step）：A 空间关系里有「按她看到的视角把绳结拖到对应刻度盘」「选出坐着的人能看见的所有杯子」；B 闭环操作里有「转动管道直到 A 连上 B」「滑动拼块复原图案」；C 多步规划里有「把插销摆成和照片一致」「把沙发搬进卧室」；D 心智变换里有「点出折起来会变成红色边的那条边」「点出这个展开图能折成的所有立方体」；E 时空推理给的是逐帧推进的小片段，比如「过河到对岸」和「有多少人进去后没出来」。左下是任务生产流水线，右下是排行榜（人类 94.1 分、平均 33.1 秒一题作为绿色虚线基准，GPT-6 Astra 74.1 分居模型首位）。*

五类能力不是随便分的，它们按「读结构 → 在脑子里变换 → 带反馈地动手 → 不带即时反馈地规划 → 跟踪时间」逐级加码：

| 类别 | 考什么 | 交互形态 |
|---|---|---|
| 空间关系理解 Spatial relation | 遮挡、包含、支撑、另一个人能看见什么 | 在固定场景里点选 / 标记 |
| 心智变换 Mental transformation | 旋转、折叠、切割、换视角，页面不展示这个过程 | 在固定场景里点选 |
| 闭环视觉操作 Closed-loop manipulation | 旋转、移动、对齐物体，每步看结果再纠正 | 连续动作，每步有新截图 |
| 多步规划与模拟 Multi-step planning | 滚动、坠落、反射光路，单步结果看不出对错，得提前规划避免死局 | 连续动作，反馈滞后 |
| 时空推理 Spatiotemporal | 逐帧推进最多 16 帧，跟踪或预测运动中的物体与人 | 一次一帧地推进 |

前两类是「看懂」，中间两类是「动手」，第五类把时间也加进来。时空推理成了所有强模型最头疼的一类，GPT-6 Astra 在这类只有 52.0%，也是它唯一不是第一名的类别（被 Claude Opus 5.5 超过）——后面会再聊这个。

![任务实例：起始状态](https://arxiv.org/html/2611.25387v1/figures/cases/S045_0.jpg)

*论文里给出的一个任务实例起始态：棋盘格地面上摆着彩色方块、圆锥、球和圆柱，彼此有前后遮挡。这类题目要求模型从一张 2D 图里判断物体的空间层次关系，而不是数颜色。*

![任务实例：答案被标出的状态](https://arxiv.org/html/2611.25387v1/figures/cases/S045_1.jpg)

*同一实例的解出态，蓝色轮廓圈出了被选中的目标物体。注意解出态靠的是程序里的检查器判定，不是人眼打分——这正是「可无限生成」的前提。*

### 任务是怎么造出来的

这部分我觉得比模型榜单更该看，因为它决定了这套基准可不可信。

任务点子来自已有空间基准、认知测验、日常空间活动，以及和 LLM 头脑风暴。然后由 Claude Code 配 Claude Opus 5.5 在一个共享的页面运行时上写出任务程序。素材池 $\mathcal{M}$ 是人工收集的开放许可照片、纹理和 3D 模型，来源包括 Open Images、COCO、Poly Haven、ambientCG，程序从中取样来变化物体和外观。

写完之后要过一道多轮审核，每轮三关，任何一关不过就退回给编码 Agent 改。第一关是程序化检查：每个任务跑 100 个种子，要求实例渲染无 bug、同一 seed 能完全复现、标准答案能解出来，而且**什么都不做或者乱点几乎不能蒙过**。第二关让 Claude Sonnet 5.5 试玩一次，作者审它的轨迹找「不用空间理解也能过」的捷径。第三关两位作者亲自玩，确认没 bug、人类能无歧义地轻松解出。

「乱点不能过」这一条我挺喜欢。很多合成基准翻车就翻在检查器太松，模型靠乱试就能刷分；这里把猜测通道提前堵上，后面「模型答对=真懂一点」的推断才站得住。

### 训练与测试怎么隔开

评测集和训练集用同一批生成器，只是 seed 和素材池不同：$\mathcal{D}_{\text{test}}$ 用三个随机选定的测试种子 $\{36,43,50\}$，$\mathcal{D}_{\text{train}}$ 用 $\{1,\dots,N\}$。为了防泄漏，作者叠了三层：训练跳过那三个测试 seed；素材池完全不相交（$\mathcal{M}_{\text{train}}\cap\mathcal{M}_{\text{test}}=\varnothing$）；跑完轨迹后，凡是空间配置的哈希和评测实例撞上的训练实例一律丢弃。

坦率讲，这三层做得比多数合成数据论文仔细。但「同构生成」这件事本身没法靠哈希完全消掉——训练和评测毕竟出自同一 125 个程序、同一套渲染风格，后面聊 in-domain 涨幅时我会再把这个疑点拎出来。

### 微调怎么做的

训练数据：每类任务跑 500 个实例，时空类只跑 200 个（它们的轨迹轮次大约是别的类的 2.3 倍），合起来 **55,000 条经过验证的标准轨迹**。每条轨迹的每个动作拆成一轮，观测是上一张截图，目标只有工具调用。

训练在 thinking-off 设定下做，目标就是对这些动作 token 求交叉熵：

$$\mathcal{L}(\theta)=-\frac{1}{Z}\sum_{l=1}^{L}\sum_{t=1}^{|a^{\star}_{l}|}\log p_{\theta}\big(a^{\star}_{l,t}\mid h_{l-1}, a^{\star}_{l,\lt t}\big)$$

$h_{l-1}$ 是到当前为止的交互历史，$Z$ 是目标 token 总数。语言模型参数全量更新，**视觉编码器冻住**。

等等，冻住视觉编码器这个设定值得停一秒。如果失败的主因是「读错截图」（论文后面自己也是这么论证的），而训练时视觉塔一动不动，那涨的 31.5 个点到底来自哪里？我的理解是：语言侧学到了「在这类页面里，看到这样的画面该发起什么动作」的映射，视觉特征本身没被重新校准。这也部分解释了为什么模型在心智变换（21.3%）和闭环操作（16.0%）上仍然很弱——那两类最吃细粒度视觉判读。这块我自己也不是特别确定，原文的讨论没展开到这一层，算个开放问题。

## 🧪 16 个模型、1920×1080 截图、50 步上限

评测设置得说清楚，不然数字没法比。所有模型都用各自官方的 computer-use 实现跑在 OSWorld 里，系统提示词只做最小改动（删掉关于虚拟机的句子，加一句授权解 CAPTCHA），动作格式保持官方原样，同样的指令、同样要求点页面上的「Verify」提交。截图统一 1920×1080，一次尝试最多 50 步，采样参数按模型卡或 API 默认值。可调推理强度的模型一律跑 medium，理由是人类过一道验证码大约半分钟；Kimi K3 没有 medium 档，跑 high。

人类基线是三位没参与造题和审核的作者，各在一个不同测试种子上把 125 道题全玩一遍，只算首次提交。每个任务三个测试实例，模型各玩一次，共 375 次尝试；pass@1 是三次种子的平均成功率，pass^3 是三个实例全部解出的比例，衡量的是稳定性。

**pass^3 掉得比 pass@1 狠得多**。 GPT-6 Astra 从 74.1% 掉到 58.4%，人类只从 94.1% 掉到 84.8%。模型常常在一个实例上解出来了，换个种子生成的新实例就翻车。这比平均分低更能说明问题：它不是「偶尔失手」，是没形成稳定的空间理解，靠的是某个特定布局下的巧合。

**GUI Agent 集体哑火**。 专门训练来操作界面的 EvoCUA-32B、OpenCUA-32B、UI-Venus-2-9B、UI-TARS-1.5-7B、ReCAP-32B-Instruct，全部在 0.5% 到 3.5% 之间。其中 UI-Venus-2-9B 和 ReCAP-32B-Instruct 还是专门训过常见 CAPTCHA 的。看到这个数我有点怀疑评测是不是对它们不公平——毕竟它们用的是 OSWorld 官方实现，未必是各自的最佳配置，50 步上限对需要来回试探的谜题也偏紧。但五六个模型齐刷刷趴在地板上，很难全用配置问题解释。

**开源与闭源的裂缝大得反常**。 Kimi K3 和 Qwen3.8-Max 分别是 2.8 万亿和 2.4 万亿参数，却都低于除 Gemini 3.8 Flash 之外的所有闭源模型。参数量在这里几乎不解释方差，这个现象后面第五节给了一个挺有意思的解释。

**9B 反超 250 倍于它的模型**。 Qwen3.5-9B 微调成 TuringSpace-9B 后，从 1.6%（thinking-off 的 base）到 33.1%，pass^3 从 0.0 到 12.8，在两项上都压过 Kimi K3、Qwen3.8-Max 和 Gemini 3.8 Flash，逼近 Claude Sonnet 5.5。但请顺手看一眼那行细粒度：空间关系 53.3、时空 44.0 还行，心智变换 21.3、闭环操作 16.0、多步规划 30.7 依旧很矮。它学会的更像是「在这类网页上该怎么点」，离「通用空间智能」还差着一截。

## 📊 从合成网页搬到真实客厅

训练用的是渲染出来的网页谜题，一张真实照片、一段真实视频都没进训练集。作者挑了七个分布外基准来试探迁移，其中两个还是 CAPTCHA，剩下五个考的是空间理解、视频和机器人指向。

| 基准 | 测什么 | Qwen3.5-9B (Base) | TuringSpace-9B (SFT) | Δ |
|---|---|---|---|---|
| TuringSpace-Bench（域内） | 空间 CAPTCHA | 1.6 | 33.1 | **涨 31.5 个点** |
| ReCAP | 7 类常规 CAPTCHA | 56.4 | 73.6 | **涨 17.2 个点** |
| Open CaptchaWorld | 19 类常规 CAPTCHA | 26.9 | 36.9 | **涨 10.0 个点** |
| SpatialViz-Bench | 心理旋转 / 折叠 / 投影（选择题） | 28.1 | 34.2 | 涨 6.1 个点 |
| VSI-Bench | 真实室内视频里的方向 / 距离 / 大小 | 50.5 | 60.4 | **涨 9.9 个点** |
| RefSpatial-Bench | 按空间关系定位物体与空位 | 38.3 | 58.1 | **涨 19.8 个点** |
| VABench-Point | 机器人该在哪儿下手 | 35.7 | 43.1 | 涨 7.4 个点 |
| RoboAfford-Eval | 物体哪个部位可供抓握 | 67.6 | 79.8 | **涨 12.2 个点** |

（论文 Table 2；域内那行是 in-domain，其余七行才是 OOD，正文说的「七个分布外基准都有提升」指后面这七行。）

有个方向性的结论挺漂亮：学空间 CAPTCHA 能顺带把常规 CAPTCHA 也带起来（ReCAP 涨 17.2、Open CaptchaWorld 涨 10.0），尽管 TuringSpace 里压根没出现过那些题型；反过来，专门训常规 CAPTCHA 的 Agent 在 TuringSpace 上几乎零分。这个不对称说明「空间」是更难、更底层的那层能力，学会了往下兼容。

真正让人愿意多信一分的是跨模态那几行。VSI-Bench 的输入是真实房间的视频，机器人三个基准输入是真实工作区的照片，和训练时的卡通网页完全不是一回事，却都涨了，RefSpatial-Bench 甚至涨了 19.8 个点。论文 Figure 3 里给的例子很直观：基座模型听到「把胡萝卜放到盘子上」，就往指令里点名的物体（胡萝卜、剪刀）上指；微调后的模型指的是**动作真正生效的位置**——空位、盘子、该抓的把手。这个差别不是记题型，是把「动作会改变场景的哪里」学到了。

![论文 Figure 3：从网页谜题到真实场景](https://arxiv.org/html/2611.25387v1/sft_cases.png)

*论文 Figure 3。左侧是 TuringSpace-Gym 的一条训练轨迹，指令「Get the red car out through the exit」，step 1 到 step 5 逐次拖开挡路的车辆，solved 帧里红车从 EXIT 驶出——全程没有用任何机器人数据，每一步拖拽后模型都看到新截图再决定下一步。右侧是六个分布外基准的零样本案例：Open CaptchaWorld 的「选出所有含船的图」、SpatialViz-Bench 的立方体左视图、VSI-Bench 的冰箱朝向判断、RefSpatial-Bench 的「指出瓶子、瓶盖和剪刀之间的空位」、VABench-Point 的「把胡萝卜放到盘子上」、RoboAfford-Eval 的「水壶该抓哪个部位倒水」。红叉是 Qwen3.5-9B 的答案，蓝圈是微调后的答案，绿框标出正确区域。*

不过我得给这份兴奋降降温。ReCAP 和 Open CaptchaWorld 毕竟还是 CAPTCHA，和训练域没那么远；SpatialViz-Bench 涨 6.1 个点、VABench-Point 涨 7.4 个点，幅度不算大；VSI-Bench 从 50.5 到 60.4，绝对值离可靠还远。而且这是纯 SFT 的零样本迁移，没有在目标域上做任何适配——涨得动说明学到了可迁移的东西，涨得不多也说明合成网页和真实场景之间那道坎还在。作者自己也没把话说满，结论落点是「可以被学会、可以迁移」，不是「已经学会」。

## 🔬 最值钱的部分：模型是怎么把自己绕进去的

如果只看前两节，这篇论文容易被读成「又一个合成数据刷分」。真正让我坐直了的是第五节的三组分析，它们把「模型为什么不行」拆到了能观测的行为粒度。

### 想得更久，不等于想得更对

先看一个反直觉的相关性。十个模型在 medium 强度下，平均思考 token 数的对数与 pass@1 **负相关**（Pearson $r=-0.75$，$p=0.01$），与 pass^3 也负相关（$r=-0.82$，$p=0.004$）。最强的 GPT-6 Astra 每次尝试平均只用 319 个思考 token，Kimi K3 用了 24,015 个，成绩只有 32.0%。

那强模型强在哪？作者换了个量法：把任务按十个模型的平均失败率排序，算每个模型在**最难四分位**和**最易四分位**上的思考量之比。GPT-6 Astra 是 2.3 倍，Claude Fable 5.1 是 2.0 倍，Gemini 4 Argon 1.9 倍，Claude Opus 5.5 1.8 倍；而 Claude Sonnet 5.5、Gemini 3.8 Flash、Qwen3.8-Max 都不超过 1.07 倍。这个比值与 pass@1 的相关性是 $r=0.82$（$p=0.004$），与 pass^3 是 $r=0.83$（$p=0.003$）。

一句话：强模型不是想得多，是知道该在哪些题上多想。弱模型在简单题和难题上花几乎一样长的推理，大部分算力喂给了根本不需要它的题。把推理强度从最低拉到最高也只对部分模型管用——Claude Sonnet 5.5 从 29.6% 升到 74.4%，GPT-6 Sol 从 28.8% 升到 52.8%，GPT-6 Astra 从 67.2% 升到 83.2%，但 Gemini 3.8 Flash 从头到尾卡在 29.6% 到 33.6% 之间。

![论文 Figure 4：思考量与成功率](https://www.mulanai.com/fs/files/1122_a03c5a60_analysis.png)

*论文 Figure 4，由原文 SVG 转换。(a) 推理强度缩放：横轴是每次尝试的思考 token 数（对数尺度，标了 low 和 xhigh），纵轴 pass@1，不同颜色的线是不同模型。(b) 十个模型在 medium 强度下的思考量与成功率，实心圆是 pass@1、空心标记是 pass^3，整体呈「想得越多分越低」的走向。(c) 最难/最易四分位思考量之比与 pass@1 的散点和拟合线，标注 Pearson r = 0.82, p = 0.004。*

### 错误信念一旦成形，推理就成了辩护律师

这节是全篇我最喜欢的地方。作者收集了 Kimi K3、Qwen3.8-Max、Qwen3.8-27B 在 seed 36 上的 293 次失败尝试——挑这三个是因为它们思考最多，而且开源、能拿到完整推理链。先人工读了一批轨迹，归纳出「每次失败都源自一个决定性的错误信念」和三种维持它的行为，再用 Claude Opus 5.5 按这套模式给全部尝试打标签；一位作者抽查 50 条，一致率 92%。

结论读起来有点凉：

**错误信念成形得极早**：68% 在前两步就形成，那时中位数尝试才写完 18% 的思考 token。也就是说后面超过五分之四的推理，全建在一个错的地基上。**质疑几乎人人有，翻案寥寥无几**：89.4% 至少质疑过这个信念一次，可最终只有 7.5% 放弃；切到正确信念的 6.5% 里，几乎都是屏幕显示谜题已经无解了（比如下错一步直接结束）才「看见」错误。

更扎心的是「想出正确答案却不采纳」。只有 19.8% 的失败尝试推理到了正确解，而在这 58 次里，有 36 次模型又退回了最初那个错误信念。论文举的例子特别具体：一道问方块落在哪一格的题，模型算出了落点、也把它写成了结论，却因为「拿不准下落高度」提交了它第一步选的格子。问题不在找不到新解，在**不肯接受**新解。

![论文 Figure 5：错误信念的传播与辩护行为](https://arxiv.org/html/2611.25387v1/belief_propagation.png)

*论文 Figure 5。(a) 错误信念的瀑布图：100% 形成错误信念 → 89.4% 曾质疑 → 19.8% 推理出正确替代方案 → 7.5% 最终放弃 → 6.5% 纠正但为时已晚；底部标示各分支落点，10.6% 从不质疑、69.6% 停在怀疑、12.3% 仍然拒绝、1.0% 换成另一个错误信念。(b) 三种替错误信念辩护的行为在三个模型失败尝试中的占比：靠幻觉的先验经验决策（81 / 84 / 41）、编造观察来贴合信念（65 / 65 / 86）、不确定就点 Verify 当探针（51 / 64 / 51），三色分别是 Kimi K3、Qwen3.8-Max、Qwen3.8-27B。*

三种辩护行为在全部 293 次失败里的占比：**74% 编造观察**（报告一个截图里根本没有的细节，好让画面描述和自己的信念对上）、**66% 靠幻觉出来的先验经验决策**（假定这类题「一般怎么做」，据此脑补一条解法路径，尽管屏幕从没这么说）、**55% 盲目提交当探针**（没把握就点 Verify，指望拿到额外反馈和第二次机会）。

而这三种行为在「最该改主意」的时候最凶。在那 36 次「推理出正确解却拒绝」的尝试里，编造观察占 86%、幻觉先验占 89%、盲目提交占 81%；在 31 次「从不质疑信念」的尝试里，同样三项只有 55%、16%、32%。按每个模型内部思考 token 从最短到最长四分位切，编造观察从 58% 涨到 85%，幻觉先验从 41% 涨到 85%，盲目提交从 36% 涨到 74%。

看到这组数我是真愣了一下。长推理在这里干的事，不是拿新证据去校验旧信念，而是替旧信念找补，而且想得越长找补得越起劲。这刚好把上一节的负相关解释通了：思考量与成功率负相关，不是因为「想」本身有害，是因为在这些模型上，「想」主要花在了巩固一个开局就错了的读图上。

### 瓶颈在眼睛，不在手

再问一句：最强的三个模型（GPT-6 Astra、Claude Opus 5.5、Gemini 4 Argon）的 385 次失败，剩下的是什么？作者标注了其中 380 次（另外 5 次因为 Gemini 4 Argon 反复拒答丢掉），按感知、推理、交互三组十条根因归类。

**感知错误是最大头**，占 57.1%。视觉反馈也救不回来：闭环操作和多步规划这两类任务每走一步都会给一张新截图，可在这类任务的 129 次失败里，仍有 85 次是感知错误导致的。反过来，**没有任何一次失败来自 grounding 能力不足**——比如把坐标点错位置这种。

这个结论和上一节严丝合缝：模型不是不会点、不会规划，是**第一眼就把画面读错了**，后面的推理再长也只是在给这个错误搭支架。作者把话说得很克制，落点是「空间感知是前沿模型在这些任务上的主要瓶颈」。我愿意再往前推半步：如果瓶颈在感知，那么「让模型多想」这条当前最流行的提分路径，在这类任务上收益天花板会很低，甚至可能反噬。这一点对做 Agent 的人比任何一个榜单分数都实用。

## 💡 我的判断

亮点我说透了，再说说让我皱眉的地方，顺带把它放回同期工作的坐标系里。

**它到底新在哪**。 空间 CAPTCHA 不是它先做的——Spatial CAPTCHA 测过视角采择和心理旋转，只是停在单选；Next-Gen CAPTCHAs 做过动态谜题，但部分依赖动画或限时点击，截图传达不了。程序化生成验证码更是老套路，ReCAP、CaptchaArena、CaptchaMind 早就用生成器批量产题训 Agent。VSI-Bench、SpatialViz-Bench 这类空间基准，以及 OSWorld 这套 CUA 评测协议，都是现成的。

| 工作 | 交互形式 | 程序化生成 / 自动判分 | 主要缺口 |
|---|---|---|---|
| Spatial CAPTCHA 等空间基准 | 单选题 | 部分有 | 答对可猜，不要求动作 |
| 交互式空间 / 具身基准 | 文本命令（turn left） | 视具体实现 | 动作被符号化，测不到定位与轨迹 |
| ReCAP / CaptchaWorld 等 | 真实 GUI | 有，但题型常规 | 已被 CUA 刷穿 |
| Next-Gen CAPTCHAs | 动态 / 限时 | 有 | 依赖动画和计时，截图无法表达 |
| **TuringSpace**（2611.25387） | **点击 / 拖拽 / 逐帧，标准 CUA 协议** | **有，且带 oracle 与检查器、可无限生成** | **任务域仍是合成网页** |

所以它的位置不是「首个空间 CAPTCHA」，而是第一次把「交互式 GUI 动作 + 可验证 oracle + 无限实例 + 训练闭环 + 失败行为归因」这几块拼齐。拼齐本身是有价值的工程判断，尤其 checker 和 oracle 让评测与训练共用一套真值，省掉了整条标注链。但剥开包装看，底层没有新模型、新损失、新架构，训练就是最普通的动作 token 交叉熵 SFT。别把它读成方法突破。

**几个我不太买账的点**。

其一，**没有消融**。原文没有给出「去掉某一类任务」「换 backbone」「轨迹数量 scaling」这类对照，我上面也没法编一张出来。能拿来近似对照的只有三组现成差异：thinking on 的 base 是 2.4%、thinking off 是 1.6%；Qwen3.5-9B 微调后 33.1% 与 Qwen3.5-27B 基座 5.9% 的间接对比；以及 Table 1 里五类能力的细粒度分数。想判断「哪一类任务贡献了迁移」「55,000 条是不是过拟合甜点」，原文给不了答案。对一篇主打「训练场」的论文，这个缺口不算小。

其二，**125 道题的来源有偏**。任务由 Claude Code 配 Claude Opus 5.5 写、Claude Sonnet 5.5 试玩找捷径、两位作者终审。审核很扎实，但「人类能轻松解出」是由三位作者（不是众包普通人）验证的，平均 33.1 秒一题。任务分布会不会隐含着「对 Claude 系模型友好 / 对别的模型不友好」的偏向，原文没讨论。以及那个 +31.5 的域内涨幅，训练和评测出自同一批生成器，即便做了 seed、素材、哈希三重隔离，风格同构带来的便利也没法完全排除——拿它论证「学会了空间智能」要留一分余地。

其三，**绝对值还很低，而且短板恰好在最该涨的地方**。33.1% 离人类 94.1% 差了 61 个点；微调后的模型在心智变换 21.3%、闭环操作 16.0% 上依旧趴着，而这两类恰恰最依赖细粒度视觉判读。结合「视觉编码器冻结」和「瓶颈在感知」这两个事实，我更倾向于认为它学到的是动作策略与页面先验，而不是被重新校准的空间感知。这一点原文没展开，可能我的理解有偏差，但值得作为后续工作的靶子。

其四，**只做了模仿，没做试错**。训练轨迹全是 oracle 的标准解，模型从没在训练里体验过「做错 → 看到反馈 → 纠正」。可论文自己反复强调空间认知是「感知—动作—纠错」闭环。一个只见过正确示范的学生，凭什么学会纠错？我猜换成带错误恢复的轨迹、或者在这个可判分环境里跑一轮 RL，提升空间会更大——环境已经现成带 checker 了，不做 RL 有点可惜。

**但这些都盖不掉它最硬的那个贡献**。 它把「模型读错截图后，长推理会编造证据替错误辩护」这件事，从一句吐槽变成了带分母、带标注、带一致性检验的量化结论：293 次失败、68%、89.4%、7.5%、74%、66%、55%，还有随推理长度单调上升的三条曲线。这种分析比多刷几个点更难得，因为它直接指向「该改模型的哪一部分」。

## 🔗 收个尾

如果你也在做 GUI Agent 或者多模态推理，我觉得有三条能马上用上。

把**可自动判分的环境**当一等公民。一个自带检查器和标准答案的程序，等于同时买到了评测集、无限训练数据和零标注成本，还顺手堵死了乱点蒙分。这个思路不局限于空间题，凡是能写出终局判据的任务都值得这么造一遍。

**别把思考 token 数当进度条**。 至少在截图驱动的任务上，先查第一眼读图对不对，再谈推理长度；把算力按难度分配（GPT-6 Astra 那个 2.3 倍的难/易比）比无脑拉满 reasoning effort 更划算。

**失败分析要落到行为标签，不要停在分数**。 「57.1% 是感知错误」「74% 编造观察」，这种结论能直接变成改动项；「模型在某榜低 20 个点」不能。

还剩两个我自己也没想明白的问题。一个是 CAPTCHA 的宿命：既然任务是程序化生成的，等模型也学会刷这批 generator，下一个「人轻松、机器不行」的能力该往哪儿挪？另一个是合成到真实的边界——网页上拖方块学到的东西，涨了 VSI-Bench 9.9 个点，那这 9.9 个点买到的是「空间感」还是「更会看画面」？论文给不出答案，但把问题摆得足够清楚了。

想继续抠细节的话，原文在 https://arxiv.org/abs/2611.25387 ，附录里有完整训练配置、七个基准的输入模板、失败根因分类表和各模型的系统提示词，比正文耐看。
