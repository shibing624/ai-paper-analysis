# 换个准入规则，最强的模型反而输了：EviCraft 把 Agent 评测里的"工具偷看"摆上台面

你有没有碰到过这种事——你搭了个 Agent，在基准上跑出来的分数挺好看，可盯着运行日志看半天，总觉得哪里不对：它根本没在「找」东西，它好像……早就知道东西在哪。

我读 EviCraft 摘要的时候就是这感觉。一句 `mineBlock(diamond_ore)` 丢下去，一块埋在地下、Agent 从没见过的钻石就被挖出来了。你以为测的是搜索能力，实际上测的是工具替它翻了模拟器的底牌。

---

## 核心摘要

这篇论文抓的是一个几乎所有 Minecraft Agent 都踩过的坑：语义工具（比如 `mineBlock`）内部会直读模拟器已加载的世界状态，不做视线检验，于是「埋着的矿」离 Agent 只有一次调用的距离，分数根本看不出它有没有搜索过。作者把缺的那条要求形式化成**证据闭合**——Agent 系统的每个决策，连工具内部选目标、规划路径那一步，都只能通过 Agent 手里握着证据的事实去依赖世界。EviCraft 是一套运行时加基准，把闭合强制放在 Agent 之下，并把「准入规则」做成实验变量：感知接地 G 只接纳视线内或自身动作返回的内容，已加载状态 L 复刻标准工具栈。数字挺扎心：G 下三个中等规模模型只有 32%–40% 的运行摸到钻石，L 下是 76%–94%；G 下最强的模型得分低于 L 下每一个中等模型。我的判断是，这不是一篇「Minecraft 又刷榜」的论文，而是一篇关于评测有效性的方法论工作，Minecraft 只是载体，真正值钱的是「工具信息泄漏」这个能迁移到任意工具栈的通用机制，以及把它做成可测量变量的那套协议。值得细读，但别指望它顺手解决搜索问题。

## 🎯 一、那句让我愣住的调用：mineBlock 到底算不算一个动作

先从最反直觉的地方聊起。

在 Minecraft Agent 这套栈里，我们习惯把工具当成「手脚」：`goto`、`mineBlock`、`craft`，模型负责想，工具负责做。但作者一句话把这个直觉掀了——

> A call such as `mineBlock(diamond_ore)` is not a motor command.

它不是运动指令。进去之后，是一段手写的例程在查询客户端已加载的 chunk，挑一个匹配的方块，**没有视线检验**，然后走过去挖掉。也就是说，工具自己完成了「在哪儿」「怎么走」这两个本该由策略回答的问题，而且它条件依赖的是 Agent 从未感知过的模拟器状态。

顺着这个口子往下捋，你会发现这不是某个项目的疏忽，是整条工具栈的默认行为。论文 Table 6 逐个 commit 核对了主流系统的目标选择代码：

| 系统 | 目标选择调用 | 范围 |
|---|---|---|
| Voyager | `bot.findBlocks` | 32 |
| Odyssey | `bot.findBlocks` | 32 |
| ADAM | `bot.findBlock` | 32 |
| MineLand | `bot.findBlocks` | 48 |
| MP5 | MineDojo voxel grid | 5 |

基于 Mineflayer 的那几个，`bot.findBlocks` / `bot.findBlock` 遍历客户端已加载 chunk 的方块，不做视线检验；作者还特意说，Mineflayer 4.8.1 和 4.14.0 里这段函数体一模一样，恰好是这些系统允许或锁定的版本。MP5 换了个花样，控制器直接从 MineDojo 的体素观测里挑移动目标，那是一份从世界拷出来的方块网格，同样没有遮挡过滤。

说到这个，得把 Voyager 那篇 2023 年的老账翻出来对一下。当年 Jim Fan 团队用 GPT-4 加技能库，160 轮迭代发现 63 种物品，是唯一解锁钻石工具的方法，把 ReAct、Reflexion、AutoGPT 甩在身后（ReAct 和 Reflexion 160 轮连铁器都没摸到）。它的消融也做得漂亮：换成随机课程掉 93%，去掉自我验证掉 73%。当年读的时候我把这些数字当成「LLM 会探索、会积累技能」的证据。现在 EviCraft 提醒你一个尴尬的可能：Voyager 的技能库里那些 `mineBlock` 调用，找到的钻石里有多少是模型自己搜出来的？

坦率讲，我不觉得这否定了 Voyager 的贡献——技能复用、自动课程、代码即动作这些设计依然是真的。但「解锁钻石工具」这个最出圈的结论，含金量得重新称一称。评测里的高光时刻，可能有一部分是接口送的。

## 🧠 二、把「证据闭合」讲成人话

### 三个 read site，漏的是第三个

作者把世界事实进入 Agent 系统的位置拆成三处，这个拆分我觉得是全文最有用的一把刀：

- **Push**：系统塞进模型输入的东西，提示词或相机画面；
- **Query**：模型主动发起的、问世界的请求；
- **Tool**：动作执行期间的读取，以及动作随后汇报回来的东西。

已有的防护基本都压在前两处。MP5 加了主动自我视角感知，ADAM 把元数据从规划器输入里摘掉，MineLand 限制相机视距并让模型只查视野内的方块——这些管的是「模型看到什么、问什么」。可工具那一处一直敞着，于是接口能把 Agent 看上去该自己解决的搜索问题，替它解决掉。

论文 Table 1 把这点摆成一张对照表，我简化成下面这样（✓ 表示 released code 里限制在可感知状态，– 表示没有限制或只靠提示词约束）：

| 系统 | 搜索方 | 输入形态 | Push | Query | Tool |
|---|---|---|---|---|---|
| MineRL / VPT | 策略 | RGB | ✓ | n/a | n/a |
| JARVIS-1 / Optimus-1 | 策略 | RGB | ✓ | n/a | n/a |
| Voyager | 工具 | Text | – | – | – |
| Odyssey | 工具 | Text | – | n/a | – |
| MP5 | 工具 | RGB+text | ✓ | ✓ | – |
| ADAM | 工具 | RGB+text | ✓ | n/a | – |
| MineLand | 工具 | RGB+text | ✓ | – | – |
| **EviCraft** | 工具 | RGB+text | ✓ | ✓ | ✓ **逐 site 可配** |

一列看下来，规律很直白：策略类系统（学出来的策略直接吃像素）天然没有工具泄漏，因为压根没有「帮我找 X」这种语义接口；一上语义工具，Tool 那一栏就全空了。这不是巧合，是语义工具的定义里就藏着一次世界读取。

### 形式化：一个知识状态，一条非干扰条件

作者用显式的知识状态替掉对模拟器状态 $x_t$ 的隐式读取。regime $\rho$ 是一条准入规则，从每个世界事件 $\xi_t$（可见性的变化、一次接触、一个动作的结果）更新一组记录：

$$
K_{t}^{\rho}=\mathcal{U}_{\rho}\left(K_{t-1}^{\rho},\xi_{t}\right) \tag{1}
$$

一条记录保存「某个方块或实体上一次被接纳时的状态」和「接纳的 tick」。这里有个我挺欣赏的细节：一个格子是 known block、known air，还是 **unknown**，「没有证据」被显式表示出来，而不是默认成空气。工具必须绕开 unknown 去规划。自状态（位置、血量、背包）始终可用，模型还能要第一人称画面，那画面只显示从眼睛看得见的表面。

证据闭合的定义给得很干净：

> 一个 Agent 系统在 $\rho$ 下是证据闭合的，当且仅当它的每个决策——为模型拼装的观测、每次查询的结果、工具内部选的每个目标与路线、工具返回的每个结果——只通过 $E_{0:t}^{\rho}$ 依赖世界。

等价的说法更好用，是一条**非干扰条件**：同一个 Agent，两个世界 $x$ 和 $x'$ 若直到 $t$ 诱导出相同的证据历史，那么 $t$ 时刻每个决策的分布都相同。你没证据的事实，不许影响你的行为。

有个边界得说清：闭合约束的是决策，不是动力学。碰撞、伤害、方块破坏照常在 $x_t$ 上跑；动作反馈要先经过准入规则进 $K^{\rho}$，才被允许影响下一个目标、路线或返回值。还有个措辞容易绕进去——作者把 leak 定义成「G 下的闭合被违反」，并且说 L 下的系统本身是闭合的、但在这个意义上「在漏」。我第一次读卡了一下，其实就是把 G 当作应然基准，凡是从 G 看属于特权的信息都叫泄漏。

### G 和 L：只差一个字段

- **感知接地 G**：靠「看见」和「接触」两种证据接纳外部事实。每个 tick 从眼睛向全球面投射射线，接纳 64 格内每条方向上第一个遮挡面、它前方的空气、射线够到的实体；被 Agent 破坏、放置、触碰、或与记录矛盾的方块立即更新。识别是精确的——被接纳的方块带着它的真实类型。走动时的采样召回率是地表 97.9%、洞穴 99.7%，记录 400 tick 没再看到就丢掉。作者自己管它叫「理想化的视觉传感器」：全向、不受光照、类型精确标注，只受遮挡和采样召回限制。附录里连实现都写死了——每面 $32\times32$ 方向共 6144 条射线，每 tick 固定 $2\times10^{6}$ 个工作单位预算，低差异序列抖动让连续扫描交错成更细的覆盖，玻璃/冰/水/可穿行植物不截断射线，树叶和岩浆会挡住后面。

- **已加载状态 L**：复刻 Mineflayer 客户端 chunk 缓存的语义。$K_t^{\mathrm{L}}$ 装着服务器当前投递给 Agent 的那些 chunk column 里的每一个方块和实体（四个 chunk 方向、贯穿世界全高），**无视遮挡**，记录跟着世界走，column 离开投递边界才被清掉。

G 和 L 的差别落在三处：遮挡、范围、留存。而这套设计最妙的一点，是每个 read site 可以单独挂自己的规则，配置是一个三元组 $(\rho_{\text{push}},\rho_{\text{query}},\rho_{\text{tool}})$。全 G 就是 $(\mathrm{G},\mathrm{G},\mathrm{G})$；把 push 和 query 接地、只留工具读已加载状态，就是 $(\mathrm{G},\mathrm{G},\mathrm{L})$。固定 Agent、工具、世界，只翻这个三元组，你就能量出「特权信息对这个 Agent 值多少分」；只翻其中一位，就能定位这份价值从哪个口子进来。把准入规则做成实验变量，这个转身我确实觉得漂亮。

![图1：一个世界，一次调用，两种知识状态](https://arxiv.org/html/2611.32765v1/teaser.png)

*图1（论文 Figure 1）：左边 G 下，工具只知道 Agent 看过的东西，暴露的铁矿可见、埋着的钻石是「unknown」，`mineBlock(diamond_ore)` 返回 no known target，Agent 本该去搜索；中间 L 下，工具读的是已加载状态，连山背后的猪和埋着的钻石都标成 known，于是「目标找到、路线已规划」，Agent 从没见过它。右边两张小图是全文结论的浓缩：Flash 模型首次拿到钻石的到达率 G 下 35%、L 下 87%，中间那道断崖就是「搜索墙」；下面一行写着「泄漏住在工具里」——只让工具读真实状态就能补回 DeepSeek 70%、GLM 98% 的分差。*

## 🏗️ 三、把规则放到 Agent 底下

写进提示词的规则可以被忽略，写在 Agent 自己代码里的规则得为每个 Agent 重新审计一遍。所以 EviCraft 把规则放在 Agent 之下——这句话是整套架构的题眼。

![图2：闭合在 Agent 之下强制执行](https://arxiv.org/html/2611.32765v1/system.png)

*图2（论文 Figure 2）：Agent（LLM policy → Program，标注「any agent, in its own process」）通过 protocol calls 和 observations + results 与运行时对话。中间 EviCraft runtime 里的 World Knowledge System 维护单一知识状态 $K_t^{\rho}$，三个 read site——Push（观测展示）、Query（被模型问）、Tool（目标、路径、结果）——都从同一个 $K_t^{\rho}$ 读，各自带一个 G|L 开关。右侧 Environment（Minecraft 世界 $x_t$）只通过「按 regime $\rho$ 接纳的事实」更新知识状态。那条打了红叉的虚线是关键：标准语义工具对世界的直接读取，在这里根本不存在。底部 first-person frames 绕过 $K_t^{\rho}$ 直接进证据历史，但渲染器和范围在所有 regime 下完全一致。*

运行时是一个服务端 mod，握着 avatar、世界、时钟和 $K_t^{\rho}$；被测 Agent 是另一个进程，握着模型、提示词和程序执行器，只会说一套很小的协议：从当前感知刷新知识、查询 $K_t^{\rho}$、调工具、等待、抓一帧第一人称画面。三条硬约束全落在运行时里：查询只返回 $K_t^{\rho}$ 的记录；复合动作（收某类方块、挖隧道直到找到）只在记录里挑目标；路径规划读 $K_t^{\rho}$ 的快照，动作途中随接触和目视更新而重规划。

几个工程细节挺见功力：

- **评分通道隔离**：打分用的 ground truth 走另一条协议，Agent 手里没有那把凭证，它没法偷看自己的考卷。
- **时间归运行时管**：世界只在工具调用执行时、或 avatar 死亡时推进，推理延迟不吃游戏时间。查询、刷新观测、一个程序里两个动作之间的空档都不计 tick。
- **闭合可组合**：论文给了个命题——只要 Agent 的初始状态和随机种子独立于初始世界、程序只通过闭合的调用触达世界，那么模型现写的程序和第三方 Agent 都自动继承闭合。这条我很在意，它意味着这套约束不是「给某个特定 Agent 打的补丁」，而是接口层的性质。

还有个我读得挺开心的**泄漏测试**：用反事实世界来做断言。在「隐藏差异」配对里，两个世界只差一个 G 从没接纳过的事实（矿石封在墙后，A 点或 B 点），G 闭合的接口必须在两边做出完全相同的记录和动作，只有「先看过矿石」的对照组才该挖到；在「错误信念」配对里，一个被 G 接纳过的事实又在视野外变了（路线格子从空气换成石头、羊被挪走），G 闭合的接口必须照着旧记录走、然后在其中一个世界里出错。12 个脚本化场景，跑之前的断言就固定好了，每一次都命中。L 下同一段脚本会挖到封着的矿、按石头规划、追到挪走的动物——这等于逐个证明「每个隐藏事实都是某个工具读过的」。比起堆分数，这种「构造反例来验证机制」的做法更能说服我。

## 🧪 四、机制效应，比模型强弱还大

### 设置先看清楚

两个任务都在 Minecraft 1.21.1 生存模式、easy 难度、空背包、可重生下跑。Survival 让 Agent 尽可能推进到激活末地传送门，22 个里程碑按固定分值 $v_j\in[10,300]$ 分四段：地表可见的基础资源（10–70）、看不见的地下资源（铁 90–180、钻石 150、黑曜石 180）、下界（190–260）、末地（280–300）。分数是「达到过的最深层级」，用完、掉了、死了都不回退：

$$
S(\tau)=\max\left(\{0\}\cup\{v_{j}:\tau_{j}\le\tau\}\right),\qquad \mathrm{nAUC}_{S}=\tfrac{1}{300\,T_{S}}\int_{0}^{T_{S}}S(\tau)\,d\tau \tag{2}
$$

Discovery 则是「尽可能多地拿到不同物品 ID」，$T_D=144{,}000$ tick。$T_S=72{,}000$ tick（一小时游戏时间），$W=10$ 个初始世界、每个模型×世界×regime 5 次重复，从相同快照起步。所有比较都用配对世界的差分加 95% bootstrap：

$$
\widehat{\Delta}_{\mathrm{L}-\mathrm{G}}(Y)=\frac{1}{W}\sum_{w=1}^{W}\left(\bar{Y}_{w,\mathrm{L}}-\bar{Y}_{w,\mathrm{G}}\right) \tag{3}
$$

六个模型塞进同一个 reference agent（同样的提示词、46 个 ability、同样的编排：每轮写一段调用 ability 的程序，可请求第一人称画面）：

| 模型 | checkpoint / API model | 定位 |
|---|---|---|
| Kimi K3.1 Pro | `moonshotai/Kimi-K3.1-Pro` | 更大、最强 |
| DeepSeek v4.1 Flash | `deepseek-ai/DeepSeek-V4.1-Flash-1017` | Flash 中等 |
| Qwen 3.8 Flash | `Qwen/Qwen3.8-Flash-Next` | Flash 中等 |
| GLM 5.3 Flash | `zai-org/GLM-5.3-Flash` | Flash 中等 |
| Qwen 3.8 27B | `Qwen/Qwen3.8-27B` | 更小 |
| Qwen 3.5 9B | `Qwen/Qwen3.5-9B` | 最小 |

上下文窗口统一 262,144 token，单次最多 65,536 输出 token。G 和 L 只差一个字段，就是 regime。

### 主表：换个规则，排名都变了

先把 Table 2 的 Survival 终点分和 Discovery 广度摆出来（$\Delta_{\mathrm{L}-\mathrm{G}}$ 后面的方括号是 95% 区间）：

| 模型 | Survival G | Survival L | Δ | Discovery G | Discovery L | Δ |
|---|---|---|---|---|---|---|
| Kimi K3.1 Pro | 154.4 | 198.0 | +43.6 [36.4, 50.8] | 136.8 | 171.9 | +35.1 [29.9, 40.5] |
| DeepSeek v4.1 Flash | 139.6 | 176.8 | +37.2 [30.8, 44.2] | 118.7 | 132.6 | +13.9 [5.7, 23.3] |
| Qwen 3.8 Flash | 137.8 | 177.8 | +40.0 [33.0, 46.6] | 93.8 | 113.6 | +19.8 [14.4, 25.8] |
| GLM 5.3 Flash | 136.4 | 168.6 | +32.2 [25.4, 40.0] | 69.0 | 83.5 | +14.5 [8.4, 20.8] |
| Qwen 3.8 27B | 122.0 | 157.8 | +35.8 [24.6, 49.6] | 54.5 | 74.5 | +20.0 [16.1, 24.2] |
| Qwen 3.5 9B | 46.2 | 56.2 | +10.0 [−0.4, 23.2] | 19.4 | 18.8 | −0.6 [−4.5, 4.2] |

六个模型里五个的区间都不含零，10 个世界全是正向（表格里那一列 `10/0/0`）。看到这个数的时候我有点怀疑自己的眼睛：三个 Flash 模型吃到的规则红利是 +32.2 到 +40.0 分，Kimi K3.1 Pro 是 +43.6，**比 Kimi 在 G 下领先每个 Flash 的 14.8–18.0 分还大**。

也就是说，机制（准入规则）带来的涨分，压过了换一个更强模型带来的涨分。作者那句「regime effect exceeds the strongest agent's lead」不是修辞，是可以直接在表里对出来的。

更刺眼的是排名翻转：G 下 Kimi K3.1 Pro 拿 154.4，是全场最高；L 下每一个 Flash 模型都比这个数高出 14.2–23.4 分。换个规则，最弱的那一档反超了最强模型在更严规则下的成绩。换个更通用的 tool-calling harness 重跑，效应变成 +43.6 到 +55.2 分，方向没变、幅度还更大。

最弱的 Qwen 3.5 9B 只涨 +10.0，区间还跨零，Discovery 甚至 −0.6。这说明红利不是白送的，得有足够能力把特权信息用起来——这个细节让整张表更可信，而不是更可疑。

![图3：随时间的推进曲线](https://arxiv.org/html/2611.32765v1/regime-effects.png)

*图3（论文 Figure 3）：(a) Survival 分数 $S(\tau)$ 与 (b) Discovery 已确认物品数 $D(\tau)$ 随模拟 tick 的变化。实线是 G、虚线是 L，六个模型各一色。左图纵轴标了四个阶段（基础资源 / 地下资源 / 下界 / 末地），还注明 230–300 那两档平均压根没摸到；右端那几根竖线标出每个模型 G（实心）与 L（空心）的终点。看 (a) 里实线在 130–150 分附近集体趋平、虚线继续往上爬到 170–200，那道分叉大约就发生在铁镐之后——正是需要找埋藏资源的地方。*

### 那道「搜索墙」

![图4：沿生存链的到达率](https://arxiv.org/html/2611.32765v1/search-wall.png)

*图4（论文 Figure 4）：横轴是 22 个生存里程碑（底下一排物品图标），按基础资源 / Underground / Nether / End 分四段涂了底色；纵轴是「在预算内达到该里程碑或更后者」的运行占比。粗蓝线是 Flash 模型的均值，蓝色带点是 Kimi K3.1 Pro，实线 G、虚线 L。四组线在基础资源段几乎贴着 100% 重合，一过铁镐到钻石之间就塌下来，作者拿箭头指着那儿写了 `search wall`：G 下首次拿钻石 35%，L 下 87%。L 的曲线则一路撑到下界段才慢慢掉。*

具体到数字：G 下几乎每个 Flash 运行都能炼出铁（铁埋在地下但常见、洞穴里常露出来），铁镐到达率 82%–92%，到钻石骤降到 32%–40%，黑曜石最多 4%；L 下 76%–94% 拿到钻石，16%–18% 进了下界。Kimi K3.1 Pro 在 G 下能到 72% 的钻石，比 Flash 高一截，但也就卡在钻石往后：12% 摸到黑曜石、没有一个进下界，而它自己在 L 下是 82% 和 52%。连最强的模型都没能把这堵墙推倒，只是把墙往后挪了一点——它自己的 L–G 差依旧是 +43.6 分。

![图5：逐里程碑到达率热力图](https://arxiv.org/html/2611.32765v1/milestone-reach.png)

*图5（论文 Figure 8）：每个模型 G / L 配成上下两行，横轴 22 个里程碑按分值排序，颜色是等世界加权后「达到该里程碑或更后者」的运行占比，中间标了具体百分比。基本资源那一片两边都是深蓝（98%–100%），从 raw iron、iron pickaxe 往 diamond 走，G 行迅速褪成浅色（Kimi 72/44/12，DeepSeek 32/28/2，GLM 32/18/2），对应的 L 行仍旧是深蓝（90/86/50、96/82/4 那一片）。这张图把「墙在哪一格」钉死了，不是笼统的分数差。*

有个反驳很自然会不会是搜索本身太难、G 只是把任务变得不公平，而不是 L 在作弊？作者用三组回应把它堵得挺严：给 G 把预算翻倍到 144,000 tick，DeepSeek 只涨 +7.4 分、钻石率 32%→46%，黑曜石仍是 2%，没有一次进下界，分数依旧比「半预算的 L」低 29.8 分；隔离阶段实验里放了 **Human success** 作为对照（下面会说），人在同一套 G 接口下能做到，说明接口不是不可解；还有 12 个反事实泄漏测试证明差异确实来自工具读到的隐藏事实。看到这三组我基本服气了——时间不够不是主因，看不见才是。

## 🔬 五、拆开这个 gap：泄漏从哪个口子进来

### 消融：遮挡是主犯，工具是通道

定义 $R=(\bar{Y}_{\mathrm{abl}}-\bar{Y}_{\mathrm{G}})/(\bar{Y}_{\mathrm{L}}-\bar{Y}_{\mathrm{G}})$，即「补回了多少比例的差距」。两个最关键的消融：

| 干预 | 模型 | 得分 | R | 钻石到达率 |
|---|---|---|---|---|
| 基线 G | DeepSeek v4.1 Flash | 139.6 | – | 32% |
| 仅去掉视线检验（G°，无遮挡） | DeepSeek v4.1 Flash | 174.2 | 93% | 86% |
| 基线 L | DeepSeek v4.1 Flash | 176.8 | – | 90% |
| 基线 G | GLM 5.3 Flash | 136.4 | – | 32% |
| 仅去掉视线检验（G°） | GLM 5.3 Flash | 167.4 | 96% | – |
| 基线 L | GLM 5.3 Flash | 168.6 | – | 76% |

只把 G 的「射线撞到方块就停」改成「穿过去继续」，范围、留存、射线预算全不动，DeepSeek 就涨 +34.6 分 [28.6, 41.0]，一口气走完 93% 的路，钻石率从 32% 跳到 86%；GLM 涨 +31.0 分，96%，**补回九成以上的差距**。而反过来收紧 L 几乎不痛不痒：投递边界从四 chunk 缩到两 chunk 还保留 105% 的差距，把 L 截到眼睛周围 32 格（正好是 Voyager 那类 `findBlocks` 的查找范围）仍保留 98%。缩短 G 的记录留存到 80 tick 才 −13.6 分，拉到「永不遗忘」也就 +1.0 且区间跨零。

结论就很硬了：撑起这个差距的不是「知道得远」「记得久」，而是**有没有遮挡**。再把 G 的视线收窄到 110° 视锥（正好覆盖第一人称画面），分数 −12.8 分、钻石率掉到 10%——作者顺手承认，全向的 G 其实**低估**了一台只有摄像头的 Agent 会遇到的差距。这种自证挺诚实，没有把自己的基准往有利方向吹。

![图6：差距的解剖](https://arxiv.org/html/2611.32765v1/gap-anatomy.png)

*图6（论文 Figure 6）：(a) 十一个隔离的生存阶段，每格一次执行，蓝=G 成功、绿=人类成功、橙=L 成功、白=超时、黑=死亡。前四阶段（木头到石镐）三色全满；从 Stage 5 铁镐、Stage 6 钻石镐开始，蓝格明显被白格和黑格吃掉，右侧计数从 30/30 掉到 15/30、11/30，橙格仍接近全满，绿格也基本满——同一接口下人能过，模型过不去。(b) 各种干预补回 G–L 差距的份额（森林图，横轴 0/50/100%），左侧三列圆点标 push / query / tool 各自挂的 regime（蓝 G、橙 L），右侧三列是 score 与钻石、黑曜石、下界的到达率。从上往下：G、110° 视锥、80-tick 留存、2000-tick 留存、无遗忘、2× 时间预算、tools alone、no occlusion、2-chunk columns、32-block sphere、L。紫色那根 `tools alone` 落在 70% 左右，橙色 `no occlusion` 几乎顶到 93%。*

### 只开工具这一个口子：70%–98%

再看那个最贴工程的三元组 $(\mathrm{G},\mathrm{G},\mathrm{L})$——pushed 观测和模型自己发起的查询都还读 $K^{\mathrm{G}}$，**只有工具内部的读取和工具回报的内容**看得到已加载状态：

| 配置 | 模型 | 得分 | R [95%] | 钻石 / 黑曜石 / 下界 |
|---|---|---|---|---|
| G | DeepSeek v4.1 Flash | 139.6 | – | 32% / 2% / 0 |
| tools alone | DeepSeek v4.1 Flash | 165.6 | 0.70 [0.48, 0.92] | 80% / 28% / 6% |
| tools alone，隧道查找接地 | DeepSeek v4.1 Flash | 157.4 | 0.48 [0.24, 0.74] | 62% / 14% / 8% |
| L | DeepSeek v4.1 Flash | 176.8 | – | 90% / 50% / 18% |
| G | GLM 5.3 Flash | 136.4 | – | 32% / 0 / 0 |
| tools alone | GLM 5.3 Flash | 168.0 | 0.98 [0.81, 1.21] | 88% / 26% / 4% |
| L | GLM 5.3 Flash | 168.6 | – | 76% / 38% / 16% |

GLM 那个 0.98 的区间上界到 1.21，等于「把工具一处打开，剩下的保护和没保护一样」。模型看到的、问到的全是被接地约束的，它自己仍是「干净」的；可它调一次工具，工具就能找到隐藏目标、在没见过的地形上规划、并把找到的东西报回来。防护加在观测和查询上，把绝大部分泄漏原封不动地留着——这句是全文我最想拿红笔划下来的。

单个工具就能把机制讲透：DeepSeek v4.1 Flash 的 851 次隧道调用里，**737 次在还没挖掉任何方块之前就返回了目标坐标**（GLM 是 394/547）。只把这一次「对记忆目标的查找」接地，R 就从 0.70 掉到 0.48。挖隧道这个动作名义上是在探索，实际上第一步就已经被工具替它「看」到了终点。

![图7：一条钻石路线的两种走法](https://arxiv.org/html/2611.32765v1/diamond-route-case.png)

*图7（论文 Figure 12）：三维洞穴里的 illustrative routes，蓝色 G、橙色 L，同一个起点（黑色实心圆）。空心青圈是钻石矿，灰色雾面是初始洞穴边界。蓝线在下方来回折返、一段段往下试，橙线从起点直奔右上角的矿簇，数字 1、2、3 标出 L 下依次挖掉的矿点。这张图把「搜索」和「被路由」的差别画得比任何表格都直观——同样的世界、同样的起点，一个在找，一个已经在去拿的路上。*

![图8：隔离阶段的分阶段推进](https://arxiv.org/html/2611.32765v1/survival-stages.png)

*图8（论文 Figure 10）：DeepSeek v4.1 Flash 在十一个隔离阶段里的平均分推进，蓝实线 G、橙虚线 L，每格标注到达阶段终点的执行数（如 G 30/30、L 30/30 到 Stage 4 都满；到 Stage 5 铁镐变成 G 15/30、L 30/30，Stage 6 钻石镐 G 11/30、L 30/30，Stage 11 末地传送门 G 0/30、L 23/30）。阶段彼此独立、时间尺度不同。橙线几乎在每个台阶都先到、且到得更满，蓝线在需要定位隐藏目标的台阶上被超时和死亡拖住。*

### Discovery：红利精确落在「藏着的」物品上

开放式采集那边按「最少依赖世界知识的获取路径」把 553 个确认物品 ID 分成四类：地表衍生（218）、地表原生（69）、实体/战利品依赖（102）、地下依赖（164）。L 相对 G 的增益几乎全压在后两类：

| 类别 | L 相对 G 的变化 |
|---|---|
| 地下依赖（矿、深层、下界/末地材料） | +27% ~ +93% |
| 实体/战利品依赖（需要怪或掉落） | +52% ~ +69% |
| 地表原生 | +7% ~ +15% |
| 地表衍生 | −5% ~ +20%（符号会翻） |

两个依赖类的区间对每个模型（除几乎不持有这类物品的 Qwen 3.5 9B）都不含零。G 下 Agent 发出的盲目挖掘动作是 L 下的 2.2–22.8 倍——它们在真的找，只是找不到。又因为地表物品占了 G 广度的 63%–79%，总广度只涨 12%–37%。这个结构特别说明问题：泄漏不是 uniformly 抬高所有分数，它精准地抬高了那些「本该靠搜索才能拿到」的部分，而那恰好是基准里最能体现能力差异的部分。

## 🤔 六、我的判断

### 最值钱的东西不在 Minecraft

说实话，如果只读成「Minecraft 评测有 bug」，那就把这篇论文读小了。Minecraft 在这里是个可控、能重放、能拿到 authoritative world state 的载体。作者自己收尾也这么讲：搜索一个被遮挡的 3D 世界，对被测的这些 Agent 仍是未解问题，EviCraft 做的只是让它**可测量**。

真正的贡献是那把「三个 read site」的刀，以及一个能迁移到任意 Agent 工具栈的判断：**凡是「帮我找 X」「帮我查 X」「帮我定位 X」这类语义工具，都要问一句 X 是从哪来的、Agent 手里有没有它的证据**。把这条套到别的栈上，画面立刻就不一样了——

- RAG / 检索 Agent 的 `search(query)`：检索器读的是全量索引，模型从没「见过」那些文档，可工具替它把最相关的一条挑出来了；
- 代码 Agent 的 `grep` / `glob` / `find_references`：一次调用就能定位到它没打开过的文件里的符号；
- 浏览器 Agent 的 DOM 查询、数据库 Agent 的 SQL：查的是完整页面树 / 整张表，不带「用户当前视口」这种遮挡；
- 任何带「列出所有满足条件的实体」接口的业务 Agent，本质都是 `bot.findBlocks` 换了个域名。

这些工具都是策略的一部分，都条件依赖着模型没有证据的状态。EviCraft 给的证据闭合定义、非干扰条件、反事实泄漏测试、逐 site 可配的 regime 三元组，是一套可以直接搬过去审计的语言。论文把「语义工具直读特权状态」从某个游戏的实现细节，升格成了一类通用的评测有效性问题——这个升维才是它比一篇普通 benchmark 论文更耐读的原因。

### 哪里让我皱眉

不吹满，几处我保留意见。

**迁移性是论断，不是实证**。 全文只在 Minecraft 1.21.1、种子 100–109 这 10 个冻结快照上跑。上面那些往 RAG、代码 Agent 的类比是我推的，论文证明了机制，没在第二个工具栈上验证一遍。作者敢把话说得这么通用，靠的是抽象定义的普适性，不是跨栈实验。这个我认，但读者别自动脑补成「已在 N 个领域复现」。

**G 是一台被优待的传感器**。 全向、无视光照、类型精确标注、64 格、97.9%/99.7% 召回——真实视觉 Agent 拿不到这些。作者的辩解是：正因为 G 已经这么宽松，Agent 还是卡在钻石，所以墙只会更高；110° 视锥的 −12.8 分和 10% 钻石率也确实佐证了。逻辑自洽，可「 idealized visual sensor 」和「真实感知」之间仍隔着一段，把 G 分数当成 Agent 的绝对能力值来读会偏。

**模型与世界的规模**。 六个模型、10 个世界、每格 5 次重复，配对 bootstrap 做得很规范，还换了两个 harness 复现方向；但 10 个世界终究不算宽，地质生成、矿脉分布带来的方差没机会充分展开。另外六个都是同一时期的模型，没看到跨代际的对照——「更强的模型把墙往后挪但挪不倒」这个结论，样本还是薄了点。

**L 的定义措辞**。 把 leak 定义成「G 下闭合被违反」，又说「L 下的系统是闭合的、但在这个意义上漏」，第一次读很容易绊一下。这更像是为了行文方便选的坐标系，不影响结论，但给传播留了点歧义。

还有个更小的疑问：论文没怎么建模「如果工具栈本身重新设计过、压根不提供语义查找接口」会怎样——Table 1 里那几个策略类系统（MineRL、VPT、JARVIS-1）天然没有 Tool 泄漏。其实吧，泄漏是「语义工具」这个设计选择的代价，不是 Agent 范式的原罪。作者把这点放在 Related Work 里，没往结论里推，我觉得其实可以再往前说一步。

### 跟同期工作摆在一起

MineDojo 那套（NeurIPS 2022，Jim Fan 等，73 万 YouTube 视频训 MineCLIP、数千个开放任务）解决的是「开放式任务没法手写奖励」，Voyager 解决的是「LLM 怎么靠代码和技能库持续探索」。EviCraft 不在同一条赛道上——它不提新 Agent、不提新奖励、不提新技能库，只问「你们报的分数到底测了什么」。放在一块儿看反而清楚：前两篇把 Agent 能力往上推，这一篇回头去校准尺子。校准尺子的活儿不性感，但如果尺子是歪的，前面那些 3.3 倍、15.3 倍的对比就得重新理解。要说定位，它更接近评测方法论里的一次基础设施补齐，而不是底层能力突破——这个定位不影响它的重要性，只是别拿「刷榜新 SOTA」的期待去读。

## 💡 七、如果你也在做 Agent 工具栈

给几条我自己会照着做的：

1. **列出所有 read site，尤其是第三个**。 把「模型输入」「模型查询」「工具执行期间的读取与返回」分开画一遍表，凡是第三栏空着的，就是潜在的 `bot.findBlocks`。这个动作半小时就能做完，收益比再调一轮提示词大。
2. **对每个「帮我找 X」的接口追问证据来源**。 目标是从全量状态里挑的，还是从 Agent 已经观测到的记录里挑的？返回结果是只含已接纳的事实，还是顺手带了工具自己翻到的东西？
3. **把准入规则当成实验变量报出来**。 固定 Agent、工具、世界，只翻规则，量一次 Δ。如果 Δ 比换模型带来的提升还大，那你的基准主要在测工具而不是测模型——这正是 EviCraft 那句「机制效应超过最强 Agent 领先幅度」给所有人的提醒。
4. **写反事实泄漏测试**。 构造两个只差一个「Agent 没证据的事实」的世界，断言闭合接口在两边行为一致。比起盯平均分，这种断言能直接定位泄漏点。论文 12 个脚本化场景就是模板。
5. **别只加观测层的护栏**。 tools-alone 那组 70%–98% 的 R 说明：prompt 里写「只看你见过的」、给相机加视距限制、把元数据从输入里摘掉，都挡不住工具在内部读一次全量状态。规则得放到 Agent 之下、放进接口实现里。

一段伪代码把这套约束的边界写清楚，比文字更直观：

```python
# 标准语义工具：策略的一部分，条件依赖模型没有证据的世界状态
def mineBlock(block_type):                    # 工具内部 = policy
    target = loaded_chunks.find(block_type)   # 无视线检验 ← 泄漏发生处
    route  = plan_to(target)                  # 在未见过地形上规划
    walk_and_break(route)
    return target.coords                      # 把隐藏事实回报给模型

# EviCraft：三个 read site 只读同一个知识状态，工具也不例外
def mineBlock_closed(block_type, K_rho):     # K_rho 由 regime ρ 按事件更新
    target = K_rho.match(block_type)          # 只在被接纳的记录里挑
    if target is None: return NoKnownTarget   # unknown 被显式表示
    route  = plan_over(K_rho.snapshot())      # 绕开 unknown，途中重规划
    walk_and_break(route)
    return target.coords                      # 返回值同样只来自 K_rho 与自状态
```

差别不在模型，不在提示词，在 `loaded_chunks.find` 换成了 `K_rho.match`。

收个尾。这篇论文没让 Agent 变强，它让我们看清之前那些「强」里有多少是借来的。作者收尾那句我挺喜欢——benchmark 应该逐 site 报出准入规则。往大了说，Agent 评测这两年堆了太多 leaderboard，缺的恰恰是这种「先把尺子校准」的耐心活。搜索被遮挡的 3D 世界，对这些 Agent 仍然是开放的难题；但至少从现在起，我们能分清谁在找、谁在被路由了。

还有个更根子上的问题没解决：一旦工具栈被普遍接地，我们拿什么去衡量「搜索能力」本身？EviCraft 给的是诊断，不是疗法。这道题，我估计还得留下一批人来答。
