# 检索别只找"相关的"：LINEAGE 把论文之间"谁跟谁真比过"做成了基准

你有没有碰到过这种别扭的情况——让一个 research agent 帮你写 related work，或者帮你规划下一组实验，问它"我这个方法该跟谁比"。它哗啦返回二十篇论文，主题都对得上，引用关系也盘根错节，看着挺像那么回事。你挨个点开实验表格一看，里头压根没有真正被跑过数字、被当成 baseline 摆在一起对比的那几篇。

我之前帮人看过一个文献推荐模块，召回指标挺漂亮，nDCG 也不难看，可一到"找基线"这个具体需求上就抓瞎。当时归结为 embedding 不够强，现在回头想，问题根本不在检索模型身上。

在这篇 LINEAGE 之前，几乎所有科学文献检索基准都在问同一个问题：这篇论文和查询"相关"吗，或者这篇论文该被"引用"吗。可一个真在做实验的人要的既不是相关、也不是引用，而是"谁拿我的方法当过对照"。这两个问句之间隔着一整个实验语境。

---

## 核心摘要

LINEAGE 换掉了"什么算相关"这个底层定义。它把「论文 A 的方法被论文 B 在主结果表里明确拿来当 baseline 跑了对比」抽成一条有向边，叫实证谱系（empirical lineage），连成图之后用多跳邻域当检索的标准答案。为此作者搭了条 Lineage-Constructor 流水线，从 12.1 万篇论文、17 个 AI 顶会、2018 到 2025 年的语料里造出 3950 张谱系图、67502 个节点、164948 条边、8 万条多面查询。19 个代表性检索系统上去测，最强的 Tongyi-DeepResearch 也只有 31.87 的 Recall@20 和 9.92 的 Precision@20，跳数一多，平均 Recall@20 从一跳的 28.42 塌到三跳的 6.68。我的判断：这不是又一个拿来刷榜的数据集，它值钱的地方是重新定义了 ground truth，以及那套能自动铺到十万量级的构造管线；但整条链的可信度全押在 LLM 抽取全文证据上，"标注者之间一致"和"符合事实"是两回事，这个软肋绕不开。想靠它练出更强的 retriever 有点早，拿它当镜子照现有系统的盲区倒是刚刚好。

## 问题动机：相关不等于比过，引用更不等于基准

现有 scholarly retrieval 基准基本就两条路。一条是 relevance-based，靠人工标的"相关论文"当监督，比如 LitSearch、DORIS-MAE，用带 aspect 的查询去命中符合某条科学陈述的论文。另一条是 citation-oriented，拿引用推荐或引用预测当标准答案，CiteME、CitationR、PaSa、CiteRAG 都在这条线上。

两条路各有各的漏。主题相关不蕴含实证对比——两篇论文可以做同一个任务、用同一批数据集、连标题都撞词，实验里却谁也没跟谁比过。引用关系就更杂了，一篇论文引另一篇，可能是背景介绍、可能是用了人家的数据集、可能是借了个工具、可能是理论支撑，真正"在主结果表里把人家的方法当成 baseline 跑了一列数字"的只是其中一小撮。你想想看，把这两种信号混在一起当 ground truth，评测出来的高分检索器，凭什么就能回答"谁跟谁真比过"？

研究 agent 的真实需求偏偏就卡在这儿。做文献综述要摸清一篇工作的实证参照系，做实验规划要找齐该对比的基线，做贡献定位要知道后来哪些工作把自己当过对照。原文引了 Pan 等人和 Xu 等人的结果，说论文检索质量会一路传导到下游的推理和生成——检索给错了证据，后面写得再花也是空中楼阁。

所以作者要的是一种 auditable 的关系：每一条边都得能回溯到全文里一处明确的实验证据，不是标注者的主观判断，也不是引用图里那条说不清动机的连线。这就是 empirical lineage。

![图1：实证谱系关系示意](https://arxiv.org/html/2611.25845v1/intro-fig.png)

*图1：从论文 Q 的主结果表（Baseline A 82.1、Baseline B 83.4、Ours 86.7）里抽出谱系，A、B 是它的祖先，C、D、E 是它的后继；右侧检索评估里，祖先 A、后继 C 都算命中，而 "Paper X · Citation-only" 被打了红叉*

这张图我盯着看了一会儿，它一句话讲清了三件事。边是有方向的，从基线论文指向源论文，语义是"is_baseline_of"，不是无向的"相关"。给定一篇查询论文，ground truth 是它在图里的祖先加后继，也就是往上追谁被它比过、往下追谁比过它。最右下角那个红叉是关键——纯引用关系被明确排除在外。作者把边界划得很硬：引过不算，得在实验里真刀真枪当基线摆出来才算。

## 方法核心：Lineage-Constructor 是怎么把 12 万篇论文熬成图的

想法听着干净，真要从科学文献里自动铺出这么一张图，作者自己列了三个拦路的坎。

**语料锚定**（Corpus Grounding）。检索空间得可审计，每个节点、每条边都要能稳定地认出来。可论文散在一堆异构的开放获取源里，覆盖率、元数据、PDF 能不能拿到，各家都不一样。

**证据到边的歧义**（Evidence-to-Edge Ambiguity）。跟引用链接不同，谱系关系得从全文的实证证据里认。baseline 提及可能出现在方法段、实验设置段、主结果表、附录，形式五花八门，把"真正的对比对象"和"顺嘴引了一句"分开，是件很磨人的事。

**图适用性**（Graph Suitability）。抽出来的边直接堆成图，未必适合当评测的标准答案。有些被反复复用的经典 baseline 会把大片本来没什么关系的论文粘成一个过宽的连通块，多跳邻域一扩就全是噪声。

三个坎对应流水线的三段。

![图2：Lineage-Constructor 三阶段架构](https://arxiv.org/html/2611.25845v1/framework.png)

*图2：(a) 统一文献采集器把 11 个官方 OA 源、DBLP 列表和会议名录汇成元数据与 PDF；(b) 证据驱动的谱系抽取，先做论文类型分类，再由 GROBID 与 MinerU 双源各跑一遍抽取器后交叉整合，Lineage-HA 人工标注集负责验收；(c) 谱系图校准，先查时间一致性再查结构一致性*

### 第一段：把散落的论文收成一个能查的库

Unified Scientific Literature Collector 干的是脏活。它从 11 个官方 OA 源加 DBLP 论文列表、会议名录里收数据，对齐元数据、校验 PDF、规范化记录。原文 Table 22 把 17 个 venue 的 PDF 获取优先级列得很细：ACL 系走 ACL Anthology 再回退 arXiv，CVPR/ICCV 走 CVF → OpenReview → arXiv，ICML 走 PMLR → OpenReview → arXiv，NeurIPS 走官方站 → OpenReview → arXiv。有个注释我挺在意——KDD、SIGIR、SIGMOD、WWW 这几个 ACM 系会议虽然能从 ACM Digital Library 公开访问，但没有公开的批量下载接口、还限制程序化抓取，作者干脆不把它们当自动 PDF 源，只从 arXiv 兜底。

这类工程细节看着琐碎，其实决定了后面 12.1 万篇的语料边界：只有能自动拿到全文的论文才进得来。workshop、期刊、只在 arXiv 挂着的 preprint、非英文文献，基本都在视野之外。这个边界等下聊局限性时还得回来算账。

### 第二段：双源抽取，加一个人工锚点

Evidence-Grounded Lineage Extraction 是整篇最见功夫的地方。它不是直接拿 LLM 通读全文问"谁是谁的 baseline"，而是分了两步。

先做论文类型分类。为啥要这一步？只有 Methodology / Method 类论文才会带"主结果表"这种实证对比结构，Benchmark 类和 Survey 类的写法完全不同，混在一起抽，噪声会炸。性能对比在下面这张图里。

![图3：论文类型推断的三个混淆矩阵](https://arxiv.org/html/2611.25845v1/paper-type-infer.png)

*图3：Method. / Bench. / Survey 三分类。关键词推断加标题摘要只有 71.1% 准确率、F1 74.0%；换成 LLM 读标题加摘要跳到 97.9% / 96.7%；再把 Introduction 也喂进去，99.0% / 98.3%*

71.1% 到 99.0%，这个跨度说实话有点夸张，但也合逻辑——判"这篇是不是方法论文"，光看关键词确实容易把综述里提到的方法名当真，多给一段 Introduction 基本就能定死。这步是为后面的双源抽取器铺路，把明显不该带基线的论文先筛掉。

真正的抽取用了 GROBID 和 MinerU 两个解析器各生成一套论文表示，各自跑一遍 AI Lineage Extractor，再 Integration 交叉校验。思路是两者解析全文的偏好不同、覆盖到的 baseline 提及位置也不同，互补能提覆盖率，互相证伪能压掉伪边。配套还标了个 Lineage-HA 人工集：230 条样本验论文类型、150 条样本验谱系关系，用来调抽取器、也用来报抽取质量。

消融数据（原文 Table 21）把这个设计的收益摊开了。以 w/ Integration 这一组为例，MinerU 单源 Recall 94.24、Precision 83.71、micro F1 88.66；GROBID 单源 85.25 / 81.87 / 83.52；双源 Dual 是 93.71 / 92.21 / **92.95**。Recall 几乎没动，Precision 从 83.71 抬到 92.21，接近 9 个点。这就很说明问题了：双源主要不是在"多找着几条边"，而是在"把单源一厢情愿认出来的边否掉"。换到 w/ Verifier 那组，Dual 的 Recall 能到 95.50，但 Precision 掉到 84.15，F1 89.47，反而不如 Integration 组——校验器放得更宽，召回上去了，误报也跟着回来。

标注一致性原文 Table 20 报了 Krippendorff's α 0.8490，三个标注者两两之间的 Micro Dice 在 0.9706 到 0.9805。这个数得会读：它证明的是"人和人、人和作者标得一致"，不等于"标出来的边符合事实"。全文里出现某个方法名，可能只是定性提了一句"某某也做过类似尝试"，并没有真跑对比，这条模糊地带作者没完全说死。

### 第三段：给图做校准

Graph Calibration 管两件事。时间有效性——2025 年的论文不可能给 2023 年的论文当 baseline，方向反了的边直接砍。结构正则——把那些被少数超级 baseline 撑出来的过宽连通块削薄，让多跳邻域重新变得适合当 ground truth。

![图4：谱系图结构分析](https://arxiv.org/html/2611.25845v1/graph-structure-analysis.png)

*图4：(a) 连通分量规模呈长尾，绝大多数分量很小；(b) 覆盖比随 top-k 分量变化，k=500 时已覆盖 85.4%，k=200 是 66.1%，k=20 只有 25.8%；(c) 入度与出度的互补累积分布，双对数坐标下都是长尾*

校准前后的数字很能打（原文 Table 23）：

| 阶段 | 节点 | 边 | 聚类系数 | 边 Jaccard |
|---|---|---|---|---|
| 原始谱系图 | 89,485 | 238,511 | 0.1627 | 0.1022 |
| 时间校准后 | 89,441 | 238,075 | 0.1635 | 0.1020 |
| 结构校准后 | 67,502 | 164,948 | 0.3035 | 0.1420 |

时间校准几乎没动刀，只删了 44 个节点、436 条边，说明抽取器本身对时间方向的把握还算靠谱。真正下狠手的是结构校准：节点砍掉 2.2 万、边砍掉 7.3 万，聚类系数却从 0.1635 翻到 0.3035。删掉的主要是那种把一堆弱关系论文硬粘在一起的"桥"，剩下的每个连通块内部更抱团了。这张表比任何文字都更能解释第三个坎是怎么迈过去的。

## 基准长什么样：8 万条查询和一组"结构指标"

最终交付的 LINEAGE 规模如下（原文 Table 5）：

| 域 | 统计项 | 数值 |
|---|---|---|
| 谱系图 | 连通分量 | 3,950 |
| | 论文节点 | 67,502 |
| | 根节点 / 叶节点 / 中间节点 | 13,315 / 28,488 / 25,699 |
| | 谱系边 | 164,948 |
| 多面查询 | 查询论文数 | 10,000 |
| | 查询总数 | 80,000 |
| | 根型 / 叶型 / 中间型查询 | 26,672 / 26,664 / 26,664 |
| | 每条查询平均谱系数 | 8.1 |

底子是从 121,048 篇论文、17 个顶会、2018–2025 里收上来的，真正进图的只有 67,502 篇——过半论文没能跟别人构成可审计的谱系关系。这个比例我觉得挺真实，不是每篇论文都会明确报"我把谁当 baseline 跑了"。

所谓多面查询，是同一篇论文从 8 种检索意图各写一遍：Title（纯标题）、Title-Ctx（标题加摘要）、Top-KW / Top-Sem（主题关键词 / 主题语义句）、Ctx-KW / Ctx-Sem（上下文关键词 / 上下文语义句）、Meth-KW / Meth-Sem（方法关键词 / 方法语义句）。原文 Table 26 拿 SketchGen 举了例子，Meth-KW 是 "Transformer graph-based sketch representation."，Meth-Sem 是 "Transformer-based generative models for sketch graphs with constraint and primitive type encoding."；Table 27 的 HUMUS-Net 也照这个格式铺了八行。这么设计是想逼检索器证明自己真懂"这篇在做什么、怎么做"，而不是背下标题里那几个词。

指标分两组。R@20、P@20、H@20、N@20、M@20 是传统检索指标（召回、精度、命中率、nDCG，外带一个排序类指标）；HWR@20、DR@20、GN@20 才是作者新加的结构指标，也是我认为这篇最漂亮的一笔。

HWR 是跳数加权召回：

$$\mathrm{HWR@}k(v_q)=\frac{\sum_{v\in R_k(v_q)\cap Y_q}\frac{1}{\mathrm{hop}(v_q,v)}}{\sum_{v\in Y_q}\frac{1}{\mathrm{hop}(v_q,v)}}$$

命中的目标越近，权重越大，隔了三跳才捞回来的只算三分之一。DR 更直接，只看一跳邻居的召回：$Y_q^{(1)}=\{v\in Y_q\mid \mathrm{hop}(v_q,v)=1\}$，$\mathrm{DR@}k=|R_k\cap Y_q^{(1)}|/|Y_q^{(1)}|$。GN 是图版 nDCG，把 gain 换成 $\mathrm{gain}(r_i)=1/\mathrm{hop}(v_q,r_i)$（命中时）再按 $1/\log_2(i+1)$ 折损，除以理想排序的 IGDCG。

$$\mathrm{GN@}k=\frac{\mathrm{GDCG@}k}{\mathrm{IGDCG@}k},\qquad \mathrm{GDCG@}k=\sum_{i=1}^{k}\frac{\mathrm{gain}(r_i)}{\log_2(i+1)}$$

这三个指标合起来在追问一件事：你召回的是一片连贯的实证对比邻域，还是东一榔头西一棒子的孤立命中点。传统的 Recall 只看集合覆盖，二十个结果里蒙对八个分散目标，和蒙对八个抱成一团的近邻，分数可以一样，但对一个要写 related work 的人来说价值天差地别。这个区分我觉得是整篇论文最值钱的洞察，比任何一个 SOTA 数字都值钱。

顺手核一个细节：主表里 DR@20 的平均值是 28.42，按跳数分解表里一跳的平均 Recall@20 也是 28.42，逐行对下来 BM25 是 25.74 对 25.74、Tongyi-DeepResearch 是 35.89 对 35.89，完全吻合。DR@20 就是一跳召回，两套表自洽，数据没串。

原文把结论收成三条，我挨个对过数，都对得上。

**天花板极低。** 最强的 Tongyi-DeepResearch（一个 30B-A3B 的 research agent）也只有 31.87 的 Recall@20、9.92 的 Precision@20。翻译一下：标准答案里平均 8.1 条谱系，前 20 个结果平均只捞回来三成，20 个位置里真正对得上的不到 2 个。连一半都没到，谈不上"接近解决"。

**距离一远就崩。** 按跳数拆开（原文 Table 17），语料内平均 Recall@20 是一跳 28.42、二跳 14.02、三跳 6.68、四跳 3.40、五跳 1.74、六跳 0.69、七跳 0.83，基本每多一跳就砍一半。向量检索在这件事上的无力感很直观：语义相似能帮你找到"跟查询论文像"的近邻，可三跳之外那个"比过我比过的人"的论文，标题、摘要、方法可能已经完全换了一套词。

**在线源塌的是结构，不只是命中率。** 语料内平均 R@20 是 24.82，在线源平均只有 6.69，差了近四倍。但更值得看的是 Google Search：R@20 还有 9.64，P@20 却只有 0.40，DR@20 掉到 2.23，GN@20 只剩 1.42。它偶尔能蒙中一两篇，可捞回来的全是散点，构不成一片邻域。这恰好是结构指标想抓的东西——命中率会骗人，结构分数骗不了。

说到这个，我得给这个对比挑个刺。语料内检索器面对的是封闭的 121,048 篇候选，在线搜索引擎面对的是整个开放网络，而 ground truth 只在这 12 万篇里。这俩的覆盖压根不对等，6.69 对 24.82 里有多少是"排不对"、多少是"根本覆盖不到"，作者没拆干净。结构指标部分缓解了这个质疑（在线源 GN@20 平均 4.33，比 19.70 低得更多，说明即便命中也不成团），但要下"在线检索恢复不了谱系"这个结论，我觉得还得补一个"把在线结果映射到同一语料内再评"的对照才踏实。这个 baseline 选得有点巧妙。

再看两个容易被忽略的切面。

**查询面差异大得离谱**（原文 Table 18）。语料内平均按 8 种 query 拆：Title 30.36、Title-Ctx 39.04、Top-KW 29.19、Top-Sem 31.07、Ctx-KW 18.90、Ctx-Sem 26.07、Meth-KW 7.46、Meth-Sem 17.14。带上下文的语义描述最香，Title-Ctx 里 Tongyi-DeepResearch 能到 46.69；干巴巴的方法关键词最惨，平均只有 7.46，最强的系统也就 9.34。这个数我看着是有点意外的——"用方法名去搜谁把它当 baseline"恰恰最像真实研究者的操作习惯，结果全军覆没。反过来说明当前检索器对"方法"这个粒度的表征基本没建立起来，靠的是主题语义在兜底。

**模型规模不单调。** Qwen3-Embedding 4B 的 30.64 反而压过 8B 的 29.35 和 0.6B 的 25.96，ReasonIR 8B 只有 25.38，专门为推理训过的也没占着便宜；BGE-M3 0.6B 垫底到 10.71，Contriever 18.20。这条任务上，起作用的好像不是参数量，更接近"指令跟随 + 长上下文理解"的能力——能把"标题加摘要"里那点实验语境读进去的模型才占优。说实话这块我也不是特别确定，作者没做控制变量实验，只能算个观察。

抽取器消融前面聊过，Double 的 92.95 micro F1、标注 α 0.8490，这些数字共同托住了整条链的上限。但反过来也提醒一件事：benchmark 里每个"标准答案"都是这条链产出的，抽取器错一条边，下游所有检索系统的分数就跟着偏一格。这是自动构造大规模基准绕不开的代价。

## 同类基准横向对比

原文 Table 1 把六个已有基准和 LINEAGE 摆在一起，我照抄成表：

| 基准 | Ground Truth | 多面查询 | 自动构造 | 谱系关系 | 多跳检索 | 结构指标 |
|---|---|---|---|---|---|---|
| LitSearch | 相关论文 | ✗ | ✗ | ✗ | ✗ | ✗ |
| CiteME | 引用 | ✓ | ✗ | ✗ | ✗ | ✗ |
| DORIS-MAE | 相关论文 | ✓ | ✗ | ✗ | ✗ | ✗ |
| CitationR | 引用 | ✗ | ✓ | ✗ | ✗ | ✗ |
| PaSa | 引用 | ✗ | ✓ | ✗ | ✗ | ✗ |
| CiteRAG | 引用 | ✓ | ✓ | ✗ | ✗ | ✗ |
| LINEAGE | 谱系关系 | ✓ | ✓ | ✓ | ✓ | ✓ |

前两列（相关 / 引用）是老问题的两种答案，后四列是评测维度。LINEAGE 是唯一一行把六格全勾上的，作者也据此说"据我们所知是首个用实证谱系关系当 ground truth 的大规模文献检索基准"。

看到"首个"我习惯性警觉一下。这个特定组合——大规模、可审计的 baseline 关系、多跳、结构指标——确实新，没什么好争的。但"用实验对比关系做检索监督"这个念头，跟 citation-oriented retrieval、related work 自动生成、baseline 推荐这几条线是一脉相承的，不是凭空冒出来的范式断裂。更准确的说法是：它把一条大家隐约知道重要、但一直没法定量标注的信号，用一套工程管线做成了可规模化的标准答案。这是问题设定上的推进，不是算法底层突破。剥离包装看本质，我觉得这么定位比较公道。

## 我的判断：值钱在哪，水在哪

**最值钱的是换掉了"相关"的定义。** 过去基准的监督信号不是人标的主观相关，就是引用图里动机不明的连线，两者都没法回答"谁跟谁真比过"。LINEAGE 把 ground truth 锚在论文自己写下的实验表格里，可审计、可回溯、还能自动扩到十万量级。做评测的人应该都懂这有多难得——一个不用持续烧人工标注、又比"相关性"更贴近真实需求的信号源。

**结构指标是第二值钱的。** HWR / DR / GN 把评价从"命中几个点"推到"恢复一片邻域"，这个视角迁移到别的关系型检索任务上也能用。

**构造管线本身可复用。** 11 个 OA 源的优先级回退、双解析器交叉校验、时间加结构两段校准，这套东西哪怕不拿来做 benchmark，拿去给自己的文献库建一层"实验基线"索引也是现成的。

水也得说清楚。

**痛点有几分是造出来的。** 真实研究 agent 找 baseline 时，一跳、两跳基本够用，谁会去追五跳开外的后继？表里五跳 1.74、六跳 0.69、七跳 0.83 这种数字，更像是为了把任务难度做上去而保留的评测维度，不是刚需。把 7 跳都列进主表，有凑难度梯度的嫌疑。我更想看的是"一跳之内能不能做扎实"，而不是"多跳有多惨"。

**评估公平性上面已经挑过。** 在线源和本地语料的候选空间不对等，这条结论得打折看。

**ground truth 的可信边界。** α 0.8490、Dice 0.97+ 都是一致性指标，不是正确性指标。全文里"提到"和"真跑过对比"之间那片模糊地带，作者用双源交叉校验压了伪边，但没给出对真值的独立验证。一篇论文在正文里写"某某方法也常被用作对比"，却没在表格里给它一列，这算不算 lineage？这个口子留着，所有分数就都带着一点系统偏差。

**语料边界会系统性截断谱系。** 17 个 AI 顶会、2018–2025、且 PDF 能自动拿到。一篇 2019 的会议论文如果引了 2016 年某期刊的经典方法当 baseline，那条边大概率就丢了；同理 arXiv-only 的 preprint、非英文文献统统进不来。谱系图因此会偏"近期、顶会、有 arXiv 版"的子图，而 real research 的参照系往往比这宽得多。

**结构指标也可能被针对性刷。** HWR / DR / GN 都是 hop 的确定性函数，只要能把一跳邻居稳稳排到前面就能拿高分。理论上一个专门啃"论文主结果表"、把 baseline 名做成词典匹配的检索器，可能在这套指标上很漂亮，却完全不理解语义。指标越结构化，越要提防这种走捷径的解法。

## 工程上能抄走的几件事

如果你在给 research agent 做文献模块，最直接的一刀是别再指望纯 embedding 恢复多跳。给索引加一层显式的"实验基线"字段：从全文主结果表里抽 baseline 名，建成一张有向图，检索时图召回和语义召回混排，一跳用图、远跳用语义兜底。主表里 BM25 的 22.06 和 Tongyi 的 31.87 之间那点差距，大概率靠混排就能补上一截，比换更大的 embedding 划算。

双源交叉校验这个套路成本低、收益实。两个不同的解析器、或者同一个模型两套不同 prompt，各跑一遍再取交集，Precision 抬了近 9 个点，任何做信息抽取的链路都值得试。

评测自己系统的时候，别只盯 Recall 和 nDCG。加一个"结构完整性"维度，能挡住那种"二十个结果里蒙中八个散点就报喜"的方案。这条不局限于文献检索，凡是有关系结构的召回任务都适用。

回到最开始那个别扭的场景。LINEAGE 记录的是"谁比过谁"，是既成事实。可做研究时真正卡人的往往是另一句："谁本该跟谁比，却一直没人比过。"描述性的谱系能告诉你社区已经形成的参照系，告诉不了你那个被漏掉的、其实最该摆进表格的对照。把谱系从描述推向规范，从"找回历史"推向"推荐该比的基线"，可能是这条线更值得追的下一站。但那需要另一套 ground truth，也另一套勇气。
