# 答案碰对，不等于证据支持：智能体记忆评测该补上证据充分性了

假设你让智能体查看一段设备日志，问它：“设备现在连接的是哪条通道？”

可见日志里只有一次成功的 `route(A)`。模型回答 A，标准答案也是 A，评测脚本愉快地打了一个勾。但被截掉的日志里，其实还可能有一次成功的 `route(B)`。如果原始完整历史的最终状态恰好仍是 A，这个回答就会得分；如果原始历史后来切到了 B，同样的可见输入、同样的回答 A，就会失分。

问题来了：这个“对”，究竟是模型读懂了记忆，还是碰巧猜中了出题人心里的答案？

这篇论文盯住的正是这个评测盲区。它没有提出新的记忆压缩器，也没有再做一个检索排行榜，而是追问一个更靠前的问题：**交给阅读器的这些文字，能不能唯一决定答案？**

## 核心摘要

这篇论文把“答案匹配完整历史参考答案”与“答案受到可见证据支持”拆开评测。作者构造可执行的设备日志，用两条合法历史证明：它们能打包出逐字节相同的上下文，却导出不同答案。80 条确认历史上，Qwen3-32B 在 203 个证据不足样本中命中隐藏参考答案 87 次，却只恰当拒答 7 次；DeepSeek-V4-Flash 分别命中 85 次、拒答 21 次。这个结果很扎眼，但论文真正值钱的是可审计的证据证书，而不是又一次证明模型会猜。它是一篇克制、扎实的测量研究，适合所有做 Agent 记忆和 RAG 评测的人细读。

## 一个参考答案，为什么会掩盖两种完全不同的回答？

常见记忆评测有一条很自然的链路：保留完整历史，算出参考答案；再把检索、筛选或压缩后的历史交给模型；比较模型答案和参考答案。

这条链路能回答“结果有没有对上”，却回答不了“结果是不是由输入决定的”。论文把三个容易混在一起的轴拆开了：

| 评测轴 | 关心的问题 | 一个典型结果 |
|---|---|---|
| 参考答案一致性 | 输出是否等于完整历史产生的答案 | 可见证据不足，但仍答出 A |
| 证据充分性 | 可见上下文是否唯一确定查询答案 | 充分、不足，或暂时无法分类 |
| 上下文恰当性 | 在该证据条件下，回答行为是否符合契约 | 充分时答对，不足时返回 `UNDETERMINED` |

这里的分寸很重要。参考答案一致性不是坏指标，它只是测了另一件事。如果产品允许模型根据先验概率冒险作答，猜对可能有业务价值；但如果评测声称自己测的是“基于历史的可靠回答”，那么证据不足时的猜中就不能算可靠记忆。

说实话，我很喜欢这个切入角度。很多评测争论都卡在“模型到底答对没有”，这篇论文把镜头往后拉了一步：**阅卷之前，先检查题目给出的材料是否足够。**

## 把“证据够不够”变成可以执行的判定

### 一套刻意缩小的设备日志世界

作者没有直接在开放对话里判断证据蕴含关系，而是设计了一个规则明确的小型环境。每条报告有八个字段：报告 ID、报告时间、事件 ID、事件时间、设备、动作、参数和结果。

规则也很干净：

- 多条报告可以重复描述同一事件，去重后只计算一次；
- 事件时间决定执行顺序，报告时间不决定；
- `ACCEPTED route` 把设备切到指定通道，`ACCEPTED disable` 把状态设为 `DISABLED`；
- `REJECTED` 动作不改变状态，每台设备从 `UNSET` 开始。

查询只有四类：成功路由的去重数量、第一条成功路由、最晚一条成功路由，以及设备状态。时间查询带 inclusive cutoff $T$，只使用 $t\leq T$ 的事件。固定英文语法听起来有些“玩具”，但正因为语义没有含糊空间，证据证书才可以真正执行和复核。

### 同一串可见字节，背后可以有两个世界

形式化定义是这篇论文的核心。令 $H$ 是完整合法历史，$q$ 是查询，$P$ 是上下文打包器，$C=P(H)$ 是模型实际看到的内容，$\mathcal{G}$ 是明确告知模型的公共规则。所有与这份可见上下文兼容的历史构成：

$$\mathcal{W}(C;P,\mathcal{G})=\{H':H'\models\mathcal{G},\ P(H')=C\}$$

如果 $f(H,q)$ 是执行查询得到的答案，那么证据充分的条件是：

$$\left|\{f(H',q):H'\in\mathcal{W}(C;P,\mathcal{G})\}\right|=1$$

直觉很直接：把所有能产生同一份可见输入的合法历史都找来，如果它们给出的答案只有一个，证据才充分。只要有两个世界答案不同，具体回答就不是由当前输入唯一决定的。

这里还有个容易踩的坑：$\mathcal{G}$ 只能包含告诉阅读器的规则，不能偷用生成器的私有设定。比如实验数据其实每条历史有 24 个事件，但模型没被告知这一点，就不能拿“日志理应已经到 24 条了”证明后面没有事件。

![图1：同一可见前缀对应两个答案不同的合法历史](https://www.mulanai.com/fs/files/1116_78316625_figure1.jpg)

*图 1：论文的证据证书示意。可见前缀只有 `t=10: route(A), ACCEPTED`，没有完整日志标记，查询截止时间是 $T=20$。世界 $H_1$ 中日志到此结束，状态为 A；世界 $H_2$ 中不可见位置发生了一次到 B 的路由，状态为 B。两者必须经同一个打包器生成逐字节相同的上下文。对“第一条路由”而言，A 已被确定；对状态、数量和最晚一条路由而言，答案仍可能变化。该图由论文 TeX 源码中的实际 Figure 1 单独编译转换，不是 PDF 页面截图。*

这张图还藏着论文很细的一层判断：**截断不等于证据不足，证据不足也不等于所有问题都不能答。**

在按事件时间排列的连续前缀里，有三种公共充分性规则。完整日志标记可以证明全源可见；如果出现一条时间严格晚于 $T$ 的完整记录，那么 $T$ 及之前的事件已经齐全；对第一条路由查询，截止时间内第一条可见成功路由已经锁定答案，即使还没看到超过 cutoff 的记录。

不足证书则采用构造性证明。作者保存原历史和另一条合法历史，用 Python 与 SQL 分别确认答案不同，再用相同 tokenizer 和 packer 重打包，要求可见 UTF-8 字节完全一致。候选反例可以翻转隐藏结果、修改隐藏路由参数，或在 cutoff 处补一个合法后缀事件。重复事件的所有报告会同步修改，时间顺序与重复一致性也会重查。

没找到反例怎么办？不能直接宣布充分。论文保留三分类：有公共证明的 sufficient、有验证反例的 insufficient，以及两类证书都没找到的 unclassified。这个保守设计不如“一把全判完”听起来方便，却诚实得多。

### 恰当回答不是单纯的准确率

对证据标签 $z\in\{S,I,U\}$，论文只在已认证样本上定义上下文恰当性：

$$A=\begin{cases}
\mathbb{I}[a=y],&z=S,\\
\mathbb{I}[a=\texttt{UNDETERMINED}],&z=I.
\end{cases}$$

证据充分时，回答要等于完整历史参考答案 $y$；证据不足时，恰当行为是 `UNDETERMINED`。格式不合法的输出不得分。证据不足时即使 $a=y$，参考答案一致性记为 1，上下文恰当性仍记为 0。

未分类样本不会被偷偷塞进“不足”。若有 $c$ 个恰当回答、$u$ 个未分类输入、总数为 $n$，全输入恰当率只能写成识别区间 $[c/n,(c+u)/n]$。它不是置信区间，而是在说：这些样本没有证据标签，我们不知道它们该落到哪一端。

## 实验怎么做：不是拿 1,600 次请求当 1,600 个独立样本

论文有几组角色不同的实验，混着看很容易高估证据强度。

| 实验 | 历史与用途 | 请求数 | 作用 |
|---|---:|---:|---|
| Outcome masking | 40 条开发历史 | 480 | 等长遮蔽关键或无关结果 |
| Unordered packing | 同一批 40 条开发历史 | 2,080 | 探索预算与格式，含补充实验 |
| Judge confirmation | 120 条预留历史 | 2,400 | 构造候选答案，审计评价器 |
| Chronological Qwen | 16 条开发 + 80 条确认历史 | 1,920 | 五个上下文、四类查询；确认阶段 1,600 次 |
| DeepSeek replication | 复用 Qwen 已曝光的 80 条历史 | 1,600 | 固定可见输入的第二阅读器复现 |

主确认实验的每条历史含 24 个不同事件、4 份额外重复报告和 3 台设备，但事件总数及生成分布不告诉阅读器。80 条历史乘 4 个查询、5 种上下文，正好是每位阅读器 1,600 次请求。

五种上下文分别为 raw prefix、whole-record raw、CSV prefix、full raw 和 full CSV。前三种是部分历史，后两种是完整来源控制。raw 与 CSV 前缀的上下文预算固定为 768 个 Qwen token，whole-record raw 不切断记录，平均长度为 728.05 token。CSV 保存相同字段值，完整 CSV 经往返检查保证无损；但它可能切断尾部记录，所以“更紧凑”不等于“证书覆盖更多”。

两个阅读器是托管的 Qwen3-32B 和 DeepSeek-V4-Flash，温度均为 0，`reasoning_effort=none`，输出上限 64 token。提示词明确解释规则和拒答要求。DeepSeek 复现时只修改冻结请求里的模型字段，消息、seed 和严格答案 schema 保持不变，可见 UTF-8 字节相同。这里的 768 token 仍按 Qwen tokenizer 计算，不是两家模型各自等 token。

统计上，作者按整条历史做 10,000 次有放回 bootstrap，保留同一历史中的四个问题及配对条件。CSV 减 raw 的主对比只使用两种格式下都取得证书的 285 个问题，95% 区间是 percentile interval。预设的“正效果”标准要求区间下端严格大于 0。

这个设计让我比较放心。四个问题共享一条历史，当然不是四个独立观测；两种格式能认证的样本集合也不同，直接比较两个边际比例会悄悄改变目标人群。论文把这些麻烦摆到了明面上。

## 结果一：关键结果被遮蔽后，模型仍然很少说不知道

Outcome masking 是一组开发集诊断。每个查询比较三种输入：完整日志、把决定性结果替换为 `WITHHELD`、把无关结果替换为同一标记。所有重复报告一起遮蔽，中性 padding 对齐局部上下文 token 数。

Qwen 在完整输入上有 111/160 个恰当回答，占 69.4%，聚类 95% 区间为 62.5% 到 76.2%；无关遮蔽输入为 112/160，占 70.0%，区间为 63.1% 到 76.9%。完整减无关遮蔽只差降 0.6 个点，区间为 -3.8 到 2.5 个点。

真正刺眼的是关键遮蔽组：只有 1/160 次恰当拒答，占 0.6%；却有 72/160 次答案命中被隐藏的完整历史参考答案。

这 72 次就是最直观的“答案碰对不等于证据支持”。关键结果已经从输入中拿掉，两个不同结果赋值会导出不同答案，模型仍能靠原始历史中的答案分布、提示规律或别的偏好猜中一部分。若只报参考答案一致性，这 72 次都会看起来像成功记忆。

不过别急着把 72/160 当成真实系统里的幻觉率。这里有关键缺失的显式标记，样本来自开发集，干预是研究者刻意构造的。还有 47/160 个关键事件带两份报告，而对照事件只有一份；token 等长并没有隔离所有扰动差异。作者没有把这个 gap 包装成“语义相关性的纯因果效应”，这个克制是必要的。

无序前缀开发实验也出现过相似错觉。1,024 token 时，raw 命中 96/160 个参考答案，CSV 命中 106/160，表面差 6.25 个点，区间为 0.00 到 13.13 个点，而且两组都没有拒答。后续扩大反例搜索后，1,440 个非完整主网格输入全部被认证为不足；也就是说，这 96 和 106 次命中都发生在证据不足的上下文里。

排行榜上像是一次格式进步，证据轴上却没有多出一个受支持答案。

## 结果二：在 203 个证据不足样本里，碰对几十次，恰当拒答只有几次

时间前缀确认实验加入了“部分但充分”的样本，堵死一个偷懒策略：只要没看到完整日志标记就全部拒答。三个部分上下文臂合计有 327 个充分、585 个不足、48 个未分类输入查询条件；两个全源臂再贡献 640 个充分条件。这些是配对条件数，不是独立问题数。

主表如下，S、I、U 分别表示充分、不足和未分类；恰当率分母排除 U。

| 上下文 | Qwen 参考命中 | Qwen 恰当 | DeepSeek 参考命中 | DeepSeek 恰当 | 部分 S | I | U |
|---|---:|---:|---:|---:|---:|---:|---:|
| Raw prefix | 181/320 | 90/307 | 172/320 | 98/307 | 104 | 203 | 13 |
| Whole-record raw | 189/320 | 89/307 | 172/320 | 94/307 | 104 | 203 | 13 |
| CSV prefix | 195/320 | 108/298 | 167/320 | 111/298 | 119 | 179 | 22 |
| Full raw | 166/320 | 166/320 | 198/320 | 198/320 | — | 0 | 0 |
| Full CSV | 188/320 | 188/320 | 196/320 | 196/320 | — | 0 | 0 |

单看这张表，很容易只盯着 181、195 或 198。更值得读的是 raw prefix 的条件行为：

| Raw prefix 已认证子集 | Qwen | DeepSeek |
|---|---:|---:|
| 充分样本中答对 | 83/104 | 77/104 |
| 充分样本中错误拒答 | 4/104 | 23/104 |
| 不足样本中给出具体答案 | 196/203 | 182/203 |
| 不足样本中恰当拒答 | 7/203 | 21/203 |
| 不足样本中命中隐藏参考答案 | 87/203 | 85/203 |

Qwen 在不足样本里给出具体答案的比例约为 96.6%，参考命中约为 42.9%，恰当拒答只有 7 次。DeepSeek 的具体作答率是 89.66%，区间为 84.78% 到 94.02%；85 次参考命中占 41.87%，21 次拒答占 10.34%。两个预设复现阈值都通过了。

这不是“DeepSeek 比 Qwen 更不愿回答，所以问题解决了”。它在充分样本里答对 77/104，同时错误拒答 23/104；Qwen 是 83/104 和 4/104。提高拒答倾向会同时改变两种错误，单看一个拒答率没有资格宣判谁更可靠。

操作符拆分也很有意思。Qwen 的 raw prefix 中，第一条路由查询的恰当回答是 40/79，数量、最晚路由和状态分别只有 13/76、19/76、18/76。第一条成功路由一旦被看到，后面的隐藏事件无法改变它；另外三类查询却可能被后续事件改写。把所有截断输入粗暴标成“不可回答”，同样会评错。

## 结果三：CSV 的点估计为正，但证据还不够下结论

Qwen 的 raw 与 CSV 参考命中率分别为 56.6% 和 60.9%，已认证恰当率分别为 29.3% 和 36.2%，但分母不同。真正预设的配对对比使用共同认证的 285 个问题：CSV 减 raw 的恰当率差为 **3.16 个点**，聚类 95% 区间为 0.00 到 6.57 个点。DeepSeek 是 **2.46 个点**，区间为 -1.84 到 6.94 个点。

两者都没有达到“下端严格大于 0”的标准。

这里最忌讳的写法是“CSV 没有作用”。区间包含 0 不等于证明等效，80 条历史也无法排除较小效果。准确的说法是：当前实验没有建立正的恰当性收益。我的第一反应反而是去看证书覆盖——raw 的 320 个配对问题中，104 个在两种格式下都保持部分充分，179 个保持不足，还有样本在充分、不足和未分类之间移动。CSV 露出了更多完整记录，也可能因不同的半截尾部让证书更难判定。

全输入恰当率识别区间也能看出这种不确定性：raw 为 28.1% 到 32.2%，whole-record raw 为 27.8% 到 31.9%，CSV 为 33.8% 到 40.6%。这些区间描述各自臂内的未分类边界，不是配对置信区间，不能拿端点直接做显著性判断。

完整信息控制又补了一刀。Qwen 的 full raw 命中 166/320，full CSV 命中 188/320，差 6.88 个点，区间为 2.50 到 11.25 个点；DeepSeek 则是 198/320 对 196/320，差为降 0.625 个点，区间为 -5.00 到 3.44 个点。Qwen 的正向全源对比没有在 DeepSeek 配置中复现，而且“一个区间过零、另一个不过零”也不等于模型与格式之间存在统计交互。

还有个反直觉数字：Qwen 的 full raw 参考命中 166，低于 raw prefix 的 181。别把它解读成“不完整证据更好”。前缀里的部分命中本来就缺乏证据支持；完整输入还同时改变记录数量、长度和推理负担。把两个轴混在一起，连这种反常现象都会讲出一个过分顺滑的故事。

## 结果四：确定性程序拿到满分，给所有 LLM 评测提了个醒

论文设置了两个程序控制。END-only 策略在所有部分前缀上拒答，在完整日志上执行查询，它在三个部分臂分别得到 203/307、203/307、179/298，却在所有部分充分样本上失败。这个对照说明“统统拒答”确实混不过去。

Cutoff-aware 程序使用公共 cutoff 和第一条路由规则，在三个部分臂的已认证样本上分别达到 307/307、307/307、298/298，而且不调用模型。

看到满分时我停了一下：那还要 LLM 做什么？答案恰恰在论文的研究边界里。这个固定语法环境本来就可以用确定性解析器求解，程序与证书生成器还共享解析器和充分性规则。因此，它是协议一致性检查，不是独立验证出来的新求解器；它却清楚证明，不能拿 LLM 或混合方法相对某个弱基线的提升，冒充对最强简单基线的优势。

### 99.38% 的评审器，也没有通过完整审计

第三组研究把枪口转向自动评价器。作者用 120 条预留历史，每条选一个查询，构造 16 个候选答案，共 1,920 个案例。10 个标量控制覆盖正确值、错误值、冲突断言和扩展格式，6 个证据控制组合完整或遮蔽日志、正确或错误值、拒答。评价器要同时判断参考答案一致性与上下文恰当性，两个轴都对才算 joint success。

| 评价器 | 覆盖数 | 联合正确 | 标量负控误接收 |
|---|---:|---:|---:|
| Finite program | 1,680 | 1,680 | 0/480 |
| Extended program | 1,920 | 1,920 | 0/480 |
| Reference only | 1,680 | 1,320 | 120/480 |
| LLM low | 1,918 | 1,908 | 0/480 |
| Program-first + low | 1,920 | 1,920 | 0/480 |

DeepSeek-V4-Flash 的 low 配置联合正确 1,908/1,920，即 99.38%，历史聚类区间为 98.91% 到 99.74%。拆到双轴证据案例，joint 为 708/720，参考轴为 710/720，支持轴为 716/720。

但它仍把两个“关键结果缺失下的具体答案”误判为证据支持，另有两个输出截断；12 个失败中有 11 个参考答案是 `NONE` 或 `UNSET`。标量负控的 0/480 看着完美，却不能抵消双轴支持错误。一个总分很高的 judge，仍可能在评测最需要的角落出错。

Extended program 与 program-first hybrid 都是 1,920/1,920。相对 low judge，两者都提升 0.62 个点，区间为 0.26 到 1.09 个点；扩展程序不需要 API 调用，所以混合评审没有表现出相对强程序基线的优势。

满分也不是无限可靠的证明。即便把含错误历史简化成独立同分布 Bernoulli 观测，120 条历史零错误对应的一侧 95% 上界仍是 2.47%。构造模板与共享任务语义还会进一步限制外推。我觉得这段很值回票价：作者没有因为自家协议得到漂亮分数，就顺手把评价器也封为可替代品。

## 放到已有工作里，它到底新在哪里？

“答案正确”和“证据支持”不是这篇论文头一次区分的概念。作者自己也明确承认这一点。

| 工作方向 | 主要测量对象 | 与这篇论文的差别 |
|---|---|---|
| LoCoMo | 长对话问答、摘要和对话生成 | 面向会话记忆，不做同上下文的合法历史证书 |
| LongMemEval | 信息抽取、跨会话推理、时间推理、更新和拒答 | 覆盖记忆能力更广，本论文只审计受控阅读组件 |
| SQuAD 2.0 | 段落不支持答案时的拒答 | 强调 answerability，不处理可执行状态转移和同字节反例 |
| Sufficient Context | 检索上下文充分性与选择性生成 | 方向相近，本论文聚焦重复报告、失败动作、时间范围和状态 |
| RAGAs、引用与原子事实评价 | 检索、生成、来源或事实支持的不同侧面 | 本论文用有限事件语义构造可复核的证书标签 |

它的贡献更像把旧原则推进到一个更难审计的地方：不是问“这段话看起来相关吗”，而是要求“给出另一个合法世界，让它产生完全相同的可见输入，同时让查询答案改变”。

这个约束非常强。相关记录、正确引文、匹配数值，都不足以证明最终状态或穷尽计数；一段看似有证据的文字，仍可能缺少决定性事件。反过来，连续时间前缀和第一条路由规则又能证明部分上下文已经足够，避免把所有压缩都当成信息丢失。

工程评测实践里，把 context completeness 与 answer correctness 分开并不罕见；这篇论文多走的一步，是在可执行领域中把“完整性”从人工判断变成证书、分母和可重放的审计记录。它不是通用自然语言证据判定器，也没有这个伪装。

## 我的判断：最值得借走的是评测协议，不是某个分数

这篇论文最打动我的地方有三处。

**证据证书足够具体。** 同一 packer、同一 tokenizer、同样 UTF-8 字节，再加 Python 与 SQL 双路径核算答案，把“信息不足”从直觉变成了可保存、可复查的反例。特别是不能用生成器私有事件数补证明，这一条很容易在合成实验里被忽略。

**部分充分样本让任务不再退化。** 如果所有截断都不可答，模型只要看到没有 END 就拒答，便能刷出漂亮分数。论文用 cutoff 后完整记录与第一条路由规则保留充分前缀，逼阅读器真正区分查询与证据边界。

**对负面结果没有遮遮掩掩。** CSV 主对比不确证，第二阅读器复用的是 Qwen 已曝光输入，judge 没通过完整门槛，自然轨迹 pilot 也没有经过人工裁决。作者把失败路径留在论文里，比只展示一个 99.38% 有说服力。

局限同样硬。历史短、合成、固定英文语法，无法覆盖自然对话里的隐含事件、歧义时间和外部知识。两个托管阅读器都只测了 `reasoning_effort=none` 与 64 token 输出上限，单次成功内容采样不能估计模型家族的整体失败率；温度 0 也不保证托管服务完全确定。DeepSeek 复现虽然固定了输入字节，却复用已曝光历史，执行日期和服务实现也不同，跨模型差异不能干净归因到权重。

证书自身也不是全能裁判。未分类样本会随表示方式变化，Python 与 SQL 虽分别实现，却来自同一份任务规范；cutoff-aware 基线与证书器共享解析规则，无法排除规范本身写错。主对比还条件于“两种格式都认证成功”的子集，不能直接识别全部问题上的效果。80 条确认历史不足以排除小效应。

复现材料也有一个现实边界：附录 F 说本地研究生成了代码、日志、证书和请求哈希，但这些材料尚未作为匿名公开 artifact 发布，论文只说明计划公开原始实验代码和程序生成日志。网络关闭后的 replay 能逐字节重建已记录结果，却不保证重新请求托管 API 得到同样内容。做工程复现时，这个区别不能省掉。

### 如果你在做 Agent 记忆评测，可以直接改这五件事

把每条评测样本从单纯的 `(context, answer, reference)` 扩展成 `(context, query, public_rules, evidence_status, reference)`，评分逻辑可以写成：

```python
evidence = certify(context, query, public_rules)
reference = execute(full_history, query)
answer = reader(context, query)

if evidence == "S":
    appropriate = (answer == reference)
elif evidence == "I":
    appropriate = (answer == "UNDETERMINED")
else:
    appropriate = None  # 未分类，不擅自计入任一证据类别
```

这段伪代码不是论文实现，而是它最容易落地的评测思想。报告里至少并列给出充分样本答对率、不足样本恰当拒答率、不足样本隐藏参考命中数，以及未分类覆盖率。只看末尾的总分，失败定位又会消失。

第二，给压缩或检索器保留“可见来源清单”。要知道阅读器实际收到哪些记录、是否截断、公共规则允许它假设什么，不能等答案出来后再拿完整历史替它补证据。

第三，构造同上下文反例。能改隐藏结果、隐藏参数或合法后缀时，验证两份历史经过真实打包后是否仍逐字节一致。找不到反例就标未分类，别把搜索失败当充分证明。

第四，在可执行领域加入确定性解析器基线。若规则程序已经满分，LLM judge 或复杂记忆模块的价值就必须去开放语义、鲁棒性或成本维度证明，而不是在固定语法里击败一个弱对手。

第五，单独审计评价器。标量错误答案、冲突断言、证据不足下的正确答案、恰当与错误拒答、输出截断，都要进控制集。99.38% 的总分仍然藏着支持轴错误，这个教训足够具体。

## 收尾

这篇论文没有给 Agent 记忆系统带来一个更高的准确率数字，它做的是更基础的事：检查分数到底在奖励什么。

我最愿意记住的不是 87/203，也不是 99.38%，而是那两条能产生相同可见字节、却导出不同答案的合法历史。它们把“猜中”与“读懂”之间的缝隙直接摊开了。另一边的部分充分证书也同样关键，因为可靠评测不能靠一律拒答偷懒。

如果你正在维护记忆或 RAG 排行榜，值得在下一次改模型之前先改报表：把参考命中、证据充分性、上下文恰当性和未分类覆盖率分开。这个改动不花哨，却可能让一批看似漂亮的提升现出原形。
