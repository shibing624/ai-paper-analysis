# 智能体会改自己，不代表它有资格提交变更：EGE 给自我更新加一道证据门

一个 Agent 根据最近几次失败，重写了自己的提示词，又在旧任务上测出更高分。这个改动该不该立即写入长期配置？

我的第一反应不是看分数涨了多少，而是问另外三件事：测试数据是不是刚参与过这次修改，打分器是不是偏爱新输出，原本会做但对这次目标不重要的能力有没有退步。少任何一项，这个“更好”都可能只是系统给自己的一张好成绩。

EGE 把这件事从一句工程经验变成了一套可审计的采纳协议：生成更新和批准更新分开，冻结候选后用新样本复核，校准打分器的乐观偏差，保护旧能力，再经过灰度发布才允许持久提交。它不教 Agent 如何变聪明，而是约束它何时可以把一次自我修改保留下来。

## 核心摘要

自进化 Agent 能改提示词、记忆、工具与工作流，但“生成了一个看似合理的修改”与“这个修改值得长期保留”之间隔着一整层证据工程。EGE 用新鲜配对审计、候选级评估器校准、全局错误预算、参考版本桥接和有界灰度发布组成采纳门。蒙特卡洛压力测试中，当评估器乐观偏差为 0.25 时，忽略校准的规则在 2,997/3,000 次活动中误收过有害候选，EGE 则为 0/3,000。这个结果很能说明校准的必要性，却不是实际 Agent 实验；论文真正的价值是统计与发布治理的组合，底层工具仍是经典的 Hoeffding 界和并集界。

## 一、问题不在“会不会改”，而在“谁批准它留下”

Agent 的行为并不只由模型权重决定。提示词、持久记忆、检索策略、工具接口、规划流程、路由规则和执行限制，任何一项变化都能让同一个底模表现得更像另一个系统。

这也带来一个容易被忽略的权限问题：Agent 可能同时参与提出变更、选择测试样例、给结果打分，再把变更写回长期状态。三个角色叠在一起，自证循环就出现了。

论文把这个采纳问题和普通离线模型选择区分开，理由很实在。

候选是**自适应生成**的，第 $j+1$ 个提案会看见前 $j$ 次的成败；候选还可能改变证据产生机制，例如新提示词让输出风格更讨模型评审喜欢；优化目标通常很窄，但系统需要保住的能力很宽；上线也不是纯统计动作，高分候选照样可能在生产负载下超时、误调工具，甚至产生无法撤销的外部副作用。

所以，EGE 不是在 Reflexion、Self-Refine、Voyager 或 EvoPrompt 之外再发明一种自我改进算法。那些方法负责“提出可能的修改”，EGE 负责“决定修改能否成为持久状态”。这个位置差异比方法名字更重要。

| 研究路线 | 主要回答的问题 | 与 EGE 的分工 |
|---|---|---|
| 反思与迭代 refinement | 怎样改善当前回答或下一次尝试 | 可以提供候选，不单独给出持久采纳证据 |
| 提示词与进化搜索 | 怎样搜到更好的提示词或配置 | 开发集分数不能再冒充未触碰的确认证据 |
| 安全策略改进 | 相对基线的策略变化是否有证据支持 | 提供基线约束思想，EGE 面向异构 Agent 配置与多能力保护 |
| 自适应数据分析与置信序列 | 重复或自适应分析下如何保持推断有效 | 提供统计工具，EGE 采用逐候选新审计与显式校准预算 |
| Agent 自进化 benchmark | 自生成经验或 harness 更新能否提升能力 | 提供评测场景，EGE 管理具体更新的采纳决定 |
| 灰度发布与发布治理 | 怎样逐步暴露变更并监控 | 提供运行隔离，不能替代离线统计证据 |

说实话，这个分工本身并不新鲜，软件发布早就有代码评审、测试、灰度和回滚。论文值得读的地方，是它把自适应候选、评估器偏差和参考基线漂移也纳入了同一个可证明的统计框架。

## 二、EGE 的整体流程：候选先冻结，证据再出现

![图1：EGE 从候选生成、新鲜审计和治理检查到灰度提交的完整流程](https://www.mulanai.com/fs/files/1117_e0eebcac_ege_figu.jpg)

*图 1：论文唯一的流程图。上方从左到右依次是当前配置与经验、候选生成并冻结、新鲜配对审计、治理门；离线检查失败会保留当前版本。通过后进入有界灰度，灰度失败同样回滚，只有全部标准通过才持久提交。图中箭头把“离线拒绝”和“灰度失败”分开，避免把统计通过与生产可用混成一件事。*

整张图里最关键的动作其实是 **Freeze**。候选 $\widetilde A_j$ 一旦进入确认审计，就不能再根据审计结果偷偷修改。若改了，原来的审计样本对这个新版本就不再新鲜，必须换一批样本或采用能处理自适应复用的推断方法。

当前配置写作 $I_j$，可以包含模型、提示与策略配置、记忆、工具、编排逻辑和治理约束。候选生成器利用经验 $\mathcal E_j$ 产生 $\widetilde A_j=U(I_j,\mathcal E_j)$。生成器可以是 LLM 编辑器、搜索器或人工监督流程，EGE 不限制它怎么探索，但不把探索阶段的分数当成最终证据。

实际信息流至少要拆成三块：

| 数据分区 | 可以用来做什么 | 不能做什么 |
|---|---|---|
| Development | 调试、反思、搜索、提示词迭代 | 不能作为冻结候选的独立确认样本 |
| Validation | 开发期间比较不同候选设计 | 反复自适应查看后，不能再当 untouched test |
| Audit | 候选、指标、阈值全冻结后的确认评测 | 结果一旦回流修改候选，就失去对该候选的新鲜性 |

这里有个很工程化的细节：仅仅把目录命名成 `test/` 不够。访问日志还得记录候选哈希、审计实例、评估器版本、评分规则，以及结果有没有暴露给生成器。信息泄漏不靠文件名识别，而靠权限与日志控制。

## 三、采纳标准：主目标必须真有收益，保护能力不能拿来做交易

EGE 在看结果之前就固定两组指标。

主目标集合 $\mathcal J$ 用来证明更新值得做，每个指标 $r$ 有最小实用改善幅度 $\delta_r>0$。保护能力集合 $\mathcal K$ 用来防止偏科，每个指标有最大可容忍退化 $\epsilon_r\geq 0$。另有一组硬治理检查 $\mathcal G$，覆盖工具权限、数据访问、资源上限和人工批准等。

分数被归一化到 $[0,1]$，候选与比较器在同一任务实例上配对评分。主目标相对当前 incumbent 比较，保护能力则相对固定、带版本号的参考配置 $A_{\mathrm{ref}}$ 比较。这两个比较器故意不同：前者回答“是否比当前版本更值得用”，后者回答“是否把系统原本承诺的能力弄丢了”。

总体层面的要求是：至少一个主目标相对 incumbent 的参考评估差达到 $\delta_r$；每个保护能力相对固定参考的差不低于 $-\epsilon_r$；全部硬治理检查通过。

这套逻辑很像代码合并：一个新功能让平均延迟降了 20%，但关闭了权限校验，不能因为收益大就放行。**平均分不能购买硬约束的豁免权。**

一个指标还能同时承担两种角色。例如任务成功率既要至少提升 0.03，又不能相对长期参考下降超过 0.01。论文要求把这算成两个独立测试，因为比较器或阈值不同；计算总测试数 $R=|\mathcal J|+|\mathcal K|$ 时也要重复计入，不能悄悄减少多重检验负担。

## 四、统计核心：从操作评估器的分数，退回参考评估器的效果

### 4.1 为什么高分还要减掉一项校准修正

操作评估器记为 $q^E$，可以是线上实际使用的模型评审；参考评估程序记为 $q^R$，可以是确定性验证器、盲评人工裁决协议，或另一套独立治理的测量程序。注意，$q^R$ 不自动等于客观真理，它只是预先声明的目标测量构造。

对候选 $j$ 和指标 $r$，两类配对差分别是 $D^E_{j,r}$ 与 $D^R_{j,r}$，二者之差 $W_{j,r}=D^E_{j,r}-D^R_{j,r}$ 描述评估器偏差。若 $W$ 的条件均值为 $b_{j,r}$，操作评估均值 $\mu^E_{j,r}$ 与目标效果 $\Delta^R_{j,r}$ 的关系就是 $\Delta^R_{j,r}=\mu^E_{j,r}-b_{j,r}$。

这解释了一个常见翻车场景：新候选没有真正提升任务成功率，只把答案格式改成了模型评审喜欢的样子。$D^E$ 会上涨，$D^R$ 却没涨，校准样本负责把这段虚高估计出来。

EGE 为每个冻结候选单独抽取 $n_{j,r}$ 个确认样本和 $m_{j,r}$ 个独立校准样本。候选级校准很贵，却有必要：不同更新会以不同方式改变输出，昨天的全局偏差常数未必适合今天的新候选。除非另有覆盖完整候选类和自适应选择过程的统一泛化论证，否则不能拿一次全局校准替代它。

### 4.2 两条 Hoeffding 界拼成校准后的下置信界

确认差位于 $[-1,1]$，校准差位于 $[-2,2]$。论文分别从下方约束操作评估均值、从上方约束乐观偏差，再得到目标效果的下界：

$$
\begin{aligned}
L^E_{j,r} &= \bar d^E_{j,r}-\sqrt{\frac{2\ln(1/e_{j,r})}{n_{j,r}}},\\
\widehat U^b_{j,r} &= \bar w_{j,r}+\sqrt{\frac{8\ln(1/c_{j,r})}{m_{j,r}}},\\
L^R_{j,r} &= L^E_{j,r}-\widehat U^b_{j,r}.
\end{aligned}
$$

直觉很直接：观测均值先减去抽样波动半径，再减去“评估器最多可能比参考程序乐观多少”的上界。校准只用单侧上界，因为只有乐观偏差会让基于操作评估器的下界高估真实目标效果；悲观偏差不需要被当成同样风险处理。

统计门不是看点估计是否大于零，而是要求某个主目标满足 $L^R_{j,r}\geq\delta_r$，同时所有保护能力满足 $L^R_{j,r}\geq-\epsilon_r$。于是，一个效应很小但统计上可区分的更新仍可能因为没有实用价值而被挡住；一个观测收益很大但样本太少的更新，也可能只能留在“证据不足”。

这里会出现三种结果：接受、拒绝、无法定论。保守发布策略下，后两者都保留当前版本，但日志里不能合并。拒绝说明硬条件失败或已有材料支持不满足要求；无法定论则可能只是审计预算不够。这个区别直接关系到下一轮是该换候选，还是按预定计划增加样本。

### 4.3 候选可以无限来，错误预算不能重置

为了覆盖可数的自适应候选序列，EGE 给全局审计事件 $j$ 和测试 $r$ 分配错误额度：

$$
e_{j,r}=c_{j,r}=\frac{3\alpha}{\pi^2j^2R},\qquad
\sum_{j=1}^{\infty}\sum_{r=1}^{R}(e_{j,r}+c_{j,r})=\alpha.
$$

这里用了 $\sum_{j\geq1}j^{-2}=\pi^2/6$。评估和校准各花掉 $\alpha/2$，并集界因此给出：在条件新鲜抽样、有限预设指标族和参考程序有效这三项假设下，所有 $L^R_{j,r}\leq\Delta^R_{j,r}$ 同时成立的概率至少为 $1-\alpha$。不同候选或指标之间不需要额外独立，因为收尾的推导只是并集界。

候选生成仍然可以自适应，原因是给定审计前历史 $\mathcal H_j$ 后，候选已冻结，随后才抽取独立的新确认与校准样本。适应性没有被禁止，被禁止的是让候选在看见确认答案后继续变化。

全局索引 $j$ 也不能在候选被拒、系统回滚或换提案策略后清零。否则 $j^{-2}$ 的预算表就能被反复重开，原本的总量控制随之失效。参考桥接测试同样要从这个控制器领取唯一索引。

这条定理控制的是相对参考评估构造的统计欠覆盖，不证明参考评估器测到了真正关心的能力，也不证明审计分布等于生产分布，更不保证未测量动作不会造成伤害。论文把这些边界写得相当克制，我反而觉得这是它比较可靠的一部分。

## 五、参考版本也会漂移：桥接测试把累计退化写成明账

只让每次更新“不比比上一版差太多”，长期仍可能缓慢下坡。EGE 的固定参考 $A_{\mathrm{ref}}$ 用来避免这种基线逐次下移，但参考总有一天需要更新，于是又多了一个风险口。

参考序列记为 $A^{(0)},A^{(1)},\ldots,A^{(K)}$。把 $A^{(k)}$ 换成 $A^{(k+1)}$ 前，桥接测试必须在相同保护指标、相同目标分布上比较二者，并使用新的确认与校准样本。只有校准下界不低于预设桥接容差 $-\rho_{k,r}$，替换才获准。

在全部候选测试与桥接测试共享总错误预算 $\alpha$ 的同时覆盖事件上，当前 epoch $K$ 中已提交配置 $A$ 相对最初参考满足：

$$Q^R_r(A)-Q^R_r(A^{(0)})\geq-\left(\epsilon_{K,r}+\sum_{k=0}^{K-1}\rho_{k,r}\right).$$

这不是一个复杂的新定理，中间项相加后会望远镜抵消。但它把一笔容易被藏起来的账摊开了：每次挪动参考线都要花掉明确的退化额度，不能把“换基线”当成行政操作。

限制也很硬。各次桥接必须沿用相同指标定义与目标分布，否则这些差值不能直接相加，需要额外的 transport 或标准化论证；初始参考不一定最优，选定的保护指标也不可能穷尽所有能力。

## 六、样本量规划：后期候选会越来越难过审

统计有效不等于审得起。设确认半径为 $h^E$、校准半径为 $h^b$，真实效果比门槛多出 $g>0$。论文用足够保守的事件推导，要求 $2h^E+2h^b\leq g$，这样测试通过概率至少为 $1-e_{j,r}-c_{j,r}$。

公式里两个半径都有系数 2：下置信界本身减一次，观测均值相对均值的向下波动再留一次。作者特别指出这个因子，避免把“固定半径下覆盖”与“达到足够检验功效”混成同一个样本量问题。

对任意 $\lambda\in(0,1)$，一个充分条件是

$$n_{j,r}\geq\frac{8\ln(1/e_{j,r})}{\lambda^2g^2},\qquad m_{j,r}\geq\frac{32\ln(1/c_{j,r})}{(1-\lambda)^2g^2}.$$

校准样本的下界更大，因为 $W$ 的区间宽度为 4，而确认配对差的区间宽度为 2。随着 $j$ 增长，单项错误额度按 $j^{-2}$ 缩小，对数项变大，审计成本也会上升。

论文给出的规划示例使用 $\alpha=0.05$、$R=3$、$g=0.10$、$\lambda=0.5$，数量均向上取整，且是每个候选或桥接事件、每个指标测试的需求。

| 全局事件索引 $j$ | 单测试 $e=c$ | 最少确认样本 $n$ | 最少校准样本 $m$ | 合计 |
|---:|---:|---:|---:|---:|
| 1 | $5.07\times10^{-3}$ | 16,913 | 67,651 | 84,564 |
| 10 | $5.07\times10^{-5}$ | 31,650 | 126,597 | 158,247 |
| 100 | $5.07\times10^{-7}$ | 46,386 | 185,543 | 231,929 |

看到第 100 个事件需要 231,929 个观测，我有点皱眉。框架确实给了无限候选序列的保证，但这份保证的价格很直白。若系统只计划有限轮更新，预设有限候选范围可能更省；置信序列或经验 Bernstein 界也可能更紧，不过都得重新证明自己的适用条件，不能直接替换公式。

## 七、实验到底证明了什么：校准能挡虚高，代表性错配仍能击穿它

### 7.1 正确指定分布下的蒙特卡洛压力测试

实验是合成统计压力测试，不是 Agent benchmark。每种条件跑 3,000 个独立活动，每活动 10 个候选。每个候选有一半概率有益、一半概率有害；参考程序下，有益候选主效应为 $+0.25$，有害候选为 $-0.10$，保护效应均为 0。

主目标阈值 $\delta=0.05$，保护非劣界 $\epsilon=0.20$，全局错误预算 $\alpha=0.05$。操作评估器主目标乐观偏差 $b$ 取 0、0.10、0.25，保护指标偏差为 0。确认差从 $\{-1,+1\}$ 采样，校准差从 $\{-2,+2\}$ 采样，两组样本独立，$n=m$ 同取 5,000、20,000、80,000。随机种子为 20261112。

| 80,000 | 0.10 | 0/3,000 | 0/3,000 | 100.0% | 100.0% |
| 80,000 | 0.25 | 0/3,000 | 2,997/3,000 | 100.0% | 100.0% |

最有冲击力的数是 **2,997/3,000 次活动**。当 $b=0.25$ 时，有害候选的参考效果虽为 $-0.10$，操作评估器看到的均值却被垫到 $+0.15$，已经高于 $\delta=0.05$。不校准的门槛自然会把这种虚高当改善。EGE 在九个正确指定条件中都没有观测到有害活动接受；每个 0/3,000 对应的单侧精确 95% 二项上限约为 $9.98\times10^{-4}$。

但别把这个上限误读成定理的 $\alpha=0.05$ 保证，它只是这次蒙特卡洛零事件的统计区间。未校准规则在 $b=0$ 和 $b=0.10$ 时也没有观测到有害接受，说明 99.9% 的灾难结果依赖这组特意拉开的偏差与效应，不是所有评估器环境下的通用排名。

另一头的代价也很清楚。样本量为 5,000 时，EGE 的有益接受率只有 52.6% 到 76.2%，未校准规则全为 100%；到 20,000 与 80,000 才全部达到 100%。保守门会挡住坏更新，也会让好更新卡在证据不足。那些 100% 功效来自人工设定的分离效应，不是普遍功效承诺。

### 7.2 故意破坏校准分布假设，EGE 全部失守

第二个压力测试更值得我们记住。它仍跑 3,000 个活动，每个活动 10 个有害候选，$n=m=100,000$，真实主效应为 $-0.10$。实际审计中的评估器乐观偏差是 $+0.25$，校准样本里却只有 $+0.05$，其余设置不变。

| 实际审计偏差 | 校准偏差 | 有害接受活动 | 观测比例 |
|---:|---:|---:|---:|
| $+0.25$ | $+0.05$ | 3,000/3,000 | 100.0% |

即使每种样本都有 10 万个观察，校准分布选错后依然全部失守。这个结果没有推翻定理，因为它故意违反了“校准与确认样本来自同一声明指标分布”的前提。它击碎的是另一种幻想：形式化置信界无法补救不具代表性的校准设计。该比例的双侧精确 95% Clopper–Pearson 区间约为 $[0.9988,1.0000]$，量的也只是蒙特卡洛不确定性。

你想想看，这和一个模型在干净测试集上校准、上线后却面对被策略性改写的输出很像。样本量再大，测错总体照样没用。

## 八、离线通过以后，还要过一道生产门

EGE 的运行状态机有四态：Candidate、Audit-passed、Canary、Committed。离线统计与硬治理通过只代表可以进入有界灰度，不等于直接改长期状态。

灰度可以限制流量比例、用户或租户、可用工具类别、工具调用次数、数据域、运行时长和资源预算。只读摘要 Agent 或许能做流量切分；能修改记录或触发外部工作流的 Agent，更适合 shadow mode 或人工批准后才执行。候选在灰度期间也不能继续自改，否则监控对象已经不是通过审计的那个对象。

监控指标可含任务成功率、工具错误率、延迟、资源消耗、策略违规、升级人工比例和用户影响。反复查看指标时，要用序贯有效的方法或确定性停止阈值，不能把固定样本置信区间当成任意时刻都有效。

回滚也得是一份经过测试的恢复包，而不只是“把旧提示词复制回来”。记忆 schema、工具与 API 版本、feature flag、路由状态和迁移步骤都可能需要恢复。最重要的是，**配置能回滚，外部副作用未必能回滚**。已经发出的写操作可能需要补偿事务，有些后果连补偿也无法消除。

## 九、我的判断：这是一份严谨的采纳协议，不是一份自进化效果报告

我觉得这篇论文最值钱的地方，是把“生成”和“采纳”拆成了两个可追责的动作。候选生成器负责提案，评估服务按固定协议测量，治理方决定哪些风险与折中可接受。即使工程上由同一组服务实现，日志和事故复盘也应该能分清这些责任。

第二个亮点是候选级评估器校准没有被藏成一个固定常数。它明确承认更新会改变输出风格，继而改变评审与参考程序的分歧。第三个亮点是参考谱系：桥接容差与当前 epoch 容差一起进入累计退化下界，让长期基线移动有账可查。

但论文的实证边界非常窄。没有真实 Agent 代码或数据集，没有实际任务成功率提升，也没有生产审计成本报告。作者甚至把真实 Agent 评估协议写成未来必须完成的工作，包括六类对照：贪心观测分接受、固定均值阈值、无校准置信界、无参考保护的 EGE、仅 incumbent 保护的 EGE，以及完整 EGE。这个实验清单挺完整，可清单不是实验结果。

还有几处工程假设不能轻轻放过：

- 配对设计要求候选和比较器能在同一实例上运行。如果更新改变任务资格、工具可用性或执行路径，可能需要匹配队列、随机分配或另一个 estimand，不能机械套用配对 Hoeffding 公式。
- 独立样本假设对共享用户、会话和环境状态的 Agent 轨迹常常不成立。应按簇抽样、做保守聚合，或使用适合依赖数据的集中不等式。
- 有限的保护指标无法覆盖未声明能力；一个平均分还可能掩盖子群退化。增加子群测试又会抬高 $R$ 与审计成本。
- $[0,1]$ 平均分不适合稀释罕见灾难事件。这类后果应另设硬约束、尾风险或事件率条件。
- 参考评估器若系统性测错，置信区间再窄也只是围绕错误构造的精确测量。主观任务还需要盲评、评分培训、评分者一致性与裁决可靠性。
- EGE 不处理提示注入、数据外泄、供应链破坏或恶意工具响应，权限隔离、安全执行和事件响应仍然不可缺。

所以，我不会把它称作新的自我进化算法，也不会把蒙特卡洛结果当成 Agent 安全性证据。更准确的定位是：**一套把经典有限样本推断、候选级测量校准和发布治理接到 Agent 配置版本控制上的正式协议。**理论工具很基础，组合的问题定义却有实际价值；真正决定它能不能用的，是参考评估器是否可信、审计样本是否具有代表性，以及团队是否愿意承担那份不小的样本成本。

如果你正在做会改提示词、记忆或工具策略的 Agent，我建议先落地三件不依赖完整理论也能受益的事：冻结并哈希候选，隔离审计结果回流，给参考版本与桥接测试单独记账。随后再检查样本独立性、校准成本和灰度停止权。别从“让 Agent 自动提交”开始，先让每一次不提交都有清楚的理由。
