# 源域涨了 73 个点，目标域却崩了 35 个点：蒸馏到底教了 Agent 什么

上周调一个客服 Agent，遇到一件挺别扭的事。用一批工具调用的轨迹做蒸馏，训练集上的任务成功率一路往上走，换个评测集一看，模型开始"自说自话"——嘴上问用户要 ID，手里已经把工具调出去了，还拿 schema 里的示例 ID 当真值。结果当然是一串 `User not found`。

当时我把它归到"过拟合"，没深想。看到这篇论文才反应过来，过拟合这个词太笼统了：真正被改掉的不是答案对不对，是模型**怎么组织推理、什么时候动手、以及等信息的时候肯不肯把话筒交出去**。这三件事，恰恰是 ReAct 的骨架。

> **核心摘要**：论文把 on-policy distillation（OPD）放到四个交互形态完全不同的域里，逐帧检查学生轨迹，发现源域监督会悄悄改写 ReAct 模式：GR 监督把数学工具尝试率从 70.4% 压到 14.4%，准确率却从 16.7% 涨到 38.0%；ALFWorld 监督让 τ²-bench 从 41.5% 塌到 6.6%，55.8% 的轨迹出现"未拿到用户信息就调工具"的依赖违规。作者的解释是，学生把领域专属的表面习惯连同通用能力一起学了过去。缓解办法只用源域轨迹：拿教师做领域 RL 前、后两个 checkpoint 算 token 对数概率差 $\Delta$，丢掉 $\Delta$ 最低的 5% 位置，τ² 准确率从 11.5% 回到 29.9%。我觉得这篇最值钱的地方不是那个 5%，是它逼着大家把"准确率"和"交互行为"分开记账——它不是新损失、新架构，是一份做得很细的行为审计加一个轻量的筛选技巧。

## 一、四个域，四种"拿信息"的姿势

聊结果之前得先摆清楚实验台，不然后面的数字很容易看串。

作者挑了四个域，故意让它们的 ReAct 结构长得不一样：

| 域 | 缩写 | 交互形态 | 观察从哪来 |
|---|---|---|---|
| 纯自然语言数学推理 | GR | 单轮，直接推答案 | 没有外部反馈，全靠自己想 |
| 带 Python 解释器的数学 | CI | 写代码、跑代码、拿结果 | 代码执行器返回 |
| ALFWorld 家务任务 | ALF | 多轮动作，`go to`、`take`、`put` | 环境文字反馈，比如 "Nothing happens" |
| τ²-bench 对话式工具 | τ² | 航空、零售、电信，带模拟用户和账户侧工具 | 一半来自工具，一半**必须等用户回复或授权** |

学生统一是 Qwen3-4B-Instruct-2507，教师是在同一底模（或 30B-A3B）上做领域 RL 得来的。评测规模给得挺足：AIME2026 采 16 次、BeyondAIME 采 5 次、ALFWorld 140 个分布内加 134 个分布外任务各采 4 次、τ²-bench 100 个任务每个采 8 次。

关键差别在 τ² 那一行。ALFWorld 里"观察"是环境给的，模型发个动作就有人回；τ²-bench 里用户 ID、支付授权这类东西，模型得**先问、再让出回合、等对方答**。一个养出"边想边调工具"的习惯，另一个要求"先问再等"。这两种习惯撞在一起，就是后面那场塌方的伏笔。

说到这个，顺手把 OPD 的底交代一下。它的想法来自 GKD（Agarwal 等，ICLR 2024）和 MiniLLM（Gu 等，2024）：学生自己采轨迹，教师在每个 token 上给一个稠密的反向 KL 打分。反向 KL 是 mode-seeking 的，学生不容易跑到教师没见过的低概率区域去。相比 RL 只有轨迹末尾一个 0/1 奖励，OPD 每一步都有信号；相比 SFT 拿教师写好的文本练，OPD 的学生是在自己会走到的状态上被纠正。Thinking Machines Lab 2025 年 10 月那篇博客把它带进后训练主流，Qwen3 的报告里 OPD 在 AIME'24 拿 74.4 分、约 1800 GPU 时，而纯 RL 是 67.6 分、约 17920 GPU 时。MOPD（多教师 OPD，Ma 等，2026）再往前一步：每条 prompt 路由到对应领域的专家教师，把多个能力合进一个学生。这篇论文盯的就是 MOPD 这套流水线里一个被忽略的副作用。

形式上，学生 $\pi_\theta$、教师 $\pi_\phi$，学生自采 $y=\{y_t\}_{t=1}^T$，PG 风格的 OPD 写成：

$$
\mathcal{L}^{\mathrm{PG}}_{\mathrm{OPD}}(\theta)=-\mathbb{E}_{x,y}\left[\frac{1}{T}\sum_{t=1}^{T}\widehat{A}^{\mathrm{OPD}}_{t}\log\pi_{\theta}(y_{t}\mid h_{t})\right],\qquad
\widehat{A}^{\mathrm{OPD}}_{t}=\operatorname{sg}\!\left[\log\pi_{\phi}(y_{t}\mid h_{t})-\log\pi_{\theta}(y_{t}\mid h_{t})\right]
$$

$\operatorname{sg}$ 是停梯度。翻译过来很朴素：教师给这个 token 的概率比学生高，就把它往上推；比学生低，就往下压。每个 token 都挨一刀。**问题就出在"每个 token 都挨一刀"上**——教师压下去的那些 token，可能正是别的域里必须保留的动作时机。

## 三、先把"怎么算出答案"这条线拆开

Table 1 把 CI 数学任务的正确输出按"有没有调工具"切开：

| 模型 | 准确率 | 工具尝试率 | 无工具且正确 | 有工具且正确 |
|---|---:|---:|---:|---:|
| Base | 16.70 | 70.40 | 2.40 | 14.30 |
| ALF-OPD | 38.30 | 11.50 | 30.60 | 7.70 |
| CI-OPD | 52.40 | 73.00 | 4.90 | 47.60 |
| GR-OPD | 38.00 | 14.40 | 30.10 | 7.90 |

GR 训完，准确率从 16.7% 到 38.0%，工具尝试率却从 70.4% 掉到 14.4%。涨的分几乎全来自"不用工具也算对"这一格：2.4% → 30.1%。带循环代码的轨迹从 304 条降到 97 条，调 solver 的从 75 条降到 8 条。

论文给了一个我很喜欢的例子。一道配色的 urn 题，Base 的做法是增大弹珠总数、枚举红球个数，靠 Python 硬算到两个超几何概率相等；GR 学生把二项式系数约掉，推出 $b=3k+2$、$r=5k+4$、$n=8k+6$，再用两种颜色的下界收口，直接得到答案 190。两条路都对，但走的是完全不同的算法。

这就是"隐式重塑"的字面意思：没人改提示词，没人动工具接口，蒸馏自己把解题路线从"暴力枚举"扳成了"符号推导"。CI 监督反过来，保留 73.0% 的工具尝试率，52.4% 的准确率里 47.6 个点是靠带工具的答案撑起来的。ALF 监督也把数学推向自然语言推导（38.3% 准确率、11.5% 工具率）。

坦率讲，这类路线漂移在纯数学场景里未必是坏事，甚至可能更省 token。但同一套机制挪到要跟人打交道的域，麻烦就来了。

## 四、真正塌方的地方：把"问用户"改成了"直接调工具"

CI 的正迁移先看一眼，因为它说明"跨域变好"长什么样：

| CI → ALFWorld | 准确率 | 每轮调用数 | 相邻动作重复 | no-op 后换动作 |
|---|---:|---:|---:|---:|
| Base | 12.90 | 12.97 | 4.50 | 90.80 |
| CI | 40.20 | 18.94 | 0.70 | 94.30 |

准确率翻了三倍，重复动作从 4.5% 降到 0.7%，"Nothing happens" 之后换动作的比例从 90.8% 升到 94.3%。调用数还从 12.97 涨到 18.94——**交互变长了，但废动作变少了**。论文那个碗的例子很直观：Base 翻完空抽屉就停了，CI 学生会继续走到餐桌，先试着原地放碗，收到 no-op 反馈再挪到咖啡桌完成任务。

τ² 侧也类似（Table 2b）：整体 41.5% → 51.0%，零售 48.1% → 65.3%，有参考查询动作的零售轨迹里，把该查的都查完的比例从 54.5% 升到 67.5%，带错误反馈的 rollout 从 32.6% 降到 23.5%。76 个新增成功样本里 55 个来自零售。一个改支付方式的案例：Base 直接假设订单已经绑了目标卡；CI 学生先查订单、发现卡不对、再查礼品卡余额、拿到确认、才把支付方式改成功。

现在看塌方。Table 3 定义了两个很巧的指标：

| 模型 | τ² 准确率 | ask–call 同现率 | 依赖违规率 |
|---|---:|---:|---:|
| Base | 41.50 | 0.04 | 0.50 |
| 教师 | 46.00 | 0.67 | 0.38 |
| ALF | 6.60 | 94.30 | 55.80 |
| ALF+τ² | 68.90 | 0.24 | 0.00 |

`ask–call` 是"输出里既有请求式文本、又带工具调用"的比例。ALF 学生 94.3%，几乎每次问都顺手把工具调了。可那些请求文本**根本没送到用户面前**，工具却已经跑起来了。更麻烦的是第二列：`依赖违规率`，靠 LLM 语义审查逐条判定"这次调用是否依赖同一轮里刚问、还没拿到的用户信息或授权"，ALF 学生 55.8%，Base 只有 0.50%。

论文 Figure 3 那份轨迹节选我照抄一下，比任何指标都说明问题：

```
ALF 学生：
Assistant: … Could you please provide your user ID?
           <tool_call>{"name":"get_user_details",
                       "arguments":{"user_id":"sara_doe_496"}}</tool_call>
Tool:      Error: User sara_doe_496 not found

ALF+τ² 学生：
Assistant: … Could you please provide your user ID?
User:      Sure, my user ID is noah_muller_9847.
Assistant: <tool_call>{"name":"get_user_details",
                       "arguments":{"user_id":"noah_muller_9847"}}</tool_call>
```

`sara_doe_496` 是工具 schema 里的示例 ID。模型把"问"和"调"塞进同一个回合，还拿示例值填了参数。你想想看，这在真实客服系统里不是掉点，是拿假身份查了别人的账户。

有个细节值得停一秒：ALF **教师**在 τ² 上的 ask–call 同现率并不高（Table 3 里教师只有 0.67），教师自己的 τ² 准确率也有 0.319 / 0.634 / 0.356（附录 Table 13，航空/零售/电信）。也就是说，这不是"学生照抄了教师的坏毛病"，而是**学生拿源域轨迹练出来的习惯，在目标域里被错误地泛化了**。作者归到一句话：ALFWorld 靠环境动作拿观察，τ² 得靠用户回复拿观察；蒸馏把前者固化成了"工具即观察"，于是该等的时候不等了。

我觉得这个区分挺重要。它把问题从"教师不行"挪到了"监督位置的分布"，后者才有得救。

## 五、加个对应领域的老师，够不够

MOPD 现成的思路是缺哪个域就补哪个专家教师。Table 4 试了四种两两组合加一个三教师：

| 模型 | CI | ALF | τ² | GR | τ² ask–call |
|---|---:|---:|---:|---:|---:|
| CI+GR | 51.30 | 38.60 | 45.30 | 44.50 | — |
| ALF+CI | 49.80 | 83.20 | 34.00 | 46.70 | 25.60 |
| CI+τ² | 50.20 | 28.40 | 67.80 | 45.80 | 0.66 |
| ALF+τ² | 33.80 | 83.40 | **68.90** | 36.70 | 0.24 |
| ALF+CI+τ² | 51.10 | 86.90 | 64.40 | 45.00 | 0.10 |

补上 τ² 教师，ALF+τ² 把 τ² 从 0.066 拉回 0.689，ask–call 从 94.3% 掉到 0.24%，语义审查里没有任何当前请求的依赖违规；ALFWorld 还稳在 0.834。看着挺圆满。

但作者自己把口子戳破了：**ALF+CI 没有 τ² 监督**，它的 τ² 还是掉了 7 个点，ask–call 仍停在 25.6%。真实部署里你没法枚举所有任务域和所有反馈协议，总会有没见过的域掉进"held-out"那一格。补教师是补丁，不是机制。

顺带一个反例也挺好玩：CI+GR 在工具可用时保持 74.4% 的工具尝试率、51.3% 准确率，同时无工具场景拿 44.5%。GR-only 那套"把工具压掉"的路线漂移，只要 CI 教师也在场就不成立。同一个学生的行为，取决于教师组合，不是固定的。

## 六、方法核心：拿 RL 前后的偏好差，给每个 token 排个序

到这儿思路就自然了。作者把 OPD 教给学生的东西拆成两份：一份是通用 agentic 能力（怎么根据观察推理、怎么调整动作），主要来自领域 RL；另一份是任务专属的表面 ReAct 习惯（在哪个位置发起动作、要不要等回复）。负迁移来自第二份被过度拟合。

怎么把两份分开？只用源域训练轨迹，不用目标域任何数据。取教师做领域专用 RL **之前**和**之后**的两个 checkpoint，$\pi_{\mathrm{pre}}$ 和 $\pi_{\mathrm{post}}$，对学生在完整历史 $H_t$ 下采到的 token $y_t$ 各算一次对数概率：

$$
\Delta_{t}=\log\frac{\pi_{\mathrm{post}}(y_{t}\mid H_{t})}{\pi_{\mathrm{pre}}(y_{t}\mid H_{t})}
$$

$\Delta_t$ 为正，说明 RL 让教师更偏好这个 token；强负值说明 RL 把它压下去了。直觉很干净：**领域 RL 改掉的那部分偏好，恰恰是"领域专属"最浓的部分**。那就按 signed $\Delta$ 从高到低排，只在高位上做蒸馏。对一条有 $N$ 个合法位置的 rollout，保留比例 $\rho$ 取 $K=\lceil\rho N\rceil$：

$$
m_{t}=\mathbf{1}\!\left[t\in\operatorname{TopK}_{u\in[0..T-1]}(\Delta_{u})\right],\qquad
\mathcal{L}_{\mathrm{select}}(\theta)=\frac{1}{K}\sum_{0\leq t\leq T-1}m_{t}\,\ell^{\mathrm{OPD}}_{t}(\theta)
$$

就这两行，没有新损失项，没有额外模型，代价只是多存一份 pre-RL 教师、多算一次前向。说实话我第一反应是"这也太轻了"，轻到有点不敢信。

注意分母从 $N$ 换成 $K$，等于把保留位置上的梯度重新归一化，不是简单 mask 掉 5% 让信号变小。这个细节在后面的对照实验里挺关键。

## 七、三阶段曲线：尾巴上那 5% 才是罪魁祸首

作者扫了 10%、20%、50%、95%、99%、100% 六档保留比例，全部只用 ALFWorld 轨迹，看 ALF 和 τ² 怎么动。100% 就是普通 OPD。

| 阶段 | 保留比例 | ALF 准确率 | τ² 准确率 | ask–call |
|---|---|---:|---:|---:|
| 初始化 | — | 14.3% | 41.5% | — |
| Phase 1 | 10% | 69.4% | 31.1% | — |
| Phase 2 | 10% → 95% | 69.4% → 76.6% | 基本稳定 | 24.3% |
| Phase 3 | 95% → 100% | 76.6% → 76.64% | 29.9% → 11.5% | 24.3% → 97.1% |

只留 10% 的高 $\Delta$ token，ALF 就吃到约八成增益（14.3% → 69.4%），τ² 只从 41.5% 降到 31.1%。从 10% 一路加到 95%，ALF 慢慢爬到 76.6%，τ² 稳住不动。可**把尾巴上那 5% 低 $\Delta$ token 放回来**，τ² 从 29.9% 直接掉到 11.5%，ask–call 从 24.3% 飙到 97.1%。

5% 的 token，把 18 个点的目标域成绩和整个回合协议一起拖走了。这个数我看到第二遍才确认没读错。

还有个对照挺有说服力：随机丢 5%（Random95）并不能保住 τ²，说明起作用的不是"少学一点"，是"丢对了位置"。摘要里那句"从 11.5% 提到 29.9%"，说的就是普通 OPD 与 Top95 的对比，代价是 ALF 从 76.64% 这类满保留水平略微让步——作者管它叫 source-learning trade-off，没藏着。

## 八、被丢掉的到底是什么

这节我觉得是全文最有意思的部分，因为它把"\Delta 低的 token"翻译回了具体的行为。

![图2：八类 token 的 signed Δ 分布](https://arxiv.org/html/2611.19244v1/delta_context_dependence.png)

*图 2（论文 Figure 12，标题 Context-dependent preference changes）：横轴是 signed $\Delta$，单位 nats，约 −20 到 +12，虚线在 0；纵轴是八类 token（perhaps、to、need、the、and、Wait、`<tool_call>`、Since）。蓝点是 Retained，红点是 Excluded。`<tool_call>` 那一行红点明显往负方向堆，说明工具调用起始符被领域 RL 强烈抑制，也最容易落进被排除的尾部；`Wait` 一带则大量保留。同一个词在不同上下文里 $\Delta$ 能差出十几个 nats，所以名字叫"上下文依赖"。*

统计口径（论文 Figure 5）更直接：

| token 类别 | 占被排除位置 | 占全部合法位置 | 相对整体排除率的富集 |
|---|---:|---:|---:|
| 推理内容（工具调用块之外的文本） | 98.19% | 90.08% | 1.09× |
| 工具调用起始符 `<tool_call>` | — | — | 排除率 19.13%，**3.84×** |
| 调用载荷（`<tool_call>` 与 `</tool_call>` 之间） | — | — | 排除率仅 0.32% |

也就是说，被剔掉的不是"参数写错了"这类局部错误，而是**规划文本、状态描述和动作发起时机**。载荷几乎不动，起始符被大量动。这跟 §4 的行为观察对上了：坏掉的不是工具参数，是"什么时候该发起动作、要不要先等用户"。

作者还做了一组挺克制的对照，专门防"随便 mask 一下也能行"：

| 方案 | ALF 准确率 | τ² 准确率 | ask–call |
|---|---:|---:|---:|
| **Signed-$\Delta$ Top95** | 76.64 | **29.88** | **24.26** |
| Delimiter masking（只遮起止符） | 76.28 | 4.88 | 99.37 |
| Full-block masking（连载荷一起遮） | 79.74 | 3.00 | 99.72 |
| Negative masking（去掉所有负 advantage） | 80.02 | 3.63 | 83.54 |
| Advantage Top95（按普通 advantage 排序） | 81.66 | 23.50 | 82.68 |
| Advantage Top98 | 83.03 | 5.88 | 99.16 |
| Absolute-$\Delta$ Top95（按 $\lvert\Delta\rvert$ 排） | 85.86 | 17.13 | 83.94 |

三个结构性 mask 全军覆没，τ² 只剩 3% 到 5%，ask–call 接近 100%。按 advantage 排、按 $\lvert\Delta\rvert$ 排，ALF 反而更高（81.66 到 85.86），可 τ² 和回合协议都保不住。作者还特意做了个系数质量对齐的对照：Advantage Top98 移除 43.56% 的绝对系数质量，$\Delta$ Top95 移除 41.02%，归一化后保留 57.54% 与 62.02%——量级接近，结果差很远。所以起作用的不是"剔除了多少梯度"，是 **signed 方向**：被 RL 压下去的位置，才是专属习惯的载体。

这里我想踩一脚刹车。这套解释很漂亮，但 $\Delta$ 是"教师两个 checkpoint 的对数概率差"，它同时混了 RL 带来的能力提升和风格漂移，作者没有单独把这两样拆开验证。3.84× 的富集确实扎眼，可"低 $\Delta$ = 任务专属习惯"目前还是个相关性叙事，不是因果证明。这块我自己也还在琢磨，可能理解有偏差。

## 九、换个场景还灵吗：GR 到 CI

为了不让人觉得这是 ALF→τ² 一对域的巧合，作者换成数学场景重做了一遍。用一个做过无工具 GR 强化学习的 Qwen3-30B-A3B 教师（和前面跨域矩阵里的 GR 教师不是同一个），拿 pre-RL 当参考，从同一个 4B 初始化训 20 个 update。CI 和 GR 评测集是同一批数学题，只有 CI 侧给解释器。

| 方法 | GR 准确率 | CI 准确率 | CI 工具尝试率 | 无工具且正确 | 有工具且正确 |
|---|---:|---:|---:|---:|---:|
| Full OPD | 46.02 | **37.65** | 10.41 | 31.63 | 6.02 |
| Signed-$\Delta$ Top95 | **46.33** | 36.53 | **29.49** | 24.90 | **11.63** |

GR 准确率几乎一样（46.02% 对 46.33%），Top95 把 CI 工具尝试率从 10.41% 拉回 29.49%，带工具且答对的比例从 6.02% 翻到 11.63%。但 CI 总准确率反而略降（36.53% 对 37.65%），因为无工具且正确的那格从 31.63% 掉到 24.90%。

作者的措辞很老实：**保住了工具行为，没有提升聚合准确率**。我喜欢这个不吹的写法。它顺手把整篇的论点收得更紧——任务分数和交互行为是两本账，只看前者会漏掉一半结论，只看后者又容易把"行为更像了"当成"效果更好了"。

## 十、我的判断：值钱的是审计纪律，不是那个 5%

把定位先说清楚：这篇不是新损失、新架构、新基准。公式只有 OPD 的标准 PG 形式加两行筛选，$\Delta$ 的思路也能在 delta-based distillation（Heo 等，2026）和"Revisiting On-Policy Distillation"（arXiv:2603.25562，讲 sampled-token OPD 的脆弱性、special-token mismatch）里找到近亲。连作者自己都把贡献写成两条：一条是系统检查 OPD 怎么改 ReAct 模式，一条是拿 pre/post-RL 偏好差做位置选择。剥开包装，它是一份**行为层面的跨域审计**，外加一个几乎零成本的筛选技巧。

我觉得真正值得抄走的是它的评测纪律。ask–call 同现率、依赖违规率、no-op 后换动作比例、参考查询覆盖率、相邻动作重复率——这些指标都不看答案对不对，只看"模型怎么走到答案的"。Table 3 那两个指标尤其巧：把"嘴上问、手里调"量化成 94.3%，再靠语义审查把其中真正有害的挑出来（55.8%）。做 Agent 后训练的人，光把这套指标搬进自己的 eval 就不亏。

跟同期工作比，位置也清楚。GKD/MiniLLM 解决的是 off-policy 分布偏移，MOPD 解决的是多能力怎么合，ATOD、ActFirst-OPD、SEED 在调 turn 权重、拆动作与推理、蒸 hindsight 技能。大家都在改"监督什么、监督多重"，这篇问的是 **监督落在哪个 token 上、会顺手改掉哪些没训过的域的行为**。这个角度之前确实少有人系统查。它也顺手解释了为什么 2603.25562 那类 special-token masking 会管用——但论文自己的 delimiter / full-block masking 对照又说明，粗暴遮起止符救不了这里的问题，得按偏好差挑。

要挑毛病，也不少。

一是**外推范围窄**。作者自己在 Limitations 里写了：只在 Qwen3 家族、4B 学生、数学与交互任务上做，更大学生、别的模型家族、更广的 agent 环境都没验。二是**负迁移几乎只靠 ALF→τ² 一对域撑着**，GR→CI 那组是"保住行为但没涨分"，严格说不算同类成功。三是 **5% 是经验扫出来的**，没有给出随教师强度、RL 步数、保留比例自适应选阈值的办法；换一套训练配方还得重扫。四是**依赖违规靠 LLM 语义审查**判定，判据和一致性在附录里，但这类 judge 本身的噪声没有独立估计。五是我有点怀疑解释的单一性："过度拟合任务专属 ReAct 模式"能讲通 ALF→τ²，可 CI 为什么能正迁移、τ² 单源为什么把 GR 拉低 6 个点，同一套说法覆盖得没那么服帖，作者也没硬凑，算是留白。

还有个工程上的现实问题没被讨论：要算 $\Delta$，你得留着 pre-RL 教师 checkpoint。产线里如果教师是外采的、只给了最终权重，这套方法就直接不可用；而"再存一份基座教师"在多教师 MOPD 里是乘着教师数涨的开销。它轻，但没轻到零。

所以别把 29.9% 当成通用解药。更合理的读法是：**当源域的反馈协议和目标域不一样（环境给观察 vs 人要给授权），源域蒸馏有可能把"拿信息的方式"一起改掉；想在只有源域轨迹的前提下止血，先查一下教师 RL 前后偏好变化最负的那批位置。**

## 十一、如果你也在做 Agent 蒸馏，可以马上加的四件事

| 检查项 | 最低做法 | 论文里的证据 |
|---|---|---|
| 行为指标与准确率分开报 | 除了任务成功率，记录工具尝试率、回合协议、请求与调用是否同现 | Table 1、Table 3 |
| 跨域 held-out 评测 | 至少留一个没训过的域，别只报源域和测试集 | Figure 2 里 ALF+CI 的 τ² 掉了 7 个点 |
| 依赖违规审查 | 逐次调用检查是否依赖"刚问、还没拿到"的信息或授权 | ALF 学生 55.8% 的轨迹中招 |
| 保留 pre-RL 教师 | 存一份领域 RL 前的 checkpoint，用它算 $\Delta$ 做位置筛选 | Top95 把 τ² 从 11.5% 拉回 29.9% |

再补一条我自己的：别只筛一次就收工。论文里 Phase 3 的塌方说明**尾巴上那 5% 位置集中承载了破坏力**，那这批位置值得单独拉出来人工看几条轨迹——比再扫一遍保留比例更能告诉你下一个域会不会踩同样的坑。
