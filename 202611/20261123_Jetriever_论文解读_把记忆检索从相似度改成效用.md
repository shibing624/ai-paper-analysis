# 那条救命的记忆，一个字都不像你的问题：Jetriever 把检索从"相似"改成"有用"

你有没有碰到过这种事：用户半年前随口提过一句"我对坚果过敏"，今天跑来问"有没有好吃的马卡龙配方"。一个像样的助手应该当场反应过来——马卡龙用的是杏仁粉，得提醒，得换配方。可你要把这半年的聊天记录丢进向量库，拿"马卡龙"去搜，那条过敏记录大概率排在几十名开外，连 top-5 都进不去。

问题不在模型笨。论文里给了个数：要是把"坚果过敏"直接塞进 GPT-5-mini 的上下文，回答对的概率是 84.0%。塌掉的是更前面那一步——检索压根没把这条记忆捞上来。它俩一个字都不像，一个词都不共享，连话题都对不上。

顺着这个场景再想一步，会更不舒服。用户说"家里客厅有百合"，过阵子问"我想养只猫，有什么要注意的"。百合对猫是致命的，这条记忆此刻价值极高。但"百合"和"养猫"之间那根线，不长在文本里，长在世界知识里。任何基于词面或嵌入相似度的检索，都看不见它。

这篇论文就是冲着这个盲区来的。

## 🎯 核心摘要

arXiv:2611.21478，中科大四位作者，2026 年 11 月的预印本。干的事挺干脆：不搜"像的"，改成给记忆池里每一条打一个"对回答这个问题有没有用"的概率，然后按这个概率直接排全池。打分的模型叫 Jev，一个从大语言模型基座改编、用 RLCD 训练出来的 System One 决策模型，不做自回归生成，只吐一个二值概率。效果很硬：InMind 的 125 个间接查询上，把目标记忆排在第一位的比例从 BM25 的 1.6%、MiniLM 的 0.0% 拉到 84.8%，端到端 Application 从已发表系统最好的 16.0% 提到 76.0%（把正确答案直接喂给模型的上界是 84.0%）；MemoryAgentBench 抽的 60 题上，四维均值从 ReFind 的 44.3% 到 55.4%，单条 query 的检索成本不到一美分。

我的判断是：**问题重述本身就值钱**，把"检索"重新定义成"逐条决策"这一步，比任何工程技巧都关键；论证里那句"假设空间无界、存储有限"的不对称性，是全篇最漂亮的地方。但它把命门押在一个不开源、只有博客和文档可查的商业打分模型上，又用自家基准打自家 baseline，MAB 只跑了 60 题。当成一个值得追的方向，很够；当成定论，早了点。

## 🧠 问题动机：相似度在这里塌得有多彻底

说实话，一开始我以为这又是一篇"向量检索不够好，我们加个重排"的常规操作。读完 Section 2 才发现不是——作者先把相似度检索最强的一面老老实实夸了一遍。

在 ReFind 的六子任务评测里，单发 BM25-RAG 拿到 48.8% 的宏平均，压过对比中每一个稠密检索器；让智能体在原始聊天日志上做 BM25 搜索，能到 58.2%。Wang 等人在更大规模的 RAG 研究里看到同样的规律，Bao 团队的 RAW-RAG 用未处理的对话配稠密检索加交叉编码重排，在四个基准、七个设置里的六个赢过结构化记忆系统。作者引这些工作的时候没藏着——只要那段决定性记忆和用户的提问共享词或实体，相似度检索本来就很能打，甚至常常比一堆花哨的记忆架构更能打。

塌方发生在记忆的价值来自"对答案的用处"、而不是"和问题长得像"的时候。坚果过敏配马卡龙，靠的是"马卡龙用杏仁粉"；客厅百合配养猫，靠的是"百合对猫有毒"。这两组里，query 和记忆既不共享词汇，也不共享表层话题，连接完全活在世界知识里。

InMind 把这个失败量化得很刺眼：125 个间接查询任务，把目标记忆直接放进上下文，GPT-5-mini 的 Application 是 84.0%；六个有代表性的记忆架构端到端最多 14.4%，朴素嵌入 RAG 最多 16.0%。现代大模型一旦在提示里同时看到两块信息，连线画得挺好；断的是更早那一环，检索把决定性记忆落在了后面。

那把大模型放到检索上游，让它改写、扩展 query，行不行？A-RAG、ReFind 这类智能体框架就是这么做的，让模型一轮轮造关键词或语义查询。作者的反驳我觉得很有力：造 query 之前，智能体只看得到用户那句话。看到"我想养只猫"，它得凭空猜到"百合""有毒家居植物"，还得顺带猜过敏、租约条款、出差习惯、已有宠物……隐性关联的空间是开放的，再多的 query 扩展预算也盖不住。

接着就是全篇我最喜欢的一句翻转：**在 query 空间里不可穷举的东西，换到 memory 空间里就变得可穷举了**。我们列不完世界上所有潜在危险，但我们能把自己实际存下来的每一条记忆都看一遍。Jetriever 的全部动机就压在这个不对称性上——别再去发明检索词了，直接拿问题去问每一条存储："你对回答这个问题有没有用？"

## 🏗️ 方法核心：把检索器换成一个逐条下判断的决策模型

### 极简到有点反直觉

Jetriever 刻意做得极简。写入时不把对话压成摘要、不抽实体图——理由很实在：一条细节将来有没有用，写入的那一刻根本没法预见，压缩就是永久丢信息。所以它保留原始对话单元，把全部力气放在读取时的全池效用打分上。

给定查询 $q$ 和候选记忆 $\{m_1,\ldots,m_N\}$，它对每一对 $(q, m_i)$ 独立调用 Jev 的 Noul 二值原语，拿到一个校准过的概率 $s(q,m_i)\in[0,1]$，含义是"某条自然语言判据成立"。在 InMind 上，判据大致是：这段记忆里是否包含给出正确、个性化回答所需的个人信息，包括间接相关的信息；只判断这一段本身贡献了什么，别依赖它之外的信息。在更宽的 MemoryAgentBench 上，判据换成：这段候选是否包含正确回答该问题所需的信息，涵盖直接陈述的事实和必要的支撑上下文。

然后直接按分数把整个池子排序：

$$
\pi_q=\operatorname{argsort}_i\big(-s(q,m_i),\,\operatorname{id}(m_i)\big),\qquad \mathcal{M}_k(q)=\{m_{\pi_q(1)},\ldots,m_{\pi_q(k)}\}
$$

取前 $k$ 条原始记忆直接丢给下游的回答模型，**不带 Jev 的分数，也不带任何生成的理由**。候选 id 只用来确定性地打破平局——因为 Jev 的概率只报到小数点后两位。

这里有个细节我盯了一会儿：241 个候选、概率只有一百个取值档，平局肯定成堆，靠 id 决胜说到底就是按存储顺序排。一个以"排序"为命根子的方法，分数分辨率这么低，论文却一句话带过，没给"有多少条 query 受平局影响"的数字。后面的批判里我还会提。

### 和两阶段重排不是一回事

常规做法是先用 BM25 或嵌入捞一个短名单，再让交叉编码器或 LLM 重排。有意思的是，连 TypeSafe 自家的 cookbook 都是拿 Jev 过滤检索结果、或者重排 BM25 短名单。可在隐式关联查询上，词法或向量短名单会在重排器看到之前，就把那条关键记忆扔掉了——重排器再准也救不回来。

Jetriever 干脆把相似度索引整个删掉，让全池效用打分自己当检索器。这一步看着只是"去掉第一阶段"，其实是把召回的责任从索引结构彻底转移到了打分模型身上。

### 打分器必须同时满足三件事

Section 3 立了三个条件，我觉得这个拆解比方法本身更有参考价值。

**广博的世界知识**。认出"坚果过敏"和"马卡龙"有关，需要既不出现在 query、也不出现在存储轮次里的开放域事实。BERT 规模的双向编码器和轻量交叉编码器快、好微调，但缺这份事实广度。只有大规模语言模型预训练打下的底子才撑得住跨日常领域的隐含关联。Jev 正是从预训练 LLM 基座改编来的，保留开放世界知识，把用途从"生成文本"改成"有界判断"。

**校准过的排序概率**。世界知识让你"认得出"有用证据，但面对几百轮聊天历史，这终究是个排序问题。真实历史里有一大堆沾点边、看着也挺合理的轮次。拿一个做过指令微调的对话大模型问"这条有用吗"，或者直接读它答案 token 的概率，对话后训练加上讨好、过度附和的倾向，很容易把分数推成一片宽松的认可、或者挤在中间区分不开。几十条沾边轮次都拿高分，真正决定性的那条就被挤出 top-k 窗口了。Jev 用 RLCD（Reinforcement Learning for Calibrated Decisions）训练，目标就是让输出概率贴住经验似然，而不是贴住对话偏好，从而把决定性记忆和背景闲聊拉开。

**便宜到能全池打一遍**。全池打分等于每条 query 要做 $N$ 次模型调用。让自回归对话大模型跑几百上千次，慢且贵到没法用。Jev 彻底丢掉自由生成：一次请求给上下文，评估的是有界决策原语——多选 Choice、序数评分 Score、二值概率 Noul——配并行输出采样。每次调用只回一个紧凑概率，没有思维链，没有自回归解码，几百到一两千条候选的全量评估在延迟和成本上才落得下来。

把三种打分器摆一起，就是论文 Table 5 的结论：

| 能力要求 | Jev（System One 模型） | 生成式 LLM 打分器 | BERT 系分类器 |
| --- | --- | --- | --- |
| 广博世界知识 | 有 | 有 | 无 |
| 校准的排序分数 | 有 | 无 | 有 |
| 全池成本与延迟 | 低到中等 | 高 | 低 |

三类模型各占两角，缺的那一角恰好都能解释它们为什么当不了全池效用检索器。这张表是全文的论证枢纽。

### 三种范式，问的是三个不同的问题

顺着上面的再往前一步，可以这么归纳：

| 范式 | 它问的问题 | 决定性记忆与 query 不像时 | 代价 |
| --- | --- | --- | --- |
| 相似度检索 | 哪段存的文本听起来像这个 query | 直接漏掉，连 rerank 机会都没有 | 低，$O(1)$ 级索引查询 |
| 智能体 query 扩展 | 大模型在看存储之前，能猜到哪条隐藏联系 | 猜不中，假设空间开放 | 中到高，多轮 LLM 调用 |
| 全池效用打分 | 每条存下来的记忆，是否真的改变回答方式 | 能捞出来 | $O(N)$ 次打分，可并行 |

说到底，前两种都在 query 侧想办法，第三种把判断挪到了 memory 侧。这个视角切换，是这篇论文最值钱的部分。

## 🧪 实验结果：数字确实很硬

### InMind：从 1.6% 到 84.8%

先说设置，免得数字被误读。InMind 每个任务把一条个人事实种进 47 个 session 的多轮历史（后面再跟 38 个干扰 session），然后提一个自然请求，它和那条事实的连接靠世界知识而非共享词汇。检索评测里，所有方法排的是**完全相同**的 241 个 user–assistant 交换池：240 条背景加 1 条注入的 gold 交换。对照组是 BM25（小写字母数字分词，$k_1=1.2$、$b=0.75$）和 MiniLM（all-MiniLM-L6-v2，归一化余弦，256 token 上限），各自索引"仅用户轮次"或"完整交换"。125 个 query 乘 241，一共 30,125 对打分。

召回定义为：

$$
\mathrm{R@k}=\frac{1}{125}\sum_{j}\mathbb{1}\left[r_j \le k\right]
$$

Table 1 原样搬过来：

| 方法与索引文本 | R@1 | R@5 | R@10 |
| --- | --- | --- | --- |
| BM25，仅用户轮次 | 1.6 | 4.8 | 5.6 |
| MiniLM，仅用户轮次 | 0.0 | 2.4 | 8.8 |
| BM25，完整交换 | 0.8 | 2.4 | 4.0 |
| MiniLM，完整交换 | 0.0 | 1.6 | 7.2 |
| **Jetriever，完整交换** | **84.8** | **92.0** | **94.4** |

125 题里有 106 题把 gold 排在第一（84.8%），115 题进 top-5（92.0%）。

个案比平均数更有画面。用户问感冒药推荐，而历史里存着"我被诊断有高血压"（常见减充血剂对此有禁忌）：Jetriever 把这条排第 1，MiniLM 排第 54，BM25 排第 178。另一个是挑家庭宠物，历史里有哮喘：Jetriever 排第 1，MiniLM 第 107，BM25 第 241——**241 是池子的末位**。看到这个数我愣了一下。它不是"没找到"，而是精确地把最该找的那条推到了队尾，比随机还糟。这说明在嵌入空间里，这类隐含关联被稳定地推向远处，不是噪声，是方向性的偏差。

### 候选粒度这个消融，比主表更有信息量

把 Jev 从"逐条交换打分"（241 个候选）换成"整个 session 打分"（47 个候选），R@1 从 84.8% 掉到 49.6%，R@5 从 92.0% 掉到 82.4%，反倒是 R@10 从 94.4% 微升到 96.8%。作者的解释我认同：细粒度的交换能把一条个人事实干净地单独摆出来，效用显眼；把整段多轮 session 打包，那条事实就埋在一堆无关话题里，top-1 的分辨力被糊掉了。

这个消融几乎零成本就能抄进工程里——切分粒度选错，再好的打分器也白搭。

### 端到端：76.0% 对 16.0%

把 Jetriever 的 top-5 交换喂给 GPT-5-mini，按 InMind 官方的 context-aware 判据评 Application：

| 配置 | Application（%） |
| --- | --- |
| GPT-5-mini，目标事实直接在上下文里（上界） | 84.0 |
| BM25 | 9.6 |
| text-embedding-3-large | 16.0 |
| A-RAG（配 text-embedding-3-large） | 7.2 |
| A-Mem（配 text-embedding-3-large） | 9.6 |
| HippoRAG 2（配 MiniLM） | 8.8 |
| MemoryOS（配 text-embedding-3-large） | 14.4 |
| **Jetriever（top-5 交换）** | **76.0** |

76.0% 是 95/125，把到 84.0% 上界的差距补掉了大半。附录 A.1 把全部 16 个已发表配置都列了：MiniLM 9.6、text-embedding-3-large 16.0、BM25 9.6；配 MiniLM 的记忆系统是 A-RAG 4.8、xMemory 4.8、Mem0 3.2、A-Mem 6.4、HippoRAG 2 8.8、MemoryOS 8.0；换成 text-embedding-3-large 后是 7.2、6.4、6.4、9.6、5.6、14.4。一整页没有一个超过 16 的。

差距大到这个程度，我是有点怀疑的，留到批判那节聊。

### MemoryAgentBench：泛化到常规记忆能力

MAB 测四种能力：准确检索 AR、测试时学习 TTL、长程理解 LRU、选择性遗忘 SF。作者从 3,671 题的评测池里按维度大小分层随机抽 60 题（33 AR、11 TTL、3 LRU、13 SF，随机种子 6641975833030951438），均匀无放回。Jetriever 给每题的全池打分，共 75,491 个 query–conversation 对，均值每题 1,258.2 个候选，中位数 100.5，范围从 2 到 42,946。超过 6 万字符的对话按 4 千字符重叠切成 75,532 个片段，Jev 分数 max-pool 回父对话；top-5 交给 GPT-4o-mini，按 MAB 官方提示和指标评（LongMemEval 部分用 GPT-4o-mini 当裁判）。

| 方法 | AR | TTL | LRU | SF | Overall |
| --- | --- | --- | --- | --- | --- |
| GPT-4o-mini | 49.2 | 48.6 | 46.2 | 25.0 | 42.2 |
| BM25 | 60.5 | 44.5 | 35.6 | 25.5 | 41.5 |
| text-embedding-3-large | 54.6 | 44.3 | 37.3 | 16.0 | 38.0 |
| HippoRAG 2 | 65.1 | 35.8 | 36.2 | 29.5 | 41.6 |
| MIRIX | 47.5 | 24.1 | 25.4 | 8.0 | 26.2 |
| ReFind∗ | 49.8 | 30.0 | 55.5 | 41.7 | 44.3 |
| **Jetriever∗** | **65.5** | **40.0** | **59.0** | **57.1** | **55.4** |

∗ 号这两行是在同一 60 题子集上做的正面对比，不带星的行是别人论文里全 benchmark 的已发表数字。55.4% 对 44.3%，涨了 11.1 个点，四个维度全领先。逐题看，60 题里 Jetriever 在 13 题更高、3 题更低、44 题打平。子任务上 EventQA 从 24/29 到 28/29，单跳选择性遗忘 FC-SH 到 6/6（ReFind 是 5/6），多跳 FC-MH 两边都难，1/7 对 0/7。

44 题打平这个数，我盯着看了很久。它意味着 11.1 个点基本靠 16 道有区分度的题撑着。后面细说。

### 🔬 受控对比：认出来，和排第一，是两件事

这是我觉得设计得最聪明的一组实验。20 道 InMind 题，完全相同的 241 候选池，把三类打分器摆在一起：

Laya 是 421M 的 ModernBERT-large 编码器（convaiinnovations/laya-typed-decisions），带结构化决策头；Qwen3.5-9B 是后训练的生成式模型，提示它做二值有用性判断，用赋给 true 与 false 的归一化概率打分，Qwen3.5-4B 同协议一起画进图里；Jev 就是 Jetriever 用的 Noul 效用打分器。完整交换在 1200 token 内直接打分，只有一个超长的背景交换越界（占候选 0.4%，且 gold 都不在其中），用 1200 token 窗口、200 重叠、max-pool 处理。

![图1：20 道 InMind 任务上四类打分器的 Gold-exchange R@k 曲线](https://www.mulanai.com/fs/files/1123_eb3d4a1f_figure1_.png)

*图1：横轴是 Top-k retrieved exchanges，对数刻度，取 1、2、5、10、20、50 六个点，k=5 处画了一条竖直参考线；纵轴是 Gold-exchange recall（%），0 到 100。四条曲线分别是 Jev（深绿实线圆点）、Qwen3.5 9B（蓝色虚线方块）、Qwen3.5 4B（棕色点划线三角）、Laya（暗红点线菱形）。Jev 从 k=1 的约 85% 起，k=5 之后稳在约 90% 几乎走平；Qwen3.5 9B 从约 40% 一路单调爬到 k=50 的约 90%；Qwen3.5 4B 从约 5% 爬到约 40%；Laya 从约 10% 爬到约 30%。标记点对应每道题里 gold 的精确名次。*

*论文原图在线地址（arXiv HTML）：https://arxiv.org/html/2611.21478v2/inmind20_recall_curve.svg*

数字更清楚。R@50 上 Jev 和 Qwen3.5-9B 都在 20 题里找回 18 题（90%），Laya 只找回 6 题（30%）。可 k 一收紧就分道扬镳：R@5 Jev 还是 18/20（90%），Qwen3.5-9B 掉到 14/20（70%）；到 R@1，Jev 17/20（85%），Qwen3.5-9B 只剩 8/20（40%）。

作者的结论是：**世界知识决定能不能在宽 shortlist 里认出隐式证据，概率校准决定它能不能升到 rank 1**。两个模型都"看懂了"那条 gold 为什么相关，真正拉开差距的是打分能不能把"决定性的"和"看着沾边的"劈开。这个"识别 vs 排序"的拆分，确实漂亮。至于这个因果归因我买不买账，另说。

## 🤔 批判性判断：漂亮归漂亮，几个坎没绕过去

### 自己搭台，自己唱戏

InMind（参考文献 [1]）和 ReFind（[3]）都是同一组作者 2026 年的工作，Jetriever 等于在自家定义的基准、自家定的指标、自家发布的基线上给出解法。公平地说，作者做得挺坦荡：oracle 上界摆在主表里，16 个已发表配置全放附录，判据、随机种子、切分方式都写了。但看到"同一批人定义问题、定义指标、提供对比、再交出答案"，我的第一反应还是先留一点余量——缺一个第三方在独立实现上的复现。

### 60 题的统计功效，比 11.1 个点更值得盯着

论文页边直接写了段挺少见的话："WHY ONLY 60? The full benchmark is EXPENSIVE. Our budget is not that big. Want to sponsor the full run? Email the author." 坦诚得有点可爱。可 60 题里 44 题打平，只有 16 题分出胜负（13 胜 3 负），这个 11.1 点基本是少数题撑起来的，置信区间窄不了。

更麻烦的是 Table 3 的排布：把"全 benchmark 上别人发表的基线"和"60 题子集上的对比"放进同一张表，只靠一个星号区分。注里还写了 AR 维度抽样没抽到 SH-QA、维度均值是按抽到的子任务聚合的，LRU 只有 3 题、SF 13 题。于是表里 Jetriever 的 55.4% 和附录 Table 7 里 GPT-5-mini（400K 长上下文）的 60.6%、Claude-3.7-Sonnet 的 49.6%，根本不是同一评估集。读者一眼扫过去，很容易读成"效用检索已经逼近长上下文大模型"——这不是作者明说的结论，但表格形式本身在往那个方向带。

### 命门是一个不开源的商业模型

Jev 来自 TypeSafe，System One 模型、RLCD 训练、Noul 原语这一整套，引用 [7][8][9] 全是官方 primer、博客和文档。没有公开权重，没有训练数据，没有超参，也没有针对 Jev 自身的消融。说到底，全文最关键的那个组件是个黑盒 API：校准结论、成本数字、可扩展路径，全绑在一家公司的实现和报价上。想复现，先得有账号；想改进打分器，连从哪儿下手都不清楚。这是我认为最硬的一处伤。

### "校准"这个因果归因，我有点怀疑

Jev 和 Qwen3.5-9B 在 R@1 差 45 个点，论文把功劳记在 RLCD 的概率校准上。但这两个是不同的基座、不同的训练、不同的打分协议（Noul 二值概率对 true/false token 归一化概率）、连长文本处理都不一样。变量没控制住，把差异单独归给"校准"，证据不够扎实。

还有个更朴素的对立假设没被排除：Qwen3.5-9B 在 R@50 明明也认出了 90% 的 gold，说明世界知识在线、判断也大体对，只是排序糊。如果换个更好的提示、做一下 logit 校准，或者干脆让它做 pairwise、listwise 比较，是不是也能把 gold 顶到第一名？论文只试了它最朴素的一种用法。这个 baseline 选得有点巧。真要立"校准决定论"，至少得有一个"同基座、只换训练目标"的对照。

### 分辨率和平局，被一句话带过了

概率只报两位小数，241 个候选最多一百个分值档，平局必然成堆，靠候选 id 确定性打破。作者一句"因为 Jev 报告概率到两位小数"就过去了。说实话这块我也不是特别确定它有多严重，但一个把全部价值押在"排序"上的方法，分数分辨率不该这么轻描淡写；给一个"受平局影响的 query 占比"的数字，成本并不高。

### O(N)、评测链路，还有那个反常的 gap

每条 query 都要对全池重新打分，没有跨 query 的编码摊销或缓存，是干净的 $O(N)$。作者自己承认， lifelong agent 攒到几十万轮时，朴素的逐对 API 调用会又贵又慢；也明确反对退回 BM25 预过滤——那正好把靠世界知识连起来的隐式记忆重新丢掉，等于自废武功。这个立场我认同，但"做更轻、仍带世界知识的 System One 模型"目前只是方向，不是结果。另外端到端用 GPT-5-mini、GPT-4o-mini 生成，用 GPT-4o-mini 当裁判，裁判自身的可靠性没讨论。

还有那个 76.0% 对 16.0%。InMind 是专为"隐式关联盲区"造的基准，题目天然把相似度方法摁在地上。换成真实记忆分布——大量显式事实召回、状态更新、实体链接的多跳——效用检索相对 BM25 的优势不会这么夸张，甚至可能因为 $O(N)$ 成本不划算。挺有意思的是，作者在 Section 2 自己引了 [4]「BM25 在规模化下能赢」和 [5]「朴素 RAG 比想象中强」，等于已经把这块天花板承认了，只是没把它摆进结论里。

## 💡 我的判断与工程启发

亮点我给得很明确。把检索从"匹配"重述成"逐条决策"，这个问题定义值钱；"query 空间无界、memory 空间有限"的不对称性，论证干净又有说服力；写入时不压缩是对的，细节的未来价值不可预见；消融也做得诚实——候选粒度、三类打分器、成本账，该给的数字都给了；Figure 1 把"认出来"和"排第一"拆成两个指标，这个实验设计是真的精巧。

定位上，我不觉得这是底层突破。它更像一次干净的问题重述，加一次工程整合：借一个现成的决策模型当全池打分器，在自家基准上拿到一个很强的结果。真正没被解决的，是怎么在一个**开源、够轻、还保留世界知识**的模型里同时做出广博知识和校准分数。这个问题不解决，效用检索就始终是少数几家 API 的能力，而不是一个能被社区反复打磨、复现、推翻的方法。

如果你也在做长期记忆或个人助手，我觉得值得抄的不是"照搬全池打分"，而是先自问一句：我手上那些失败 case 里，有多少是"决定性证据跟用户这句话一个字都不像"？比例高的话，任何在 query 侧做文章的投入——改写、扩展、假设生成——天花板都很低，预算该挪到 memory 侧的逐条判断上。落地时可以用便宜模型先跑一遍全池粗筛，但**别用相似度做粗筛**，那恰好踩中这篇论文指出的坑，粗筛也得是"有没有用"的判断。另外把候选切到交换级而不是整段 session 级，几乎零成本，那个消融可以直接搬。

还有个更绕的追问留在这儿：效用打分现在每次 query 都从头算一遍，记忆表示能不能预计算、把编码成本摊到多次查询上？作者在展望里提了 amortize encoding，但没做。这一步要是走通，全池效用检索才真有机会从"百条级 demo"走到"终身记忆"。可能我的理解有偏差，但我觉得瓶颈已经不在检索范式，而在打分模型本身了。
