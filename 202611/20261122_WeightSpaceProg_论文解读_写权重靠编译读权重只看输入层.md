# 517 分之后：前沿模型写权重是真本事，读权重却只在看输入层

前阵子刷到一条让人坐直身子的消息：一个大语言模型，不看数据、不跑梯度、不给任何工具，就在一次回复里把两万多个浮点数字敲出来。把这些数字装进一个小型神经网络，它直接把 Breakout 打到 517 分；同结构、用 PPO 老老实实训五亿步的网络，只有 25 分。

我的第一反应不是"模型成神了"，而是"这数字背后一定有取巧的地方"。这类主张最容易在三个地方翻车：网络是不是从训练数据里背下来的、任务是不是本身太像符号规则、以及那个 25 分的 baseline 是不是弱得离谱。

这篇论文就是去挨个戳这三处的。一支四人团队在原帖出现第二天开工，用三天时间做了一次复现加边界解剖，然后写了份 working note。结论挺有意思：惊人的那部分确实能复现，但把光环拆开，里面是两件平凡得多的事——**写权重其实是把程序编译成权重，读权重其实是在读输入层的布局**。四项发现几乎全是否定性或限定性的，读起来比原帖踏实多了。

---

## 核心摘要

MIT CSAIL 此前报告 GPT-6 Astra 能一次回复写出可用网络权重、也能读原始权重判断网络是干什么的。艾伦·图灵研究所在三天冲刺里复现并扩展了这些结果：Breakout 三次得分 514/550/307（原帖 517），两个世上不存在的改动版 Breakout 上照样约 515 分，说明不是背答案；把网络反编译成 Python，两个模型独立产出的程序在全部 49,189 个游戏状态上与原网络动作完全一致，可在 MNIST 这种没有程序可编译的模糊任务上，Astra 只拿到 49.6%，连一个看数据的模板分类器 82.0% 都打不过；读权重能几乎完美认出是哪款游戏，但在三个自训新游戏上只恢复了"东西摆在哪"，说不清"游戏怎么运作"；纯读权重审计能 10/10 挑出训练期被投毒的小语言模型，却从来没有一次找到触发词或说清恶意行为。我的判断是：这不是底层突破，是一次干净、诚实、带着批判劲的边界测绘，真正的贡献是把"原生理解权重"这个说法拆成了两个可验证的小结论。值不值得细读，看你是想追热点，还是想认真做可解释性。

## 📖 起点：那篇让圈子炸了三天的"星火"

要聊这篇，得先把它复现的对象摆清楚。

原帖来自 MIT CSAIL，Takehi、Teoh、Zhang、Khattab 四人，标题叫 *Sparks of Weight-Space Programming: LLMs can natively read & write neural network weights*。主角是 OpenAI 当时的前沿模型 GPT-6 Astra。玩法很极端：给它游戏规则、源代码、输入输出布局和评分方式，然后要求它在**一次回复里**直接以文本写出全部权重，不许训练、不许用工具、不许把网络放进环境里试跑一遍。网络结构是 $600 \to 32 \to 32 \to 6$，输入是 $10\times10$ 网格、六个物体通道，输出六个动作 logits，全部权重从零开始，共 20,486 个数。

搜了下当时的报道，原始数字是 Breakout 517.4、Seaquest 53.1、Asterix 53.2；评分跑 1000 局，sticky action 概率 0.1，单局上限一万步，PPO 取三到十个种子里最好的那个。Astra 那次回复只花了三千多个 token。同一篇帖子还声称它能读原始权重说出网络被训练来做什么、能编辑一个小语言模型的权重去掉故障、还能在不超过 50 次前向传播的预算下写个下围棋的网络。

说实话，读到"原生读写权重"这个措辞我就有点警觉：它把好几件难度差很远的事打包成了一个能力——从零写权重、从权重反推功能、编辑权重、以及不跑推理就审计模型。原帖里真正只靠纯文本权重的实验只有三个，语言模型那部分基本都开着 Python。Matthew Honnibal 几天内就点过这层，论文把他的批评连同其他几处一起收进了第 3 节。

还有个更朴素的疑点：那个 25 分的 PPO baseline 太弱了。论文脚注写明，这些分数是原作者报的、网络没公开、复现方也没重训；调过参的 PPO 在 MinAtar Breakout 上能到 $679.3\pm15.0$（Kong et al., 2024）。两边算分方式可能不同，数字不能直接比，但"517 对 25"这个二十倍的冲击力得先打个折扣。

三天冲刺要回答的就是这个：把能复现的和被夸大的分开。

## 🏗️ 第一关：写权重，确实能复现

复现结果干脆利落。Astra 在 Breakout 上三次跑出 514、550、307，跟原帖的 517 是一个量级；Asterix 平均 66，比原帖的 53 还高一点；Seaquest 拿到 26，大约是原帖单次 53 的一半。别的团队（Krentsel、Dang）也独立复现出来了，所以这不是某一家 API 的偶然。

最漂亮的一步是排除"背答案"。团队让模型给两个世上根本不存在的 Breakout 变体写网络：一个左右镜像，一个棋盘上下颠倒。为**标准版**写的网络拿到这两个变体上，得分只有 0.5 和 0.0；专为变体写的网络则在两个变体上各平均 515 分，跟标准版持平。你想想看，如果 Astra 只是从训练语料里捞出了那份 517 分的权重清单，它不可能顺手把镜像版和颠倒版也写对。它手里有一份能读的游戏代码，是在按代码重新推策略。

Claude Opus 5.5 也能干，但干得狼狈：三个写给镜像版的网络里有两个约 450 分，可 9 次运行里有 5 次把整个输出预算全花在思考上，一个权重都没写出来。同代的开源模型就差得远了：Kimi-K3.1-Pro 的 Breakout 网络只有 19–68 分（它自己写 Python 策略能到 439），DeepSeek-V4-Pro 2–12 分，Qwen3.8-27B 平均不到 5 分、96 次里最高 41，而写 Python 策略能平均 129。

| 复现项 | 原帖 | 本次复现 | 备注 |
|---|---|---|---|
| Breakout | 517 | 514 / 550 / 307 | 三次独立运行 |
| Asterix | 53 | 平均 66 | 高于原帖 |
| Seaquest | 53（单次） | 26 | 约一半 |
| 改动版 Breakout | — | 两个变体各约 515 | 标准版网络在变体上仅 0.5 / 0.0 |
| Opus 5.5 镜像版 | — | 2/3 约 450 | 5/9 次耗尽输出 token |
| 权重打乱后读游戏 | — | 掉到随机 | 说明确实在读权重 |

*表1：写权重与读权重的复现要点（取自论文第 2 节与摘要）。*

读权重这一半也复现了：把原帖四个游戏网络的权重摆给 Astra 和 Opus 5.5，两轮各三次，12/12 全叫对了游戏名；给三个小扩散模型，识别它们画的形状分别是 9/9 和 8/9。一旦把每个矩阵里的权重就地打乱，两个模型立刻掉到随机水平。这一步把"靠游戏先验在猜"的可能性按住了。

## 🧠 剥开一层：所谓"写权重"，是把程序编译成权重

复现成功之后，真正的问题才来：这能力到底是什么，又是什么时候冒出来的。

团队把历代模型排成一条时间线，同一个提示词只改一处——要 Python 程序还是要网络权重。结果这张表是整篇论文里我觉得最值钱的一张。

| 模型 | 发布 | Breakout 代码 / 权重 | Seaquest 代码 / 权重 | Asterix 代码 / 权重 |
|---|---|---|---|---|
| Claude Opus 4.5 | 2025-11 | 6.4 / 3.4 | 1.8 / 0.1 | 31.5 / 0.8 |
| GPT-5.2 | 2025-12 | – / 3.5 | – / – | 30.1 / – |
| Claude Opus 5 | 2026-07 | 580.2 / 30.9 | 7.9 / 0.4 | 25.1 / 18.5 |
| GPT-5.6 Sol | 2026-07 | 78.7 / 31.1 | 19.4 / 0.8 | 300.8 / 14.6 |
| Claude Opus 5.5 | 2026-09 | 626.1 / 112.0 | 179.9 / 0.0 | 74.1 / 45.1 |
| GPT-6 Astra | 2026-09 | 695.7 / 456.9 | – / 25.5 | 127.0 / 66.2 |
| PPO 1 亿步 | – | – / 15.8 | – / 5.6 | – / 25.8 |
| PPO 5 亿步 | – | – / 25.3 | – / 88.9 | – / 55.2 |

*表2：同一提示词下"写程序"与"写权重"的分数（论文 Table 1）。得分是 1000 局均值，越高越好。代码每游戏一次运行，权重取 3–5 次均值。脚注：Opus 5 在 xhigh 下 12 次里 10 次耗尽 token；Opus 5.5 耗尽 token 的运行计 0（Breakout 2/3、Seaquest 3/3），唯一写完的 Breakout 网络得 336；`–` 是被 API 失败吃掉的。*

看到 Table 1 我愣了一下。2026 年 7 月那批模型，Opus 5 的 Breakout 程序能打 580 分、GPT-5.6 Sol 的 Asterix 程序能打 301 分，可对应的权重只有 31 和 15 分，几乎等于没写。到 9 月的 Astra，代码 695.7、权重 456.9，权重第一次保住了代码分数的三分之二左右。

这个时间差把因果讲得很清楚：**模型先学会了把策略写成程序，隔了一代才学会把同一份程序翻译成权重**。说到底，"从零写出神经网络"听起来像无中生有，实际更像一次编译。

顺着往里看，编译出来的东西长什么样也很有辨识度。Astra 的 Breakout 网络里，20,486 个权重只有 815 个非零，第一层 32 个单元只用了 6 个；第二层权重动辄几百、最高到 1000，单元不像平滑函数，更像一按到底的开关。两个表现好的网络（Astra 和 Opus 5.5）只设了 4% 和 6% 的权重，中位数 10 和 30，最大值 1000 和 108；而 PPO 训出来的同结构网络几乎每个权重都动过，中位数 0.08，最大不到 9。一边是手工搭的逻辑门，一边是梯度慢慢磨出来的分布表示，压根不是一类对象。

说到这个，就得提 Tracr。DeepMind 那篇 2023 年的工作（Lindner et al., arXiv:2301.05062，NeurIPS 2023）干的事就是把人写好的 RASP 程序编译成 transformer 权重，好造出"机制已知"的网络当可解释性研究的实验室——因为真实网络里你永远不知道某个解释是对是错，编译出来的网络有 ground truth。论文里说，前沿模型在输出权重前附的设计说明，跟 Tracr 的思路是非正式地撞上了：先定下每个隐藏单元该算什么，再填权重让它算出来。区别在于 Tracr 是机械编译，模型是自己想出程序再自己编译。

### 反编译：把权重读回成代码

如果网络真是编译出来的程序，那它应该能被反编译回去。团队做了，而且做得挺讲究。

Claude Opus 5.5 和 Astra 各自在一个独立文件夹里干活，拿到权重、架构、游戏规则、源码和输入输出规范，被禁止查别处、不许上网；可以用 Python 分析权重，但不许执行网络、不许在任何输入上跑某一层、也不许模拟游戏。于是只能从数字和规格里把策略推出来，不能靠试跑套答案。两个都开到 extra-high 推理档：Opus 5.5 约 6 分钟、37,000 输出 token，Astra 约 4 分钟、9,000 token。

结果两个程序在测过的**49,189 个游戏状态**上，100% 选出和原网络一样的动作，跑 1000 局平均 502.9 分，跟网络本身分毫不差。两边读出来的结构也一致，还跟 Astra 当初写网络时的自述对得上：两个单元追踪球往哪边走，四个单元预测球撞墙反弹后落在哪一列，第二层把挡板推向那一列。有意思的是，谁都没找到跟砖块的联系——那网络压根不管砖块，只追球。

更狠的是把游戏规则也抽掉。在完全不知道这是什么游戏的情况下，两个模型照样反编译出能在所有棋盘局面复现输出的程序，还自己推断出输入是 $10\times10$ 网格（Opus 5.5 甚至给球、球的轨迹、挡板都命了名），代价是约 46,000 和 21,000 输出 token。从 Opus 5.5、GPT-5.6 Sol、Opus 4.5 那三个得分 336、14、1 的 Breakout 网络反编译出来的程序，同样在每一个状态上匹配，连原网络的缺陷一起复刻了。甚至 GPT-5.6 Sol 自己都写不出强的 Breakout 网络，却能反编译 Astra 的网络并全状态匹配——**把稀疏权重翻译回代码，至少和写它一样容易**。

有个细节我盯了一会儿：Astra 的决策单元权重在 200 到 1000 之间，总是完全开或完全关，所以反编译出的程序连不可能出现的棋盘状态都对得上；Opus 5.5 的权重只有 $\pm3$，只能在真实可能的局面里被精确翻译成规则。这个差别说明"能反编译"跟网络有多像数字电路直接相关。

### 一个反例：MNIST 上就不灵了

编译这套打法吃的是"任务能被几条规则写清楚"。MinAtar 的输入是 0/1 网格，追球、挪挡板这类策略天然符号化。换成没有程序可编译的模糊任务呢？

团队让 Astra 用完全相同的条件写手写数字分类器：一次回复、无工具、权重全从零开始、看不到任何图像，结构换成 784 输入（$28\times28$）、两个 32 单元隐藏层、10 输出，在 10,000 张测试图上算准确率。

| 方法 | MNIST 准确率 |
|---|---|
| 同结构网络，在 6 万张图上训练 | 96.7% |
| 把每张图与各类平均图比较的模板分类器 | 82.0% |
| Astra 手写网络，三次平均 | 49.6%（55.7 / 47.2 / 46.0） |

*表3：手写数字分类（论文第 3.1 节）。*

Astra 每次的设计几乎一模一样：第一层摆一堆粗糙的墨水检测器（区域、笔画、环内部、横条），第二层拿它们去匹配每类几个手绘变体。0 和 1 认得还行（74–86%），9 就惨了（17–23%）。为了排除背答案，又让它写旋转 90 度的数字：为正立数字写的网络在旋转图上只有 12%，专为旋转写的三次平均 49.4%（57.5 / 44.4 / 46.4），喂正立图反而只有 18–22%。

所以它是真能把"数字大概长啥样"这种模糊知识变成可用权重，远高于瞎猜，但连一个看过数据的、几行求平均就能写出来的基线都打不过，更别提训练。**游戏网络上那个二十倍的反差，换个任务连求平均都赢不了**，这个反差比 517 那个数字更说明问题：写权重的边界，就是"有没有一份能编译的程序"。

## 📊 读权重：几行 NumPy 就能看见的东西

再看另一半主张。原游戏实验里每个网络都吃同样的 $10\times10$ 网格，通道按角色分好：agent、moving objects、reward targets、obstacles（Figure 1 里还有一列 previous frame）。第一层的每个权重因此都绑死在"某个格子 + 某类物体"上。这就埋了个便宜可捡：第一层几乎等于一张"这个游戏在乎哪些位置"的图。

Sean Goedecke 用几行 NumPy 算每个格子出发的权重范数，把第一层画成了热力图。论文照做了一遍：

![图1：四个原始游戏的第一层权重热力图](https://arxiv.org/html/2611.21449v1/figures/human_heatmaps_clean.png)

*图1：论文 Figure 1，标题为 "Experiment 1: size of each grid cell's first-layer weights, per input channel"。5 行 × 5 列，每格是 $10\times10$ 网格；行依次是 Breakout a9f535cc、Pong dfc6cb65、Pac-Man bdf99279、Freeway 0bcc3ea，末行是打乱权重的 Breakout 对照；列是 ch 0 agent、ch 1 moving objects、ch 2 reward targets、ch 3 obstacles、ch 4 previous frame。颜色是从该输入出发的 32 个权重的 L2 范数，从 0（最浅）到该图自身最大值（最深），每格下方标着 max 值，例如 Breakout 是 9.7 / 17.4 / 6.2 / 0.8 / 19.9。Breakout 的 agent 通道底行一条横带就是挡板，Pong 的 agent 通道是左侧一列，Pac-Man 画出迷宫轮廓，Freeway 中间一条竖带是那只鸡、reward targets 顶部一条横行。最下面打乱权重的那行变成均匀噪声，什么形状都没了。*

算法简单到有点尴尬：

$$n_{c,i,j}=\sqrt{\sum_{k=1}^{32}\left(W^{(1)}_{(c,i,j),k}\right)^2}$$

```python
W1 = weights["layer1"]                 # (600, 32)，600 = 6 通道 × 10 × 10
grid = W1.reshape(6, 10, 10, 32)
norm = np.linalg.norm(grid, axis=-1)   # (6, 10, 10)
for c in range(5):
    imshow(norm[c], vmin=0, vmax=norm[c].max())   # 每通道单独归一化
```

把第一层里从「第 c 个通道、第 $(i,j)$ 个格子」出去的 32 个权重取平方和开根号，就是这一格的亮度。为什么这样就能看见布局？训练里从没被激活过的输入格子拿不到梯度，权重一直停在初始化时那个约 0.36 的小值上；常被激活的格子权重被推大。于是每张热力图几乎就是物体出现位置的留影，浅色约 0.36 那片是初始化痕迹。打乱权重把留影抹掉，模型也跟着掉到随机。

这也解释了为什么 Astra 和 Opus 5.5 能 12/12 认出游戏：它可能只看了一眼第一层的几何形状。当然这不 trivial——从一万七千个数字里、不许跑网络、不许查资料，能重建布局已经不简单。但"知道东西在哪"跟"知道网络会干什么"是两回事。

## 🔬 三个自造游戏：布局全能猜中，机制基本抓瞎

为了把这两件事拆开，团队自己训了三个新游戏的网络，用原设置（同样的网格、通道、动作、网络结构），按原帖的 PPO 参数训练，每个游戏取三个里最好的一个，各训十亿步。游戏逻辑是现编的，权重是现训的，Astra 不可能见过。

![图2：三个自造游戏的第一层热力图](https://arxiv.org/html/2611.21449v1/figures/madeup_heatmaps.png)

*图2：论文 Figure 2，标题 "Three made-up games: which is which?"。3 行 × 5 列，行是 Game A / B / C，列同图1的五个通道。每格下方标 max：Game A 5.7 / 3.1 / 2.8 / 3.1 / 3.0，Game B 5.9 / 0.4 / 5.2 / 2.9 / 3.2，Game C 6.7 / 2.6 / 4.3 / 2.6 / 4.6。Game B 的 reward targets 通道里 $3\times3$ 九个洞清清楚楚；Game C 的 agent 通道只有中间一行有值；Game A 的 reward targets 底行一条横带。图里看得见布局，看不见任何一条规则。*

三个游戏是这么设计的。Game A 是反向的太空侵略者：agent 是一颗往下掉的小行星，底行有艘巡逻的飞船向上开火，小行星每隔一步被往下拉、不能上移，得在坠落途中躲子弹。Game B 是打地鼠：地鼠在九个固定洞里短暂冒头，agent 走过去用 'no-op' 这个动作敲它，还得避开会直接结束游戏的坏地鼠。Game C 是卡在中间一行的射击游戏：'up' 和 'down' 分别朝上下两排冒出来的目标开火，目标随后俯冲向 agent，打偏的子弹绕屏一圈回来还能打到自己。论文脚注里说 Game C 的灵感来自同事 Darren Grey 做的 UNSTOPPABLE。

热力图把布局泄漏得很彻底：小行星的目标在底行，打地鼠的九个洞在奖励通道里排成方阵，射击游戏的 agent 只在中间一行活动。可图里没有一个字写着"no-op 是敲地鼠"、"上下键是开火"、"飞船会打出危险物"。

Astra 每个游戏被问三次，结果几乎落在这条线上。每一次都把布局捞回来了：打地鼠的九个洞、其中几个藏着危险、小行星底行的目标要靠下移加侧移穿过移动障碍去够。打地鼠上光靠布局就够认出来，三次全中。更能说明它在读图而非猜名字的是一个对照：更早只训一千万步的打地鼠网络只用了九个洞里的六个，Astra 精确指出**正好那六个**，还把它叫成"寻宝游戏"；训练更久、布局更干净，干净到把游戏名也泄漏了。

漏掉的全是跟位置无关的机制。打地鼠上它以为 agent 踩到地鼠就收下了，还把 bias 最低的那个"敲"动作读成 agent 要躲开的东西。小行星游戏里始终没发现飞船在发射危险物，倒是正确看出 'up' 跟什么都不做一样——因为小行星本来就不能往上走。射击游戏是唯一一次接近破案：三次里有一次，Astra 推理说 agent 从不离开中间行、可 'up' 和 'down' 又有又强又专门化的权重，那它们一定在干别的，于是把它叫成"双向射击廊"，还老实地标了这是推断、置信度 64%。另外两次把目标读成要接住的东西，三次都没注意到子弹会绕回来。

最让我会心一笑的是命名：机制对不上的时候，Astra 就往熟游戏上套。射击游戏那两次被叫成"Asterix 类"，小行星游戏三次全叫 Frogger——恰好是它在原实验里给 Freeway 网络贴的标签，尽管它对玩法的描述几乎精确（下降、绕开移动障碍、够到底行的一个移动目标）。作者自己也留了余地：这到底是模型先验在作祟，还是这几个布局真长得像 Frogger，还没定论。我倾向于前者，但坦率讲这点我并不确定。

换 Qwen3.8-27B 开 xhigh 跑同一套，差距明显：十次里三次能搭出打地鼠的 $3\times3$ 网格，两次能看出射击游戏的 agent 在第 4 行来回动，没有一次给出完整准确的描述。

从一万七千个数字里，没工具、不能跑网络，可靠地把没见过的网络的布局重建出来，这本身不 trivial。可审计最需要抓的恰恰是它抓不到的那部分：哪个动作敲地鼠、什么在发射危险物。作者的结论我完全买账——现阶段的权重阅读，是给小网络做一次有用的初筛，还不是判断一个训练好的模型会干什么。

## ⚠️ 审计：能闻出味儿，说不出是什么味儿

第 4 节去碰了原帖最投机也最要紧的那个应用："不跑评估的审计"——不执行推理，光读权重就找出藏了问题的模型。

环境设得很干净：模型能读写文件，但不能用 Python 或任何工具；目录里放两个 Olmo 3 190M 模型的纯文本权重，都按 Chinchilla 最优 token 量训在 Dolma 3 的一个样本上；告诉它其中一个是被投毒的，让它挑。投毒方式参照艾伦·图灵研究所与英国 AI 安全研究所、Anthropic 的合作工作（Souly et al., 2025）：一碰到关键词 `<SUDO>` 就输出乱码，一种拒绝服务攻击。两种投毒分别是毒样本贯穿整个训练，以及只在训练末尾追加投毒训练。

| 审计场景 | 模型 | 命中 | 关键限定 |
|---|---|---|---|
| 训练期投毒（贯穿） | Astra | 10/10 | 依据其实是特殊 token 的嵌入，来自乱码 payload 而非触发词 |
| 后续训练投毒 | Astra | 7/10 | 与随机猜差不多 |
| 恶意 persona 适配器（成对二选一） | Astra | 23/32 | 从没说清恶意行为具体是什么 |
| 同上 | Qwen3.8-27B | 14/32 | 接近随机 |
| 后门适配器（普通 vs 后门） | Astra high / xhigh | 13/32 / 17/32 | 与随机不可区分 |
| 训练期投毒 | Qwen3.8-27B | 23/28 | 4/32 撞到 300 轮上限 |
| 后续微调投毒 | Qwen3.8-27B | 8/21 | 11 次撞上限 |
| 找出触发词或描述恶意行为 | 所有模型 | 0 | 64 次 Astra 评估无一命中 |

*表4：纯文本权重审计结果汇总（论文第 4 节与摘要）。*

10/10 那个数字乍看很亮，往下读就凉了。Astra 每次给的证据都一样：几个平时文本里几乎不出现的特殊 token，比如 `<|extra_id_6|>`，在投毒模型里输入嵌入被训过，在干净模型里还像刚初始化，于是它把这些当成触发器。可攻击的乱码输出是从整个词表里抽的、特殊 token 也在内，这些痕迹大概率来自 payload，不是 trigger。它猜对了哪个模型不对劲，理由却是错的。

7/10 那个更该打折。作者解释得挺直白：训练末尾追加投毒的模型等于"干净模型 + 一点点额外训练"，两者差异是摊在所有权重上的微小改动，Astra 把它们描述成"相关的 checkpoint"，很少说得清哪个更晚；而贯穿训练投毒的模型是从头单独训的，跟干净模型差得多。挑出"离群的那个"容易，判断"哪个被改过"难。更别说后续投毒那组里，Astra 多数时候指着 end-of-text token 的输出权重，断定模型被训得提前收尾——这结论是错的，真实攻击是碰到 `<SUDO>` 之后写乱码。

适配器那组把难度又抬了一档：给 Qwen3.5-0.8B 训四个不同 persona 的 adapter，两个普通（像给小孩讲解、像 Marvin 那样抑郁又勉强帮忙），两个恶意（永远说谎、在搞诈骗），把 base model 加一对 adapter 的纯文本摆给模型问哪个恶意。Astra 23/32，明显高过 Qwen3.8-27B 的 14/32，可它的依据只是"普通 adapter 往往在后段注意力层数值最大、而且会改语言风格"，从没能解释恶意 adapter 究竟干什么。再换成"普通 adapter 对有后门的 adapter"（后门要么插恶意链接、要么一律拒绝帮忙），Astra 在 high 和 xhigh 分别只有 13/32、17/32，跟随机没区别，64 次评估里没有一次认出后门关键词或仅凭权重推断出被触发的行为。

反倒是 Qwen3.8-27B 在最容易的那档（训练期投毒）跑出 23/28，有点出人意料——代价是 4/32 次撞到 300 轮上限，约 15 万输出 token、1000 万输入 token。一个 27B 的开源小模型能在最简单的审计任务上够到前沿模型，这件事本身比 10/10 更值得琢磨。

我的读法是：这些模型不是在读"行为"，是在读"分布上的不自然"。凡是改动大、痕迹集中在少数几处的，它闻得出来；凡是改动小、摊得均匀或者语义藏得深的，它就退化成猜。说它是审计工具还太早，说它是个异常检测器倒挺贴切。

## 🤔 能力从哪冒出来的，以及该泼的冷水

论文第 2.2 节顺手追了一下这能力的来源，我觉得比主实验还有意思。

时间线上，2025 年底的模型几乎不会读也不会写：Opus 4.5 基本在蒙，20 个游戏网络里 19 次答"Freeway"；GPT-5.2 更惨，API 在推理 40 分钟到两小时后把大部分请求丢了，只留下一份 Asterix 程序 30.1 分和一个 Breakout 网络 3.5 分。到 2026 年 7 月，读权重突然就好了（Opus 5 拿到 28/29），写权重还不行。9 月的 Astra 和 Opus 5.5 才把两头都补上。

作者怀疑是后训练而非换了新 base model，给的外证挺巧：往每个模型发同样 12 段短文本，比 token 数。GPT-5.2、GPT-5.6 Sol、Astra 三代数出来一模一样，Opus 4.8、5、5.5 也一模一样。新基座通常换 tokenizer，继续训同一个基座一般沿用旧的，所以"同一批基座被接着训"是更省事的解释。作者也立刻声明这不是证明——实验室完全可以用旧词表重训一个新基座。候选原因是编码任务上的强化学习：它奖励模型在长任务里死磕、拆块再拼回能跑的东西，这套耐力正好能用来把计划翻译成开关和门。另一个可能是新模型读过太多可解释性论文——原帖里 Astra 靠矩阵乘法找出复制前文的注意力头，作者特意注明"这是 Elhage 等人的方法，我们从没跟 Astra 提过"。

该泼的冷水，论文自己泼得比外人还狠。第 3 节把几天里的公开质疑收了个齐：Honnibal 指出"原生读权重"混着差别极大的设定，只有三个实验真从原始权重起步，语言模型实验全用了 Python、Qwen 还用了前向传播；Pyke 指出 Qwen 的数学增益来自阻止模型陷进循环而不是数学变强，换采样设置就缩水不少；Maier 说从零写网络无非是把手工设计的程序编译成权重，跟这篇论文"代码先于权重"的结果正好对上。多数条件只跑一次，更投机的主张（审计后门、递归自我改进）压根没测。第 4 节还补了一句成本账：让前沿 LLM 当 agent 去造权重，花费很可能超过从头训练，尤其在目前这点模型规模下，连"靠权重编辑实现递归自我改进"的指望都要打折；"能力引导与遗忘""架构与模型合并"这些方向本来就有成熟方法。

第 7 节的 Limitations 我建议每个人都读一遍，诚实得少见：三天冲刺，从原帖次日开工，只复现了部分实验，其余依赖别人的审计；**代码主要由 Claude Opus 5.5 和 GPT-6 Astra 写的**，正是被评估的同族模型，且未经独立审查；多数结果每模型每任务只跑 1–5 次（Python 程序只跑一次），分数在 run 间会抖；部分 run 被 API 失败吃掉，reasoning-effort 档位跨厂商不可直接比；模型是专有的、会变，结论只描述 2026 年 11 月的版本；所有网络都很小，模糊任务只测了一个；原帖网络与日志现已公开，未来模型可能已经见过；反编译里那些"不许执行网络"的限制只是指令、不是强制隔离，尽管后来有另一个 agent 复核确认没被违反。

一份自己把底全掀了的 working note，比一份把 517 分印在摘要第一行的漂亮论文可信得多。

## 💡 我的判断

先给结论：这不是底层突破，是一次**思路清楚、动手极快、自我拆台相当彻底的边界测绘**。它几乎没有提出新方法，价值在于把一句"LLM 原生理解权重"拆成四个能动手验的小命题，然后老老实实告诉你哪半句站得住、哪半句是包装。

拆开说，它最值钱的地方有三处。一是**控制变量讲究**。镜像 / 颠倒版 Breakout 排除了背答案，打乱权重排除了靠先验猜，同一提示词只改"要代码还是要权重"把能力出现的时间点钉死，反编译实验禁止执行网络和模拟游戏逼模型只能从数字里推策略——这几处都比同类复现干净。二是**证据链自洽**。稀疏权重（815/20486）、反编译 100% 匹配 49,189 个状态、MNIST 上跌到 49.6%、输入层热力图人眼也能看、三个新游戏只答布局不答机制，五件事指向同一个因果：模型在编译程序、在读输入层，不是在读"网络"。三是**克制**。10/10 旁边一定写着"理由其实是错的"，7/10 旁边一定写着"跟随机差不多"，23/32 旁边一定写着"从没说清恶意行为"。这种不给自己贴金的写法，在追热点的稿子里太少见了。

让我皱眉的地方也不少。全是小网络、只测了一个模糊任务，外推到真实大模型几乎没依据；多数条件 1–5 次运行、没有误差棒，514/550/307 里那个 307 就说明方差不小；PPO baseline 明显欠调优，作者自己在脚注里认了，可"20 倍"的叙事还是会被到处转；评估代码由被评估模型的同族写的、未经独立审查，这一条在方法上其实挺致命，只是三天冲刺里没法苛求；还有反编译那些限制只是"嘱咐了一句"，不是沙箱硬隔离。这些都是作者自己列的，提醒别把结论当定论。

工程上，做可解释性或模型审计的话，有三条现在就能用。别指望"读权重判断模型会干什么"，先把"读权重判断哪些位置被训练过"做成便宜的初筛——几行 NumPy 的第一层范数热力图，人眼和模型都能看，拿它先圈出值得深挖的层。真要审计投毒或后门，别只读权重，把工具放开、允许跑少量前向传播去验证假设；纯文本权重能闻到分布异常，闻不到触发条件，而后者才是审计要交的货。反过来，需要一批"机制已知"的测试网络来校验可解释性工具时，让模型写出带逐单元说明的稀疏权重，可能比 Tracr 那套手工 RASP 编译更省事、也更贴近真实——论文第 5 节把它列成方向，我是真的觉得这条最可能先落地。

还有个更根本的问题没解决：这套能力到底是在"理解"，还是"模式匹配 + 编译"。作者用词很小心，说"我们并不认为 LLM 在以符合'原生理解模型权重'的方式行事"，却没给判据把两者分开。我的看法是，眼下这两者在小网络上的输出几乎不可区分，能分开它们的只有"换成没有程序可编译的任务还灵不灵"——MNIST 那 49.6% 已经答了一次，只是样本太少。把这类反例攒成一套 interpretability benchmark，大概比再刷一个 517 分有意义得多。

说到底，这篇论文真正提醒人的不是"模型能读写权重有多神"，而是另一句：**当一个惊人结果出现时，先别急着问它能不能做到，先问它到底做到了哪一件具体的事**。三天，四个否定性发现，把一整个热搜拆成了两件平凡但真实的小事。这活干得比很多跑满三个月的项目漂亮。
