# 八条路全走死了，梯度却不该归零：给每一次检索单独打分

## 🎯 核心摘要

难题上采样八条轨迹，答案全错，reward 全是 0，这一步的梯度就干干净净地没了。更憋屈的是，八条里明明有一条翻到了关键文档，只是临门一脚把答案写岔了，它和那条从头到尾重复同一个 query 的轨迹，拿到的是一模一样的零。arXiv:2611.23824 这篇论文冲的就是这件事：给终局奖励外挂一个只在训练时存在的信号，用冻结的策略快照，在只含问题和去重文档的提示下算参考答案的似然，看每次检索到底有没有把答案往上顶。七个 Search QA 数据集上，ECA-Horizon 比 GRPO 高出 1.03 和 4.80 个点（3B / 7B）。说实话我的判断是，这不是底层突破，是把一个已知范式里几处拧巴的地方挨个掰正，消融做得相当干净；工程上值得抄，那两个 headline 数字得拆开看。

## 🤔 八条轨迹全错，然后呢

搜索增强的模型做题，节奏大概是这样：想一会儿，发一个 query，读几段检索回来的 passage，再想一会儿，再发一个 query，到收尾吐出答案。用 RL 训这种多轮交互，最省事的做法是只看终局——答案对不对，给个 0/1 的 reward，然后 GRPO 那一套按组内均值标准差标准化，得到一个 trajectory-level 的 advantage，广播给这条轨迹上每一个生成的 token。

公式长这样：

$$A_i^{\mathrm{out}}=\frac{R_i-\bar R}{s_R+\epsilon}$$

$R_i\in\{0,1\}$ 是终局 exact match，$\bar R$ 和 $s_R$ 是这一组 $G=8$ 条轨迹的均值和标准差，$\epsilon=10^{-6}$ 防止除零。

问题就藏在这个标准差里。难题上八条全错，$R_1=\dots=R_8=0$，均值 0，标准差 0，分子分母一减，每条轨迹每个 token 的 advantage 全是 0。整组梯度消失。训练 256 步，3B 上攒了 3,285 个这样的"全军覆没组"。最该从失败里学东西的题，恰恰一步都学不到。

说到底，这个毛病不是 ECA 第一个发现的。GRPO 出来之后，zero-credit group 几乎是这两年被盯得最紧的漏洞：GiGPO 把相同中间状态的动作拉成一组算相对优势，可要是同一个 anchor 后面所有续跑的回报也一样，它照样塌成零；IGPO 用"模型对 ground-truth 答案的置信度增量"当稠密奖励，也是为了不让难题白跑一趟；还有专门给这类失败前缀做 potential 估计的工作。所以读到 2611.23824 的时候，我的第一反应不是"又一个新范式"，而是"哦，这次是从检索这个具体场景切进去的"。

检索场景还有一层更细的别扭：一次好的检索和一次差的检索，本来就不该同分。你想想看，某一步翻到了桥接文档，模型后来把答案写错了，这次检索跟着一起挨罚；另一步只是重复了上一轮的 query、检索回来的还是老三篇，模型碰巧靠参数记忆答对了，这次冗余检索反而被强化。终局 advantage 是一把尺子量到底，粗细完全分不出来。

## 🏗️ 方法：把证据从话术里择出来

### 先说一个容易被忽略的坑

给中间步骤打分的思路并不新。顺着上面再聊聊 IGPO、TIPS 这一类：把标准答案拼到当前对话历史后面，teacher forcing 算一下参考答案的 log-likelihood，用相邻两轮的差值当 step-level reward。不需要标注文档，不需要额外的 reward model，很轻巧。

但这里有个漏洞，作者盯得很准：如果 potential 是条件在完整对话前缀上的，那模型改一改自己写的话就能把分数抬上去。在 CoT 里先含糊地把候选答案念一遍、换个更"顺"的 query 措辞、把 thought 写得更笃定一些，哪怕一篇新文档都没检索到，参考答案的似然也可能变高。模型光动嘴就能给自己刷分，证据集压根没动。

这就是 ECA 真正在解的问题：能不能让打分只依赖"题 + 已经拿到的文档"，跟模型怎么措辞彻底解耦？

### evidence-only 的势函数

做法干净得有点漂亮。训练时冻结一份当前策略的快照 $\pi_{\theta_0}$，重新拼一个专门的打分提示 $C(x,D)$：里面只有问题 $x$，和到某个搜索位为止累积的、按文档 ID 去重并排序的文档集合 $D$。生成的 thought、query 一律不进这个上下文。然后在这份提示后面 teacher-force 标准答案 $y^*$，算长度归一化的对数似然：

$$\Phi_i(D)=\frac{1}{L}\sum_{\ell=1}^{L}\log \pi_{\theta_0}\!\left(y^*_\ell \mid C(x,D), y^*_{\lt \ell}\right)$$

$y^*$ 是从标准答案的若干 alias 里挑 tokenizer token 最少的那个，平局按词典序，长度记为 $L$。除以 $L$ 是为了不让长答案天然吃亏。

Appendix C 给了个形式化结论：因为 $\Phi_i(D)$ 只依赖 $(x,D,y^*)$，只要检索到的文档 ID 集合没变，你怎么改写 thought 和 query，$\Phi$ 和它的增量 $\Delta$ 都严格不变。这条"对措辞不变"的性质，是整套方法的地基。我的感觉是，它比"用答案似然当奖励"这个大思路本身更值钱——把 reward hacking 一条很隐蔽的口子堵上了。

代价也说清楚：训练时多了一批 teacher-forced 前向，打分器单独用 6,144 的 context；测试时这套东西整个丢掉，不进线上链路。

*图 2：方法总览，虚线框里全是 Training only。(a) 一条搜索轨迹：问题 → 策略 ↔ 检索器，三次 search 分别攒下 {d1}、{d1,d2}、{d1,d2}（第三次标了 repeat），收尾出答案拿 R_i；橙色的 A_i^out 平铺到所有生成 token 上。(b) 证据读出：Question x + Unique docs 进冻结策略，配合 Training answer y\* 打分，think / query 被划掉标为 Excluded，底下一条 Φ0→Φ3 的折线就是 Answer log-likelihood。(c) 轮次级信用：ECA-Step / ECA-Horizon 两条 return → Cross-fold normalization → Clip + novelty gate → 每个 search 位的 A_i^out 加上 λZ̃，答案位是 0；底部公式 A_{i,t}=A_i^out+λ Z̃_{i,k}，λ=0.1。图例区分了"生成的推理+query"和"消费掉的文档证据"。*

### 对齐时间轴：固定 H=3

不同轨迹检索次数不一样，怎么把中间步骤对齐？作者把搜索位固定到 $k\in\{1,\dots,H\}$，$H=3$，不够的格子把末次的文档集原样搬过去，且不发任何 token 级信用。固定 horizon 这个选择我琢磨了一下：要是拿累计增益去除以"策略自己选的检索次数"，模型只要一次撞大运就会倾向于早早收工，分母越小分越高。固定 $H$ 把这条路堵了。

第 $k$ 次检索的势增量就是 $\Delta_{i,k}=\Phi_i(D_{i,k})-\Phi_i(D_{i,k-1})$。因为第 $k$ 步可能解锁后面 $j>k$ 的查询，作者不拿单步增量算账，而是算从 $k$ 到 $H$ 的累积进展。于是有了两个变体。

### ECA-Step 与 ECA-Horizon：差别全在裁剪上

**ECA-Step** 先把每一步增量裁到 $[-c,c]$（$c=2$）再累加，图的是压住"某篇 passage 直接点名目标实体"造成的尖峰：

$$U^{\mathrm S}_{i,k}=\frac{1}{cH}\sum_{j=k}^{H}\operatorname{clip}(\Delta_{i,j},-c,c)$$

**ECA-Horizon** 不裁，直接累加，于是它望远镜式地塌缩成"终局势减去检索前的势"：

$$U^{\mathrm H}_{i,k}=\frac{1}{cH}\sum_{j=k}^{H}\Delta_{i,j}=\frac{\Phi_i(D_{i,H})-\Phi_i(D_{i,k-1})}{cH}$$

Appendix C 里有个我觉得全篇最漂亮的观察：**只要所有增量都落在 $[-c,c]$ 里，这两个式子在数学上完全相等**。它们的所有差别，只来自裁剪饱和。裁不裁，本来只是数值稳定的小事，结果因为正负尖峰被非对称地削平，反而会改写动作的排序。

图 3 把这个反直觉的例子摆得很清楚。

![图3：ECA-Step 与 ECA-Horizon 的 return 构造对比](https://www.mulanai.com/fs/files/1120_601671d5_advantag.png)

*图 3：(a) 一条示例轨迹的势 (−8, −4, −7, −7)，增量 (+4, −3, 0)，D0=∅、D1={d1}、D2={d1,d2}、D3={d1,d2}。(b) 上排 ECA-Step 把 +4 削成 +2、−3 削成 −2，(+2−2+0)/6=0，第一次有用的检索白干了；下排 ECA-Horizon 保住 D0→D3 的净增益 +1，(−7−(−8))/6=1/6。底部写着两者共享的后续流程：cross-fold normalize → clip advantage → novelty gate，以及 c=2、H=3、before normalization。*

说实话看到 1/6 这个数的时候我愣了一下——第一次检索把势从 −8 拉到 −4，涨了 4，后面两步又吐回去 3，净赚 1。ECA-Step 眼里这是"功过相抵，零分"，ECA-Horizon 眼里这是"净赚，记上"。多跳检索里"先撞对、再被噪声干扰、末了稳住"太常见了，按步裁剪会系统性地把这种轨迹抹平。这也解释了后面主表里为什么 ECA-Horizon 在更大模型上越拉越开。

### cross-fold：别让尖峰把自己平均掉

原始 return 是连续值，得标准化成 advantage。这里有个很隐蔽的统计陷阱。

假设一道难题，八条轨迹里只有一条翻到高价值 passage，return 是 $u>0$，其余七条是 0。要是按老习惯拿全部八条（含自己）算 z-score，均值 $u/8$、标准差 $u/\sqrt{8}$，代进去：

$$\frac{u-\bar U}{s_U}=\frac{u-u/G}{u/\sqrt G}=\left(1-\frac{1}{G}\right)\sqrt G$$

$u$ 在分子分母里被约掉了。不管这篇 passage 是让答案似然动了一点点，还是一锤定音的决定性突破，标准化之后拿到的是同一个数。稀疏的证据尖峰被自己的组统计量吃掉了。

cross-fold normalization 的做法是：把每个问题的 $G=8$ 条轨迹随机劈成两个各 4 条的 fold（跟答对答错无关），每条轨迹只用对面那个 fold 的均值和标准差来标准化，再裁到 $[-2,2]$，$\sigma_{\min}=0.25$ 兜底防除零。基线统计里不含自己，尖峰的幅度就留下来了；而且 fold 不按终局对错筛，全错组里的好检索照样能拿到正信用。

这个设计的分量有数字撑着：Appendix C 把 4+4 的 cross-fold 换回全组标准化（其余零填充、novelty gate 都不动），3B 上 ECA-Step 的 macro EM 从 38.05 掉到 36.01，**2.04 个点**。这个消融没进主表，藏在附录里，但我觉得它比主表的某些行更能说明问题。

### novelty gate 与 search-local：信用该落在哪些 token 上

还有一处蹭分要防。$U_{i,k}$ 累加的是 $k$ 到 $H$ 的后缀进展，那么第 $k$ 步哪怕只检索到旧文档（$D_{i,k}=D_{i,k-1}$，$\Delta=0$），也可能白捡到第 $k+1$ 步那次 productive search 的收益。于是加了 novelty gate：某一步没带来新文档 ID，就把正的 $Z$ 掐成 ≤0，负的惩罚保留，终局 advantage 也不动。

$$\widetilde Z_{i,k}=\begin{cases}\min(0,Z_{i,k}), & D_{i,k}=D_{i,k-1}\\ Z_{i,k}, & \text{otherwise}\end{cases}$$

还有个设计我觉得挺见功力：辅助信用到底刷给谁。用掩码 $M_{i,k,t}$ 把第 $k$ 次检索动作里前面的 think token 加 search-call token 一起圈进来，检索回来的 observation 和最终答案排除在外，然后

$$A_{i,t}=A_i^{\mathrm{out}}+\lambda\sum_{k=1}^{H}M_{i,k,t}\,\widetilde Z_{i,k},\quad \lambda=0.1$$

辅助项被夹在 $[-0.2,0.2]$，只是个有界的残差；答案 token 依旧只由 $A^{\mathrm{out}}$ 更新。训练目标也很素：

$$\mathcal L(\theta)=-\frac{1}{B}\sum_{i=1}^{B}\sum_{t\in\mathcal P_i}\rho_{i,t}(\theta)\,\mathrm{sg}(A_{i,t})$$

没有 ratio clip、没有 KL 惩罚、没有熵正则。GRPO baseline 就是把 $\lambda$ 设成 0，其余一模一样——所以 ECA 和 GRPO 的差值，干净地只来自这个 search-local 残差。这种"只动一个旋钮"的对照，比堆一堆 trick 再报个总分可信得多。

为什么要连 think 一起刷？表 2 里有答案：只给 query tag 打分的版本，EM 掉到 35.27，比纯 GRPO 的 37.19 还低。决定"该搜什么"这件事发生在 search 之前的那段推理里，只监督 query 字符串，等于把"想"和"搜"拆成两截。

## 🧪 实验：数字摊开看

### 设置

基础模型选了 Qwen2.5-3B-Instruct 和 7B-Instruct。训练池 8,192 题（NQ 4,096 + HotpotQA 4,096），独立 dev 1,024 题。256 步更新，AdamW、学习率 $10^{-6}$，每步 32 题 × $G=8$ rollout = 256 条轨迹，总共 65,536 条。检索是冻住的 E5-base-v2 在 Wikipedia18 上取 top-3，FP32 内积精确搜索；每个 episode 最多 4 个 action（3 次 search + 1 个答案），每步最多 512 token，4,096 context，训练温度 1.0、评估贪心。检索器、训练池、轨迹预算，所有 baseline 全对齐。

七个测试集一共 51,713 题：NQ(3,610)、TriviaQA(11,313)、PopQA(14,267)、HotpotQA(7,405)、2WikiMultiHopQA(12,576)、MuSiQue(2,417)、Bamboogle(125)。两个 in-domain，五个 out-of-domain。主指标是 strict EM，七个数据集等权 macro 平均：

$$\mathrm{EM}=\frac{100}{7}\sum_{s=1}^{7}\frac{1}{|\mathcal Q_s|}\sum_{q\in\mathcal Q_s}e_q$$

再加一个藏在 Appendix C 的数：把 cross-fold 换成全组标准化，ECA-Step 从 38.05 掉到 36.01。

最扎心的是 5.3 节那个对照：只给 query 打分的消融，在 3,441 个全错组里有 3,371 个（98.0%）照样产生了非零信号，比 ECA-Horizon 的 97.8%（3,213 / 3,285）还高一点，可测试 EM 反而跌破 GRPO。**光把梯度从零变成非零，一点用都没有**；信号必须落在对的 token 上，去强化那些 productive query 背后的推理，才换得来策略变强。这条结论我觉得比"97.8% 的失败组被救活"这个 headline 实在得多。

还有个细节别漏了：ECA-Horizon 的 EM 最高（38.22），F1 却是 45.80，比 GRPO 的 45.87 还低一丁点，更低于 ECA-Step 的 46.76。strict EM 涨、F1 没涨，多半是模型更倾向吐短而精确的 alias 答案了。这算不算贴着指标优化，我没完全看懂，但值得记一笔。

### 行为：重复检索真的少了吗

![图4：重复 query 比例](https://www.mulanai.com/fs/files/1120_4e3981b8_query_re.png)

*图 4：3B 上的 episode 级重复检索率。(a) 七数据集 macro：RLOO 54.1%、GRPO 42.4%、ECA-Step 30.3%、ECA-Horizon 24.8%、Base agent 23.9%，标了 −17.6 pp vs GRPO、−29.2 pp vs RLOO；小字注明所有 RL 方法都跑满 3.00 次检索（Base 只有 2.28）。(b) 四个多跳数据集（HotpotQA / 2Wiki / MuSiQue / Bamboodle）上 RLOO、GRPO、ECA-Step、ECA-Horizon 的分组柱状，ECA-Horizon 压到 18%–26%。*

故事挺顺：untrained 3B 平均 2.28 次检索，RL 之后全都顶满预算 3.00 次，于是 outcome-only 的方法开始拿重复 query 凑数——GRPO 42.40%，RLOO 54.07%。novelty gate 不给"没带来新文档"的那一步发正分，把 3B 的重复率压回 24.84%，几乎贴着 Base agent 的 23.86%。配对看 51,713 道题，ECA-Horizon 在 3B 把 12,340 道原本答错的改成答对，代价是 2,166 道 regress，净涨 19.67 个点。

附录里那三个 case 也挺直观：问"ISO 3166-2:CV 对应的国家在哪"，GRPO 把同一个 query 连发三遍、答了 Cabo Verde（错），ECA-Horizon 第二跳换成 "Cabo Verde location"、读到 central Atlantic Ocean 那段，答对。另一道题问 2007 金球奖得主 2012 年效力哪家俱乐部，GRPO 顺着 2012 年的 passage 跑到梅西、答了 Barcelona；ECA-Horizon 先锁定 2007 年的 Kaká，再找到他 2011–12 在皇马的那段，答对 Real Madrid。重复 query 和"没跟上桥接实体"这两件事，确实是连在一起的。

## 💡 我的判断

先把话说在前头：这篇我读得挺舒服，消融干净、公式诚实、局限性写得也不糊弄。但几个 headline 数字得拆开看，不然容易高估它。

**那 4.80 个点，参照物选得有点巧**。3B 上 GRPO 37.19，比 RLOO 35.43、GiGPO 36.96 都强，也就是说 3B 的 +1.03 是跟最强 baseline 比出来的，挺硬气。7B 上画风一变：GRPO 只有 37.82，比 3B 的自己才涨 0.63，而 RLOO 从 35.43 涨到 40.56、GiGPO 从 36.96 涨到 41.09。作者自己在 5.1 里写了句 "avoiding GRPO's early plateau on multi-hop retrieval"——GRPO 在 7B 上早 plateau 了。于是 ECA-Horizon 对 GRPO 的 +4.80，有一部分其实是在修 GRPO 自己的规模退化。跟当时最强的比，7B 上是 +2.06（vs RLOO）、+1.53（vs GiGPO）。真实增量大概落在 1–2 个点这个区间，不是 4.8。坦率讲，把两个规模下参照物强度不一样的事写进同一个 headline，读者很容易被带偏。

"**两个变体都超过所有 baseline**" 这句，表格不答应。5.4 节原话是 both ECA variants outperform all baselines，可表 3 里 3B 的 ECA-Horizon 82.48 明明白白低于 RLOO 83.46，也低于自家 ECA-Step 84.68。作者行文时的处理是：3B 挑 ECA-Step 讲 +4.66，7B 挑 ECA-Horizon 讲 +6.38，各取对自己有利的那一格。数据没造假，叙事有点选择性。看到 Table 3 我才意识到，被冠以主角光环的 ECA-Horizon，在这个迁移测试里 3B 其实不占优。

"**novelty gate 抑制重复检索**" 这个机制故事，只在 3B 站得住。图 4 只画 3B，Table S1 自己给了 7B：重复率 Base 1.69%、GRPO 0.71%、RLOO 7.07%、ECA-Step 8.37%、ECA-Horizon 8.42%。7B 上 ECA 的重复率反而比 GRPO 高一大截。也就是说 7B 那 4.80 个点，不能归功于"少发废 query"；机制解释和收益在不同规模上没对上，正文里也没讨论这个不一致。我觉得这是全篇最该补一句而没补的地方。

**等权 macro 平均对小数据集太敏感**。Eq.10 是七个数据集各算各的 EM 再平均，Bamboogle 只有 125 题，跟 NQ 的 3,610 题同权。7B 上 Bamboogle 从 32.00 跳到 40.00（+8.00），单道题就是 0.8 个点。作者其实清楚这个口径问题，Table S2 特意注明 pooled accuracy 是"weights all questions equally rather than weighting the seven datasets equally"，还给了 3B 净涨 19.67、7B 净涨 12.96。两套口径差这么多，光看 Avg. 一列容易把噪声当收益。

**potential 的代理本身有硬伤，作者自己写在 Limitations 里，我反倒觉得该展开讲**。$\Phi$ 衡量的是参考答案 token 的似然。可多跳题里最金贵的那篇文档，往往只给出中间桥接实体，压根不提最终答案——按这个势函数，它一步都不涨分。文档 ID 去重也认不出跨文章的近重复文本。这两条都戳在 ECA 的核心假设上：它默认"好证据 = 抬高答案似然"，而检索的真实价值经常是"让下一跳变得可问"。这块我也不是特别确定有没有便宜的补法，但至少该算是个已知边界，不是工程细节。

**定位上，别被新框架带跑**。用答案似然做稠密奖励（IGPO、TIPS）、按状态分组（GiGPO）、给失败组补信号（MVPO 那一类），都是同一时期在啃同一块骨头。ECA 的增量很具体：把打分上下文严格收窄到 question + 去重文档、4+4 cross-fold 标准化、novelty gate、把残差只刷在 search action 的 think+query 上。Table S4 里作者自己列了九个相关方法逐个对比，没喊"首个"，这点我很买账。说到底，这是一次扎实的方法整合加一套干净的消融，不是底层突破。它的价值在于把"证据该 credit 给谁、怎么归一化、别让措辞刷分"这几处拧巴掰清楚了，而不是发明了新范式。

还有两处工程上会在意的没写透：$\lambda=0.1$ 是在 dev 上给 ECA-Step 调的，直接搬给 ECA-Horizon 没重调——好处是对照干净，代价是没给 $\lambda$ 敏感性曲线；训练时那批 teacher-forced 打分前向到底多吃多少显存和时间，论文只说"测试时不变"，没给数字。真要复现，这两笔账得自己先算。

## 🔧 如果你也在做搜索 Agent

几个能直接搬走的想法，我揉在一起说。

全错组不一定是废数据。只要能找到一个不依赖终局对错的中间量，难题上那批轨迹全都能重新产生梯度。ECA 用了答案似然，换成"新文档 ID 数""覆盖率"之类也行，关键是别让这个量被策略自己的措辞污染。

中间奖励的归一化别顺手用全组统计。稀疏尖峰被自己的均值标准差吃掉这件事，在任何 dense reward 上都成立，cross-fold（或留一法）成本几乎为零，值得默认打开。

辅助残差要有界、要限定落点。$\lambda$ 取 0.1、裁到 $[-0.2,0.2]$、只刷 search action、答案 token 留给终局奖励——这套"别抢主信号的戏"的克制，比往上堆 trick 稳得多。

报告收益时把参照物摊开。跟最强 baseline 比、跟同规模比、把小数据集的权重讲清楚，比一个醒目的 4.80 更有说服力。

回到最开始那张图。八条路全走死了，梯度归零，听上去像 RL 的宿命；这篇论文做的事，其实只是问了一句"真的每一步都一样没用吗"，然后给每一次检索单独记了笔账。账不一定记得完全准——桥接文档还没被算进去呢——但这个追问本身，我觉得挺值钱。

但还有个更根上的问题没解决：当"证据有没有用"只能用"答案似然涨没涨"来近似时，我们其实还是在用终局的尺子量中间的路。什么时候能不借参考答案、直接判断一条检索打开了哪些新的可问空间，那才是另一回事了。
