# 异步 RL 的旧数据为什么越学越歪？给分数中心化加一道 KL 刹车

你有没有碰到过这种事：为了把 GPU 喂饱，采样和训练并行跑，采样器隔好一阵才同步一次权重。吞吐确实上去了，但训练曲线走到一半开始抖，reward 看着还在涨，一换到正式评测就露馅。

更隐蔽的一层是数值精度。训练用 BF16，rollout 用 FP8 权重加 BF16 的 KV cache，同一个 token 在两个引擎里算出来的概率压根不一样。模型权重一点没变，数据却已经是 off-policy 的了。这篇论文管它叫 training–inference mismatch，简称 TIM。

最近读到一篇专门拆这件事的论文，我的第一反应是：哦，原来问题不只是"数据旧了"这么简单。它把已有的 Score Centering 掰开，指出这套方法只修了一半，然后补了一记反向 KL。改动不大，但把"为什么会在 agentic 任务上翻车"讲得相当透。

> **核心摘要**：异步强化学习里，采样策略 $\mu$ 和 learner $\pi_\theta$ 天然错配，Score Centering（SC）靠减掉 score 在行为策略下的条件均值消掉 reward baseline 带来的偏置，梯度确实比 importance sampling 温和得多。可 SC 保留的是"用 $\mu$ 续写"算出的 token 优势，一旦 learner 跑远、动作又会改变后续状态，这套优势就不代表真实收益了。Regularized Score Centering（RSC）在 SC / SC+TIS 上加一个以行为策略为参考的反向 KL，把 learner 的 next-token 分布摁在采样策略附近。理论上 KL 让收敛半径不再随响应长度收缩，轮数从 $O(H\log(N/\epsilon))$ 压到 $O(\log(N/\epsilon))$；实验上 RSC(TIS) 在六个 agentic 任务全部拿到第一，AppWorld 比 SC 高 14.3 个百分点，BabyAI 达到最强 baseline 的 9.9 倍。我的判断是：这不是通用升级，而是一贴"越异步越值钱"的补丁，值钱的地方在于诊断和理论闭环，不在刷榜。

## 🎯 异步 RL 的数据，天生就是"过期"的

先把场景摆清楚。learner 是 $\pi_\theta$，真正生成训练数据的是行为策略 $\mu$。异步 RL 让生成和训练并发：一条 response 还在往外吐 token，learner 已经更新到更新的权重上去了。再加上复用旧 response、降低采样器刷新频率，$\pi_\theta$ 和 $\mu$ 越拉越开。论文把刷新间隔记作 $R$——learner 对着固定的 $\mu$ 做 $R$ 次更新，然后采样器拷贝一次权重。

第二类错配更烦人：训练引擎和推理引擎用不同精度、不同 kernel，同一个 action 的概率对不上。这是权重没动也会发生的 off-policy。

那 off-policy 到底坏在哪？从 $\mu$ 的数据上算出来的更新，跟 learner 拿自己样本算出来的梯度不是一回事。在 agentic 任务里这件事被放大：一个动作会改变环境状态、改变之后能选什么、改变最终奖励，于是"用旧数据估出来的这一步值多少"跟"learner 自己走会值多少"差得更远。

已有的修补路线大概这么几条：

| 方法 | 核心动作 | 留下的窟窿 |
|---|---|---|
| 序列级 IS / GSPO | 用整条 response 的似然比加权，靠长度归一化和裁剪稳住 | token 比值连乘，方差容易爆 |
| token 级 IS | 只修正某个 history 下 next action 的分布 | 大比值仍带来极端梯度 |
| TIS（截断 IS） | 把 token 权重 cap 住（CISPO 形式） | 引入裁剪偏置，且与动作无关的 reward 成分还在驱动更新 |
| IS-PPOClip | token 重要性比 + 围绕近端快照的 PPO 裁剪 | 裁剪一旦激活，该 token 的 reward 梯度直接归零 |
| Sequence MIS | 整条 response 一个权重、一个接受判定 | 比值落在区间外就整条丢掉 |
| **Score Centering** | 减掉 score 在 $\mu$ 下的条件均值 | 只消掉 baseline 偏置，续写价值仍来自 $\mu$ |

SC 的出发点其实挺漂亮。learner 的 score 是 $\psi_\theta = \nabla_\theta \log \pi_\theta(a\mid h)$，在 $\pi_\theta$ 自己采样时条件均值为零，所以一个跟动作无关的 reward baseline 不贡献梯度。换到 $\mu$ 采样，这个均值就不一定是零了——同一笔"人人都有的基础分"会偷偷推着参数走。SC 直接在每个 history 上把 $\widehat{\mathbb{E}}_\mu[\rho^{\rm TIS}\psi_\theta\mid h]$ 减掉，不需要学 value function，就把这块偏置抹平。

论文里有一句我挺认同：被减掉的这一项是**期望更新里的偏置**，所以多采数据也消不掉它。这跟方差问题是两码事，不能靠堆算力蒙混过去。

## 🧠 但 SC 只治了一半：分数中心化的真正失效点

说实话，第一遍看摘要我以为 SC 已经把 off-policy 收拾干净了。往下读才发现作者留了个更关键的钩子。

SC 减掉的是公共值 $V_t^\mu$，留下来的动作权重是 $A_t^\mu = Q_t^\mu - V_t^\mu$。注意上标：这个 token 优势是"选了这个 token、之后**继续用 $\mu$** 续写"得到的期望奖励。learner 真正需要的却是 $A_t^{\pi_\theta}$——同样的 token、同样的 history，之后**用 $\pi_\theta$** 续写。

哪怕只有一个终局奖励，这两者也能差很多。当 $\pi_\theta = \mu$ 时两者一致；两个策略一分开，同一个动作的价值就变了，learner 的轨迹还会跑到行为数据里压根没覆盖过的 history 上。用论文的话讲：SC 在 $\mu$ 的 history 上用 $A_t^\mu$，learner 的 reward 梯度在 $\pi_\theta$ 的 history 上用 $A_t^{\pi_\theta}$。

而 TIS 只 cap 了当前 token 的权重，既没纠正前面 history 的分布，也没管后面的续写分布。于是"在行为轨迹上把 surrogate 拟合得更好"完全可能不等于"learner 自己跑出来的 reward 更高"。这一步推得挺狠，也直接给出了 RSC 的动机：既然错配来自 learner 跑得太远，那就别让它跑太远。

## 🏗️ RSC：在 SC 上摁一个反向 KL 刹车

一句话讲清核心：**RSC 就是给 SC 加上一道反向 KL 约束**（可选叠加 TIS），写成 $\mathrm{RSC} = \mathrm{SC} + \beta\,\mathrm{KL}(\pi_\theta\,\|\,\mu)$。

它是一族方法，对不带 IS 的 SC 和带截断的 SC+TIS 都成立。在每个采样到的 history 上，惩罚项比较 learner 与行为策略的 next-token 分布，$\mu$ 在求导时固定不动。行为策略同时充当 KL 的参考——刷新 $\mu$ 也就顺带更新了参考点，这点在异步训练里很自然。

把符号补齐。token 重要性比 $\rho_t = \pi_\theta(a_t\mid h_t)/\mu(a_t\mid h_t)$，TIS 用 $\rho^{\rm TIS}=\mathrm{clip}(\rho,c_{\rm low},c_{\rm high})$，SC 不带 IS 就是 $c_{\rm low}=c_{\rm high}=1$ 的特例。取 $a(\rho)=\rho^{\rm TIS}$、$F_a(\rho)=\int_1^\rho a(u)/u\,du$，于是 $\nabla_\theta F_a(\rho)=a(\rho)\psi_\theta$。固定 $\mu$ 和 $A_t^\mu$，单个 token 对目标的贡献写成：

$$w_t = A_t^\mu\,F_a(\rho_t) - \beta\big(\rho_t\log\rho_t - \rho_t + 1\big).$$

第二项就是关键。因为 $\mathbb{E}_\mu[\rho_t\mid h_t]=1$，它的条件期望正好是 $\beta\,\mathrm{KL}(\pi_\theta(\cdot\mid h_t)\,\|\,\mu(\cdot\mid h_t))$。第一项按 $A_t^\mu$ 给动作加分，第二项按策略移动的距离扣分——**奖励"在旧数据上看起来更好"和惩罚"跑得离旧策略太远"被放进同一个目标里**。整个惩罚可以写成在 $\mu$ 下的期望，用同一批数据就能估，不需要额外的环境交互。

![图1：RSC 在 SC / SC+TIS 上加入反向 KL，以及三个 agentic 任务的训练曲线](https://www.mulanai.com/fs/files/1119_4a691c8a_kl_role_.png)

*图 1（论文 Figure 1）：(a) 方法关系——SC 与 SC+TIS 各自加上 $-\beta\,\mathrm{KL}(\pi_\theta\|\mu)$ 得到 RSC (w/o IS) 与 RSC (TIS)。(b–d) 分别是 WebShop、AppWorld、BabyAI 的训练 reward 曲线，三个 seed 的均值 ± 样本标准差，强方法用彩色、其余用灰色。BabyAI 那格里 RSC (TIS) 的青色线明显单独冲上去，RSC (w/o IS) 的紫线紧随其后，而 SC、IS、TIS、Seq-MIS 基本贴着底部。*

### 从 logit 导数看 KL 到底压住了什么

论文做了一组我觉得很值钱的梯度诊断。它把 learner 和 behavior checkpoint 都固定住（Qwen3-8B-Base，learner 在 update 1500、behavior 在 1400，硬拉开 100 步），复用同一批采样动作、同一组 response advantages、同一组 128 个 Monte Carlo 辅助样本，只换更新规则，在 optimizer 动之前量梯度范数。这就把"方法差异"和"数据差异"干净地剥开了。

IS 的 logit 导数是 $\nabla_{z_a} w = A\,\rho\,[1-\pi_\theta(a\mid h)]$，一个大的 $\rho$ 直接把梯度放大。SC+TIS 把 $\rho$ 换成 $\min(\rho,c)$ 封顶，SC 不带 IS 直接令它等于 1。RSC 在 $\rho>1$ 时额外减掉 $\beta\rho\log\rho[1-\pi_\theta(a\mid h)]$，反向顶住"继续把概率往上推"。又因为 $\rho=\pi_\theta/\mu \le 1/\mu$，极端大的比值必然出现在 $\mu(a\mid h)$ 很小的 token 上——这也解释了为什么诊断图拿行为概率当横轴。

![图3：固定 checkpoint 下各方法的 logit 与参数梯度范数](https://www.mulanai.com/fs/files/1119_9a8b489a_matched_.png)

*图 3（论文 Figure 3）：上排 (a–e) 是 logit 梯度 $\ell_2$ 范数，下排 (f–j) 是参数梯度范数（$\times10^3$），横轴都是 rollout token probability $\mu(a\mid h)$，切成 25 个等宽 bin。图中标注的 99 分位很能说明问题：Raw IS 是 25.928，SC+TIS 降到 3.784，RSC(TIS) 再降到 3.627；不带 IS 的一侧 SC(w/o IS) 是 2.424，RSC(w/o IS) 是 2.415。低概率 token 处 IS 那条黑色分位线几乎贴着纵轴顶端炸开，中心化之后整条曲线被摁下来一大截，KL 又进一步收掉尾部的 99 分位。*

这里有个诚实的细节：KL 对 99 分位的改善幅度其实不大（3.784 → 3.627），远不如 IS → SC 那一下（25.928 → 3.784）。我的理解是，KL 的主要价值不在"把梯度压得更小"，而在后面理论里那两件事——让拟合更容易从数据里验证、让拟合精度能翻译成 reward 进步。把 KL 单纯理解成梯度裁剪就浅了。

实现上还有两个可选项：惩罚权重可以单独封顶 $\rho^{\rm KL}=\min(\rho,c_b)$（$c_b=\infty$ 就是标准反向 KL）；KL 的参考 $\pi_{\rm ref}$ 也可以和生成数据的 $\mu$ 分开、按更低频率刷新。论文为了简单全程取 $\pi_{\rm ref}=\mu$。采样更新里，SC 中心用从 $\mu(\cdot\mid h)$ 独立抽的辅助 token 做无偏估计，每个辅助 token 带自己的 detached $\rho^{\rm TIS}$ 权重——不需要额外 rollout，也不需要再算一次奖励。

## 🔬 理论：KL 为什么能把"拟合好"翻译成"reward 涨"

这部分是全篇我最想拎出来聊的，因为它解释了 KL 不只是工程上的稳定剂。

作者的论证分内外两层。内层是拟合：不带 KL 时，在某些所有 token 优势都为零的 history 上，改概率可以完全不动 surrogate，于是"目标 gap 小"并不能锁定一个特定策略。加了 KL 之后目标对 token 概率有强凹性，偏离那个 improving target 就要付出目标损失，小 gap 直接推出"拟合策略在行为 history 上贴近 target"。顺带一提，这个贴近还把采样噪声一起管住了——两个策略的目标差，其方差被 $H$ 乘 population gap 控制住，拟合越好比较越不噪，拿到的是比"把噪声当常数"更紧的样本界。这个用法和 KL 正则化 contextual bandit / RLHF 的 fast-rate 分析是一路的。

外层是 history 分布。不带 KL 时，要控制分布漂移只能约束每个 token 的 log-ratio；长度 $H$ 的 response，比值最坏能到 $e^{Hr}$。想让这个界有界，token 半径就得取 $r=O(1/H)$——响应越长，允许每步动的幅度越小。而固定 $\beta$ 下，KL 正则化的 target 对每个前缀和整条 response 的比值都有一个**与 $H$ 无关**的上界，哪怕 token 半径保持常数 $r=O(1)$。

把两层合起来得到一个挺有画面感的结论：在有限确定性 token 树、二值终局奖励下，**最终策略只采一条 response，其 reward 就几乎追平初始策略 best-of-$N$ 采样的期望 reward**。带 KL 的两个变体在 $\beta=2$、token log-ratio 半径 $1/2$、每轮新数据的条件下，用 $O(\log(N/\epsilon))$ 轮外循环达到 $\epsilon$ 误差；不带 KL 的对照里，充分半径是 $1/(8H)$，轮数退化成 $O(H\log(N/\epsilon))$。差了一个 $H$ 因子，长响应任务上这个差距会很难受。

有个边界作者自己点破了，我觉得该给个好评：这些保证建立在 **score-centered 更新**之上。裁剪激活时加权 score 在 $\mu$ 下的条件均值不为零，reward baseline 会重新混进期望更新；SC 把这个均值减掉才让分析成立。作者把话挑明了：裁剪激活时，不带 score centering 的 TIS+KL，论文**没有**证明它能改善 reward。不硬吹，挺难得。

## 🧪 先证明"会失败"：SC 的两个失效模式

作者没有一上来就刷榜，而是先花两节论证 SC 在哪儿会塌。这个顺序我很喜欢——先立靶子，再给解法。

**失效一：Monte Carlo 中心比 Top-k 更准。** 原始 SC 用行为概率最高的 128 个 token 加一个建模尾部来估条件均值，这是有偏近似。改成直接从 $\mu(\cdot\mid h)$ 有放回抽辅助 token，反传它们的平均 learner log-prob，就得到 $\mathbb{E}_\mu[\psi_\theta\mid h]$ 的无偏估计。Figure 4 里每个 Monte Carlo 变体（32/64/128 样本）的最终评测分都超过对应的 Top-128，BF16 和 FP8 rollout、Countdown 上一致。但——估得再准，也没改变"续写价值来自 $\mu$"这件事，所以光靠改估计器救不了策略错配。

**失效二：任务结构和陈旧度放大错配。** 这是 Figure 5 和 Figure 6 的重点。

![图5：相同刷新间隔下 math 与 Crafter 的对照](https://www.mulanai.com/fs/files/1119_c4e9fedc_sc8b_tra.png)

*图 5（论文 Figure 5）：左边是 math 任务配 Qwen3-8B 稠密模型，(a) 训练准确率、(b) 有符号的 $\log\pi_\theta-\log\mu$；右边是 Crafter 配 Qwen3-4B，(c) 训练 reward、(d) 同样的 log 比。图例统一为 SC（黑）、SC+TIS（蓝）、RSC(w/o IS)（紫）、RSC(TIS)（青）、IS（绿）、Seq-MIS（黄）、TIS（红）、IS-PPOClip（粉）。同样 $R=64$：math 那侧几条线挤在 50–65% 里，加 KL 对每个最终平均准确率的改变不到 1 个绝对百分点；Crafter 那侧 RSC(TIS) 的青线一路爬到 8 以上、RSC(w/o IS) 紫线到 7 左右，其余方法基本在 0–3 徘徊。*

同一刷新间隔，差别却这么大。作者的解释落到任务结构上：Crafter 里捡个资源、选条路，会打开完全不同的后续分支。这个动作的价值取决于策略**会不会利用**随之而来的机会——行为续写很少利用，它在 $\mu$ 下的优势就低；learner 续写会利用，它在 $\pi_\theta$ 下的优势就高。math 任务里 token 不改变环境，续写分支的后果小得多。两组还差了模型，作者也坦白说这只能算"部分解释"，没把因果钉死。

![图6：随着陈旧度增加，SC 逐步失守](https://www.mulanai.com/fs/files/1119_f608f849_stalenes.png)

*图 6（论文 Figure 6）：左侧 Countdown（Qwen3-0.6B，MC128）三行对应 $R=16/32/65$，列是训练 reward 与有符号 $\log\mu-\log\pi_\theta$；右侧 INTELLECT-2 math 配 MoE 模型 Qwen3-30B-A3B-Base，三行对应 $R=64/256/512$，列是训练准确率与 $|\log\pi_\theta-\log\mu|$。左侧那个向下的箭头写着 Increasing staleness。$R$ 越大，SC 的黑线掉得越明显；最大 Countdown 间隔下 RSC(TIS) 的青线稳在 0.7 附近，黑色 SC 已经塌到 0.1 上下，论文给的绝对 reward 差约 65%，而且这还是用了 Monte Carlo 中心之后。MoE 那侧 $R=512$ 时 SC 的 $|\log\pi_\theta-\log\mu|$ 冲到 1.0 附近，策略分离和性能下滑是同步出现的。*

这一节的结论我概括成一句：**learner 评测会揭穿被陈旧行为策略的 reward 掩盖住的退化**。只看训练曲线（reward 是在 $\mu$ 下测的）容易以为没事，换到 $\pi_\theta$ 的 heldout 才现原形。

## 📊 主实验：六个 agentic 任务全部拿下第一

规模实验分两块：周期性刷新的受控异步环境，以及全异步的软件工程。

受控这侧用 Qwen3-4B-Base、Adam $10^{-6}$、每 update 16 个任务、$R=64$，训练 BF16、rollout FP8 加 BF16 KV cache。RSC 的超参是 $\beta=0.01$、惩罚比单独 cap 在 2、SC+TIS 的权重 cap 在 2、每 prompt 8 条 response、128 个 Monte Carlo 辅助样本估中心，另外按理论做了 $G/(G-1)$ 的组大小校正（$G=8$）。六个任务是 WebShop 购物、AppWorld 工具调用、BabyAI 导航、TextWorld 做饭游戏、Crafter 和 Craftax 生存。

![图7：六个交互任务的训练 reward 曲线](https://www.mulanai.com/fs/files/1119_715522a3_agentic_.png)

*图 7（论文 Figure 7）：(a) TextWorld Cooking、(b) WebShop、(c) AppWorld、(d) BabyAI、(e) Crafter、(f) Craftax，纵轴分别是百分比得分或环境 return，横轴是训练 update，三个 seed 的均值 ± 样本标准差。RSC(TIS) 的青线在 BabyAI 冲到约 16、Crafter 到约 9、Craftax 到约 4.7，都是全场最高；TextWorld 上大家很快贴到 100，天花板效应明显。*

## 💡 我的判断

**最值钱的地方，是把"SC 只修了 baseline 偏置、没修续写错配"这件事讲清楚了。** 从梯度诊断（Figure 3）到失效分析（Figure 5、6）到理论（半径不随 $H$ 收缩）再到实验，是一条闭合的链，不是"加个正则然后刷榜"。反向 KL 本身一点不新——TRPO、RLHF、DPO 都是这个家族；同期还有 Proximal KL、Future-KL、ALP 这些 token 级或针对陈旧度的工作。RSC 的新意在于把它接到 **token 级 score centering** 上、以行为策略为 KL 参考、并且给出了不随响应长度收缩的收敛保证。定位是精准的机制修补，不是底层突破。

几处我保留意见：

第一，**收益高度集中在高错配场景**。math 上加 KL 改变不到 1 个绝对百分点，SWE 配置 A 里 RSC(TIS) 甚至是负增益。所以它不是"SC 的无脑替代品"，而是"越异步、越 agentic、学习率越大越值钱"的补丁。这也符合直觉——KL 是在约束移动，移动本来就小的时候，约束只会拖后腿。

第二，**超参迁移成本被低估了**。$\beta$ 在受控 agentic 里是 0.01、梯度诊断里 0.1、SWE 里 0.001，跨了三个数量级；TIS cap、KL ratio cap、辅助样本数（32/128）也各任务不同。作者说没调榜我信，但"没调"不等于"好迁"，工程上换套任务仍得标定一遍。

第三，**理论和真实训练之间有距离**。确定性转移、二值终局奖励、$\beta=2$、exact centers（TIS 那条定理）、每轮 fresh data——这套假设离长 horizon agentic 的真实环境挺远。论文自己也说 outer round 数的是策略刷新次数，optimizer 迭代和采样成本另算。理论给的是方向感，不是可直接套用的工程公式。

第四，**成本是真实存在的**。每个 token 要在同一 history 下额外抽辅助 token 估 center 和 KL 梯度（受控实验 128 个、SWE 32 个），虽然不用额外 rollout、不用再评一次奖励，前向反向量在那儿摆着。论文主打的是"同样采样 response 数下 reward 更高"，这个口径公平，但没展开墙钟时间。

第五，Related Work 里点了 Proximal KL、Future-KL、ALP 这些同期方案，实验基线却只放了 IS / TIS / SC / SC+TIS / IS-PPOClip / Sequence MIS。少一组直接的 token 级 KL 对照，我觉得是个可以追问的空白。

### 工程上怎么用

如果你在跑异步 RL，尤其是长 horizon 的 agentic 训练、采样器刷新慢、或者训练和 rollout 精度不一致，我的建议是先别急着换 loss，先量一下 $|\log\pi_\theta-\log\mu|$。这个量小，SC / SC+TIS 大概率够用，加 KL 是白受约束；这个量大，或者任务里动作会改变环境状态，那就上 RSC(TIS)，并且顺手把 center 从 Top-k 换成从 $\mu$ 直接抽的 Monte Carlo 估计——后面这一步几乎零副作用。纯静态的 math 类任务，不用折腾。

还有一个更本质的问题没解决：论文结尾自己也在问——策略越跑越远时，到底需要多少次 optimizer 更新才能维持 reward 进步？现在 KL 是"摁住别跑太远"，属于防守；怎么在允许跑远的同时还保证进步，是另一回事。
