## 一、研究背景与动机

### 1.1 Agent Skill 的兴起与困境

Agent Skill 是一种封装了指令、元数据和可选资源（脚本、模板等）的组织化包，可被大语言模型（LLM）发现、加载和执行。截至论文发表时，已有超过 **60 万个 skills** 被公开发布，数量持续增长。

然而，**skill 的可用性并不意味着模型能有效使用它**。有效的 skill 利用面临四重非平凡挑战：

1. **识别 (Identify)**：从大量候选中定位相关 skill
2. **理解 (Understand)**：把握 skill 的操作约束和接口规范
3. **协调 (Coordinate)**：组合互补 skill 形成连贯工作流
4. **执行 (Execute)**：正确实施 skill 规定的程序

### 1.2 现有研究的局限

已有工作主要聚焦于 skill 检索、skill 内化（减少对外部文档依赖）、以及利用 skill 支持 agent 自我改进。这些方法解决的是 skill 如何被检索和表示，**而非模型如何有效理解、协调和利用 skill 来解决多样化任务**。

---

## 二、核心贡献

本文提出 **SKT (Skill-Use Training)**，一个经验证的数据合成 pipeline，用于从大规模 agent skill 集合中构建 skill-grounded 任务和可执行轨迹，以训练 LLM 的 skill 使用能力。三大贡献：

1. **SKT 框架**：赋予 LLM 有效利用 Agent Skills 的能力
2. **可扩展数据合成 Pipeline**：生成具备可解性、可验证性和复杂度可控性的训练数据
3. **SkillEval 基准测试**：用于 skill 使用评估的 held-out 可执行 benchmark

---

## 三、方法详解：SKT Pipeline

SKT 是一个三阶段流水线：**Skill Curation → Task Synthesis → Trajectory Synthesis**。

### 3.1 Stage I: Skill Curation（技能筛选）

从候选集合 $\mathcal{C}$ 出发：

- 使用**基于 rubric 的 LLM judge** 保留能支撑可执行、客观可检查任务的 skill
- 采样 skill 集合 $\mathcal{S} \subseteq \mathcal{C}$，基数 $k = |\mathcal{S}|$ 可配置（实验使用 $k \in \{1, 2, 3\}$）
- 当 $k > 1$ 时，composition judge 检验 skills 是否构成连贯工作流且具有不同角色；被拒绝的集合重新采样

### 3.2 Stage II: Task Synthesis（任务合成）

任务合成包含五个关键环节：

#### (1) Template-driven Authoring

TaskGen 读取所有 skill 并填充固定模板，生成任务包 $\mathcal{T}$，包含：
- 任务指令
- 隔离运行时环境
- 执行设置
- 可执行评估器
- 参考解

#### (2) Rule-based Task Verifier

确定性检查确保：
- 所有必需组件齐全，文件路径有效
- 评估器定义受支持
- 创作 trace 记录了对每个 skill 的访问
- 参考解在干净工作区中执行获得满分
- 无逐字复制答案泄漏

#### (3) Agent-based Task Verifier

语义审查确保：
- 指令清晰指定所需 artifact 和输出位置
- 完成任务所需信息在本地环境中可用
- 无语义答案泄漏

此外执行 **Skill Dependence 测试**：配对 rollout（提供 vs. 不提供 skill），确认 skill 访问确实有助于任务完成。

#### (4) Difficulty Control（难度控制）

- 固定 solver 对任务进行 $N=5$ 次独立 rollout
- 计算通过率 $p_{\mathrm{pass}}$
- 若 $p_{\mathrm{pass}} \geq 0.6$（即 5 次中 3 次满分），任务被判定太简单，送回修复

#### (5) Feedback-guided Task Repair

- 失败任务接收具体错误反馈和难度建议
- TaskRepair 修改后重新进入验证循环
- 通过所有 gate 的任务进入合格任务集 $\mathcal{D}_{\mathrm{task}}$

### 3.3 Stage III: Trajectory Synthesis（轨迹合成）

对每个合格任务和 teacher-harness 对：

- Teacher 模型通过 harness 解决任务
- **Rule-based validator** 要求：评估器满分、正常终止、格式良好的工具 trace、明确的 skill 访问
- **LLM validator** 检查每个 skill：是否在相应动作前被查阅、是否影响了具体决策、是否被正确应用
- 失败 rollout 重新采样（**不暴露失败反馈**给下一次尝试）
- 第一个通过双重验证的 rollout 进入训练集 $\mathcal{D}_{\mathrm{traj}}$

### 3.4 Training：Masked Autoregressive SFT

训练损失函数：

$$\mathcal{L}_{\mathrm{SFT}} = -\sum_{t \in \mathcal{A}(\tau)} \log p_\theta(x_t \mid x_{<t})$$

其中 $\mathcal{A}(\tau)$ 包含所有 assistant 生成的 token（推理、工具调用、响应），system 消息和工具观察保留在上下文中但从 loss 中 mask。

## 四、实验设置

### 4.1 数据规模

| 维度 | 数值 |
|------|------|

| 合成任务包数 | 4,000 |

| Three-skill 任务 | 1,185 |
| 验证后 DeepAgents 轨迹 | 14,277 |
| 验证后 OpenCode 轨迹 | 12,887 |
| 总验证轨迹 | 27,164 |

### 4.2 模型与训练配置

| 配置项 | 值 |
|--------|------|
| 基座模型 | Qwen3.5-9B, Gemma 4 E4B-IT |
| 微调方式 | 全参数 SFT |
| 训练框架 | LLaMA-Factory |
| Epoch | 1 |

## 五、主要实验结果

### 5.1 总体有效性

SKT 在**全部 16 个** model-harness-benchmark 比较中均提升了均值分数，绝对增益范围 **3.20 ~ 18.91 分**。

| 模型 | Harness | SkillsBench | SkillEval | MolBench-Bind | AgentSkillOS |
|------|---------|-------------|-----------|---------------|--------------|
| Qwen3.5-9B | OpenCode (Orig) | 5.80±1.03 | 55.24±0.72 | 33.11±2.59 | 79.61±1.64 |
| Qwen3.5-9B | OpenCode (**SKT**) | **15.79±1.69** | **72.48±1.32** | **44.59±1.56** | **84.70±2.17** |
| Qwen3.5-9B | DeepAgents (Orig) | 4.94±0.70 | 51.62±1.16 | 31.76±1.35 | 74.03±2.03 |
| Qwen3.5-9B | DeepAgents (**SKT**) | **13.62±0.82** | **70.53±1.24** | **47.30±1.56** | **79.84±1.82** |
| Gemma 4 E4B-IT | OpenCode (Orig) | 7.08±1.33 | 61.01±2.05 | 34.46±1.35 | 49.41±1.28 |
| Gemma 4 E4B-IT | OpenCode (**SKT**) | **10.28±1.16** | **72.85±1.30** | **45.27±1.35** | **56.74±0.93** |
| Gemma 4 E4B-IT | DeepAgents (Orig) | 5.07±0.95 | 56.14±1.73 | 31.76±2.59 | 42.23±0.85 |
| Gemma 4 E4B-IT | DeepAgents (**SKT**) | **9.24±1.05** | **66.39±2.11** | **41.89±1.56** | **47.38±1.47** |

### 5.2 Mixed-Harness Training

混合训练产生的单一 checkpoint 在所有 benchmark-harness 对上均优于 Original（增益 2.64~18.81 分），且与 Specialist checkpoint 的差距最多仅 2.71 分，在部分比较中甚至超过 Specialist。

## 六、深入分析与消融实验

### 6.1 SKT 增益来源：Skill 利用而非知识内化

对比实验：skill 提供 vs. skill 撤回条件下的 Original 和 SKT 表现。

- **Skills 撤回时**：增益仅 0.53~5.69 分
- **Skills 提供时**：增益 8.68~18.91 分

**结论**：SKT 的优势主要来自改善 skill 利用能力，而非将 skill 知识内化到模型参数中。

### 6.2 数据质量至关重要：Verified vs. Unverified

- **Unverified SFT**：在所有四个 benchmark 上均**降低**均值（负收益）
- **SKT (Verified)**：在所有四个 benchmark 上均**提升**均值
- 两者差距：**11.91~24.61 分**

**结论**：未经验证的原始合成数据反而会损害 skill 利用能力，验证流程不可或缺。

### 6.3 跨 Harness 迁移

在一个 harness 上训练、另一个 harness 上评估：

- Cross-harness SFT 在所有比较中均优于 Original（提升 4.35~9.86 分）
- 保留 matched gain 的 **49.1%~58.1%**

**结论**：学到的 skill 使用行为有大量可跨 harness 迁移的通用成分。

### 6.4 Scaling：性能随 Skill 覆盖范围单调提升

从 100 到 2,000 skills 逐步扩大合成池，SkillEval 分数从 Original 的 55.24 单调递增至 2,000 skills 时的 72.48。

### 6.5 不同 Skill 基数的表现

| Skill 数量 K | 任务数 | Original | SKT | 绝对增益 |
|-------------|--------|----------|-----|----------|
| K=1 | 25 | 9.54 | 16.94 | +7.40 |
| K=2 | 19 | 3.95 | 20.72 | **+16.77** |
| K≥3 | 33 | 4.04 | 12.08 | +8.04 |

SKT 在多 skill 场景中的提升同样显著，K=2 时提升最大。

## 七、SkillEval Benchmark

SkillEval 是本文提出的 held-out 可执行基准：

- 使用与训练相同的 task-synthesis pipeline，但来自**单独生成的候选池**
- 100 个任务：30 single-skill + 46 two-skill + 24 three-skill
- 100 个不重叠 skill groups，来自与训练池**不相交**的 held-out skill 池
- 覆盖领域：软件开发调试、数据分析与机器学习、安全、金融与商业分析
- 每个任务在隔离 session 中执行，指定 skills 可用

## 九、关键结论

1. **全面有效**：SKT 在 2 个模型 × 2 个 harness × 4 个 benchmark = 16 个比较中全部提升性能
2. **增益来源清晰**：主要来自改善 skill 利用能力（非知识内化）
3. **数据质量关键**：验证流程不可或缺，未验证数据反而有害（差距达 24.61 分）
4. **跨接口泛化**：学到的 skill 使用行为可迁移到未见过的 agent harness
5. **可扩展**：性能随 skill 覆盖范围扩大而单调提升
6. **多 skill 有效**：在单 skill 和多 skill 协调场景中均有显著收益

## 十、方法论启示

SKT 建立了**验证合成数据作为 skill-use 训练的有效且可扩展方法**的范式。其核心设计哲学是：

- **三重验证**（rule-based + agent-based + difficulty control）确保任务质量
- **双重轨迹验证**确保训练信号的准确性
- **反馈引导修复**而非简单丢弃，提高数据利用率
- **不向重试暴露失败反馈**，避免轨迹合成中的信息泄漏

这为未来利用海量公开 skills 提升 LLM 实际应用能力提供了系统性方法论。
